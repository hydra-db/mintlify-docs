Add fields to an existing database's `database_metadata_schema`. SDK methods: `client.databases.update_metadata_schema()` (Python) and `client.databases.updateMetadataSchema()` (TypeScript). `GET /databases/{database}/metadata-schema` returns the current schema in the same field shape, so you can feed it back into `add_fields`.

<Warning>
  Additive only: it cannot delete or rename fields, or change the type or flags of existing ones. It also cannot add dense or sparse search lanes, because it does not alter the existing vector collections. If a field must take part in semantic or BM25 metadata search, create a database with the final schema and re-ingest into it.
</Warning>

<RequestExample>

```bash cURL
curl -X PATCH 'https://api.hydradb.com/databases/acme_corp/metadata-schema' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "add_fields": [
      {
        "name": "region",
        "data_type": "VARCHAR",
        "enable_match": true
      },
      {
        "name": "priority",
        "data_type": "INT64",
        "enable_match": true
      }
    ]
  }'
```

## Request

### Path parameters

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Database whose metadata schema you are extending. Formerly `tenant_id`, which is still accepted as a deprecated alias. |

### Body

| Name | Description |
| --- | --- |
| <Field name="add_fields" type="array" required /> | Fields to append, at least one. A field that already exists with an identical definition is skipped, so you can resend your full field list. |

Each `add_fields[]` item uses the same field shape as `database_metadata_schema` on [Create Database](/api-reference/v2/endpoint/create-tenant):

| Field | Description |
| --- | --- |
| <Field name="name" type="string" required /> | New metadata key. Must start with a letter, contain only letters, numbers, and underscores (up to 255 characters), and not be a reserved system name. |
| <Field name="data_type" type="string" /> | `VARCHAR`, `BOOL`, `INT8`, `INT16`, `INT32`, `INT64`, `FLOAT`, `DOUBLE`, `JSON`, or friendly aliases such as `string`, `integer`, `float`, `boolean`, `object`. Defaults to `VARCHAR`. `ARRAY` returns `400`; for multi-value fields declare `VARCHAR` and store the values comma-joined. |
| <Field name="max_length" type="integer" /> | Max length for `VARCHAR`. Default `1024`; maximum `65535`. |
| <Field name="enable_match" type="boolean" /> | Enables exact-match metadata filtering on this field. |
| <Field name="enable_dense_embedding" type="boolean" /> | Returns `400` on a new field. Dense lanes can only be declared at [database creation](/api-reference/v2/endpoint/create-tenant). |
| <Field name="enable_sparse_embedding" type="boolean" /> | Returns `400` on a new field. Sparse (BM25) lanes can only be declared at database creation. |
| <Field name="filterable" type="boolean" /> | Legacy shorthand for `enable_match: true`. Prefer `enable_match`. |

## Rules

- Names are compared case-insensitively. A field that differs from the existing one in type, `max_length`, or flags returns `409`, as does one name declared twice in a request with different definitions.
- A database can have at most 32 custom metadata fields. Skipped fields do not count toward the new total.
- Reserved names such as `source_id`, `chunk_id`, `metadata`, and `document_metadata` are rejected.
- The embedding-flag rejection applies to new fields only. Resending an existing field that already has those flags is a no-op.
- MongoDB filter indexes for `enable_match` fields are created before the merged schema is saved.

## Response

A success returns `database`, the deprecated `tenant_id`, and `added_fields` directly, without the `success` and `data` envelope. `added_fields` lists only the fields this call added, so an empty list means the database already had everything you sent. Errors use the standard [error envelope](/api-reference/v2/error-responses).

## Errors

- `400`: an invalid request body (`INVALID_INPUT`), or a field the rules reject: empty `add_fields`, an invalid name or type, `ARRAY`, more than 32 fields, or an embedding flag.
- `404 DATABASE_NOT_FOUND`: the database does not exist.
- `409`: a field conflicts with an existing field or with another entry in the same request, or the database changed during the request. Retry the last case.
- `500`: saving the schema or creating the index failed. Retry.

<Note>
  Apart from a malformed body and a missing database, this endpoint currently returns `error.code: "INTERNAL_ERROR"` for `400`, `409`, and `500` alike. Branch on the HTTP status and read `error.message`, which names the field and the rule it broke.
</Note>
