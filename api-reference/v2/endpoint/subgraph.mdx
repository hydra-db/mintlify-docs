Use this endpoint when a search result needs more context, such as the replies to a Slack message. Pass an ID from [Query](/api-reference/v2/endpoint/query) or [List Context](/api-reference/v2/endpoint/list-documents) to retrieve the starting item, connected items, and their relationships.

The endpoint follows threads, parent-child relationships, and explicit links between sources. For relationships extracted from text, such as service dependencies, use [Inspecting Context Relations](/api-reference/v2/endpoint/source-relations).

<RequestExample>

```python Python SDK
subgraph = client.context.subgraph(
    id="slack_C0BE77_1788320073",
    database="acme_corp",
    collection="eng_slack",
    depth=3,
)
```

```typescript TypeScript SDK
const subgraph = await client.context.subgraph({
  id: "slack_C0BE77_1788320073",
  database: "acme_corp",
  collection: "eng_slack",
  depth: 3,
});
```

```bash cURL
curl -G 'https://api.hydradb.com/context/slack_C0BE77_1788320073/subgraph' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2" \
  --data-urlencode "database=acme_corp" \
  --data-urlencode "collection=eng_slack" \
  --data-urlencode "depth=3"
```

</RequestExample>

## Path parameters

| Name | Description |
| --- | --- |
| <Field name="id" type="string" required /> | The item to start from. Any `id` returned by Query, List Context or Ingest. URL-encode it if it contains reserved characters. An id containing a literal `/` cannot be written as one path segment; pass those as `GET /context/subgraph?id=...` instead (Python and TypeScript SDK 2.1.7 use this form for every id). |

## Query parameters

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Owning database. |
| <Field name="collection" type="string or null" /> | Collection scope. If omitted, the default collection is used. |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22;" /> | Which graph the `id` belongs to. The two graphs are completely separate. (default=`"knowledge"`) |
| <Field name="depth" type="integer" /> | Maximum traversal depth in hops. Range `1` to `10`. (default=`5`) |
| <Field name="max_sources" type="integer" /> | Maximum number of members returned. Range `1` to `1000`. When this clips the traversal, `is_truncated` is `true`. (default=`200`) |
| <Field name="acl" type="string[]" /> | Principals to answer as (document ACLs). The subgraph then contains only items those principals may see, filtered at every hop. Repeated (`acl=a&acl=b`) or comma-separated. Omit for no ACL scoping. |

## How items connect

Each item includes its distance from the starting source in `depth`. The starting source has `depth: 0`.

- `discovered_via` identifies the source that led to this item.
- `discovered_relation` describes the connection, such as `same_thread`, `parent`, `child`, or a link declared at ingestion.

## Reading the response

- `sources[]` contains the starting source and connected items. Pass a `source_id` to [Inspect Context](/api-reference/v2/endpoint/fetch-content) to read its content.
- `relations[]` describes links between those sources, such as thread membership and parent-child relationships.
- `auxiliary_relations[]` includes related people, comments, and attachments.
- `is_truncated` and `auxiliary_truncated` indicate that response limits were reached.

## Errors

Common codes: `400 INVALID_INPUT` (missing `database` or `id`, `depth` outside `1` to `10`, or `max_sources` outside `1` to `1000`), `404 DATABASE_NOT_FOUND`, `500 INTERNAL_ERROR` (a transient graph read failure; retry the request). See [Error Responses](/api-reference/v2/error-responses) for the full list.
