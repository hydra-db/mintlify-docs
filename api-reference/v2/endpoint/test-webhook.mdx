---
title: "Test Webhook"
description: "Send a synthetic test event to the registered endpoint to verify connectivity."
openapi: "api-reference/v2/openapi.json POST /webhooks/indexing/test"
---

Sends a synthetic `indexing.status_changed` event to the registered webhook URL and reports whether your endpoint accepted it. It does not create a real indexing delivery record.

The test payload carries `"test": true` so production receivers can ignore it:

```json
{
  "event": "indexing.status_changed",
  "delivery_id": "test_<random>",
  "id": "test_document",
  "database": "<org_id>",
  "collection": "<org_id>",
  "status": "completed",
  "timestamp": "<ISO-8601 timestamp>",
  "test": true
}
```

<RequestExample>

```bash cURL
curl -X POST 'https://api.hydradb.com/webhooks/indexing/test' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2"
```

</RequestExample>

<ResponseExample>

```json 200
{
  "delivered": true,
  "status_code": 204,
  "message": "Test delivery succeeded."
}
```

</ResponseExample>

## Interpreting the response

| Result | Meaning |
| --- | --- |
| `delivered: true` | Your endpoint returned a `2xx` status; the webhook path works end to end. |
| `delivered: false` | The request failed or your endpoint returned a non-`2xx` status. `status_code` and `message` carry the details. Confirm the URL is public and returns `2xx` quickly. |

If the test succeeds but signed production events fail verification, check that your receiver computes the HMAC over the **raw** request body, not parsed JSON. See the [security checklist](/essentials/v2/webhooks#7-security-checklist).
