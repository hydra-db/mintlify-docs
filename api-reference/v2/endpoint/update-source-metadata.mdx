import { Field } from "/snippets/field.jsx";

Change one source's metadata in place, by ID, without re-ingesting. HydraDB updates the source row and its indexed chunk metadata, so [`/query`](/api-reference/v2/endpoint/query) and [`/context/list`](/api-reference/v2/endpoint/list-documents) filters see the change.

```http
PATCH /context/{id}/metadata
```

<Note>
  The legacy route `PATCH /context/sources/{source_id}/metadata` still works but is deprecated. It runs the same handler, with `source_id` as the `id`.
</Note>

<RequestExample>

```bash cURL
curl -X PATCH 'https://api.hydradb.com/context/policy_main/metadata' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "collection": "team_docs",
    "database_metadata": {
      "department": "legal",
      "priority": 7
    },
    "additional_metadata": {
      "author": "Legal Team",
      "doc_version": 3
    }
  }'
```

```python Python SDK
result = client.context.update_source_metadata(
    "policy_main",
    database="acme_corp",
    collection="team_docs",
    database_metadata={"department": "legal", "priority": 7},
    additional_metadata={"author": "Legal Team", "doc_version": 3},
)
```

```typescript TypeScript SDK
const result = await client.context.updateSourceMetadata({
  id: "policy_main",
  database: "acme_corp",
  collection: "team_docs",
  databaseMetadata: { department: "legal", priority: 7 },
  additionalMetadata: { author: "Legal Team", doc_version: 3 },
});
```

</RequestExample>

## Request

### Path parameters

| Name | Description |
| --- | --- |
| <Field name="id" type="string" required /> | Existing source ID: the `id` you supplied at ingest, or the one HydraDB returned. |

### Body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Owning database. Deprecated alias: `tenant_id`. |
| <Field name="collection" type="string" required /> | Collection that contains the source. No default on this endpoint. Deprecated alias: `sub_tenant_id`. |
| <Field name="database_metadata" type="object" /> | Schema-backed fields to merge into the source's `metadata`. Keys must satisfy the database metadata schema when one exists. Deprecated alias: `tenant_metadata`. |
| <Field name="additional_metadata" type="object" /> | Free-form fields to merge into the source's `additional_metadata`. |
| <Field name="acl" type="string[] or null" /> | Replaces the source's access-control list, so send the complete new list. `[]` or `null` revokes access for everyone. Omit it to keep the stored list. See [Access Control](/essentials/v2/access-control). |

At least one of `database_metadata`, `additional_metadata`, or `acl` is required.

<Warning>
  Send schema-backed fields as `database_metadata`; the `metadata` field from ingest and list is not accepted here. `tenant_metadata` still works as a deprecated alias, and `database_metadata` wins if you send both.

  `document_metadata` is **not accepted** either: any non-null value returns `400`, whatever its size. It is an `additional_metadata` alias on [`/context/ingest`](/api-reference/v2/endpoint/ingest-context) only.
</Warning>

## Behavior

- **Merge, not replace:** keys you send are inserted or overwritten, and keys you omit are kept. `acl` is the exception: it replaces the stored list.
- **One existing source per call:** this endpoint does not create sources or support bulk edits.
- **Dense or sparse fields:** editing a field with `enable_dense_embedding` or `enable_sparse_embedding` synchronously refreshes the matching vector store metadata search lane.
- **Match-only fields:** an edit to `enable_match`-only fields stays in MongoDB, and `vector_sync_required` is `false`.

## Validation and errors

- **`400`:** missing `database` or `collection`, empty metadata payload, `document_metadata` sent, a key the schema does not declare, wrong type, reserved key, payload over the size limit, nesting too deep, or `null` for a dense or sparse enabled field.
- **`404`:** no source with this `id` in the `(database, collection)` scope.
- **`500`:** the edit failed. Retry it.

If the metadata saves but the dense or sparse vector store sync fails, the call still returns `200`, without `vector_synced` and with `vector_sync_error` explaining why. Retry the same edit; it is idempotent and converges.

### Size limits

`database_metadata` (and its `tenant_metadata` alias) is capped at **16 KiB**, and `additional_metadata` at **1 KiB**. Each cap covers the whole map as compact JSON in UTF-8 bytes, so keys, quotes, and punctuation count.

The cap applies to the payload in **this** request, before the merge, not to the stored result, so a small edit to an already large map is accepted. Over the cap, the whole edit fails with `400` and the message reports both numbers:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_INPUT",
    "message": "invalid metadata edit: additional_metadata is too large (1065 bytes when serialized; the maximum is 1024). Reduce the number or size of metadata fields."
  }
}
```

See [Size limits](/essentials/v2/metadata#size-limits) in Scoping using metadata.
