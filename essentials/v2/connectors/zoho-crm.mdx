Sync the Zoho CRM modules you select: leads, contacts, accounts, deals, tasks, cases, notes, and custom and other modules. Each record is one document, with its description and its other visible fields as labeled lines. Each note and each file attached to a record is its own document, linked to that record. Uploaded files in supported formats are read, and their text is searchable.

Zoho CRM sharing and permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. In a module that has only a creation date, edits to older records can be missed. Records deleted in Zoho CRM stay in HydraDB.

<Note>
Zoho CRM is in beta.
</Note>

## Permissions

<Warning>
Zoho CRM permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Zoho CRM module visibility, record owners and record sharing are not reproduced.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Zoho CRM uses an OAuth client id and secret with a refresh token for the account.

<ResponseField name="client_id" type="secret string" required>
The Zoho OAuth client id.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The Zoho OAuth client secret.
</ResponseField>

<ResponseField name="refresh_token" type="secret string" required>
A Zoho OAuth refresh token for the account.
</ResponseField>

<ResponseField name="data_center" type="string">
The Zoho data center of the account, such as `com`, `in`, `eu`, `com.au`, `jp` or `ca`. Defaults to `com`, the US data center. A refresh token works only in its own data center.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create an OAuth client">
    In Zoho, create an OAuth client and generate a refresh token for the account you want to sync.
  </Step>
  <Step title="Create the connector">
    Paste the client id, client secret and refresh token. If your Zoho account is not in the US data center, set `data_center`, or the token is rejected.
  </Step>
  <Step title="Select modules">
    HydraDB lists the modules in the account. Select the ones to sync. Only selected modules sync.
  </Step>
</Steps>

One connector reads one Zoho CRM account.

<Accordion title="Connect through the API">

Use provider `zoho_crm` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default. A module with no modification or creation date is read in full.
- **New and changed items:** A module with a modification date picks up records changed since the last sync. A module with only a creation date picks up new records. A module with neither is read in full on every sync. Files are listed only for records synced in the same sync.
- **Edits:** An edited record updates its document when its module has a modification date or is read in full. In a module with only a creation date, edits to older records can be missed.
- **Deletions:** Records deleted in Zoho CRM stay searchable in HydraDB.
- Zoho users are read on every sync to name record owners. They are not documents of their own.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

### Leads, contacts and accounts

- **One document:** One lead, contact or account.

- **Link back:** The record's URL field, else its website, when it has one. This can be the company's website rather than the record in Zoho CRM.
- **Files:** Files attached to the record are their own documents.

- **Date:** When the note was last modified, else when it was created.

## How it fits into the graph

- Leads, contacts and accounts use the Contact class.
- Deals, tasks and cases use the Ticket class.
- Notes use the Comment class.
- Attachments use the Page class.
- Solutions and custom modules use the Page class.
- Events, meetings and calls use the Meeting class.
- Emails use the Email class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Zoho CRM creates**

- A note to the record it is on, in any module.
- A file to the record it is attached to.
- A deal or contact to its account, and a contact to its account as a member.
- Any record to every record named in its lookup fields, up to 100 per record.
- No links to other tools.

**People and groups**

- A lead or contact stands for that person, identified by name and email.
- The owner of each lead, contact and account.
- The author of each note.
- Owners of other records appear only in their text.

**Found in the text**

Descriptions, note content, the text read from attached files, and the other fields of each record. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Modules you did not select.
- Hidden, unreadable and virtual fields.
- Profiles, roles, territories, currencies and organization settings.
- The contents of link attachments, and the text of files over 50 MiB.
- Files attached to notes.
- Zoho CRM sharing and permissions.
