Sync one Mixpanel project's events, daily funnel results, saved cohorts and project annotations. Each event is one document that names the event, the user and up to 30 of the event's properties. The user's name and email come from their Mixpanel profile when one exists.

Mixpanel permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Events without an insert id can be treated as one event, so some of them can be lost. Annotations sync only with a service account. Cohorts and annotations deleted in Mixpanel stay in HydraDB.

<Note>
Mixpanel is in beta.
</Note>

## Permissions

<Warning>
Mixpanel permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Mixpanel uses the project's API secret. Add a service account as well to sync annotations.

<ResponseField name="api_secret" type="secret string" required>
The Mixpanel project's API secret.
</ResponseField>

<ResponseField name="username" type="string">
A service account's username, from Organization Settings, Service Accounts. Needed to sync annotations.
</ResponseField>

<ResponseField name="password" type="secret string">
That service account's secret. Set it together with `username` and `project_id`.
</ResponseField>

<ResponseField name="project_id" type="string">
The Mixpanel project id, a number. Required when you use a service account.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create a service account, for annotations">
    To sync annotations, create a service account in Mixpanel under Organization Settings, Service Accounts. Without one, everything except annotations syncs.
  </Step>
  <Step title="Create the connector">
    Paste the project's API secret as `api_secret`. If you created a service account, add its username as `username`, its secret as `password`, and the project id as `project_id`.
  </Step>
  <Step title="Configure the connector">
    HydraDB lists one account-wide resource, All data. Select it to sync the whole project the credentials reach.
  </Step>
</Steps>

One connector reads one Mixpanel project.

<Accordion title="Connect through the API">

Use provider `mixpanel` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default. Events and annotations reach back at most 365 days, and funnel results at most 90 days.
- **New and changed items:** Events, funnel results and annotations are read by date. Cohorts are read by when they were created.
- **Edits:** An event read again with the same insert id, or a funnel day read again, replaces its document. A cohort is read by its creation time, so a later edit to an older cohort may not come across. A change to a user's profile does not update events already synced.
- **Deletions:** Deleted cohorts and annotations are not removed. A cohort or annotation deleted in Mixpanel stays searchable in HydraDB.
- If a Mixpanel request keeps failing after retries, the sync fails instead of skipping that data.
- Event times are converted using UTC. The connection form has no project-timezone setting.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Mixpanel item

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `mixpanel`. Not searchable.
</ResponseField>

### Events

- **One document:** One event. An event read again with the same insert id updates the same document. Events without an insert id, as older events can be, may be treated as the same event, and all but one of them lost.
- **Title:** The event name, or `Mixpanel event <id>` when there is none.
- **Text:** `Event`, `User` and `When` lines, then up to 30 of the event's properties in alphabetical order as `property: value`. Mixpanel's `$` and `mp_reserved_` prefixes are removed from property names. The title is searchable too.
- **Date:** The event time in UTC. Times are converted from the project timezone, which defaults to UTC, so events from a project set to another timezone can have shifted times.
- **Link back:** None.
- **Files:** None.

<ResponseField name="event" type="Searchable text">
The event name, written as the title and the `Event` line.
</ResponseField>

<ResponseField name="User" type="Searchable text">
The user's name and email from their Mixpanel profile, as `name (email)`. When no profile name or email is found, for example because the Mixpanel plan has no user profiles, the line shows the raw `distinct_id` instead. Older events keep the name and email they were synced with.
</ResponseField>

<ResponseField name="time" type="Searchable text, Result date">
When the event happened, written as the `When` line. It sets the result date.
</ResponseField>

<ResponseField name="Event properties" type="Searchable text">
Up to 30 non-empty properties with a single value each, such as a plan name. Properties past the 30th, and properties whose value is an object or a list, are not kept or searchable.
</ResponseField>

<ResponseField name="additional_metadata.mixpanel_event" type="Query filter">
The event name. Limits a query to one event name. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.mixpanel_distinct_id" type="Query filter">
The user's `distinct_id`. Limits a query to one user's events, whether or not their profile was found. Not searchable.
</ResponseField>

### Funnel days

- **One document:** One funnel's results for one day.
- **Title:** The funnel name, or `Mixpanel funnel <funnel_id>:<date>` when there is none.
- **Text:** `Funnel` and `Date` lines, then one line per step: `Step N: <step label or event> - count <count>`. The title is searchable too.
- **Date:** The funnel day.
- **Link back:** None.
- **Files:** None.

<ResponseField name="name" type="Searchable text">
The funnel name, written as the title and the `Funnel` line.
</ResponseField>

<ResponseField name="date" type="Searchable text, Result date">
The day, written as the `Date` line. It sets the result date when Mixpanel supplies no date and time for the day.
</ResponseField>

<ResponseField name="datetime" type="Result date">
The date and time Mixpanel supplies for the funnel day. When present, it sets the result date. Not searchable.
</ResponseField>

<ResponseField name="funnel_id" type="Searchable text">
The funnel id. Searchable only in a title used when the funnel has no name.
</ResponseField>

<ResponseField name="additional_metadata.mixpanel_funnel_id" type="Query filter">
The funnel id. Limits a query to one funnel. Not searchable.
</ResponseField>

### Cohorts

- **One document:** One saved cohort.
- **Title:** The cohort name, or `Mixpanel cohort <id>` when there is none.
- **Text:** The `Cohort` line, the description and a `Members` line with the member count. The title is searchable too.
- **Date:** When the cohort was created.
- **Link back:** None.
- **Files:** None. The list of members is not synced.

<ResponseField name="name" type="Searchable text">
The cohort name, written as the title and the `Cohort` line.
</ResponseField>

<ResponseField name="description" type="Searchable text">
The cohort description.
</ResponseField>

<ResponseField name="count" type="Searchable text">
How many members the cohort has, written as the `Members` line.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the cohort was created, as Mixpanel reports it. Not searchable.
</ResponseField>

### Annotations

- **One document:** One project annotation.
- **Title:** The start of the description, up to 80 bytes, or `Mixpanel annotation` followed by its id when there is no description. A long title in a non-Latin script can be cut in the middle of a character.
- **Text:** The annotation's description. The title is searchable too.
- **Date:** The annotation date.
- **Link back:** None.
- **Files:** None.

<ResponseField name="description" type="Searchable text">
The annotation text, which also supplies the title.
</ResponseField>

<ResponseField name="date" type="Result date">
The date the annotation is attached to. Not searchable.
</ResponseField>

**Example searches**

- When did jane@example.com last complete Checkout Completed?
- How many users reached each step of the Onboarding funnel on 2026-11-02?
- What is the Power users cohort, and how many members does it have?

## How it fits into the graph

- Events use the Record class.
- Funnel days use the Record class.
- Cohorts use the Record class.
- Annotations use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Mixpanel creates**

- None. Events are not linked to funnels, cohorts or each other.
- No links to other tools.

**People and groups**

No people are attached to items. The user named in an event's `User` line is part of the text only.

**Found in the text**

The event, funnel, cohort and annotation text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Annotations, when no service account is set.
- Cohort members.
- Daily event counts and retention reports.
- Revenue reports. Mixpanel retired them.
- User profiles as their own documents. A profile only supplies the name and email shown on events.
- Event properties past the 30th, and properties whose value is an object or a list.
- Deletions: cohorts and annotations deleted in Mixpanel stay in HydraDB.
