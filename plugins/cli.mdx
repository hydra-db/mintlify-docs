## Quickstart

The CLI is open source. [Raise an issue](https://github.com/hydra-db/hydradb-cli/issues) or [contribute on GitHub](https://github.com/hydra-db/hydradb-cli).

<Steps>
  <Step title="Install CLI">
    <Tabs>
      <Tab title="curl">
        ```bash
        curl -fsSL https://cli.hydradb.com/install | bash
        ```

        Installs the wheel from the latest [GitHub release](https://github.com/hydra-db/hydradb-cli/releases). Uses `pipx` when available so the CLI stays isolated, and falls back to `pip install --user`.
      </Tab>
      <Tab title="pip">
        ```bash
        pip install https://github.com/hydra-db/hydradb-cli/releases/download/v0.2.0/hydradb_cli-0.2.0-py3-none-any.whl
        ```
      </Tab>
    </Tabs>

    <Note>
      Requires Python 3.10 or later, and `hydradb-cli` 0.2.0 for the commands and flags on this page. See [Deprecated aliases](#deprecated-aliases).

      Do not run `pip install hydradb-cli`. It installs **0.1.0**, which predates every command name on this page. PyPI publishing is paused, so releases are served from GitHub until it resumes.
    </Note>
  </Step>
  <Step title="Get credentials">
    - Create an API key from the [HydraDB dashboard](https://dashboard.hydradb.com/keys)
  </Step>
  <Step title="Authenticate">
    ```bash
    hydradb login
    ```

    Enter your API key at the masked prompt. The key is saved to `~/.hydradb/config.json` with file permissions `0600` (readable and writable only by your account). No database is required to authenticate.

    Scripts and agents can skip login: inject `HYDRADB_API_KEY` through your environment or secret manager. This avoids saving the key to the CLI config or exposing it as a command-line argument in process listings. Set `HYDRADB_DATABASE` separately when a command needs a database.
  </Step>
  <Step title="Verify your config">
    ```bash
    hydradb doctor
    ```

    | Overview of variables | Description | Default |
    | --- | --- | --- |
    | `HYDRADB_API_KEY` | Your HydraDB API key | _Required_ |
    | `HYDRADB_DATABASE` | Default database for scoped commands; not required for login or listing databases | - |
    | `HYDRADB_COLLECTION` | Collection within the database | - |
    | `HYDRADB_BASE_URL` | API base URL | `https://api.hydradb.com` |
    | `HYDRADB_OUTPUT` | Default output format (`human` or `json`) | `human` |
  </Step>
  <Step title="Choose a database after authentication">
    ```bash
    hydradb database list
    hydradb config set database my-db
    ```

    Or create a database with `hydradb database create my-db`, then select it with `hydradb config set database my-db`. Authentication and database selection are separate.
  </Step>
</Steps>

### Output formats

Every command supports `--output human` (default, Rich-formatted tables) or
`--output json` (machine-readable). Set default:

```bash
export HYDRADB_OUTPUT=json
```

Or set it per command, before the subcommand:

```bash
hydradb -o json list --database my-db
```

Human-readable scope notices and diagnostics go to stderr. JSON stdout stays one document you can pipe into `jq`: context commands include the effective `scope`, and API warnings stay in `warnings` (or `response_warnings` if the payload already uses that name). Inspect the returned scope when using defaults or switching databases; a null collection means the API selected the collection without reporting its name.

Payload-owned scope keys are preserved. If the server already returns `scope`, CLI provenance uses `cli_scope`. If the server owns both keys, the CLI returns `{"data": <original response>, "cli_scope": <CLI provenance>}` instead of overwriting either value; all original fields remain under `data`.

## Commands

Every command that reads or writes context takes `--database` to choose the database and `--collection` to scope to a collection within it. Both fall back to your configured defaults, so you can omit them after selecting a scope, not merely after login. If a scoped command has no database, its error explains how to list databases and pass or configure one.

### Context 

| Command | Description |
|---|---|
| `hydradb query` | Query context |
| `hydradb ingest` | Ingest a memory, knowledge text, or one or more knowledge files |
| `hydradb list` | List ingested sources, both knowledge and memories |
| `hydradb inspect SOURCE_ID` | Fetch a source's content by ID |
| `hydradb delete IDS...` | Delete memories or knowledge sources by ID |
| `hydradb relations SOURCE_ID` | Explore context graph relations for a source |
| `hydradb verify IDS...` | Check per-source indexing status |

#### Ingesting

`ingest` uses the client's auto selector by default to choose a request layout, not a backend content classifier. Pass `--type knowledge` or `--type memory` to choose explicitly, or give it file paths: files are always knowledge sources. The CLI's auto selector is not an API `type` value.

```bash
# Route text automatically
hydradb ingest --text "The user prefers dark mode and uses VS Code" --database my-db

# Store knowledge text
hydradb ingest --type knowledge --text "Project uses PostgreSQL 15 with pgvector" --database my-db

# Upload one or more files
hydradb ingest ./docs/architecture.md ./docs/runbook.md --database my-db

# Read from stdin
cat notes.txt | hydradb ingest --database my-db
```

| Option | Description |
|---|---|
| `--type` | Client-side auto selection by default, or choose `knowledge` or `memory` explicitly |
| `--text`, `-t` | Text to ingest. Use `-` to read from stdin |
| `--infer` / `--no-infer` | Extract insights and build the context graph (default on) |
| `--title` | Optional title |
| `--source-id` | Client-assigned source identifier |
| `--user-name` | User name (for memory only) |
| `--markdown` | Treat memory or knowledge text as Markdown |
| `--upsert` / `--no-upsert` | Update existing sources with the same `source_id` (default on) |

<Note>
  `--text`, `--title`, `--source-id`, `--user-name`, `--markdown` and `--no-infer` do not
  apply to file ingest. Passing them alongside file arguments is rejected rather than
  silently ignored.
</Note>

#### Querying

```bash
# Some examples

# Search knowledge
hydradb query "How is authentication implemented?" --type knowledge --database my-db

# Search only memories
hydradb query "What IDE does the user prefer?" --type memory --database my-db

# Deterministic keyword search
hydradb query "PostgreSQL migration" --operator and --database my-db
```

| Command | Description |
| --- | --- |
| `--type` | Context type to query: `memory` or `knowledge`. Omit to search both |
| `--operator` | Keyword operator: `or`, `and`, or `phrase`. Setting it switches the query to keyword (text) search |
| `--max-results`, `-n` | Maximum results, 1 to 50 (default `10`) |
| `--mode`, `-m` | Retrieval mode: `fast` or `thinking`. Omit it and the API picks one per query (`auto`) |
| `--alpha` | Hybrid search weight (`0.0` keyword to `1.0` semantic). Omitted means the API default, `0.8` |
| `--recency-bias` | Preference for newer content (`0.0` to `1.0`). Omitted means `0.6`. Pass `0` to turn it off |
| `--graph-context` / `--no-graph-context` | Include context graph relations. On by default. `--no-graph-context` only takes effect in `fast` mode |
| `--query-explicit-relations` / `--no-query-explicit-relations` | Include or skip deterministically linked sources in thinking mode. On by default |
| `--additional-graph-context` | A factual string hint to guide retrieval, not a filter. `--additional_graph_context` is also accepted |

#### Inspecting

```bash
# List what is stored
hydradb list --type knowledge --database my-db

# Read one source back
hydradb inspect 39e8872d-1c4a-4f0b-9c1e-7d2a5b8e4f10 --database my-db

# Check indexing progress
hydradb verify 39e8872d-1c4a-4f0b-9c1e-7d2a5b8e4f10 --database my-db

# Delete (prompts unless --yes)
hydradb delete 39e8872d-1c4a-4f0b-9c1e-7d2a5b8e4f10 --type knowledge --database my-db --yes
```

`list` accepts `--type`, `--page` and `--page-size` (1 to 100). `inspect` accepts `--mode content` (default), `url`, or `both`. `delete` defaults to `--type knowledge`, so pass `--type memory` to remove a memory.

### Database management

| Command | Description |
|---|---|
| `hydradb database create DATABASE` | Create a new database |
| `hydradb database list` | List all databases for the authenticated user |
| `hydradb database collections [DATABASE]` | List collections within a database |
| `hydradb database stats [DATABASE]` | Row-count statistics |
| `hydradb database readiness [DATABASE]` | Whether the database is provisioned and ready for ingestion |
| `hydradb database monitor [DATABASE]` | Stats and readiness combined |
| `hydradb database delete DATABASE` | Delete a database and all its context (irreversible)<br /><br />Add flag --yes to skip confirmation |

### Authentication and configuration

| Command | Description |
|---|---|
| `hydradb login` | Authenticate and save credentials to `~/.hydradb/config.json` |
| `hydradb logout` | Remove stored credentials |
| `hydradb doctor` | Check resolved config and API reachability |
| `hydradb config show` | Show current CLI configuration |
| `hydradb config set KEY VALUE` | Save a setting. See [Persistent configuration](#persistent-configuration) for the keys |

### Persistent configuration

Use `hydradb config set` for `database`, `collection`, or `base_url`, and `hydradb config show` to inspect the resolved configuration. Environment variables override saved settings; per-command scope flags override both. Set the output format with `HYDRADB_OUTPUT` or `--output`. Use the masked login prompt or `HYDRADB_API_KEY` for credentials.

### Deprecated aliases

`--kind` is the older alias for `--type` on context commands. New scripts should use `--type`. Existing `--tenant-id` and `--sub-tenant-id` scope flags remain aliases for `--database` and `--collection`.

For query hints, `--additional-graph-context` takes precedence over the older `--additional-context` and `--context` flags, including when the canonical hint is empty. For linked-source retrieval, `--query-explicit-relations` / `--no-query-explicit-relations` take precedence over the older `--follow-forceful-relations` and `--query-forceful-relations` pairs. Explicit `false` is preserved. Conflicting `--type` and `--kind` values are rejected rather than guessed.

## Scripting and automation

Use `--output json` to pipe results into `jq`, Python, or other tools:

```bash
# List sources as JSON and pull out their IDs
hydradb -o json list --database my-db | jq '.sources[].id'

# Query and extract just the matched text
hydradb -o json query "user preferences" --type memory --database my-db \
  | jq '.chunks[].chunk_content'

# Batch upload: ingest accepts many files in one invocation
hydradb ingest ./docs/*.md --database my-db

# Or drive it from find
find ./docs -name "*.md" -exec hydradb ingest --database my-db {} +
```

`query` returns `chunks`, each with `chunk_content`, `source_title` and
`relevancy_score`. `list` returns `sources`. Both memories and knowledge appear in the
same `sources` array, distinguished by their `type`.
