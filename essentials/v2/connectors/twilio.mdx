Sync the communication logs of one Twilio account and the subaccounts its credentials can reach. Each SMS or MMS message, each voice call, each conference and each debugger alert is one document. A call includes the text of Twilio's own transcriptions of its recordings. HydraDB does not transcribe audio, and recordings and MMS media files are not downloaded.

Twilio permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Phone numbers are searchable text, not people. Items deleted in Twilio stay in HydraDB.

<Note>
Twilio is in beta.
</Note>

## Permissions

<Warning>
Twilio permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Twilio uses your Account SID and Auth Token.

<ResponseField name="account_sid" type="string" required>
The Twilio Account SID.
</ResponseField>

<ResponseField name="auth_token" type="secret string" required>
The account's Auth Token.
</ResponseField>

**Connector settings**

<ResponseField name="messages_update_overlap_hours" type="string">
Hours of message history each sync reads again to catch later changes, such as a new delivery status. Sent as a string. 168 by default. `0` turns the overlap off.
</ResponseField>

<ResponseField name="recordings_update_overlap_hours" type="string">
Hours of recording history each sync reads again to catch later changes. Sent as a string. 24 by default. `0` turns the overlap off.
</ResponseField>

<Accordion title="Connector-wide defaults (1)">

<ResponseField name="user_agent" type="string">
The user agent sent to Twilio. A default is set.
</ResponseField>

</Accordion>

### Set it up

<Steps>
  <Step title="Copy your credentials">
    In the Twilio console, copy the Account SID and Auth Token.
  </Step>
  <Step title="Create the connector">
    Enter `account_sid` and `auth_token`.
  </Step>
  <Step title="Select the account">
    HydraDB offers one resource that covers the whole account. Select it to sync.
  </Step>
</Steps>

One connector reads one Twilio account, plus every subaccount its credentials can reach. You cannot pick subaccounts one by one.

<Accordion title="Connect through the API">

Use provider `twilio` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Messages are found by send time. Calls, conferences and alerts are found by their last update. After the first sync, each sync also reads the last `messages_update_overlap_hours` of messages again.
- **Edits:** A message update, such as a new delivery status, is caught when it happens inside the overlap. An update to a call that ended long ago is not guaranteed to be picked up. A new recording or transcription does not on its own update a call that is already synced. A change to a message's media or a conference's participants updates that message or conference.
- **Deletions:** Messages, calls, conferences and alerts deleted in Twilio stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Twilio item

<ResponseField name="additional_metadata.twilio_sid" type="Query filter">
The message, call, conference or alert SID. Picks out one item. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `twilio`. Not searchable.
</ResponseField>

### Messages

- **One document:** One SMS or MMS message.
- **Title:** The message text, or `Twilio message` and its SID. Search matches the message text, not this title.
- **Text:** `SMS` with the direction, then `From:` with the sending number and `to` with the receiving number, then the message text, then `Media:` with each attachment's content type. The send time is written as a Sent line when Twilio reports one.
- **Date:** When the message was sent, else when it was created, else when it was last updated.
- **Link back:** None.
- **Files:** MMS media is listed by content type. The files are not downloaded.

<ResponseField name="from" type="Searchable text">
The sending number. It is text only and is not attached as a person in the graph.
</ResponseField>

<ResponseField name="to" type="Searchable text">
The receiving number. It is text only and is not attached as a person in the graph.
</ResponseField>

<ResponseField name="direction" type="Searchable text">
The direction, such as `inbound` or `outbound-api`.
</ResponseField>

<ResponseField name="sent_at" type="Searchable text, Result date">
When the message was sent, written as the Sent line when present.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When Twilio created the message. The result date when the send time is missing. Not searchable.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the message last changed. The result date only when the send and creation times are both missing. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="status" type="Stored only">
The delivery status, such as `delivered` or `failed`. It is not searchable and not a filter.
</ResponseField>

<ResponseField name="media_count" type="Stored only">
How many media items came with the message.
</ResponseField>

</Accordion>

### Calls

- **One document:** One voice call.
- **Title:** `Call`, the direction and the phone numbers that are available. With no numbers, `Twilio call` and its SID.
- **Text:** `Call` with the direction, `From:` and `To:` numbers, `Status:`, `Duration:` in seconds, `Caller:` and `Answered By:`. Then `Transcript:` with the text of every Twilio transcription of the call's recordings. The creation time is written as a Started line. The title is searchable too.
- **Date:** When the call started, else when it was created, else when it was last updated.
- **Link back:** None.
- **Files:** None. Recordings are not downloaded. Only Twilio's own transcription text is used.

<ResponseField name="from" type="Searchable text">
The caller's number, formatted when available. In the title and the text. Not attached as a person.
</ResponseField>

<ResponseField name="to" type="Searchable text">
The called number. In the title and the text. Not attached as a person.
</ResponseField>

<ResponseField name="direction" type="Searchable text">
The call's direction. In the title and the text.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The call status, such as `completed`, `no-answer` or `busy`, written as the Status line.
</ResponseField>

<ResponseField name="duration" type="Searchable text">
The call length in seconds, written as the Duration line.
</ResponseField>

<ResponseField name="start_time" type="Result date">
When the call started. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When Twilio created the call record, written as the Started line. It can differ from the actual start. The result date when the start time is missing.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the call record last changed. The result date only when the start and creation times are both missing. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="end_time" type="Stored only">
When the call ended.
</ResponseField>

<ResponseField name="has_transcript" type="Stored only">
Whether transcription text was included.
</ResponseField>

</Accordion>

### Conferences

- **One document:** One conference call.
- **Title:** The conference's friendly name, or `Twilio conference` and its SID.
- **Text:** `Status:`, `Region:` and `Ended:` with the reason, then `Participants:` with each participant's label and call SID. The creation time is written as a Started line. The title is searchable too.
- **Date:** When the conference was last updated, else when it was created.
- **Link back:** None.

<ResponseField name="participants" type="Searchable text, Graph identity">
The participants' labels, written as the Participants line. The graph records each as a participant, by label, not by email address.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The conference status, written as the Status line.
</ResponseField>

<ResponseField name="started_at" type="Searchable text">
When the conference was created, written as the Started line.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the conference last changed. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the conference was created. The result date when the update time is missing. Not searchable as its own field, though the same time is the Started line.
</ResponseField>

### Alerts

- **One document:** One Twilio debugger alert, an error or a warning.
- **Title:** The alert text, or `Twilio alert` and its SID.
- **Text:** The alert text, then `Level:`, `Error code:`, `Request:` with the method and URL, and `More info:` with a link. The alert SID is written as a Key line, the log level as Status and Priority lines, and the time as a Created line. The title is searchable too.
- **Date:** When the alert was last updated, else when it was generated.
- **Link back:** The alert's address in Twilio's API.

<ResponseField name="SID" type="Searchable text">
The alert's SID, written as the Key line.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The log level, written as the Status line.
</ResponseField>

<ResponseField name="priority" type="Searchable text">
The log level, written as the Priority line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the alert was generated, else when Twilio created it, written as the Created line. The result date when the update time is missing.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the alert last changed. Not searchable.
</ResponseField>

**Example searches**

- Which outbound calls went unanswered yesterday?
- What did the caller say on the recorded support call this morning?
- What errors did our Twilio account raise about the request URL?

## How it fits into the graph

- Messages use the Message class.
- Calls use the Meeting class.
- Conferences use the Meeting class.
- Alerts use the Ticket class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Twilio creates**

The connector creates no links. A call is not linked to its conference or recordings: transcription text is part of the call document.

**People and groups**

- Conference participants, by their labels.
- Phone numbers are text only. They are not attached as people.

**Found in the text**

Message text, call details and transcripts, conference details and alert text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Recording audio and MMS media files.
- Transcripts of recordings that Twilio did not transcribe. HydraDB does not transcribe audio.
- Phone number inventories, balances, keys, usage records, addresses, applications, queues and other account configuration.
- Deletions: items deleted in Twilio stay in HydraDB.
