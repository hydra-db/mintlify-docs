## What syncs

**Indexed object types**

- `users`
- `groups`
- `applications`
- `system_logs`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Create an API token: Okta admin console → Security → API → Tokens → Create Token. There is no scope picker and no role selector on that dialog; the token silently inherits the role of whoever creates it.
2. That inheritance is the thing to get right. To get a least-privilege token you must be signed in AS a Read-only Administrator when you mint it; minting as a Super Admin gives you a Super Admin token with nothing in the UI saying so. Check the Role column in the token list afterwards to confirm what you actually created.
3. The create form has a required dropdown, "API calls made with this token must originate from". Leaving it unset fails with only "We found some errors" and no indication of which field. Choose Any IP unless you have defined an Okta network zone covering HydraDB's egress addresses.
4. Set the org URL to your own org host, keeping the /api/v1/ path and the trailing slash: `https://<org>.okta.com/api/v1/` . The -admin host answers the API too, so either hostname works; the path and trailing slash are the part that matters.
5. Two expiry traps. The token is bound to its creating user, so deactivating that person breaks the sync with 403s. And Okta expires a token after 30 days of no use, while the admin session itself is short-lived; so mint it and paste it in one sitting.
6. Nothing is picked after connecting: Okta syncs the whole org. Users, groups, applications and system log events are indexed, with group membership, app assignments and MFA enrolment folded into the user, group and application records.

Use provider `okta` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
