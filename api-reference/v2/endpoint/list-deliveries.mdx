Lists delivery attempts for this API key's webhook, newest first. Use it to audit what was sent, find failures worth retrying, and confirm events were delivered without checking your own receiver logs.

<RequestExample>

```bash List deliveries
curl 'https://api.hydradb.com/webhooks/indexing/deliveries?limit=20' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2"
```

```bash Only failed deliveries
curl 'https://api.hydradb.com/webhooks/indexing/deliveries?limit=20&status=failed' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2"
```

```bash Next page
curl 'https://api.hydradb.com/webhooks/indexing/deliveries?limit=20&cursor=<next_cursor>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2"
```

</RequestExample>

## Query parameters

| Name | Description |
| --- | --- |
| <Field name="limit" type="integer" /> | Number of deliveries to return, between `1` and `100`. |
| <Field name="status" type="string" /> | Filter by delivery state: `pending`, `sweeping`, `delivered`, `failed`, or `permanently_failed`. |
| <Field name="cursor" type="string" /> | Pagination cursor. Pass the `next_cursor` from the previous response to fetch the next page. |

<ResponseExample>

```json 200
{
  "deliveries": [
    {
      "delivery_id": "<delivery_id>",
      "doc_id": "<id>",
      "status": "delivered",
      "indexing_status": "completed",
      "event_type": "indexing.status_changed",
      "attempts": 1,
      "error_code": null,
      "error_message": null,
      "created_at": "<ISO-8601 timestamp>",
      "updated_at": "<ISO-8601 timestamp>"
    }
  ],
  "count": 1,
  "next_cursor": null
}
```

</ResponseExample>

When `next_cursor` is not `null`, pass it back as `cursor` to fetch the next page.

<Note>
Delivery history uses `doc_id` internally. The outbound webhook payload sent to your endpoint uses `id` for the same value  -  the ID you supplied during ingestion.
</Note>

## Delivery states

| State | Meaning |
| --- | --- |
| `pending` | The event was recorded and is waiting to be sent. |
| `sweeping` | HydraDB has claimed the event for delivery or retry. |
| `delivered` | Your endpoint returned a successful status code. |
| `failed` | The current send attempt failed and will be retried. |
| `permanently_failed` | HydraDB stopped retrying this event. |
