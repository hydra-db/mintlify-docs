Page through the items stored in one database and collection, for example to find IDs or audit what was ingested. Every item is listed under `sources`, whether you sent it as a context item, uploaded it as a file, or a connector synced it. Do not send `type`.

Narrow results with `ids` and `filters`, and return only the fields you need with `include_fields`. See [Metadata Filters](/essentials/v2/metadata#list-contextlist) for the metadata workflow.

<RequestExample>

```python Python SDK
items = client.context.list(
    database="acme_corp",
    collection="user_alex",
    page=1,
    page_size=50,
    filters={
        "source_fields": {"context_category": "user_preference"},
    },
    include_fields=["title", "timestamp", "additional_metadata", "context_category"],
)
```

## Filters

`filters` accepts three categories:

```json
{
  "filters": {
    "metadata": { "department": "Finance", "region": "US" },
    "additional_metadata": { "author": "Alice Smith" },
    "source_fields": { "app_provider": "slack", "title": "standup notes" }
  }
}
```

- `metadata`: schema-backed fields, which an item carries as `attributes` at ingest.
- `additional_metadata`: free-form fields, which an item carries as `custom_attributes` at ingest. No schema declaration is required.
- `source_fields`: built-in and connector fields. Supported keys are `type`, `title`, `description`, `url`, `timestamp`, `context_category`, `app_provider`, `app_kind`, `app_external_id`, and `app_parent_id`. Unsupported keys return `400`. Pair external IDs with `app_provider`.

Matching rules:

- Values must match exactly, except `source_fields.title`, which matches a case-insensitive prefix.
- All filter pairs combine with AND. When `ids` is non-empty, filters apply only to those IDs, and pagination still applies.
- Range, contains, and OR operators are not supported. For OR behavior, run separate calls and combine the results in your application.
- A `null` filter value returns `400`.

## Field projection

Pass `include_fields` to keep response payloads small. Only the listed fields are populated, plus `id`, `database`, and `collection`, which are always returned. Treat omitted fields as unavailable in that response. Omit `include_fields` or pass `null` to return everything.

- Allowed values are `title`, `type`, `description`, `note`, `timestamp`, `metadata`, `additional_metadata`, `context_category`, and `relations`, plus the deprecated aliases `tenant_metadata` and `document_metadata`.
- `content`, `url`, and `attachments` are not valid values. They are stripped from list responses, and requesting one returns `400`. Fetch them per item with [Inspect Context](/api-reference/v2/endpoint/fetch-content).

## Behavior notes

- **Item content:** A row carries the item's ID, title, and metadata, not its text. Read the text and `inferred_content` with [Inspect Context](/api-reference/v2/endpoint/fetch-content).
- **`context_category`:** Present on an item you labeled at ingest. Absent when you sent no label or `auto`.
- **Access control:** `acl` lists the principals to list as. Omitting it, or sending `[]` or `["*"]`, disables caller-supplied filtering. For enforced connectors, the authenticated caller is used instead; see [ACL enforcement](/essentials/v2/connectors#enforce-acl).
- **Limits:** `ids` accepts at most `100` IDs. `page_size` ranges from `1` to `100` (default `50`), and `page` starts at `1`.
