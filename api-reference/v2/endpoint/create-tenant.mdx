## Request body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Account-scoped database identifier, up to 255 characters. Only lowercase letters, digits, `-`, and `_` are allowed; anything else, including uppercase or spaces, returns `400`. Formerly `tenant_id`, which is still accepted as a deprecated alias. |
| <Field name="database_metadata_schema" type="array" /> | Defines database-level metadata fields. See [Scoping using metadata](/essentials/v2/metadata#step-1a-declare-the-schema-at-database-creation) for schema parameters. Formerly `tenant_metadata_schema`, which is still accepted as a deprecated alias. (default=`null`) |

## Successful response

Creation is asynchronous. Poll [Database Status](/api-reference/v2/endpoint/tenant-status) until the database is ready before you use it.

## After you create a database

- **Default collection:** no collection exists until your first write. The first time you ingest without an explicit `collection`, HydraDB creates the database's default collection, which then stores all context written without a `collection`. Create more collections at any time to scope data to users, teams, or projects.
- **Retry failed databases:** if a database appears in `data.failed_databases` from [List Databases](/api-reference/v2/endpoint/list-tenants), fix the reported issue and re-create it with `POST /databases`. Poll status again before ingestion.
- **Ingest, then wait for indexing:** once the database is ready, start [ingesting context](/api-reference/v2/endpoint/ingest-context). Check [ingestion status](/api-reference/v2/endpoint/source-status) and start querying once the new sources show `graph_creation` (already searchable) or `completed`.

## Defining a metadata schema

<Warning>
  Schema field names are **immutable** after database creation. You can add per-document free-form metadata at ingestion time, and add new database-level fields later with [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema). Updates are additive only: no delete, rename, or type change. Dense and sparse search lanes (`enable_dense_embedding`, `enable_sparse_embedding`) can only be declared here, at creation. Plan your schema before you create the database.
</Warning>

A schema enables exact-match metadata filtering (`enable_match`) or semantic and BM25 search over metadata text fields (`enable_dense_embedding` and `enable_sparse_embedding`). For data types, limits, shorthand flags, and examples, see the [metadata](/essentials/v2/metadata) guide.

Each `enable_dense_embedding` or `enable_sparse_embedding` flag adds one vector field, and a database can have at most 6. A field with both flags uses two. Going over returns `400`, as does declaring an `ARRAY` field.

## Errors

- `400 INVALID_INPUT`: missing or invalid `database`, or an invalid schema.
- `403 FORBIDDEN`: your plan's database limit is reached.
- `409 DATABASE_ALREADY_EXISTS`: the `database` is already in use. The deprecated `POST /tenants` route returns `INVALID_INPUT` here instead.
- `500 INTERNAL_ERROR`: retry. If the message says the rollback also failed, delete the database first, then create it again.
