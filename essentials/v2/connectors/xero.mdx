Sync contacts, invoices, payments and bank transactions from one Xero organisation. Each record is one document. Invoices and bank transactions link to their contact, and payments link to the invoice they settle. Files attached to contacts, invoices and bank transactions are separate documents, and their text is searchable when the file can be downloaded and read.

Xero permissions are not imported, so every synced record is visible to everyone who can query the collection unless you set an access rule. Records deleted in Xero stay in HydraDB. Accounts, items, credit notes, quotes and other Xero objects are not synced.

<Note>
Xero is in beta.
</Note>

## Permissions

<Warning>
Xero permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Xero uses the client id and client secret of a Xero developer app, with a refresh token and the id of the organisation you connect.

<ResponseField name="client_id" type="secret string" required>
The client id of your Xero app, from its Configuration page.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The client secret of the same app.
</ResponseField>

<ResponseField name="refresh_token" type="secret string" required>
A refresh token from completing Xero's OAuth flow for the organisation.
</ResponseField>

<ResponseField name="tenant_id" type="secret string" required>
The id of the Xero organisation the tokens belong to.
</ResponseField>

<ResponseField name="access_token" type="secret string">
Leave it empty. HydraDB obtains access tokens itself.
</ResponseField>

A Xero refresh token can be used only once. Each time it is used, Xero issues a new one, and HydraDB stores it itself.

### Set it up

<Steps>
  <Step title="Create a Xero app">
    In the Xero developer portal, create an app and copy its client id and client secret.
  </Step>
  <Step title="Authorise the organisation">
    Complete Xero's OAuth flow for the organisation you want to connect. Copy the refresh token and the organisation's tenant id.
  </Step>
  <Step title="Create the connector">
    Paste the values as `client_id`, `client_secret`, `refresh_token` and `tenant_id`. Saving the connector does not test the credentials, because a test would use up the single-use refresh token. The first sync is the test.
  </Step>
  <Step title="Select the organisation">
    Select the `All data` resource. It syncs contacts, invoices, payments, bank transactions and their attached files together. You cannot select individual contacts or invoices.
  </Step>
</Steps>

One connector reads one Xero organisation.

<Accordion title="Connect through the API">

Use provider `xero` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads contacts, invoices, payments and bank transactions updated since the last sync. Attached files are checked for the contacts, invoices and bank transactions in that window.
- **Edits:** An updated record replaces its document.
- **Deletions:** Deleted records are not removed. A record deleted in Xero stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Xero item

<ResponseField name="additional_metadata.xero_id" type="Query filter">
The Xero id: the contact id, the invoice, payment or bank transaction id, or the attachment id. Finds one record. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's records. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `xero`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="stream_type" type="Stored only">
The record type, such as `contacts` or `invoices`.
</ResponseField>

<ResponseField name="Other Xero fields" type="Stored only">
The other fields HydraDB reads from Xero for the record. Kept for inspection only. A query does not match them and cannot filter on them.
</ResponseField>

</Accordion>

### Contacts

- **One document:** One contact: a customer or a supplier.
- **Title:** The contact's name. Otherwise the first and last name.
- **Text:** Contact details: the name, first and last name, email, phone numbers, lifecycle stage (the contact status), URL (the website), whether the contact is a person or an organization, the organization name and the update time. Then the name again, followed by `Email`, `Phones`, `Website`, `Status` and `Account number` lines. The title is searchable too.
- **Date:** When the contact was last updated in Xero.
- **Link back:** None.
- **Files:** Files attached to a contact arrive as separate attachment documents linked to it.

<ResponseField name="display_name" type="Searchable text, Graph identity">
The contact's name. It forms the title, and names a person contact in the graph.
</ResponseField>

<ResponseField name="first_name" type="Searchable text, Graph identity">
The contact's first name. Forms the title when there is no name, and makes the contact a person.
</ResponseField>

<ResponseField name="last_name" type="Searchable text, Graph identity">
The contact's last name. Forms the title when there is no name, and makes the contact a person.
</ResponseField>

<ResponseField name="email" type="Searchable text, Graph identity">
The contact's email address. Identifies a person contact in the graph.
</ResponseField>

<ResponseField name="entity_type" type="Searchable text, Graph identity">
Person when the contact has a first or last name, otherwise organization. Decides whether the graph records the contact as a person.
</ResponseField>

<ResponseField name="provider_user_id" type="Searchable text, Graph identity">
The Xero contact id. Identifies a person contact in the graph. An organization contact is not made a person from it.
</ResponseField>

<ResponseField name="phones" type="Searchable text">
The contact's phone numbers, without their area and country codes joined on.
</ResponseField>

<ResponseField name="organization_name" type="Searchable text">
The contact's name, when it differs from the person's name. Adds the organization to the contact details. It does not link the person to a separate company.
</ResponseField>

<ResponseField name="ContactStatus, Website, AccountNumber" type="Searchable text">
The contact's status, website and account number.
</ResponseField>

<ResponseField name="UpdatedDateUTC" type="Searchable text, Result date">
When the contact was last updated. It is the result date and appears in the contact details as `Updated`.
</ResponseField>

### Invoices

- **One document:** One sales or purchase invoice.
- **Title:** `Invoice <number> - <contact>`. When a part is missing, the record type and id are used instead.
- **Text:** The reference, then `Contact`, `Type`, `Status`, `Total` and `Amount due` with the currency, `Due date` and `Line items` lines. The title is searchable too.
- **Date:** When the invoice was last updated in Xero.
- **Link back:** The URL set on the invoice in Xero, when there is one. Otherwise none.
- **Files:** Files attached to an invoice arrive as separate attachment documents linked to it.

<ResponseField name="Contact" type="Searchable text, Graph connection">
The contact the invoice belongs to. Its id links the invoice to the contact's document. Its name is in the title and the `Contact` line. The id itself is not searchable.
</ResponseField>

<ResponseField name="InvoiceNumber" type="Searchable text">
The invoice number, in the title.
</ResponseField>

<ResponseField name="Line items" type="Searchable text">
Each line's description. Quantities, prices and account codes are stored but not searchable.
</ResponseField>

<ResponseField name="UpdatedDateUTC" type="Result date">
When the invoice was last updated. Not searchable.
</ResponseField>

### Payments

- **One document:** One payment against an invoice.
- **Title:** `Payment <amount> <currency> - <contact>`. When a part is missing, the record type and id are used instead.
- **Text:** The reference, then `Contact`, `Invoice` (the invoice number), `Amount`, `Type`, `Status` and `Date` lines. The title is searchable too.
- **Date:** When the payment was last updated in Xero.
- **Link back:** None.

<ResponseField name="Invoice" type="Searchable text, Graph connection">
The invoice the payment settles. Its id links the payment to the invoice's document. The invoice number and contact name are in the text, and the contact name can be in the title.
</ResponseField>

<ResponseField name="Amount" type="Searchable text">
The payment amount, with its currency when Xero supplies one. In the title and the `Amount` line.
</ResponseField>

<ResponseField name="UpdatedDateUTC" type="Result date">
When the payment was last updated. Not searchable.
</ResponseField>

### Bank transactions

- **One document:** One bank transaction.
- **Title:** `Bank transaction - <contact>`. When a part is missing, the record type and id are used instead.
- **Text:** The reference, then `Contact`, `Type`, `Status`, `Total`, `Date` and `Line items` lines. The title is searchable too.
- **Date:** When the transaction was last updated in Xero.
- **Link back:** The URL set on the transaction in Xero, when there is one. Otherwise none.
- **Files:** Files attached to a bank transaction arrive as separate attachment documents linked to it.

<ResponseField name="Contact" type="Searchable text, Graph connection">
The contact the transaction belongs to. Its id links the transaction to the contact's document. Its name is in the title and the `Contact` line. The id itself is not searchable.
</ResponseField>

<ResponseField name="Line items" type="Searchable text">
Each line's description. Quantities, prices and account codes are stored but not searchable.
</ResponseField>

<ResponseField name="UpdatedDateUTC" type="Result date">
When the transaction was last updated. Not searchable.
</ResponseField>

### Attached files

- **One document:** One file attached to a contact, an invoice or a bank transaction.
- **Title:** The file name, or the attachment id when there is none.
- **Text:** When the file is read, its text, followed by a `Data` section with the parent record's id and type. When it is not read, `Parent`, `Parent type`, `File` and `Content type` lines. The title is searchable either way.
- **Date:** None. HydraDB does not keep when a file was added or changed.
- **Link back:** None that opens in the Xero app.
- **Files:** Supported files are downloaded and read. When a file cannot be downloaded or read, only its details are searchable.

<ResponseField name="File text" type="Searchable text">
The text read from the file, such as a receipt PDF.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The Xero id of the contact, invoice or bank transaction the file is attached to. Links the file to that record, and the graph places the file under it. Not a query filter.
</ResponseField>

<ResponseField name="ParentType" type="Searchable text">
`contacts`, `invoices` or `bank_transactions`: the kind of record the file is attached to.
</ResponseField>

<ResponseField name="MimeType" type="Searchable text">
The file's media type. Searchable only when the file was not read. Otherwise kept for inspection.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="ContentLength" type="Stored only">
The file size in bytes.
</ResponseField>

</Accordion>

**Example searches**

- What is still due on invoice INV-0042 for Acme Ltd?
- Which payments settled invoice INV-0042, and when?
- What is the email and phone number for supplier Office Supplies Co?

## How it fits into the graph

- Contacts use the Contact class.
- Invoices use the Page class.
- Payments use the Page class.
- Bank transactions use the Page class.
- Attached files use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Xero creates**

- An invoice to its contact.
- A bank transaction to its contact.
- A payment to the invoice it settles.
- An attached file to its contact, invoice or bank transaction, and under that record.
- No links to other tools.

**People and groups**

- Each contact with a first or last name, as a person, identified by name, email and Xero contact id.
- Other contacts are organizations. A person contact is not linked to a separate company.

**Found in the text**

References, line descriptions, contact details and the text of attached files. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Accounts, items, credit notes, purchase orders, quotes, journals, manual journals and other Xero objects.
- Files attached to anything other than contacts, invoices and bank transactions.
- Deletions: records deleted in Xero stay in HydraDB.
- When an attached file was added or changed.
