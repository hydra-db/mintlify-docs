Sync the meetings booked through Calendly in one organization. Each scheduled meeting is one document that combines its time, location, hosts and guests with the event type's description and every invitee's booking-form answers and cancellation reasons.

Calendly permissions are not imported, so every synced meeting is visible to everyone who can query the collection unless you set an access rule. Canceled meetings stay in HydraDB, marked canceled, with their cancellation reasons. A change to only an invitee or an event type does not update a meeting's document until the meeting itself changes.

<Note>
Calendly is in beta.
</Note>

## Permissions

<Warning>
Calendly permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Calendly uses a personal access token and your organization's Calendly API URI.

<ResponseField name="auth_token" type="secret string" required>
A Calendly personal access token.
</ResponseField>

<ResponseField name="organization_url" type="string" required>
Your organization's Calendly API URI, in the form `https://api.calendly.com/organizations/<uuid>/`. It limits the sync to that organization.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create a personal access token">
    Create a Calendly personal access token.
  </Step>
  <Step title="Find your organization URI">
    Find your own organization's API URI, in the form `https://api.calendly.com/organizations/<uuid>/`.
  </Step>
  <Step title="Create the connector">
    Paste the token as `auth_token` and the URI as `organization_url`.
  </Step>
  <Step title="Select the organization">
    HydraDB lists one item for the whole organization. Select it. You cannot pick individual meetings.
  </Step>
</Steps>

One connector reads one Calendly organization.

<Accordion title="Connect through the API">

Use provider `calendly` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads meetings updated within the window set by `lookback_days`, 30 days by default. Meetings with no update time are read regardless.
- **New and changed items:** Each sync reads the meetings, invitees and event types updated since the last sync.
- **Edits:** A meeting whose update time changes is read again and rebuilt with its current event type and invitees. A change to only an invitee or an event type does not update the meeting's document until the meeting itself changes.
- **Deletions:** A canceled meeting stays in HydraDB with its status and any cancellation reasons. Meetings deleted in Calendly stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Meetings

- **One document:** One scheduled meeting, with its invitees.
- **Title:** The meeting name, or `Calendly event <uri>` when it has none.
- **Text:** The meeting name, a `Status` line, a `When` line with the start and end, a `Location` line, `Hosts` and `Guests` lines, and the event type's description. Then each invitee with name or email, status, cancellation reason and answered booking questions, then the meeting notes. The event type's name appears only when it has a description. The title is searchable too.
- **Date:** When the meeting was last updated, else when it starts.
- **Link back:** The meeting's join link, such as a Zoom or Google Meet link, not a Calendly page. It can be empty, for example for an in-person meeting.
- **Files:** None.

<ResponseField name="status" type="Searchable text">
`active` or `canceled`, written as the `Status` line.
</ResponseField>

<ResponseField name="start_time" type="Searchable text, Result date">
When the meeting starts, written in the `When` line. Sets the result date when the meeting has no update time.
</ResponseField>

<ResponseField name="end_time" type="Searchable text">
When the meeting ends, written after the start in the `When` line when there is a start.
</ResponseField>

<ResponseField name="hosts" type="Searchable text">
Host names, or emails when there is no name, written as the `Hosts` line. Hosts are not attached to the meeting as people in the graph.
</ResponseField>

<ResponseField name="location" type="Searchable text">
The location type, such as `zoom` or `physical`, written as the `Location` line.
</ResponseField>

<ResponseField name="join_url" type="Searchable text">
The join link. Used as the link back, and written in the `Location` line when the meeting has a location type.
</ResponseField>

<ResponseField name="event_type_name" type="Searchable text">
The event type's name, written before its description when the description is not empty. To limit a query to one event type, filter on `additional_metadata.container_name`.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the meeting was last updated. Sets the result date and decides which meetings each sync reads. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.calendly_uri" type="Query filter">
The meeting's Calendly API URI. Picks out one meeting. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
The event type's URI, also kept as `event_type`. Limits a query to meetings of one event type. It does not link meetings together. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_name" type="Query filter">
The event type's name. Limits a query to an event type by name. Not searchable under this key.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
Always `event_type`. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's meetings. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `calendly`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="created_at" type="Stored only">
When the meeting was booked, as distinct from when it takes place.
</ResponseField>

<ResponseField name="invitee_count" type="Stored only">
How many invitees with a name or email were found when the document was built.
</ResponseField>

</Accordion>

**Example searches**

- Who booked a demo with us this week and what did they say they need?
- Why did invitees cancel their onboarding calls last month?
- Which meetings are booked under the Intro call event type?

## How it fits into the graph

- Meetings use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Calendly creates**

No links between meetings or to other tools. The event type is a query filter, not a link.

**People and groups**

The connector does not attach hosts, guests or invitees to a meeting as people. Their names and emails are part of the meeting text.

**Found in the text**

The whole meeting text, including who booked, their booking answers and why they cancelled. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Routing forms, organization memberships and user records.
- Event types and bookings as documents of their own.
- Meetings last updated before the first sync's window.
- Calendly sharing permissions.
- Deletions: meetings deleted in Calendly stay in HydraDB.
