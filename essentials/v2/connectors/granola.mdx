Sync Granola meeting notes from the folders you select. Each note is one document with the meeting details, Granola's AI summary and the transcript, each line labelled with its speaker.

Granola sharing is not imported, so every synced note is visible to everyone who can query the collection unless you set an access rule. Only notes the API key can see are synced, and only Business and Enterprise plans can create a key. Notes deleted in Granola can stay in HydraDB.

<Note>
Granola is in beta.
</Note>

## Permissions

<Warning>
Granola permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- An access rule set on a folder applies to the notes that folder's sync returned. A note in several selected folders follows the rule of the first selected folder that returned it.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Granola uses an API key. Only Business and Enterprise plans can create one.

<ResponseField name="api_key" type="secret string" required>
A Granola API key.
</ResponseField>

What the key can see decides which notes are synced. A key scoped to workspace or public notes sees more than a personal-only key.

### Set it up

<Steps>
  <Step title="Create an API key">
    In the Granola desktop app, open Settings, Connectors, API keys and create a key.
  </Step>
  <Step title="Create the connector">
    Paste the key as `api_key`.
  </Step>
  <Step title="Select folders">
    HydraDB lists the workspace's folders. Select the folders whose notes you want to sync.
  </Step>
</Steps>

One connector reads the notes its API key can see in one Granola workspace.

<Accordion title="Connect through the API">

Use provider `granola` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads notes edited within the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the notes edited since the last sync, with their transcripts.
- **Edits:** An edited note is read again and replaces its document. After an edit, the note can be synced without its transcript text if Granola still holds transcript lines from the note's previous version.
- **Deletions:** Notes deleted in Granola can stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Notes

- **One document:** One Granola note with its transcript.
- **Title:** The note title, or `Granola note <id>` when it has none.
- **Text:** The title, then a `Meeting` line when the calendar event's title differs from the note title, a `When` line, an `Owner` line, an `Attendees` line and a `Folders` line. Then Granola's summary under `Summary`, and the transcript under `Transcript`, one speaker-labelled line per segment, in order. Transcript lines from an older version of the note are left out. The title is searchable too.
- **Date:** When the note was last edited, else when it was created.
- **Link back:** The note in Granola's web app.
- **Files:** None.

<ResponseField name="summary" type="Searchable text">
Granola's AI summary, written under `Summary`. A query can match it without matching the transcript.
</ResponseField>

<ResponseField name="owner" type="Searchable text">
The owner's name or email, written as the `Owner` line. The owner is not attached to the note as a person in the graph.
</ResponseField>

<ResponseField name="attendees" type="Searchable text">
Each attendee's name, or email when there is no name, written as the `Attendees` line. An attendee's email is kept even when the name is shown.
</ResponseField>

<ResponseField name="folders" type="Searchable text">
The names of the folders the note is in, written as the `Folders` line, so a query can name a folder in plain words.
</ResponseField>

<ResponseField name="event_title" type="Searchable text">
The linked calendar event's title, written as the `Meeting` line when it differs from the note title.
</ResponseField>

<ResponseField name="scheduled_at" type="Searchable text">
The linked calendar event's start, written as the `When` line. It does not set the result date.
</ResponseField>

<ResponseField name="updated_at" type="Searchable text, Result date">
When the note was last edited. Sets the result date and decides which notes each sync reads. Written as the `When` line when the note has no scheduled start.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the note was created. Sets the result date only when there is no edit time. Written as the `When` line only when there is neither a scheduled start nor an edit time.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
The id of the note's first folder. Limits a query to notes whose first folder is that folder. A note in several folders matches only its first. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
Always `folder`. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's notes. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `granola`. Not searchable.
</ResponseField>

<ResponseField name="Folder" type="Access rule">
The first selected folder whose sync returned the note. An access rule you set on that folder applies to the note. It can differ from the folder in `additional_metadata.container_id`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="organiser" type="Stored only">
The linked calendar event's organizer email. It is not part of the searchable text and is not attached to the note as a person.
</ResponseField>

<ResponseField name="has_transcript" type="Stored only">
Whether the transcript made it into the note's text.
</ResponseField>

</Accordion>

**Example searches**

- What did we decide in Monday's roadmap meeting?
- What did the customer say in the Acme intro call?
- Summarize my notes in the Hiring folder from last week.

## How it fits into the graph

- Notes use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Granola creates**

No links between notes or to other tools.

**People and groups**

The connector does not attach the owner, attendees or speakers to a note as people. Their names are part of the note text.

**Found in the text**

The whole note: meeting details, summary and transcript. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Folders you did not select, and notes the API key cannot see.
- Granola note sharing and permissions.
- Folders as documents of their own, audio, and transcript lines as documents of their own.
- The original Markdown summary, the linked calendar event's id, its invite list and its scheduled end time.
- Deletions: notes deleted in Granola can stay in HydraDB.
