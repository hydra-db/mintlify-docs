Queries the provider (Slack, GitHub, Linear, Notion, or Gmail) and returns every resource available to the connector's credentials: channels, repos, teams, projects, databases, pages, or labels. Call this before [Configure](/api-reference/v2/endpoint/configure-connector) to decide which resources to activate.

<RequestExample>

```bash cURL
curl 'https://api.hydradb.com/connectors/{connector_id}/discover' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2"
```

</RequestExample>

## Path parameters

| Name | Description |
| --- | --- |
| `id` | Connector UUID returned by `POST /connectors`. |

<ResponseExample>

```json 200
{
  "provider": "slack",
  "resources": [
    {
      "id": "{resource_id}",
      "name": "general",
      "resource_type": "channel",
      "metadata": {
        "is_member": true,
        "is_private": false,
        "num_members": 27
      }
    },
    {
      "id": "{resource_id_2}",
      "name": "engineering",
      "resource_type": "channel",
      "metadata": {
        "is_member": true,
        "is_private": false,
        "num_members": 32
      }
    }
  ],
  "channels": [
    {
      "id": "{resource_id}",
      "name": "general",
      "resource_type": "channel",
      "metadata": {
        "is_member": true,
        "is_private": false,
        "num_members": 27
      }
    }
  ]
}
```

</ResponseExample>

Each item in `resources` represents one syncable unit. Pass the `id` value as `resource_id` (and `resource_type`) to [Configure](/api-reference/v2/endpoint/configure-connector) to activate the ones you want.

Each provider also returns a top-level grouping key (`channels`, `repos`, `teams`, `projects`, `pages`, `databases`, or `mailboxes`) containing the same resources by type. Always read from `resources` for provider-agnostic code.

## Provider metadata fields

<AccordionGroup>

<Accordion title="Slack — channels">

Resource type: `channel`. Grouped under the top-level `channels` key.

| Field | Type | Description |
| --- | --- | --- |
| `is_member` | boolean | Whether the bot/user token is a member of the channel. Only member channels can be synced. |
| `is_private` | boolean | Whether the channel is private. Private channels require the token to have explicit access. |
| `num_members` | integer | Number of members in the channel at discovery time. |

Use `is_member` to filter before calling [Configure](/api-reference/v2/endpoint/configure-connector) — attempting to sync a channel where `is_member` is `false` will result in a sync error.

</Accordion>

<Accordion title="GitHub — repositories">

Resource type: `repository`. Grouped under the top-level `repos` key.

| Field | Type | Description |
| --- | --- | --- |
| `private` | boolean | Whether the repository is private. |
| `description` | string | Repository description, if set. |

The resource `id` is the full repository name in `owner/repo` format (e.g. `acme/backend`). The `name` field contains only the repository name without the owner.

</Accordion>

<Accordion title="Linear — teams and projects">

Two resource types are returned: `linear_team` and `linear_project`. Grouped under the top-level `teams` and `projects` keys respectively.

**Teams** (`linear_team`):

| Field | Type | Description |
| --- | --- | --- |
| `key` | string | Team key identifier (e.g. `ENG`). |

**Projects** (`linear_project`):

| Field | Type | Description |
| --- | --- | --- |
| `slug_id` | string | Project slug identifier. |
| `team_id` | string | ID of the associated team, if any. |
| `team_name` | string | Name of the associated team, if any. |
| `team_key` | string | Key of the associated team, if any. |

</Accordion>

<Accordion title="Notion — databases and pages">

Two resource types are returned: `notion_database` and `notion_page` (top-level pages only). Grouped under the top-level `databases` and `pages` keys respectively.

| Field | Type | Description |
| --- | --- | --- |
| `url` | string | Public URL to the database or page in Notion. |

Only top-level pages are returned — nested child pages are synced automatically when their parent is activated.

</Accordion>

<Accordion title="Gmail — mailboxes">

Resource type: `gmail_label`. Grouped under the top-level `mailboxes` key.

The resource `id` and `name` are both the IMAP mailbox name (e.g. `INBOX`, `[Gmail]/Sent Mail`). Non-selectable mailboxes are excluded. No additional metadata fields are returned.

</Accordion>

</AccordionGroup>
