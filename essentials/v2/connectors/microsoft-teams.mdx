Use the Microsoft Teams connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `channel_messages`
- `chat_messages`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Connect with an Azure AD app registration (app-only, client credentials): in the Azure portal open Microsoft Entra ID → App registrations → New registration (any name, no redirect URI). Copy the Directory (tenant) ID as tenant and the Application (client) ID as client_id, then under Certificates &amp; secrets create a client secret and paste its Value (shown once) as client_secret.
2. Under API permissions → Add a permission → Microsoft Graph → Application permissions (not Delegated) add Team.ReadBasic.All, Channel.ReadBasic.All, ChannelMessage.Read.All, TeamMember.Read.All, ChannelMember.Read.All and User.ReadBasic.All, plus Chat.Read.All to offer people's Teams chats, then click Grant admin consent (a Global or Application Administrator). The connect step reads the token's roles; without Chat.Read.All no chats appear in the picker.
3. Reading channel and chat messages with application permissions is a Microsoft Teams protected API: after consent, submit https://aka.ms/teamsgraph/requestaccess with the Application (client) ID and tenant ID (Microsoft usually answers within a week). Until it is approved every Teams sync fails with 403 even though the permission shows as granted; the picker works regardless.
4. Pick the teams and the people whose Teams chats to sync in the resource-selection step. A team syncs its standard channels (root posts and replies each become a message document, replies linked to their root); a chat user syncs the 1:1, group and meeting chats they take part in. Chats are opted in per person on purpose: they are the most private surface Graph exposes.
5. Every message carries who may see it in Microsoft 365: the team's members for a standard channel, the channel's members (plus the teams it is shared with) for a private or shared channel, and the participants for a chat. With Enforce ACL enabled for a provider reporting acl_supported: true, permission-aware search shows each message only to those people. A complete roster is authoritative; when Microsoft omits, truncates or refuses a roster, the message remains tenant-public under the current fail-open policy and carries a persistent rbac_warning instead of applying a partial allow-list.
6. Private and shared channels are skipped by default (Teams shows them only to their members); set include_private_channels to true to index them, restricted to their members.
7. Each sync reads only what changed: Graph orders a channel's posts by the last activity of the whole thread, so an old post that gets a new reply is picked up. Edits re-index the message. A message deleted in Teams after it was indexed is replaced by a hidden stub on the next sync.
8. Rotate the client secret before it expires (Azure defaults to 6-24 months): an expired secret stops every sync with a message naming the fix. Pasting a new secret value re-enables the connector.

Use provider `microsoft_teams` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
