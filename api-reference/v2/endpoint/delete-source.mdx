title: "Delete Context"
description: "Delete items by their IDs."

---

Delete one or more items by ID: context items, uploaded files, or both in one call.

Send `database`, `collection`, and `ids` as top-level fields in the request body. Include the same `collection` used at ingestion. Omitting it targets the default collection. Do not send `type`. On a unified database, `"knowledge"`, `"memory"`, and `"all"` return `400 CORPUS_TYPE_UNSUPPORTED`. A split database, created before unified databases became the default, takes `type`; see [Split databases](/essentials/v2/split-databases).

<RequestExample>

```python Python SDK
client.context.delete(
    database="acme_corp",
    collection="user_alex",
    ids=["pref_alex_tone", "chat_alex_refund"],
)
```

```typescript TypeScript SDK
await client.context.delete({
  database: "acme_corp",
  collection: "user_alex",
  ids: ["pref_alex_tone", "chat_alex_refund"],
});
```

```bash cURL
curl -X DELETE 'https://api.hydradb.com/context' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "collection": "user_alex",
    "ids": ["pref_alex_tone", "chat_alex_refund"]
  }'
```

</RequestExample>

## Status codes

By default the call can return `200` even when nothing was deleted. Check `data.deleted_count` for the number deleted and `data.results[]` for each ID's outcome.

<span id="opt-in-to-honest-status-codes"></span>

### Strict status codes

Send `X-HydraDB-Delete-Status: strict` to receive error statuses when deletion fails.

| Status | Code | Meaning |
| --- | --- | --- |
| `200` | None | At least one item was deleted. Check `results[]` for each ID. |
| `404` | `NOT_FOUND` | Nothing matched the supplied IDs. |
| `409` | `SOURCE_PROCESSING` | An item is still indexing. Retry after indexing completes. |
| `500` | `INTERNAL_ERROR` | Deletion failed. Retry the request. |

A batch is not deleted while any requested item is still indexing. Check [Ingestion Status](/api-reference/v2/endpoint/source-status) before retrying.
