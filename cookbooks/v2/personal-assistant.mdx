A personal assistant has two jobs: remember what a person tells it, across sessions, and find the one item they mean among years of their email and photos. This cookbook builds both in one collection per user.

| Benchmark | Result | What it shows here |
| --- | --- | --- |
| [LongMemEval-S](https://benchmarks.hydradb.com/longmemeval) | 90.79% overall, 97.43% on knowledge updates | Facts and preferences kept current across about 50 sessions |
| [BEAM 1M](https://benchmarks.hydradb.com/beam-1m) | 82% overall | Memory that holds up over months of history |
| [ATM-Bench](https://benchmarks.hydradb.com/atm-bench) | 0.918 recall@10 | The one right email, photo, or video found among 11,034 look-alikes |

## 1. Create a database with one collection per user

Each user's context lives in their own collection, named by their user ID. Nothing one user saves can appear in another user's query.

```python assistant.py
import io
import json
import os

from hydra import answer, client, connect, create_database, source_ids, wait_indexed

DATABASE = "assistant"
USER = "user_maya"

create_database(DATABASE)
```

## 2. Remember each session

When a session ends, save its turns as a [memory](/essentials/v2/context#2-save-memories). Send the dialogue as `user_assistant_pairs` with `infer: true`: HydraDB extracts the preferences and facts, including ones that are implied, and reconciles them with what it already holds. Saving session by session is how the LongMemEval run ingested its conversations.

```python assistant.py
def remember_session(turns):
    """turns is a list of (user message, assistant reply) pairs."""
    result = client.context.ingest(
        type="memory",
        database=DATABASE,
        collection=USER,
        memories=json.dumps([{
            "user_assistant_pairs": [{"user": u, "assistant": a} for u, a in turns],
            "infer": True,
            "user_name": "Maya",
        }]),
    )
    wait_indexed(DATABASE, USER, source_ids(result))


remember_session([
    ("I'm vegetarian, and I usually cook on weeknights.", "Noted."),
    ("Book me a table Friday somewhere near the office in Shoreditch.", "Done."),
])
remember_session([
    ("We moved offices last week. I'm in King's Cross now.", "Got it."),
])
```

## 3. Add the person's email and photos

Email and media are knowledge, saved in the same collection. A [connector](/essentials/v2/connectors) syncs the person's mailbox. Photos and videos have no text to search, so caption each one with a vision model in your application, then upload the caption, any text read from the image, and the date and place as a small file. This mirrors the ATM-Bench setup, where every item is text plus its timestamp, location, and tags.

```python assistant.py
# Each provider has its own credentials: client.list_providers(id="gmail")
# returns the shape. Use this user's own credentials and collection.
connect("gmail", DATABASE, USER, credentials=json.loads(os.environ["GMAIL_CREDENTIALS"]))


def add_photo(photo_id, caption, taken_at, place):
    text = f"# Photo taken {taken_at} in {place}\n\n{caption}\n"
    result = client.context.ingest(
        type="knowledge",
        database=DATABASE,
        collection=USER,
        documents=[(f"{photo_id}.md", io.BytesIO(text.encode()), "text/markdown")],
        document_metadata=json.dumps([{
            "id": photo_id,
            "additional_metadata": {"taken_at": taken_at, "place": place},
        }]),
    )
    wait_indexed(DATABASE, USER, source_ids(result))


add_photo(
    "photo_2026_06_21_0934",
    "A blue oyster stall on the harbour wall. Sign reads 'Wheelers'.",
    "2026-06-21",
    "Whitstable",
)
```

## 4. Answer from memories and items together

`type: "all"` searches the user's memories and knowledge in one call. `acl` is the user's own email, so the query returns only what this person may see.

```python assistant.py
def ask(question):
    result = client.query(
        database=DATABASE,
        collection=USER,
        query=question,
        type="all",
        mode="thinking",
        acl=[os.environ["USER_EMAIL"]],
    )
    return answer(question, result, "When facts conflict, the most recent one is current.")


print(ask("Suggest somewhere for a team dinner near my office."))
print(ask("What bookings or trips do I have coming up?"))
print(ask("What was the name on that oyster stall?"))
```

## Run it

Set `GMAIL_CREDENTIALS` and `USER_EMAIL`, and run:

```bash
python assistant.py
```

The first answer suggests vegetarian options near King's Cross, not Shoreditch. The second comes from the person's own email. The third gives "Wheelers" from the photo caption.

## Common mistakes

- **Saving a transcript with `infer: false`:** that stores the dialogue word for word, and the preference inside it is harder to find. Use `infer: true` for raw conversation.
- **Forgetting `collection` on the query:** a query without it reads the default collection, which holds nothing for this user.
- **Ingesting images without text:** queries match text. Put a caption, any text in the image, and the date and place into the file you upload.
