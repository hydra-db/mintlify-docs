description: "Sync deals, leads, projects, tasks, persons, organizations, activities and notes from one Pipedrive account. Pipedrive visibility settings are not enforced."

Sync a whole Pipedrive account: deals, leads, projects and project tasks, persons, organizations, activities such as calls and meetings, and notes. Each record is one document. Stage, pipeline, organization, person, activity type, product and lead label ids are turned into names. A note or activity links to every deal, person, organization and lead it is attached to.

Pipedrive's visibility setting is kept as a filter but does not restrict who can read an item, so every synced item is visible to everyone who can query the collection unless you set an access rule. Records deleted in Pipedrive stay in HydraDB. Pipedrive mail, files and call logs are not synced.

<Note>
Pipedrive is in beta.
</Note>

## Permissions

<Warning>
Pipedrive permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Pipedrive's `visible_to` setting is stored as `additional_metadata.visible_to`. You can filter on it, but it does not decide who can read an item.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Pipedrive uses a personal API token.

<ResponseField name="api_token" type="secret string" required>
A Pipedrive personal API token. The connector reads every record this token can see.
</ResponseField>

### Set it up

<Steps>
  <Step title="Copy an API token">
    In Pipedrive, copy the personal API token of a user who can see the records you want in HydraDB.
  </Step>
  <Step title="Create the connector">
    Paste the token as `api_token`.
  </Step>
  <Step title="Configure the connector">
    Pipelines are offered for selection, but selecting them does not narrow the sync. The connector syncs every record the token can read in the account.
  </Step>
</Steps>

One connector reads one Pipedrive account.

<Accordion title="Connect through the API">

Use provider `pipedrive` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads records whose update time moved past the last sync. A deal's line items are read again whenever the deal changes.
- **Edits:** An edited record is read again and updates its document.
- **Deletions:** Deleted records are not removed. They stay searchable in HydraDB. A record Pipedrive marks as deleted is flagged, so you can leave it out with `additional_metadata.is_deleted`, or `additional_metadata.active_flag` for notes.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## How it fits into the graph

- Deals use the Ticket class.
- Leads use the Ticket class.
- Projects use the Ticket class.
- Tasks use the Ticket class.
- Persons use the Record class.
- Organizations use the Record class.
- Activities use the Record class.
- Notes use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Pipedrive creates**

- A note or activity to every deal, person, organization and lead it is attached to.
- An activity to each person who took part.
- A deal or lead to its organization and contact person.
- A person to their organization.
- A project to every linked deal, organization and person.
- A task to its project and its parent task.
- No links to other tools.

**People and groups**

- The author of each note.
- Owners of deals, leads, persons, organizations and activities appear in the text, where HydraDB can identify them.
- Project owners and task assignees are kept with the item but not attached to it as people.

**Found in the text**

Notes, activity notes, deal titles, and project and task descriptions, along with the rest of each record's text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Pipedrive mail messages and mail threads.
- Files, call logs and deal stage-change history.
- Deal participants and followers.
- Custom field values.
- Project boards and phases, task audit users and lead marketing attribution.
- Records removed from Pipedrive entirely: they stay in HydraDB.
