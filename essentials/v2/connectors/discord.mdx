Use the Discord connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `messages`

## Connect

1. Create a Discord application and bot in the Developer Portal, reset/copy the bot token, and invite it to each server with OAuth2 scope bot. Grant View Channels and Read Message History on every selected channel; the connector is read-only and never sends messages.
2. Enable Message Content Intent under Developer Portal → Bot → Privileged Gateway Intents. The connector verifies the application flag and refuses to sync when it is absent instead of silently indexing empty content fields.
3. Pick the Discord servers to sync. Every readable message in their text and announcement channels, active threads, public archived threads, and joined private archived threads becomes a message source. User, role and channel mentions are rewritten to human display names; attachments contribute filenames but their bytes are not downloaded.
4. Discord bot tokens have no granular API scope picker and do not expire automatically. Rotate a leaked token in the Developer Portal. Discord enforces rate-limit buckets and the connector honors Retry-After before retrying.
5. Discord exposes no guild-member email addresses, so provider roles and channel overwrites cannot be mapped safely to HydraDB login emails. Under the current fail-open RBAC policy Discord sources are tenant-public with a persistent warning unless a customer HydraDB resource ACL is configured.
6. The REST history API exposes existing messages and edits but not deletion events. A deleted Discord message can remain indexed until the connector is rebuilt from a fresh snapshot; real-time deletion capture requires the Discord Gateway and is intentionally not claimed by this pull connector.

Use provider `discord` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
