title: "DeepSeek Harness"
description: "Give the DeepSeek Harness long-term memory with the native HydraDB plugin."
---

The [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`)
plugin recalls relevant context before each turn, syncs workspace docs when files
change, and captures conversations as durable memory. It is a native
[Cordis](https://github.com/deepseek-ai/deepseek-harness) plugin that wires onto
the harness interception seams.

| dsh seam | Engine action |
| -------- | ------------- |
| `agent/created` | sync workspace docs into HydraDB when a session opens |
| `agent/pre-step` (turn's first step) | recall memory/knowledge and prepend it to the step messages |
| `tools/post-execute` (file-writing tools) | incremental workspace sync |
| `session/event` -> `turn/end` | capture the completed turn |

<Steps>
  <Step title="Install">
    The package ships as a dsh bundle, so `dsh plugin add` installs it from npm
    and wires it as a profile layer in one step:

    ```bash
    dsh plugin --profile <name> add dsh-hydradb
    ```

    dsh appends it to the profile's bundles and inserts the plugin row
    automatically, with no manual config file editing.

    <Note>
      Requires the DeepSeek Harness (`dsh`) and Node.js 18+.
    </Note>
  </Step>

  <Step title="Configure">
    Set credentials in the environment, or pass them in the bundle's `config`
    block:

    ```bash
    export HYDRADB_API_KEY="your-api-key"
    export HYDRADB_DATABASE="your-database"
    ```

    Optional: `HYDRADB_COLLECTION` (collection scope) and `HYDRADB_BASE_URL`.
    The dsh-prefixed names `HYDRA_DEEPSEEK_API_KEY` and `HYDRA_DEEPSEEK_TENANT_ID`
    also work; the canonical `HYDRADB_*` names take precedence.
  </Step>

  <Step title="Run">
    Recall fires on the first step of each turn and prepends relevant memory to
    the prompt. Run a one-shot task with the `headless` command, reusing the same
    profile you installed the plugin into (any other dsh surface works too):

    ```bash
    dsh --profile <name> headless "What did we decide last session?"
    ```
  </Step>
</Steps>

**Manual actions** come from the shipped skills: `query`, `ingest`, `doctor`,
`setup`, and `last-recall`.

It runs on the same engine as the [Claude Code plugin](/plugins/claude-code), so the [modes](/plugins/claude-code#modes) and [config variables](/plugins/claude-code#config-variables) there apply here too.
