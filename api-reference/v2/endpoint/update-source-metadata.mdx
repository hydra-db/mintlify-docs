title: "Update Source Metadata"
description: "Merge database metadata and additional metadata into one existing source, without re-ingesting it."

---

Update one existing source's metadata or ACL without re-ingesting its content. Changes also apply to the indexed chunks used by Query and List Context. See [Metadata and Filters](/essentials/v2/metadata#6-update-metadata-without-re-ingesting) for the metadata workflow.

```http
PATCH /context/{id}/metadata
```

`id` is the ID you supplied at ingest, or the source ID HydraDB returned. The route `PATCH /context/sources/{source_id}/metadata` is a deprecated alias that still works; migrate to the route above. `source_id` and `id` identify the same source.

<RequestExample>

```python Python SDK
response = client.context.update_source_metadata(

    collection="team_docs",
    database_metadata={"department": "legal", "priority": 7},

```

## Request rules

- `collection` is required. This endpoint does not default it.
- At least one of `database_metadata`, `additional_metadata`, or `acl` is required.
- `database_metadata` merges into the source's `metadata`, and its keys must satisfy the database metadata schema when one exists. `additional_metadata` merges into the source's free-form `additional_metadata`.
- The endpoint does not accept `metadata` or `document_metadata`.

<span id="behavior"></span>

## How updates apply

- Metadata keys included in the request are added or overwritten. Omitted keys keep their existing values.
- Sending `acl` replaces the entire stored ACL, so send the complete new list. `[]` or `null` revokes access for everyone. Omit `acl` to keep the stored list. See [Access Control](/essentials/v2/access-control).
- The source must already exist. This endpoint does not create sources.
- The endpoint edits one source at a time. Bulk metadata edits are not supported.
- Updated metadata is visible to [`/query`](/api-reference/v2/endpoint/query) metadata filters and [`/context/list`](/api-reference/v2/endpoint/list-documents) filters.
- If an edited database metadata field has `enable_dense_embedding` or `enable_sparse_embedding`, HydraDB synchronously refreshes the relevant metadata search index and the response has `vector_sync_required: true`. Otherwise no vector refresh is needed and `vector_sync_required` is `false`.

## Partial failures

A `200` response can still report an incomplete edit:

- **`vector_sync_error`:** The metadata was saved but the dense or sparse vector store sync failed. `vector_synced` is absent. Retry the same idempotent edit to converge.
- **`partial_commit`:** The edit was saved in one store but a later write failed. Retry the same edit.
- **`vector_acl_synced` absent after an `acl` edit:** The new list is still enforced, but an added principal may miss this source in results until it is re-indexed.

## Validation and errors

| Status | When it happens |
| --- | --- |
| `400` | Missing `database`, missing `collection`, empty metadata payload, `document_metadata` supplied, unknown database metadata key when a schema exists, wrong type, reserved key, over-size payload, too-deep nesting, or `null` for a dense/sparse-enabled field. |
| `404` | Source does not exist for the `(database, collection, id)` scope. |
| `500` | The edit failed. Retry the same idempotent edit to converge. |

### Size limits

`database_metadata` is capped at **16 KiB**. `additional_metadata` is capped at **1 KiB**. See [metadata size limits](/essentials/v2/metadata#stored-metadata) for how HydraDB measures these caps.

Limits apply to the request payload, before merging with stored metadata. An oversized request returns `400` with the actual and maximum sizes:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_INPUT",
    "message": "invalid metadata edit: additional_metadata is too large (1065 bytes when serialized; the maximum is 1024). Reduce the number or size of metadata fields."
  }
}
```
