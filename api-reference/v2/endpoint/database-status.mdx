Reports whether a database has finished provisioning. Database creation is asynchronous, so poll this endpoint until `infra.ready_for_ingestion` is `true` before you ingest or query.

<RequestExample>

```python Python SDK
response = client.databases.status(database="my_first_database")

if response.data.infra.ready_for_ingestion:
    print("Database is ready.")
```

```typescript TypeScript SDK
const response = await client.databases.status({
  database: "my_first_database",
});

if (response.data?.infra?.readyForIngestion) {
  console.log("Database is ready.");
}
```

```bash cURL
curl -X GET 'https://api.hydradb.com/databases/status?database=my_first_database' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2"
```

</RequestExample>

**Layout:** `type` is the database's layout, fixed when it was created. Every new database is `unified`: one corpus, ingested through `context`, queried without a `type`. A database created before unified became the default reports `split`; see [Split databases](/essentials/v2/split-databases).

**Readiness signals:** `infra.ready_for_ingestion` is `true` only when all four underlying signals are `true`. For a single check, read that field.

- `infra.scheduler_status`: lifecycle provisioning has finished. It is `false` while the database is still being created, even if some collections already exist.
- `infra.graph_status`: the graph layer is ready.
- `infra.vectorstore_status.knowledge` and `infra.vectorstore_status.memories`: the vector store is ready. A unified database keeps every item in one store, and both fields report it.

**Stale database IDs:** If `database` does not exist, the call returns `404 DATABASE_NOT_FOUND`. Confirm that the create call succeeded before you poll.

**Querying too early:** A `POST /query` sent before `ready_for_ingestion` is `true` returns `422 TENANT_INFRA_NOT_READY`.
