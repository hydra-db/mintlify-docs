Use the attio connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `records`
- `list_entries`
- `notes`
- `tasks`
- `comments`
- `list_entry_comments`
- `meetings`
- `call_transcripts`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Connect with a workspace API key: Attio workspace settings → Developers → API keys. The key is static and does not expire, so this connection never needs reconnecting.
2. Grant the key the read scopes for records, objects, lists, list entries, notes, tasks, comments and users. A key missing a scope fails with a 403 that names it; granting them all up front is faster than finding out one at a time.
3. Pass the key as access_token. Objects (people, companies, deals, custom ones) and lists are picked in the resource-selection step after connecting; leaving the objects/lists credential fields empty is the normal path.
4. With permission-aware search on, a private list's entries are restricted to the workspace's admins and the members the list is shared with; a list shared with the whole workspace, and every record, note, task, comment and meeting, is readable by everyone in your workspace. Attio's API does not expose team grants, so a member who reaches a list only through a team does not see it here. The key needs the List Configuration: Read and User Management: Read scopes; without them the list is readable by everyone, with a warning, until you reconnect.

Use provider `attio` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
