---
title: "Update Connector"
description: "Change a connector's instructions, sync interval or credentials in place."
openapi: "api-reference/v2/openapi.json PATCH /connectors/{id}"
---

Update a connector's instructions, sync interval, credentials, or source-permission enforcement. Omitted fields keep their existing values.

- HydraDB validates every field before saving. Invalid input changes nothing.
- Credentials are saved before other settings. If a server error occurs afterward, only the credentials may have changed. Retrying the same request is safe.

- `custom_instructions` applies to resources without their own instructions. Maximum 4,000 characters. Send `""` to clear it. Changes affect future syncs. See [Custom Ingestion Instructions](/essentials/v2/connectors#custom-ingestion-instructions).
- `sync_interval_seconds` reschedules the next sync. Stay within the returned `min_sync_interval_seconds` and `max_sync_interval_seconds`, or send `0` for the provider default.
- `credentials` reconnects the existing connector. Send the provider's complete credential set. Resources and saved sync positions are preserved.
- `follow_source_permissions` enables or disables caller-bound enforcement of this connector's captured source permissions. Existing connectors remain `false` until an owner enables it. Send `true` to enforce captured permissions on every content read, or `false` to return to opt-in request `acl` filtering. Omit it to keep the current value. The change takes effect on the next content request for already-synced documents and does not require re-ingestion. Only a workspace owner in a signed-in dashboard session can set it; `true` requires the provider to report `rbac_support: true`. API-key-authenticated requests cannot set it. See [Permissions on synced content](/essentials/v2/connectors#enforce-source-permissions-as-the-caller) and [Access Control](/essentials/v2/access-control).

To enable enforcement later, send this field in a separate PATCH request, or use **Follow source permissions** in the dashboard's connector settings:

```json
{
  "follow_source_permissions": true
}
```

Do not combine `follow_source_permissions` and `credentials` in the same PATCH request. Send them in separate requests.

Only `custom_instructions`, `sync_interval_seconds`, `credentials`, and `follow_source_permissions` can be updated. A connector's `name`, `database`, `collection` and `provider_account_scope` cannot be changed after creation. Omit them from the request; unsupported fields can cause a `400` response.

<RequestExample>

```python Python SDK
client.connectors.update(
    "{connector_id}",
    custom_instructions=(
        "Aurora was renamed to Nimbus in January 2025; they are the same product. "
        "Index all Aurora content under Nimbus."
    ),
    sync_interval_seconds=3600,
)
```

```typescript TypeScript SDK
await client.connectors.update({
  id: "{connector_id}",
  customInstructions:
    "Aurora was renamed to Nimbus in January 2025; they are the same product. " +
    "Index all Aurora content under Nimbus.",
  syncIntervalSeconds: 3600,
});
```

```bash cURL
curl -X PATCH 'https://api.hydradb.com/connectors/{id}' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "custom_instructions": "Aurora was renamed to Nimbus in January 2025; they are the same product. Index all Aurora content under Nimbus.",
    "sync_interval_seconds": 3600
  }'
```

</RequestExample>

<ResponseExample>

```json 200
{
  "connector_id": "{connector_id}",
  "sync_interval_seconds": 3600,
  "follow_source_permissions": false,
  "next_sync_at": "2026-06-01T13:00:00Z",
  "min_sync_interval_seconds": 300,
  "max_sync_interval_seconds": 604800,
  "custom_instructions_updated": true
}
```

</ResponseExample>

`custom_instructions_updated` and `credentials_updated` are present when the request changed those fields. Sending `{}` changes nothing and returns the current interval and the allowed range.

## Errors

- `400`: the request includes an unsupported field, `follow_source_permissions` is combined with `credentials`, the provider does not report `rbac_support` for `follow_source_permissions: true`, `custom_instructions` is over 4,000 characters, or `sync_interval_seconds` is outside the provider's range. Nothing is changed.
- `403`: the request tries to set `follow_source_permissions` without a workspace owner's signed-in dashboard session.
- `404`: no connector with this id in your organization.
- `409`: another update changed the permission setting at the same time. Reload the connector and retry.
- `422`: `credentials` does not match the provider's `credential_schema`.
- `503`: the provider capability catalog is unavailable. Retry the request.
