The Slack connector reads the public and private channels you select in one Slack workspace. Each message becomes one document, and each thread reply is its own document linked to the message that started the thread.

Files shared in a message are downloaded and read with it. A private channel's messages can be limited to the channel's members.

## Before you connect

Slack uses a token from a Slack app installed in your workspace. A bot token or a user token works.

**Credentials**

<ResponseField name="access_token" type="secret string" required>
A Slack bot token, which starts with `xoxb-`, or a user token, which starts with `xoxp-`.
</ResponseField>

**Scopes to add to the Slack app**

- `channels:read`: lists public channels in the channel picker.
- `channels:history`
- `groups:read`: lists private channels in the channel picker.
- `groups:history`
- `users:read`
- `users:read.email`: without it, permissions cannot be captured for any private channel.
- `files:read`

If neither `channels:read` nor `groups:read` is granted, connecting fails with a message that names the missing scope.

**Set it up**

<Steps>
  <Step title="Create a Slack app">
    Create a Slack app for your workspace and add the scopes above.
  </Step>
  <Step title="Install it">
    Install the app in the workspace and copy its token.
  </Step>
  <Step title="Create the connector">
    Paste the token as `access_token`.
  </Step>
  <Step title="Select channels">
    Discover lists every public and private channel that is not archived and that the token can see, with whether it is private, whether the app is a member, and its member count. Select the channels to sync.
  </Step>
</Steps>

Use provider `slack` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list what the credentials can reach, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

Create one connector per account, each with that account's own credentials. One token covers one Slack workspace.

To connect several Slack accounts, give each connector its own `provider_account_scope`, for example `slack-account-a` and `slack-account-b`. Both are caller-provided example identifiers. HydraDB stores the value as given and does not check it against Slack's own account ids. Two connectors that share a scope and write to the same collection can overwrite each other's items. See [several accounts from one provider](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider).

## What gets synced

**What the labels mean**

- **Title:** names the item in results.
- **Searchable:** part of the text a query matches.
- **Date:** the time HydraDB uses for recency.
- **Filter:** a key a query can filter on, typed exactly as shown.
- **Link:** connects this item to another item.
- **Person or group in the graph:** a person or group the knowledge graph attaches the item to.
- **Access:** decides who can read the item.
- **Stored with results:** kept on the document, and shown when you open or inspect it. A search does not match it.
- **Not kept:** the provider has it, and HydraDB does not keep it.

### Messages

- **One document:** One Slack message: a message posted in a channel, or a single reply in a thread.
- **Title:** The channel name with `#`, a colon and the message's first line, cut to about 80 characters, for example `#general: Deploy is done`. A reply reads `#general thread: ...`. A message with no text is titled `Slack message`.
- **Text:** The message text, with mentions turned into display names. Then the pretext, title and text of any legacy attachments, and one `[file: name]` line per shared file. The sender is written as a `From` line and the time as a `Sent` line.
- **Date:** The message's Slack timestamp.
- **Link back:** A Slack permalink to the message. A reply links to itself inside its thread. Empty if the workspace address could not be read.
- **Files:** Each shared file is downloaded and read, and its text becomes searchable with the message. A file is skipped if Slack gave no download address, the download fails, or the file is too large.

## How it fits into the graph

**What each item becomes**

- Messages: a message, a chat or conversation message, kept with its author and its thread.

**Connections Slack creates**

- A thread reply to the message that started the thread.
- Every message to its thread, including a message nobody replied to.
- No links to items in other tools.

**People and groups it names**

- The sender of each message.
- People mentioned in a message.
- An editor is kept with the message but not added to the graph.

**What HydraDB reads from the text**

Topics, decisions, people and organisations named in prose, in the message text, legacy attachment text and shared file text. Each reply is read together with the text of its thread's first message.

There is no per-connector setup for this. Every connector maps its items onto the same shared model, and HydraDB finds people, organizations, projects, products and other entities in the text the same way for every source. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Permissions

This connector can carry Slack permissions into search.

- **Who can read an item:** A public channel's messages can be read by the whole workspace. A private channel's messages can be read by its members. HydraDB reads this once per channel on each sync; there is no per-message permission.
- **How a person is identified:** A member's email address, in lower case. Bots and deactivated users have no email and are left out.
- **When permissions cannot be read:** If HydraDB cannot read a channel's privacy, members or member emails, an access rule you set on that channel stays in force. Without a rule, the connector status shows a permission warning, and depending on your deployment's setting the messages either stay readable or are hidden until permissions can be read.

- A private channel with more than 1,000 members who have emails, or more than 3,000 members in all, cannot be captured. Set an access rule on such a channel.
- Without `users:read.email`, permissions cannot be captured for any private channel.

Captured permissions filter search only when **Enforce ACL** is on for the connector. Only a signed-in human workspace owner or writer can turn it on, in the dashboard connector settings. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl). You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

Database and collection names decide where content lands; collection names do not authorize access.

## Keeping in sync

- **First sync:** A newly selected channel reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads recent history for new messages, and new replies on threads whose latest reply moved. A second pass, every 6 hours by default, walks the channel's whole history in steps to find new replies on older threads.
- **Edits:** A routine sync does not pick up an edit to a message that is already indexed.
- **Deletions:** Deleted messages are not removed. A message deleted in Slack stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` to change it.

## Not synced

- Archived channels: discovery does not offer them.
- Direct messages and group direct messages.
- System messages: joins, leaves, renames, topic and purpose changes, pins, bots being added or removed, and thread broadcasts.
- Edits and deletions made after a message was indexed.
- Reactions.

## Questions this lets you answer

- What did the team decide about the release last week?
- What did Priya say in the thread about the pricing change?
- Which messages were posted by the alerts bot?
- What does the PDF shared in the design channel say about the new layout?

## Good to know

- **Naming a channel does not filter to it.** When a message has text, search matches the message, not its `#channel` title. A channel name in a query does not reliably limit results to that channel.
- **A name that could not be read stays an id.** If HydraDB could not read a person's name, the message keeps the raw Slack id, and later syncs do not go back to fix it.
