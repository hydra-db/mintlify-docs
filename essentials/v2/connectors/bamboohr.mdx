Sync the BambooHR employee directory and time off. Each employee is one document with their job title, manager, department, division, location, work email, work phone and status, linked to their manager. Each time-off request and each who's-out entry is one document, linked to the employee it belongs to.

BambooHR permissions are not imported, so every synced employee and absence is visible to everyone who can query the collection unless you set an access rule. HR data is often sensitive. Departed employees and cancelled absences stay in HydraDB. Compensation, employee files and custom fields are not synced.

## Permissions

<Warning>
BambooHR permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

BambooHR uses an API key together with your company's subdomain.

<ResponseField name="auth_token" type="secret string" required>
A BambooHR API key.
</ResponseField>

<ResponseField name="subdomain" type="string" required>
Your company's subdomain from its BambooHR address, for example `acme` for `acme.bamboohr.com`.
</ResponseField>

### Set it up

<Steps>
  <Step title="Get an API key">
    Get a BambooHR API key. HydraDB syncs the employee directory and time off that this key can read.
  </Step>
  <Step title="Create the connector">
    Paste the key as `auth_token` and your company's subdomain as `subdomain`.
  </Step>
  <Step title="Configure the connector">
    HydraDB lists one account-wide resource, All data. Select it to sync everything the key can read as one unit.
  </Step>
</Steps>

One connector reads one BambooHR company, the one named by `subdomain`.

<Accordion title="Connect through the API">

Use provider `bamboohr` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads the whole employee directory the key can see. Time-off requests updated within the window set by `lookback_days`, 30 days by default, whatever the dates of the leave. Who's-out entries for the dates in that window.
- **New and changed items:** Each sync reads the whole directory again, time-off requests updated since the last sync, and who's-out entries for the dates the sync covers. Future absences are not guaranteed to appear as who's-out entries.
- **Edits:** A changed employee or time-off request replaces its document. A who's-out entry is read again only while its dates fall in the window a sync covers.
- **Deletions:** Not removed. A departed employee or a cancelled absence stays in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every BambooHR item

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's documents. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `bamboohr`. Not searchable.
</ResponseField>

### Employees

- **One document:** One employee in the directory the API key can read.
- **Title:** The employee's display name. Otherwise the first and last name.
- **Text:** The name, then `Job Title`, `Reports To`, `Department`, `Division`, `Location`, `Email`, `Phone` and `Status` lines. The title is searchable too.
- **Date:** None. The directory has no change time, so ranking by date cannot order employees.
- **Link back:** None.

<ResponseField name="display_name" type="Searchable text">
The directory display name. Forms the title and the name in the text.
</ResponseField>

<ResponseField name="first_name, last_name" type="Searchable text">
The employee's first and last name. Used for the title and the name in the text only when there is no display name.
</ResponseField>

<ResponseField name="job_title" type="Searchable text">
The job title, in the `Job Title` line.
</ResponseField>

<ResponseField name="reports_to" type="Searchable text, Graph connection">
The manager's name from the employee's latest job information, in the `Reports To` line. When the name matches an employee in the directory, links the employee to that manager. Two people with the same name can cause a wrong link or no link.
</ResponseField>

<ResponseField name="department, division, location" type="Searchable text">
Where the employee sits in the organisation, in the `Department`, `Division` and `Location` lines.
</ResponseField>

<ResponseField name="work_email, work_phone" type="Searchable text">
The work email and work phone, in the `Email` and `Phone` lines.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The employment status, in the `Status` line.
</ResponseField>

<ResponseField name="additional_metadata.bamboohr_employee_id" type="Query filter">
The BambooHR employee id. Finds one employee. Not searchable.
</ResponseField>

### Time-off entries

- **One document:** One time-off request, or one who's-out calendar entry.
- **Title:** The employee's name.
- **Text:** The employee's name, then `Type`, `Status`, `Start` and `End` lines. The title is searchable too.
- **Date:** The first day of the absence.
- **Link back:** None.

<ResponseField name="employee_id" type="Graph connection">
Links the absence to the employee it belongs to. Not searchable.
</ResponseField>

<ResponseField name="type" type="Searchable text">
The kind of time off, such as Vacation or Sick, in the `Type` line.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The approval status, in the `Status` line.
</ResponseField>

<ResponseField name="start" type="Searchable text, Result date">
The first day of the absence, in the `Start` line. It is the result date.
</ResponseField>

<ResponseField name="end" type="Searchable text">
The last day of the absence, in the `End` line.
</ResponseField>

<ResponseField name="additional_metadata.bamboohr_time_off_id" type="Query filter">
The BambooHR time-off id. Finds one request or entry. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="created" type="Stored only">
When a time-off request was created. Who's-out entries have none.
</ResponseField>

</Accordion>

**Example searches**

- Who does Priya report to?
- Who works in the Finance department?
- What is Sam's work email and job title?

## How it fits into the graph

- Employees use the Record class.
- Time-off entries use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections BambooHR creates**

- An employee to their manager, when the manager's name matches an employee in the directory.
- A time-off request or who's-out entry to its employee.
- No links to other tools.

**People and groups**

Employees and their managers, through the manager link. Departments, divisions and locations are not attached as groups. They are in the text only.

**Found in the text**

Each employee's directory lines and each absence's type and status. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Compensation, custom reports, photos, employee files and custom fields.
- Job history other than the latest manager.
- Time-off amounts, employee notes, per-day breakdowns and the actions allowed on a request.
- A guaranteed calendar of future absences.
- Deletions: departed employees and cancelled absences stay in HydraDB.
