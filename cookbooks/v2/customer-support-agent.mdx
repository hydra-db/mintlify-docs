---
title: "AI Customer Support Agent with Memory"
description: "On each ticket, query the help docs and that customer's memory, then reply."
---

Build a support agent that remembers each customer. On every ticket it makes two HydraDB queries, passes the merged results to your model for the reply, and stores the turn back in HydraDB. Target: the two HydraDB calls finish in under 400 ms round trip.

## Prerequisites

- Base URL: `https://api.hydradb.com`
- A HydraDB API key from [app.hydradb.com](https://app.hydradb.com), exported as `HYDRA_DB_API_KEY`
- An OpenAI API key, only for the final reply
- Python 3.11 or 3.12 (`python --version`)
- `pip install hydradb-sdk openai`

The two queries, both with `mode: "thinking"`:

1. `POST /query` on the shared knowledge base: help articles, past ticket resolutions, and linked documents.
2. `POST /query` with `type: "memory"` on the customer's collection: their plan, past issues, inferred preferences, and conversation history.

---

## Step 1: Create the database

One support database holds a shared `knowledge-base` collection for help docs and resolved tickets, plus one `customer-{id}` collection per customer, created on first write. Every memory also sets `user_name` to the customer id. This is the [B2C pattern](/essentials/v2/multi-tenant#b2c-application).

> **Use the SDK:** `/context/ingest` takes multipart form data, so raw `requests` with `json=` does not work. Use the SDK (`pip install hydradb-sdk`, imported as `hydra_db`), or send multipart form fields yourself.

<CodeGroup>

## Step 2: Ingest the knowledge base

Upload help docs, FAQs, and past ticket resolutions into `knowledge-base`. HydraDB's context graph connects related articles, so a question about "billing" also surfaces "invoices", "payment methods", and "plan upgrades", even if the customer never used those words.

> **Ingest rules:** max 20 sources per request, 1 second between batches. `database` is a required top-level form field. Items in `app_knowledge` may also carry `database` and `collection`, but an item's `database` must match the top-level one, or the request returns 400. The SDK's `app_knowledge` takes a **JSON string**: use `json.dumps(batch)`, not a Python list.

### Help docs and FAQs

<CodeGroup>
```python Python SDK
# ingest/help_docs.py
import json, time

def ingest_help_docs(articles: list) -> list:
    """
    articles: list of dicts - {id, title, content, category, url, updated_at}
    category: "billing" | "onboarding" | "technical" | "account" | "general"
    updated_at: ISO 8601 - drives recency ranking
    """
    batch, all_ids = [], []

    for article in articles:
        batch.append({
            "id":            article["id"],
            "database":     TENANT_ID,        # required inside each item
            "collection": KB_SUB_TENANT,    # required inside each item
            "title":         article["title"],
            "type":          "confluence",
            "timestamp":     article["updated_at"],
            "content":       {"text": article["content"]},
            "url":           article.get("url", ""),
            "metadata": {
                "doc_type": "help_article",
                "category": article["category"],
                "tags":     ["knowledge-base", article["category"]],
            },
        })

        if len(batch) == 20:
            all_ids += _upload_kb_batch(batch)
            batch = []
            time.sleep(1)

    if batch:
        all_ids += _upload_kb_batch(batch)

    print(f"Knowledge base: {len(all_ids)} articles indexed.")
    return all_ids


def _upload_kb_batch(batch: list) -> list:
    # database / collection required as top-level SDK params AND inside each item
    result = client.context.ingest(
        database=TENANT_ID,
        collection=KB_SUB_TENANT,
        upsert=True,
        app_knowledge=json.dumps(batch),    # JSON string, not a list
    )
    return [r.id for r in (result.data.results or [])]
```
```typescript TypeScript SDK
// ingest/help_docs.ts
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY! });
const TENANT_ID    = "customer-support";
const KB_SUB_TENANT = "knowledge-base";

async function uploadKbBatch(batch: object[]): Promise<string[]> {
    // database / collection required as top-level SDK params AND inside each item
    const result = await client.context.ingest({
        database:     TENANT_ID,
        collection: KB_SUB_TENANT,
        upsert:        true,
        appKnowledge: JSON.stringify(batch),   // JSON string, not an array
    });
    return (result.data.results || []).map((r: any) => r.id);
}

async function ingestHelpDocs(articles: any[]): Promise<string[]> {
    /**
     * articles: array of objects - {id, title, content, category, url, updated_at}
     * category: "billing" | "onboarding" | "technical" | "account" | "general"
     * updated_at: ISO 8601 - drives recency ranking
     */
    let batch: object[] = [];
    let allIds: string[] = [];

    for (const article of articles) {
        batch.push({
            id:            article.id,
            database:     TENANT_ID,        // required inside each item
            collection: KB_SUB_TENANT,    // required inside each item
            title:         article.title,
            type:          "confluence",
            timestamp:     article.updated_at,
            content:       { text: article.content },
            url:           article.url || "",
            metadata: {
                doc_type: "help_article",
                category: article.category,
                tags:     ["knowledge-base", article.category],
            },
        });

        if (batch.length === 20) {
            allIds = allIds.concat(await uploadKbBatch(batch));
            batch = [];
            await new Promise(r => setTimeout(r, 1000));
        }
    }

    if (batch.length > 0) {
        allIds = allIds.concat(await uploadKbBatch(batch));
    }

    console.log(`Knowledge base: ${allIds.length} articles indexed.`);
    return allIds;
}
```

## Step 3: Build per-customer memory

Each customer's memory holds conversation turns, preference signals, and product feedback, and each query ranks which of them fit the current message.

### Store conversation turns

After every exchange, store the customer message and agent reply with `infer: false`, so the exact words come back in later searches.

<CodeGroup>
```python Python SDK
import json

# memory/conversation.py
import json

def store_conversation_turn(
    customer_id: str,
    ticket_id:   str,
    customer_msg: str,
    agent_reply:  str,
):
    """
    user_name = customer_id so HydraDB builds a per-customer memory profile.
    infer: false - store verbatim, don't extract implicit signals here.
    """
    text = (
        f"[Ticket: {ticket_id}]\n"
        f"Customer: {customer_msg}\n"
        f"Agent: {agent_reply}"
    )
    client.context.ingest(
        type='memory',
        database=TENANT_ID,
        collection=customer_sub_tenant(customer_id),
        upsert=True,
        memories=json.dumps([{
            "text":      text,
            "user_name": customer_id,   # ties memory to this customer
            "infer":     False,          # store verbatim conversation turn
        }]),
    )
```

## Step 4: Handle a support request

Run both queries and merge them: the knowledge base holds the fix, and the memory holds who the customer is and what they already tried.

- `mode: "thinking"`: expands each query into several and reranks the results.
- `graph_context: true` on the knowledge base call: links entities across documents, with a deeper graph slice than fast mode.
- `alpha: 0.8`: the recommended starting point, leaning semantic. Lower it when messages carry literal tokens such as error codes.
- `type: "memory"` with the customer's collection: reads only that customer's memories.
- Memory chunks first in the merged list: the model weighs them more.

### Search customer context

<CodeGroup>
```python Python SDK
# support/search.py

def recall_customer_context(
    customer_id:  str,
    customer_msg: str,
    max_results:  int = 12,
) -> dict:
    """
    Two-call search pattern:
    1. search (type="knowledge") - searches knowledge base (docs, resolved tickets)
    2. search (type="memory") - searches customer's personal memory
    Merge both before passing to LLM.
    mode: "thinking" enables personalised ranking on both calls.
    collection scopes each call to the right data store.
    """
    # Call 1: knowledge base - help docs, resolved tickets, FAQs
    kb_data = client.query(
        database=TENANT_ID,
        collection=KB_SUB_TENANT,
        query=customer_msg,
        max_results=max_results,
        mode="thinking",    # personalised ranking
        graph_context=True,          # cross-document entity linking
        alpha=0.8,           # balanced semantic + keyword
    )

    # Call 2: customer personal memory - preferences, history, account facts
    mem_data = client.query(
        type="memory",
        database=TENANT_ID,
        collection=customer_sub_tenant(customer_id),
        query=customer_msg,
        max_results=8,
        mode="thinking",
    )

    # Merge: personal memory first (higher personalization weight),
    # then knowledge base chunks, then combined graph context
    return {
        "chunks":        (mem_data.data.chunks or []) + (kb_data.data.chunks or []),
        "graph_context": kb_data.data.graph_context or {},
    }
    # chunks[n]["chunk_content"]   - the actual text
    # chunks[n]["source_title"]    - which doc or memory it came from
    # chunks[n]["relevancy_score"] - HydraDB's confidence (0–1)
```
```typescript TypeScript SDK
// support/search.ts
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY! });
const TENANT_ID     = "customer-support";
const KB_SUB_TENANT = "knowledge-base";

async function recallCustomerContext(
    customerId:  string,
    customerMsg: string,
    maxResults:  number = 12,
): Promise<{ chunks: any[]; graphContext: any }> {
    /**
     * Two-call search pattern:
     * 1. fullRecall        - searches knowledge base (docs, resolved tickets)
     * 2. recallPreferences - searches customer's personal memory
     * Merge both before passing to LLM.
     * mode: "thinking" enables personalised ranking on both calls.
     * collection scopes each call to the right data store.
     */
    // Call 1: knowledge base - help docs, resolved tickets, FAQs
    const kbData = await client.query({
        database:     TENANT_ID,
        collection: KB_SUB_TENANT,
        query:         customerMsg,
        maxResults:   maxResults,
        mode:          "thinking",   // personalised ranking
        graphContext: true,         // cross-document entity linking
        alpha:         0.8,          // balanced semantic + keyword
    });

    // Call 2: customer personal memory - preferences, history, account facts
    const memData = await client.query({
        type: "memory",
        database:     TENANT_ID,
        collection: `customer-${customerId}`,
        query:         customerMsg,
        maxResults:   8,
        mode:          "thinking",
    });

    // Merge: personal memory first (higher personalization weight),
    // then knowledge base chunks, then combined graph context
    return {
        chunks:        (memData.data?.chunks || []).concat(kbData.data?.chunks || []),
        graphContext: kbData.data?.graphContext || {},
    };
    // chunks[n].chunk_content   - the actual text
    // chunks[n].source_title    - which doc or memory it came from
    // chunks[n].relevancy_score - HydraDB's confidence (0–1)
}
```

### Generate a personalized response

The memory chunks give the customer's plan, what they already tried, and how they like to be addressed; the knowledge base chunks give the solution.

<CodeGroup>
```python Python SDK
# support/respond.py
from openai import OpenAI
openai_client = OpenAI()

def handle_ticket(
    customer_id:  str,
    customer_msg: str,
    ticket_id:    str,
) -> str:
    """
    Full support handling flow:
    1. Search customer context from HydraDB
    2. Generate personalized response via LLM
    3. Store the exchange back into HydraDB memory
    Returns the agent's reply string.
    """
    # Step 1: Search
    context_data = recall_customer_context(customer_id, customer_msg)
    chunks       = context_data["chunks"] or []
    graph_ctx    = context_data["graph_context"]

    # Build context string for the LLM - ranked chunks, most useful first
    context_text = "\n\n".join(
        f"[{c.source_title or ''} | score:{c.relevancy_score or 0:.2f}]\n{c.chunk_content or ''}"
        for c in chunks
    )

    # Include entity relationship paths if available
    entity_paths = graph_ctx.query_paths if graph_ctx else []
    entity_text  = "\n".join(str(p) for p in entity_paths[:3])

    # Step 2: Generate response
    completion = openai_client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": (
                    "You are a customer support agent. Use ONLY the provided context to answer. "
                    "Adapt your tone and format to what the customer's memory profile indicates they prefer. "
                    "If you see from prior tickets that something was already tried, do not suggest it again. "
                    "If you cannot resolve the issue from the context, say so clearly and offer escalation. "
                    "Always end with: is there anything else I can help you with?"
                ),
            },
            {
                "role": "user",
                "content": (
                    f"Customer message: {customer_msg}\n\n"
                    f"Context from HydraDB (use this to answer):\n{context_text}\n\n"
                    f"Related entity relationships:\n{entity_text}"
                ),
            },
        ],
        temperature=0.2,
    )
    reply = completion.choices[0].message.content

    # Step 3: Store exchange in HydraDB memory for future personalization
    store_conversation_turn(customer_id, ticket_id, customer_msg, reply)

    return reply
```
```typescript TypeScript SDK
// support/respond.ts
import OpenAI from "openai";

const openaiClient = new OpenAI();

async function handleTicket(
    customerId:  string,
    customerMsg: string,
    ticketId:    string,
): Promise<string> {
    /**
     * Full support handling flow:
     * 1. Search customer context from HydraDB
     * 2. Generate personalized response via LLM
     * 3. Store the exchange back into HydraDB memory
     * Returns the agent's reply string.
     */
    // Step 1: Search
    const contextData = await recallCustomerContext(customerId, customerMsg);
    const chunks      = contextData.chunks || [];
    const graphCtx    = contextData.graphContext || {};

    // Build context string for the LLM - ranked chunks, most useful first
    const contextText = chunks
        .map((c: any) => `[${c.source_title} | score:${(c.relevancy_score || 0).toFixed(2)}]\n${c.chunk_content}`)
        .join("\n\n");

    // Include entity relationship paths if available
    const entityPaths = (graphCtx.queryPaths || []).slice(0, 3);
    const entityText  = entityPaths.map((p: any) => String(p)).join("\n");

    // Step 2: Generate response
    const completion = await openaiClient.chat.completions.create({
        model: "gpt-4o",
        messages: [
            {
                role: "system",
                content:
                    "You are a customer support agent. Use ONLY the provided context to answer. " +
                    "Adapt your tone and format to what the customer's memory profile indicates they prefer. " +
                    "If you see from prior tickets that something was already tried, do not suggest it again. " +
                    "If you cannot resolve the issue from the context, say so clearly and offer escalation. " +
                    "Always end with: is there anything else I can help you with?",
            },
            {
                role: "user",
                content:
                    `Customer message: ${customerMsg}\n\n` +
                    `Context from HydraDB (use this to answer):\n${contextText}\n\n` +
                    `Related entity relationships:\n${entityText}`,
            },
        ],
        temperature: 0.2,
    });
    const reply = completion.choices[0].message.content!;

    // Step 3: Store exchange in HydraDB memory for future personalization
    await storeConversationTurn(customerId, ticketId, customerMsg, reply);

    return reply;
}
```

## Step 5: Escalation and human handoff

Hand unresolved issues to a human with the account history, what the AI already tried, similar past tickets, and the customer's preferences, so nobody asks the customer to repeat the issue.

<CodeGroup>
```python Python SDK
# support/escalate.py

def escalate_to_human(
    customer_id: str,
    ticket_id:   str,
    customer_msg: str,
    ai_attempts:  list,     # [{tried, outcome}, ...]
) -> dict:
    """
    Escalate a ticket to a human agent with full HydraDB context.
    Returns the escalation payload ready to send to Zendesk, Linear, etc.
    """
    # Search full customer memory profile
    customer_profile = client.query(
        type="memory",
        database=TENANT_ID,
        collection=customer_sub_tenant(customer_id),
        query="customer account history preferences past issues plan",
    )

    # Search similar past tickets resolved by humans
    similar_data = client.query(
        database=TENANT_ID,
        query=f"{customer_msg} resolved escalated human agent",
        max_results=5,
    )
    similar_tickets = similar_data.data.chunks or []

    escalation = {
        "ticket_id":    ticket_id,
        "customer_id":  customer_id,
        "current_issue": customer_msg,
        "ai_attempts":  ai_attempts,
        "customer_profile": customer_profile,

            {
                "source":     t.source_title or "",
                "resolution": (t.chunk_content or "")[:500],

        customer_id,

    )
```

```typescript TypeScript SDK
// support/escalate.ts
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY! });
const TENANT_ID = "customer-support";

async function escalateToHuman(
    customerId:  string,
    ticketId:    string,
    customerMsg: string,
    aiAttempts:  { tried: string; outcome: string }[],
): Promise<object> {
    /**
     * Escalate a ticket to a human agent with full HydraDB context.
     * Returns the escalation payload ready to send to Zendesk, Linear, etc.
     */
    // Search full customer memory profile
    const customerProfile = await client.query({
        type: "memory",
        database:     TENANT_ID,
        collection: `customer-${customerId}`,
        query:         "customer account history preferences past issues plan",
    });

    // Search similar past tickets resolved by humans
    const similarData = await client.query({
        database:   TENANT_ID,
        query:       `${customerMsg} resolved escalated human agent`,
        maxResults: 5,
    });
    const similarTickets = similarData.data?.chunks || [];

    const escalation = {
        ticket_id:    ticketId,
        customer_id:  customerId,
        current_issue: customerMsg,
        ai_attempts:  aiAttempts,
        customer_profile: customerProfile,
        similar_resolutions: similarTickets.map((t: any) => ({
            source:     t.source_title,
            resolution: t.chunk_content.slice(0, 500),
            score:      t.relevancy_score || 0,
        })),
        note_for_human_agent:
            "Full context retrieved from HydraDB. " +
            "Do NOT ask the customer to repeat their issue - it's all above. " +
            "Check similar_resolutions for previously successful fixes.",
    };

    // Store escalation as a memory so future agents know it happened
    await storeCustomerPreference(
        customerId,
        `Ticket ${ticketId} was escalated to a human agent. AI could not resolve: ${customerMsg.slice(0, 200)}`
    );

    return escalation;
}
```

```python
# interfaces/email_webhook.py
import hashlib
import uuid
from flask import Flask, request, jsonify
flask_app = Flask(__name__)

@flask_app.route("/support/email-webhook", methods=["POST"])
def handle_email_ticket():
    """Webhook for inbound support emails. Compatible with SendGrid, Postmark."""
    data         = request.json or {}
    customer_email = data.get("from", "")
    customer_msg   = data.get("text", "")
    ticket_id      = data.get("message_id", str(uuid.uuid4()))
    # Hash the email into a stable, collision-free, valid collection id.
    # In production, prefer a CRM lookup (as the Slack interface does).
    customer_id    = "cust-" + hashlib.sha256(customer_email.lower().strip().encode()).hexdigest()[:32]

    reply = handle_ticket(customer_id, customer_msg, ticket_id)
    return jsonify({"reply": reply, "ticket_id": ticket_id})

if __name__ == "__main__":
    flask_app.run(port=8080)
```

## Benchmarks

2,400 real support tickets (billing, technical, onboarding, and account), with and without HydraDB memory, scored by human raters for quality and relevance. Each line gives the generic support bot first, then HydraDB.

- **First-contact resolution rate:** 38% vs 71% (+87%).
- **"Agent knew my history" (CSAT signal):** 12% vs 84% of sessions (+600%).
- **Unnecessary escalation rate:** 41% vs 9% (down 78%).
- **Repeated troubleshooting steps (already tried):** 67% vs 4% of tickets (down 94%).
- **P95 search latency (HydraDB step):** under 200 ms for the HydraDB agent (sub-second). Not applicable to the generic bot.

> **Benchmark methodology:** the drop in repeated steps comes from memory: a third SSO report no longer gets "try clearing your browser cache" again. Figures come from internal HydraDB testing; see the [full paper](https://research.hydradb.com/hydradb.pdf). Results vary by corpus size, content quality, and query distribution.

## Run it

1. Run `setup.py` to create your database and verify the connection.
2. Run the ingestion scripts with your real help docs and past tickets.
3. Seed a few customer memories from your CRM.
4. Wire `handle_ticket` into your support channel (email, Slack, or web chat).

There is no retraining step: each turn stored with `context.ingest(type="memory")` is ranked into that customer's next query.
