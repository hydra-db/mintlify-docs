---
title: "Authentication and API versioning"
description: "Authenticate HydraDB V2 requests, configure SDK clients, and troubleshoot authentication errors."
---

Every HydraDB V2 request requires a valid API key.

Raw HTTP requests must also include the `API-Version: 2` header. The official
Python and TypeScript SDKs add this header automatically.

## Get an API key

Get your API key from [app.hydradb.com](https://app.hydradb.com).

Store it in an environment variable instead of placing it directly in source
code:

```bash
export HYDRA_DB_API_KEY="your_api_key_here"
```

Treat your API key as a secret:

- Do not commit it to Git.
- Do not expose it in browser or client-side code.
- Do not print it in application logs.
- Use environment variables or a secrets manager in deployed environments.

## Authenticate a REST request

Raw HTTP requests require an authorization header and the V2 API-version
header:

```bash
curl -i -s "https://api.hydradb.com/databases" \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2"
```

| Header | Purpose |
|---|---|
| `Authorization: Bearer <api-key>` | Authenticates the request using your HydraDB API key. |
| `API-Version: 2` | Routes the request to the V2 API contract. |

## Use the official SDKs

Pass the API key when creating the client.

```python
import os

from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```

```typescript
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});
```

The official SDKs automatically include `API-Version: 2`. You do not need to
add the version header manually when using the standard SDK clients.

See [SDKs – Python and Node](/api-reference/v2/sdks) for installation and
method mappings.

## Troubleshoot authentication errors

| Status | Meaning | What to check |
|---|---|---|
| `401 Unauthorized` | The API key is missing, expired, or invalid. | Confirm that the environment variable is set and the request sends a correctly formatted Bearer header. |
| `403 Forbidden` | Authentication succeeded, but the API key cannot access the requested resource or operation. | Confirm that the requested resource is available to the current API key and account. |

For raw HTTP requests, also confirm that the request includes:

```http
API-Version: 2
```

Do not automatically retry `401` or `403` responses. Correct the credentials or
resource access first.

See [Error Responses](/api-reference/v2/error-responses) for the complete error
reference and retry guidance.

## Authentication checklist

Before debugging an endpoint request, verify that:

- `HYDRA_DB_API_KEY` is defined in the current environment.
- The API key is not an example or placeholder value.
- Raw HTTP requests include an `Authorization: Bearer ...` header.
- Raw HTTP requests include `API-Version: 2`.
- SDK clients receive the token during initialization.
- The requested resource is accessible to the current API key.
