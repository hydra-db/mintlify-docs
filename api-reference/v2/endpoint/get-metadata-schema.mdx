Use this endpoint to read a database's declared `database_metadata_schema`: the fields set at database creation plus any added later with [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema).

Each entry in `fields` uses the same shape that [Create Database](/api-reference/v2/endpoint/create-tenant) and [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema) accept, so the response can be passed back into `add_fields` unchanged. This makes it straightforward to reconcile the schema your application expects against what the database has already declared.

<RequestExample>

```bash cURL
curl 'https://api.hydradb.com/databases/acme_corp/metadata-schema' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2"
```

```python Python
import requests

response = requests.get(
    "https://api.hydradb.com/databases/acme_corp/metadata-schema",
    headers={
        "Authorization": f"Bearer {HYDRA_DB_API_KEY}",
        "API-Version": "2",
    },
)
```

```typescript TypeScript
const response = await fetch("https://api.hydradb.com/databases/acme_corp/metadata-schema", {
  headers: {
    Authorization: `Bearer ${process.env.HYDRA_DB_API_KEY}`,
    "API-Version": "2",
  },
});
```

</RequestExample>

## Request

### Path parameters

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Database whose metadata schema should be read. Formerly `tenant_id`; the `tenant_id` alias is still accepted (deprecated). |

## Response

`fields` lists every declared custom metadata field with its full definition: `name`, `data_type`, `max_length` (VARCHAR only), and the `enable_match` / `enable_dense_embedding` / `enable_sparse_embedding` flags. Values are returned exactly as stored; flags that are `false` are omitted.

A database with no custom metadata fields returns `200` with an empty `fields` list. An unknown or deleting database returns `404`.

## Errors

| Status | When it happens |
| --- | --- |
| `400` | Missing database path segment. |
| `404` | Database not found, or the database is being deleted. |
| `500` | Transient backend error while resolving the database or reading the schema. Retry the request. |
