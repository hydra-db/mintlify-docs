Sync a Zoom account's cloud recordings, scheduled meetings and webinars, plus Team Chat messages and shared PDF and DOCX files. Each recording is one document with the text of its transcript, captions, summary and timeline files, and links to the scheduled meeting it came from. Each scheduled meeting and each webinar is one document with its topic, time, host and agenda. Each Team Chat file is a separate document linked to the message that shared it for the same user.

Zoom permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. HydraDB does not transcribe video: only the text files Zoom produces are searchable. A transcript that becomes available after its recording was synced is not guaranteed to be added. Recordings and meetings deleted in Zoom stay in HydraDB.

<Note>
Team Chat message and file support is awaiting release. The setup and content descriptions below include that upcoming support.
</Note>

<Note>
Zoom is in beta.
</Note>

## Permissions

<Warning>
Zoom permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Zoom uses a Server-to-Server OAuth app that you create in the Zoom Marketplace.

<ResponseField name="account_id" type="secret string" required>
The app's Account ID.
</ResponseField>

<ResponseField name="client_id" type="secret string" required>
The app's Client ID.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The app's Client Secret.
</ResponseField>

**Scopes the connector reads with**

- `user:read:admin`: lists the account's users, to name hosts and to find each user's meetings and webinars.
- `cloud_recording:read:admin`
- `meeting:read:admin`
- `webinar:read:admin`
- `team_chat:read:list_user_channels:admin`: optional, lists Team Chat channels for each selected user.
- `team_chat:read:list_user_messages:admin`: optional, reads channel messages and the IDs of their shared files. The acting user also needs Chat Messages Edit permission.
- `team_chat:read:file:admin`: optional, reads shared PDF and DOCX file details and download links.

The Team Chat scopes are optional for recording-only connections. Enable them and Chat Messages Edit permission to sync chat files. If Zoom refuses one user or file, later accessible users and files still sync; an account-wide scope denial stops requests only for the affected content type. Permission warnings name the missing access. A plan without webinars syncs no webinars. If the user list is refused, no scheduled meetings, webinars or Team Chat content are synced.

### Set it up

<Steps>
  <Step title="Create a Server-to-Server OAuth app">
    In the Zoom Marketplace, create a Server-to-Server OAuth app and add the scopes above.
  </Step>
  <Step title="Copy its credentials">
    Copy the app's Account ID, Client ID and Client Secret.
  </Step>
  <Step title="Create the connector">
    Paste them as `account_id`, `client_id` and `client_secret`.
  </Step>
  <Step title="Select the account">
    HydraDB lists one item for the whole Zoom account. Select it.
  </Step>
</Steps>

One connector reads one Zoom account. Recordings are read across the account. Scheduled meetings, webinars and Team Chat channels are read for each user on the account. Selecting the whole account includes its users' channels; when individual users are selected, only their selected time windows are read.

<Accordion title="Connect through the API">

Use provider `zoom` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads recordings that started within the window set by `lookback_days`, 30 days by default. Team Chat messages and their shared files use the selected time window, limited to the last six months of messages available from Zoom.
- **New and changed items:** Each sync reads recordings, scheduled meetings and webinars by start time, and reads the account's users again in full. Team Chat reads the selected users' channels and messages within their time windows; older messages and files stay searchable when a later window omits them.
- **Edits:** A change to an older scheduled meeting or webinar that does not touch its start time may not be picked up. A transcript that becomes available after its recording was synced is not guaranteed to be added.
- **Deletions:** Recordings, meetings and webinars deleted in Zoom stay searchable in HydraDB.
- If a transcript, caption, summary or timeline file fails to download, the recording is still synced without that file's text.
- Team Chat PDF and DOCX downloads are limited to 50 MiB per file. When a file download or text extraction fails, its filename remains searchable but its contents are unavailable.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Zoom item

<ResponseField name="host" type="Searchable text, Graph identity">
The host's name, or email when there is no name, written as the `Host` line. The graph records the item as hosted by that person.
</ResponseField>

<ResponseField name="start_time" type="Searchable text, Result date">
The start time: when a recording started, or when a meeting or webinar is scheduled to start. Written in the `When` line and, as `started_at`, a `Started` line. Sets the result date and decides which items each sync reads.
</ResponseField>

<ResponseField name="duration" type="Searchable text">
The length in minutes, written as the `Duration` line.
</ResponseField>

<ResponseField name="additional_metadata.host_id" type="Query filter">
The host's Zoom user id, also kept as `host_id`. Limits a query to one host's items. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
On recordings, the Zoom account id. On scheduled meetings and webinars, the id of the Zoom user they belong to, so it limits a query to one user's meetings. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
`zoom_account` on recordings and `zoom_user` on scheduled meetings and webinars. Separates recordings from scheduled meetings and webinars. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `zoom`. Not searchable.
</ResponseField>

### Recordings

- **One document:** One cloud recording, with the text of its files.
- **Title:** The meeting topic, or `Zoom recording <id>` when it has none.
- **Text:** The topic, a `When` line, a `Duration` line in minutes and a `Host` line. Then, under `Transcript`, the transcript and caption text, followed by any summary or timeline text. Timings in transcript and caption files are removed. Summary and timeline files are kept as Zoom supplies them. The topic is searchable too.
- **Date:** When the recording started.
- **Link back:** The recording's share link in Zoom.
- **Files:** Only the text files Zoom produces: transcript, captions, summary and timeline. Their text joins the recording's text. Video and audio files are not downloaded.

<ResponseField name="host_email" type="Searchable text, Graph identity">
The host's email. Lets the graph identify the host as the same person in other tools. Searchable only when the host has no name and the email is used as the `Host` line.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="recording_count" type="Stored only">
How many recording files Zoom reported.
</ResponseField>

<ResponseField name="total_size" type="Stored only">
The total size of the recording files, in bytes.
</ResponseField>

<ResponseField name="has_transcript" type="Stored only">
Whether any transcript, caption, summary or timeline text was added. A summary or timeline alone sets it, so it does not prove that spoken transcript text is present.
</ResponseField>

</Accordion>

### Scheduled meetings and webinars

- **One document:** One scheduled meeting or one webinar.
- **Title:** The topic, or `Zoom meeting <id>` or `Zoom webinar <id>` when it has none.
- **Text:** The topic, a `When` line, a `Duration` line in minutes and a `Host` line, then the agenda. The topic is searchable too.
- **Date:** The scheduled start, else when the meeting or webinar was created.
- **Link back:** The join link.

<ResponseField name="agenda" type="Searchable text">
The agenda, written after the header lines.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the meeting or webinar was created. Sets the result date only when there is no scheduled start. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="webinar_id" type="Stored only">
The webinar's numeric id, on webinars only.
</ResponseField>

</Accordion>

### Team Chat messages

- **One document:** One channel message for one user. The same message seen by two selected users remains two separate documents.
- **Title:** The message text, or `Zoom Team Chat message` when it is empty.
- **Text:** The message text.
- **Date:** When the message was sent.

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="channel_id" type="Stored only">
The Team Chat channel containing the message.
</ResponseField>

<ResponseField name="user_id" type="Stored only">
The account user whose channel list exposed the message.
</ResponseField>

</Accordion>

### Team Chat files

- **One document:** One PDF or DOCX file shared by one message for one user. Sharing the same file in another message or through another selected user creates a separate document.
- **Title:** The filename, or `Zoom Team Chat file` when it has none.
- **Text:** The extracted PDF or DOCX text. If extraction is unavailable, only the filename is searchable.
- **Date:** When Zoom reports that the file was modified, if available.
- **Files:** PDF and DOCX only, up to 50 MiB per download. Audio, video and other file formats are not downloaded.

<ResponseField name="parent_id" type="Graph connection">
Links the file to the message that shared it for the same user. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="file_id" type="Stored only">
The stable Zoom file ID, independent of its temporary download link.
</ResponseField>

<ResponseField name="channel_id" type="Stored only">
The channel containing the sharing message.
</ResponseField>

<ResponseField name="user_id" type="Stored only">
The account user whose channel list exposed the file.
</ResponseField>

</Accordion>

**Example searches**

- What was discussed in last Thursday's all-hands recording?
- What is on the agenda for next week's board meeting?
- What does the project plan PDF shared in Team Chat say?

## How it fits into the graph

- Recordings use the Meeting class.
- Scheduled meetings and webinars use the Meeting class.
- Team Chat messages use the Page class.
- Team Chat files use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Zoom creates**

- A recording to the scheduled meeting it recorded.
- A Team Chat file to the message that shared it for the same user.
- No links to other tools.

**People and groups**

- The host of each recording, scheduled meeting and webinar.
- On recordings, the host's email as well, so the host can be matched to the same person in other tools.
- Meeting participants are not synced, so they are not attached as people.

**Found in the text**

The text of each recording's transcript, caption, summary and timeline files, each scheduled meeting's and webinar's agenda, Team Chat messages and extracted PDF and DOCX contents. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Audio and video recording files.
- Participant lists and in-meeting chat messages.
- Team Chat history older than six months or outside the selected time window.
- Team Chat files other than PDF and DOCX, and file contents that exceed the 50 MiB download limit.
- Timings and cue details in transcript and caption files.
- A file's text when its download fails or the file is unavailable.
- Items Zoom refuses because of your plan or the app's scopes.
- Deletions: recordings and meetings deleted in Zoom stay in HydraDB.
