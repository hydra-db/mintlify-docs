Sync a whole Copper account: opportunities, leads, tasks, projects, people, companies, and the notes and logged interactions on them. Each record or activity is one document. An activity links to the record it is logged on.

One account-wide resource covers everything the API key can read. Copper permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Records deleted in Copper stay in HydraDB. Activities with no text, such as stage changes, are skipped.

<Note>
Copper is in beta.
</Note>

## Permissions

<Warning>
Copper permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Copper uses an API key together with the email of the Copper user the key belongs to.

<ResponseField name="api_key" type="secret string" required>
A Copper API key.
</ResponseField>

<ResponseField name="user_email" type="string" required>
The email of the Copper user the API key belongs to.
</ResponseField>

### Set it up

<Steps>
  <Step title="Get an API key">
    In Copper, get an API key. Note the email of the Copper user it belongs to.
  </Step>
  <Step title="Create the connector">
    Paste the key as `api_key` and the user's email as `user_email`.
  </Step>
  <Step title="Configure the connector">
    HydraDB lists one account-wide resource, All data. Select it to sync everything the key can read in the account.
  </Step>
</Steps>

One connector reads one Copper account.

<Accordion title="Connect through the API">

Use provider `copper` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads records and activities modified since the last sync.
- **Edits:** An edited record is read again and updates its document.
- **Deletions:** Deleted records are not removed. A record deleted in Copper stays searchable in HydraDB.
- If the account does not have a Copper add-on feature enabled, the record type that needs it is skipped with a warning and the other types still sync.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Copper item

<ResponseField name="additional_metadata.copper_id" type="Query filter">
The Copper record id. Targets one record, and keeps later syncs on the same document. Tasks carry a `task:` prefix and projects a `project:` prefix, so include it when you filter on a task or project. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.copper_object" type="Query filter">
The record type, such as `opportunities`, `people` or `activities_search`. Limits a query to one type. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `copper`. Not searchable.
</ResponseField>

### Opportunities, leads, tasks and projects

- **One document:** One opportunity, lead, task or project.
- **Title:** The record's name.
- **Text:** The record's free-text details, then `Label: value` lines. Opportunities: `Name`, `Company`, `Status`, `Value` with its currency, `Close date` and `Assignee`. Leads: `Name`, `Company`, `Title`, `Status`, `Value`, `Email` and `Assignee`. Tasks: `Name`, `Status`, `Priority`, `Due date`, `Tags` and `Assignee`. Projects: `Name`, `Status`, `Company`, `Tags` and `Assignee`. The name is searchable too.
- **Date:** When the record was last modified, else when it was created.
- **Link back:** None. Use `additional_metadata.copper_id` to find the record in Copper.

<ResponseField name="assignee" type="Searchable text, Graph identity">
The assigned user's name, or their email when the name is missing, written as the `Assignee` line. The graph records the record as assigned to that person.
</ResponseField>

<ResponseField name="status" type="Searchable text">
The Copper status, such as Open, Won, Lost or Completed, written as the `Status` line.
</ResponseField>

<ResponseField name="monetary_value" type="Searchable text">
An opportunity's or lead's value, written as the `Value` line.
</ResponseField>

<ResponseField name="company_name" type="Searchable text">
The related company's name on opportunities, leads and projects, written as the `Company` line.
</ResponseField>

<ResponseField name="close_date" type="Searchable text">
An opportunity's close date, written as the `Close date` line.
</ResponseField>

<ResponseField name="priority" type="Searchable text">
A task's priority, written as the `Priority` line.
</ResponseField>

<ResponseField name="due_date" type="Searchable text">
A task's due time, written as the `Due date` line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the record was created, written as a `Created` line. Used as the result date only when the modification time is missing.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the record was last modified. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (4)">

<ResponseField name="pipeline_id" type="Stored only">
An opportunity's pipeline id. It is not turned into a name.
</ResponseField>

<ResponseField name="pipeline_stage_id" type="Stored only">
An opportunity's stage id. It is not turned into a name.
</ResponseField>

<ResponseField name="completed_date" type="Stored only">
When a task was completed. It is not the result date.
</ResponseField>

<ResponseField name="object_type" type="Stored only">
The record type. Filter on it with `additional_metadata.copper_object`.
</ResponseField>

</Accordion>

### People and companies

- **One document:** One person, or one company.
- **Title:** The person's or company's name.
- **Text:** The record's free-text details, then `Label: value` lines. People: `Name`, `Company`, `Title`, `Emails` and `Assignee`. Companies: `Name`, `Email domain` and `Assignee`. The name is searchable too.
- **Date:** When the record was last modified, else when it was created.
- **Link back:** None. Use `additional_metadata.copper_id` to find the record in Copper.

<ResponseField name="assignee" type="Searchable text">
The owner's name, written as the `Assignee` line, where HydraDB can identify the person. It does not create an assignee relationship.
</ResponseField>

<ResponseField name="company_name" type="Searchable text">
A person's company, written as the `Company` line.
</ResponseField>

<ResponseField name="title" type="Searchable text">
A person's job title, written as the `Title` line.
</ResponseField>

<ResponseField name="email_domain" type="Searchable text">
A company's email domain, written as the `Email domain` line, so a company can be found by its domain.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the record was last modified. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the record was created. Used as the result date only when the modification time is missing. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="object_type" type="Stored only">
`people` or `companies`. Filter on it with `additional_metadata.copper_object`.
</ResponseField>

</Accordion>

### Activities

- **One document:** One note or logged interaction that has text. Activities with no text, such as stage changes, are skipped.
- **Title:** `Comment by` and the name of the user who logged it. Without an author, the first 80 characters of the text. The activity type is not used as the title and is not searchable.
- **Text:** The activity's details text, with the author, the record it is logged on, and its created and updated times.
- **Date:** When the activity record was last modified, else when it was created.
- **Link back:** None.

<ResponseField name="author" type="Searchable text, Graph identity">
The user who logged the activity, as a name. The graph records the activity as written by that person.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The record the activity is logged on, written as a `Parent` line. Links the activity to that record when it is a person, lead, opportunity, company, project or task.
</ResponseField>

<ResponseField name="additional_metadata.copper_parent_id" type="Query filter">
The bare id of the record the activity is logged on, with no prefix. Returns every activity logged on one record. Not searchable.
</ResponseField>

<ResponseField name="updated_at" type="Searchable text, Result date">
When the activity record was last modified, written as an `Updated` line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the activity record was created, written as a `Created` line. Used as the result date only when the modification time is missing.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="activity_date" type="Stored only">
When the activity happened. It is not the result date.
</ResponseField>

<ResponseField name="parent_type" type="Stored only">
The type of record the activity is logged on: person, lead, opportunity, company, project or task.
</ResponseField>

</Accordion>

**Example searches**

- Which opportunities for Acme are open and what are they worth?
- What was the last note logged on this lead?
- Which tasks are due this week and who owns them?

## How it fits into the graph

- Opportunities, leads, tasks and projects use the Ticket class.
- People and companies use the Record class.
- Activities use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Copper creates**

- An activity to the person, lead, opportunity, company, project or task it is logged on.
- An opportunity to its company and its primary contact.
- A person to their company.
- A task or project to its related record, and a project to its company.
- A link is made only to record types this connector syncs. No links to other tools.

**People and groups**

- The assignee of each opportunity, lead, task and project.
- The author of each activity.
- The assignee of a person or company appears only in its text.

**Found in the text**

The free-text details of every record, the `Label: value` lines, and the text of notes and logged interactions. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Activities with no text, such as stage changes.
- Custom field values.
- Pipelines, stages, tags, lead statuses, loss reasons and other Copper settings, as documents of their own.
- Files attached to records.
- Deletions: deleted records stay in HydraDB.
