Creates an isolated database, optionally with a metadata schema. Creation is asynchronous: poll [Database Status](/api-reference/v2/endpoint/database-status) until `infra.ready_for_ingestion` is `true` before you ingest or query.

<RequestExample>

```python Python SDK
response = client.databases.create(
    database="my_first_database",
    database_metadata_schema=[
        {
            "name": "category",
            "data_type": "VARCHAR",
            "max_length": 256,
        },
        {
            "name": "product_description",
            "data_type": "VARCHAR",
            "max_length": 4096,
            "enable_dense_embedding": True,
            "enable_sparse_embedding": True,
        },
    ],
)
```

## Request body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Account-scoped database identifier. Use a stable ID up to 255 characters of lowercase letters, digits, `-`, and `_`; anything else, including uppercase or spaces, returns `400`. |
| <Field name="database_metadata_schema" type="array" /> | Database-level metadata fields. See the [schema field reference](/essentials/v2/metadata#schema-field-reference) for field options. |

## Metadata schema rules

- Existing field names and types cannot change. [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema) can add fields later.
- Dense and sparse metadata search can only be enabled at database creation, with `enable_dense_embedding` and `enable_sparse_embedding`.
- Each flag adds one vector field. A database can have at most six vector fields. Exceeding this limit or declaring an `ARRAY` field returns `400`.

## After creation

1. **Wait for provisioning:** Poll [Database Status](/api-reference/v2/endpoint/database-status) until `infra.ready_for_ingestion` is `true`.
2. **Ingest:** Start [ingesting context](/api-reference/v2/endpoint/ingest-context). Ingesting with a new `collection` name creates that collection. Omitting `collection` uses the default collection, also created on first ingestion. No separate create call is needed.
3. **Query:** Check [ingestion status](/api-reference/v2/endpoint/source-status), and query once sources show `graph_creation` (searchable) or `completed`.

**Failed provisioning:** If the database appears in `data.failed_databases` from [List Databases](/api-reference/v2/endpoint/list-databases), address the reported issue, re-create the database with `POST /databases`, and poll status again before ingesting.

## Errors

Common codes: `400 INVALID_INPUT` (missing or invalid `database`, or an invalid schema), `403 FORBIDDEN` (your plan's database limit is reached), `409 DATABASE_ALREADY_EXISTS` (the `database` is already in use; the deprecated `POST /tenants` route returns `INVALID_INPUT` instead), and `500 INTERNAL_ERROR` (retry; if the message says the rollback also failed, delete the database first, then create it again). See [Error Responses](/api-reference/v2/error-responses) for the full list.
