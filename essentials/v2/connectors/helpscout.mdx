Sync conversations from the Help Scout mailboxes you select. Each conversation is one document with its preview, customer, assignee, mailbox and tags. Each customer message, agent reply and internal note is its own document, linked to its conversation. The full text lives in those message documents, not in the conversation.

Help Scout permissions are not imported, so every synced conversation and message, including internal notes, is visible to everyone who can query the collection unless you set an access rule. Conversations deleted in Help Scout stay in HydraDB. Help Scout Docs and attachments are not synced.

## Permissions

<Warning>
Help Scout permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Internal notes are synced with every other message. Help Scout's own audience for a note is not imported. Set an access rule on a mailbox whose notes must stay private.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Help Scout uses the App ID and App Secret of a Help Scout app. HydraDB gets a fresh access token from them on every sync, so there is no refresh token to manage.

<ResponseField name="client_id" type="secret string" required>
The App ID of a Help Scout app owned by the account you connect.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The App Secret of that app.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create a Help Scout app">
    In the Help Scout account you want to connect, create an app and copy its App ID and App Secret.
  </Step>
  <Step title="Create the connector">
    Paste the App ID as `client_id` and the App Secret as `client_secret`.
  </Step>
  <Step title="Select mailboxes">
    HydraDB lists the account's mailboxes. Select the ones to sync. Only conversations in selected mailboxes are synced.
  </Step>
</Steps>

One connector reads one Help Scout account. An app belongs to one account, so each account needs its own app.

<Accordion title="Connect through the API">

Use provider `helpscout` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected mailbox reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads conversations that changed since the last sync. A conversation counts as changed when a user updated it or the customer started waiting on it. Every message in a changed conversation is read again.
- **Edits:** A changed conversation is read again with all its messages, and updates their documents.
- **Deletions:** Deleted conversations and messages are not removed. They stay searchable in HydraDB.
- A connector created before mailboxes could be selected syncs the whole account.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Help Scout item

<ResponseField name="additional_metadata.helpscout_id" type="Query filter">
The conversation id on a conversation, the thread id on a message. Targets one item, and keeps later syncs on the same document. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `helpscout`. Not searchable.
</ResponseField>

### Conversations

- **One document:** One conversation.
- **Title:** The conversation subject.
- **Text:** The conversation preview, or the subject when the preview is empty. Then `Customer`, `Assignee`, `Mailbox` and `Tags` lines. The status and creation time are part of the text too. The subject is searchable too. The preview is short, so search the messages for the full text.
- **Date:** When the conversation was last updated, else when it was created.
- **Link back:** The conversation in Help Scout.

<ResponseField name="status" type="Searchable text">
The conversation status: active, pending, closed or spam, written as a `Status` line.
</ResponseField>

<ResponseField name="customer" type="Searchable text">
The primary customer's name or email, written as the `Customer` line, where HydraDB can identify the person.
</ResponseField>

<ResponseField name="assignee" type="Searchable text">
The assigned user's name or email, written as the `Assignee` line, where HydraDB can identify the person.
</ResponseField>

<ResponseField name="mailbox" type="Searchable text">
The mailbox name, written as the `Mailbox` line, where HydraDB can identify the mailbox. It does not create a link to a mailbox.
</ResponseField>

<ResponseField name="tags" type="Searchable text">
The tag names, written as the `Tags` line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the conversation was created, written as a `Created` line. Used as the result date only when there is no update time.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the conversation was last updated. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="state" type="Stored only">
Published, draft or deleted.
</ResponseField>

<ResponseField name="number" type="Stored only">
The conversation number Help Scout shows. It is part of the link back.
</ResponseField>

<ResponseField name="mailbox_id" type="Stored only">
The mailbox id. The mailbox name is in `mailbox`.
</ResponseField>

</Accordion>

### Messages

- **One document:** One customer message, agent reply or internal note that has a body. Status-only entries are skipped.
- **Title:** `Comment by` and the author's name. Without an author, the first 80 characters of the text.
- **Text:** An `Author` line, then the message body converted from HTML to text. The creation time is part of the text too.
- **Date:** When the message was created.
- **Link back:** None. Open the conversation from its own document.
- **Files:** Attachments are not synced.

<ResponseField name="author" type="Searchable text, Graph identity">
The name or email of whoever wrote the message, else the customer, written as the `Author` line. The graph records the message as written by that person.
</ResponseField>

<ResponseField name="mentions" type="Searchable text, Graph identity">
Names @mentioned in an internal note. The names stay in the note text, and the graph records each as mentioned.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The conversation the message belongs to. Links the message to its conversation, so the whole exchange can be returned together.
</ResponseField>

<ResponseField name="additional_metadata.helpscout_conversation_id" type="Query filter">
The id of the conversation the message belongs to. Returns every message in one conversation. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the message was created, written as a `Created` line.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="type" type="Stored only">
`customer`, `message` or `note`, so you can tell a customer message from an internal note.
</ResponseField>

<ResponseField name="status" type="Stored only">
The message's status in Help Scout.
</ResponseField>

</Accordion>

**Example searches**

- What did the customer say in the latest conversation about a refund?
- Which open conversations are assigned to Maria?
- Which conversations mention refunds in the billing mailbox?

## How it fits into the graph

- Conversations use the Ticket class.
- Messages use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Help Scout creates**

- A message to its conversation.
- No links to other tools.

**People and groups**

- The author of each message.
- Names @mentioned in an internal note.
- The customer, the assignee and the mailbox appear in the conversation text, where HydraDB can identify them.

**Found in the text**

The conversation preview with its customer, assignee, mailbox and tag lines, and the body of every message. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Mailboxes you did not select.
- Help Scout Docs, the knowledge base, which uses a separate API and key.
- Customer profiles and happiness ratings.
- Users, teams, workflows, saved replies and mailbox folders, as documents of their own.
- Conversation custom field values.
- Attachments.
- Deletions: deleted conversations and messages stay in HydraDB.
