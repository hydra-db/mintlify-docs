title: "List Context"

Page through the sources stored in one database and collection, for example to find IDs or audit what was ingested. `type` selects what to list: `knowledge` (the default: documents and app sources), `memory`, or `all` for both.

Narrow results with `ids` and `filters`, and return only the fields you need with `include_fields`. See [Metadata Filters](/essentials/v2/metadata#7-list-sources-with-metadata-filters) for the metadata workflow.

<RequestExample>

```python Python SDK
sources = client.context.list(
    database="acme_corp",
    type="knowledge",
    page=1,
    page_size=50,
    filters={
        "metadata": {"department": "legal"},
        "source_fields": {"title": "Compliance"},
    },
    include_fields=["title", "type", "timestamp", "additional_metadata"],
)
```

## Filters

`filters` accepts three categories:

```json
{
  "filters": {
    "metadata": { "department": "Finance", "region": "US" },
    "additional_metadata": { "author": "Alice Smith" },
    "source_fields": { "app_provider": "slack", "title": "standup notes" }
  }
}
```

- `metadata`: schema-backed metadata fields.
- `additional_metadata`: free-form metadata. No schema declaration is required.
- `source_fields`: built-in and connector fields. Supported keys are `type`, `title`, `description`, `url`, `timestamp`, `app_provider`, `app_kind`, `app_external_id`, and `app_parent_id`. Unsupported keys return `400`. Pair external IDs with `app_provider`.

Matching rules:

- Values must match exactly, except `source_fields.title`, which matches a case-insensitive prefix.
- All filter pairs combine with AND. When `ids` is non-empty, filters apply only to those IDs, and pagination still applies.
- Range, contains, and OR operators are not supported. For OR behavior, run separate calls and combine the results in your application.
- A `null` filter value returns `400`.

## Field projection

Pass `include_fields` to keep response payloads small. Only the listed fields are populated, plus `id`, `database`, and `collection`, which are always returned. Treat omitted fields as unavailable in that response. Omit `include_fields` or pass `null` to return everything.

- Allowed values are `title`, `type`, `description`, `note`, `timestamp`, `metadata`, `additional_metadata`, and `relations`, plus the deprecated aliases `tenant_metadata` and `document_metadata`.
- `content`, `url`, and `attachments` are not valid values. They are stripped from list responses, and requesting one returns `400`. Fetch them per source with [Inspect Context](/api-reference/v2/endpoint/fetch-content).
- Projection applies only to `type=knowledge`.

## Behavior notes

- **Memories:** For `type=memory`, read `data.user_memories[]`. Each entry includes a `memory_id`, source details, and metadata. Read the memory text and `inferred_content` with [Inspect Context](/api-reference/v2/endpoint/fetch-content).
- **Memory listing unavailable:** If the memory store cannot be read, the call still returns `200` with an empty `user_memories` and `message` set to `"Memories temporarily unavailable"`. Check `message` before you treat an empty list as "no memories".
- **Access control:** `acl` lists the principals to list as. Omitting it, or sending `[]` or `["*"]`, disables caller-supplied filtering. It is ignored for `type=memory`. For enforced connectors, the authenticated caller is used instead; see [ACL enforcement](/essentials/v2/connectors#enforce-acl).
- **Limits:** `ids` accepts at most `100` IDs. `page_size` ranges from `1` to `100` (default `50`), and `page` starts at `1`.
