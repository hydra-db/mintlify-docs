Sync messages and replies from the public and private Slack channels you select in one workspace. Each message and each thread reply is one document, and a reply links to the message that started its thread. Shared files are downloaded and their text is searchable with the message when the download and text reading succeed.

Private-channel membership restricts search only when Enforce ACL is on and HydraDB can read the channel's members. Direct messages are not synced. Edits and deletions made in Slack after a message is synced are not picked up.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow Slack permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** A public channel's messages can be read by everyone who can query the collection. A private channel's messages can be read by its members. HydraDB reads this once per channel on each sync. There is no per-message permission.
- **How a person is identified:** A member's email address, in lower case. Bots and deactivated users have no email and are left out.
- **When permissions cannot be read:** If HydraDB cannot read a channel's privacy, members or member emails, the connector reports a permission warning. On HydraDB Cloud, with Enforce ACL on, such an item follows the access rule you set on its resource. With no rule, it is hidden from search. Self-hosted deployments can be configured differently. Permission warnings appear in [Get Connector Status](/api-reference/v2/endpoint/get-connector-status).
- A private channel with more than 1,000 members who have emails, or more than 3,000 members in all, cannot be captured. Set an access rule on such a channel.
- Without `users:read.email`, permissions cannot be captured for any private channel.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

Slack uses a token from a Slack app installed in your workspace. A bot token or a user token works.

<ResponseField name="access_token" type="secret string" required>
A Slack bot token, which starts with `xoxb-`, or a user token, which starts with `xoxp-`.
</ResponseField>

**Scopes to add to the Slack app**

- `channels:read`: lists public channels for you to select.
- `channels:history`
- `groups:read`: lists private channels for you to select.
- `groups:history`
- `users:read`
- `users:read.email`: without it, permissions cannot be captured for any private channel.
- `files:read`

If neither `channels:read` nor `groups:read` is granted, connecting fails with a message that names the missing scope.

### Set it up

<Steps>
  <Step title="Create a Slack app">
    Create a Slack app for your workspace and add the scopes above.
  </Step>
  <Step title="Install it">
    Install the app in the workspace and copy its token.
  </Step>
  <Step title="Create the connector">
    Paste the token as `access_token`.
  </Step>
  <Step title="Select channels">
    HydraDB lists the non-archived channels the token can see. For each channel, it shows privacy, app membership and member count. Select the channels to sync.
  </Step>
</Steps>

One token covers one Slack workspace.

To connect more than one Slack workspace, give each connector its own `provider_account_scope`, such as `slack-account-a` and `slack-account-b`. These are labels you choose, not Slack's own account ids, and HydraDB does not check them. Two connectors that share a scope and write to the same collection can overwrite each other's items. See [several accounts from one provider](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider).

<Accordion title="Connect through the API">

Use provider `slack` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected channel reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** New messages and replies are synced from recent history. New replies on older threads are checked every 6 hours by default. That check covers channel history over multiple syncs, so older replies may arrive later.
- **Edits:** A routine sync does not pick up an edit to a message that is already synced.
- **Deletions:** Deleted messages are not removed. A message deleted in Slack stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Messages

- **One document:** One Slack message: a message posted in a channel, or a single reply in a thread.
- **Title:** The channel name with `#`, a colon and the message's first line, cut to about 80 characters, for example `#general: Deploy is done`. A reply reads `#general thread: ...`. A message with no text is titled `Slack message`. When a message has text, search matches the message, not this title, so a channel name in a query does not reliably limit results to that channel.
- **Text:** The message text, with mentions turned into display names. Then the pretext, title and text of any legacy attachments, and one `[file: name]` line per shared file. The sender is written as a `From` line and the time as a `Sent` line.
- **Date:** The message's Slack timestamp.
- **Link back:** A Slack permalink to the message. A reply links to itself inside its thread. Empty if the workspace address could not be read.
- **Files:** Each shared file is downloaded and read, and its text becomes searchable with the message. A file is skipped if Slack gave no download address, the download fails, or the file is too large.

<ResponseField name="author" type="Searchable text, Graph identity">
The display name of the person or bot that posted, written as the `From` line. The graph records the message as sent by that person. If the name could not be read, the raw Slack id is kept, and later syncs do not go back to fix it.
</ResponseField>

<ResponseField name="Shared files" type="Searchable text">
The text read from each shared file, searchable with the message.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
The message time, written as the `Sent` line.
</ResponseField>

<ResponseField name="mentions" type="Searchable text, Graph identity">
Display names of people mentioned in the message. The graph records each as mentioned.
</ResponseField>

<ResponseField name="additional_metadata.slack_ts" type="Query filter">
The message's Slack timestamp. Picks out one exact message. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.slack_thread_ts" type="Query filter">
The timestamp of the thread's first message, empty outside a thread. Limits a query to one thread. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.slack_subtype" type="Query filter">
Slack's message subtype, such as `bot_message` or `file_share`. Includes or excludes bot posts and file shares. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.slack_bot_id" type="Query filter">
The bot id when a bot posted the message. Includes or excludes one bot's messages. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.slack_reply_count" type="Query filter">
How many replies the thread has. Finds thread starters by how many replies they drew. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's messages. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `slack`. Not searchable.
</ResponseField>

<ResponseField name="parent_id" type="Graph connection">
For a reply, the message that started its thread. Joins the reply to that message, so the whole conversation can be returned together. Not searchable.
</ResponseField>

<ResponseField name="thread_id" type="Graph connection">
The thread a message belongs to. Groups every message of one thread together in the graph. Not searchable.
</ResponseField>

<ResponseField name="Channel" type="Access rule">
The selected channel. For a private channel, its members decide who can read its messages. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (6)">

<ResponseField name="attachment_count" type="Stored only">
How many legacy attachments the message had.
</ResponseField>

<ResponseField name="file_count" type="Stored only">
How many shared files Slack listed, including any that could not be downloaded.
</ResponseField>

<ResponseField name="is_edited" type="Stored only">
Whether Slack marked the message as edited when it was read. Later edits are not picked up automatically.
</ResponseField>

<ResponseField name="edited_by" type="Stored only">
The display name of the editor, when edited. The editor is not added to the graph as a person.
</ResponseField>

<ResponseField name="edited_at" type="Stored only">
The edit time, when edited. The result date stays the original message time.
</ResponseField>

<ResponseField name="slack_files" type="Stored only">
The details Slack supplied for each shared file, kept even when a file's text could not be read.
</ResponseField>

**Example searches**

- What did the team decide about the release last week?
- What did Priya say in the thread about the pricing change?
- Which messages were posted by the alerts bot?

## How it fits into the graph

- Messages use the Message class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Slack creates**

- A thread reply to the message that started the thread.
- Every message to its thread, including a message nobody replied to.
- No links to items in other tools.

**People and groups**

- The sender of each message.
- People mentioned in a message.
- An editor is kept with the message but not added to the graph.

**Found in the text**

The message text, legacy attachment text and shared file text. Each reply is read together with the text of its thread's first message. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Archived channels: HydraDB does not list them for selection.
- Direct messages and group direct messages.
- System messages: joins, leaves, renames, topic and purpose changes, pins, bots being added or removed, and thread broadcasts.
- Edits and deletions made after a message was synced.
- Reactions.
