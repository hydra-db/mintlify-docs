## Pattern

A successful HTTP status or a new push does not prove all documents match their source. Failed comparisons, failed deletions and omitted response schemas can silently leave a searchable corpus stale or incomplete.

The workflow, deletion, git comparison and OpenAPI rendering in #332:

## Why it happens

Per-event diffs do not track the last successful write, catch-and-empty helpers erase failures, and response codes are easier to render than referenced schemas.

## Catch it earlier

Run `python -m unittest discover -s scripts -p 'test_sync*.py'`. Inject unsuccessful delete bodies, invalid refs and recursive response schemas; verify that CI always reconciles all pages.

## Refactor that removes it

Reconcile the full navigation on each CI run. Treat git failure as fatal, request strict deletion status and confirm each ID, and render nested response schemas with a depth bound.
