Use the Notion connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `pages`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

Set a stable, distinct `provider_account_scope` for each connected account yourself, for example `notion-account-a` and `notion-account-b`. These are caller-provided example identifiers, not validated native account-ID formats. The API stores the supplied value; it does not derive or validate the provider's account identity. Reusing a scope can make sources with matching external IDs overwrite each other in the same destination.

Use provider `notion` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
