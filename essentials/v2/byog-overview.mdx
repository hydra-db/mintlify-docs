**Bring Your Own Graph (BYOG)** lets you use your own entities and relations in HydraDB instead of relying only on what HydraDB extracts. You can write **openCypher** queries against an isolated graph, or attach a graph to your ingested sources with no Cypher at all.

This page is an overview of how BYOG works. For the complete guide with every endpoint, example query, response format, and error code, head over to the [BYOG API reference](/essentials/v2/bring-your-own-graph).

## Core concepts

- **Database:** the top-level container for your graph collections, visible only to your organization.
- **Collection:** an isolated graph inside a database. Each query runs against one collection and cannot see another. Collections are created on first write.
- **Your own keys:** internal node `id`s can be reused after deletes and don't survive export or import. Key your data on a property you own, such as `ext_id`, and `MERGE` on it.
- **Parameters:** pass data through `params`, never by building it into the query string.

## Quickstart: create a graph with Cypher

```bash
# 1. Create a database
curl -X POST "https://api.hydradb.com/byog/databases" \
  -H "Authorization: Bearer $HYDRADB_API_KEY" -H "API-Version: 2" -H "Content-Type: application/json" \
  -d '{"database": "crm"}'

# 2. Write nodes (the collection is created on first write)
curl -X POST "https://api.hydradb.com/byog/query" \
  -H "Authorization: Bearer $HYDRADB_API_KEY" -H "API-Version: 2" -H "Content-Type: application/json" \
  -d '{
    "database": "crm",
    "collection": "contacts",
    "query": "UNWIND $rows AS row MERGE (p:Person {ext_id: row.ext_id}) SET p += row RETURN count(p) AS written",
    "params": {"rows": [{"ext_id": "u1", "name": "Alice"}, {"ext_id": "u2", "name": "Bob"}]}
  }'
```

Rows come back in `data`, one object per row, keyed by your `RETURN` aliases. Always alias the columns you read.

<Note>
Check the `status` returned when you create a database. `ready` means you can query immediately. `provisioning` means you should wait for [Database Status](/api-reference/v2/endpoint/database-status) to report readiness.
</Note>

## Supported Cypher and dialect differences

HydraDB supports all of openCypher except server-side procedures (`CALL db.*`, `CALL apoc.*`) and `LOAD CSV`. Send data through `params` instead.

- **Existence checks** use bare pattern predicates: `WHERE (p)-[:KNOWS]->()`. The `EXISTS { }` block is not accepted.
- **`shortestPath`** goes in a `RETURN` or `WITH` clause, and the traversal must be directed.

## Add a knowledge graph without Cypher

To replace extraction with your own entities and relations for a source, pass `graph_payload` to [`POST /context/ingest`](/api-reference/v2/endpoint/ingest-context), keyed by source ID:

```json
{
  "billing-policy-doc": {
    "entities": {
      "alice":   { "name": "Alice Carter", "type": "PERSON", "namespace": "employees" },
      "billing": { "name": "Billing Policy", "type": "POLICY", "namespace": "policies" }
    },
    "relations": [
      { "source": "alice", "target": "billing", "predicate": "OWNS" }
    ]
  }
}
```

HydraDB skips extraction for that source (it's still chunked and embedded). Your relations appear in `/query` `graph_context` tagged `origin: "byog"`, and the payload persists across re-ingests.

## Migrate from Neo4j or Memgraph

Most application Cypher ports directly. Migrate one collection at a time: load nodes first, then relationships matched on your own key, then compare counts. See the [full Neo4j migration script](/essentials/v2/bring-your-own-graph#migrate-from-neo4j-or-another-cypher-compatible-database).

## Limits

Request bodies are capped at 256 KiB. Reads time out at 8 s and writes at 30 s. Result sets beyond the deployment cap are silently truncated, so paginate large reads with `ORDER BY`, `SKIP` and `LIMIT`. Index any property you filter on.

## FAQ

<AccordionGroup>
  <Accordion title="What is Bring Your Own Graph (BYOG)?">
    BYOG lets you supply your own graph to HydraDB, either by querying it with openCypher or by attaching entities and relations to sources at ingest.
  </Accordion>
  <Accordion title="Can I use Cypher with HydraDB?">
    Yes. HydraDB supports openCypher over a REST API, except procedure calls and `LOAD CSV`.
  </Accordion>
  <Accordion title="Can I migrate from Neo4j to HydraDB?">
    Yes. Export nodes and relationships, then replay them into a collection using `MERGE` on your own key.
  </Accordion>
  <Accordion title="Can AI agents query the graph?">
    Yes. Agents can run the same Cypher through the [HydraDB MCP](/plugins/mcp) graph tools.
  </Accordion>
</AccordionGroup>
