title: "Retry Delivery"

import { Field } from "/snippets/field.jsx";

Queues one delivery for another send attempt. Only deliveries in the `failed` or `permanently_failed` state can be retried manually  -  `pending` and `sweeping` deliveries are already in flight, and `delivered` events are final.

HydraDB also retries `failed` deliveries automatically in the background. Reach for manual retry when a delivery is `permanently_failed`, or when you have just fixed your receiver and don't want to wait for the next automatic attempt.

<RequestExample>

```bash cURL
curl -X POST 'https://api.hydradb.com/webhooks/indexing/deliveries/<delivery_id>/retry' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2"
```

</RequestExample>

## Path parameters

| Name | Description |
| --- | --- |
| <Field name="delivery_id" type="string" required /> | ID of a `failed` or `permanently_failed` delivery, from [List Deliveries](/api-reference/v2/endpoint/list-deliveries) or a webhook payload. |

<ResponseExample>

```json 200
{
  "delivery_id": "<delivery_id>",
  "queued": true,
  "message": "Delivery queued for retry."
}
```

</ResponseExample>

The retried event arrives at your endpoint with the **same** `delivery_id` as the original attempt. Idempotent receivers that deduplicate on `delivery_id` handle retries safely  -  see the [Webhooks guide](/essentials/v2/webhooks#6-delivery-and-retries).
