Sync issues, merge requests and their notes, Markdown files on the default branch, releases, project descriptions and commit messages from the GitLab projects you select. Each issue, merge request, note, file, release, project and commit is one document, and a note links to its issue or merge request.

A private project's items are limited to its members only when Enforce ACL is on and HydraDB can read every member's email. Confidential issues and internal notes are kept only as empty placeholders. Code and diffs are not synced, and items deleted in GitLab can stay in HydraDB.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow GitLab permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** Access follows the project. A public or internal project can be read by everyone who can query the collection. A private project can be read by its active members at any access level, including inherited group members and members of groups the project is shared with. A confidential issue, or an internal or confidential note, is kept only as a placeholder with no content, and with Enforce ACL on no one can read it.
- **How a person is identified:** A member's email address, from the member list when GitLab shows it, else from the member's public profile email.
- **When permissions cannot be read:** If a member's email is hidden, the member list is incomplete, there are too many members to express, or no member can be expressed, the connector reports a permission warning for the whole project. On HydraDB Cloud, with Enforce ACL on, such an item follows the access rule you set on its resource. With no rule, it is hidden from search. Self-hosted deployments can be configured differently. Permission warnings appear in [Get Connector Status](/api-reference/v2/endpoint/get-connector-status).
- Most GitLab users hide their public email, so a private project often needs an access rule you set.
- Visibility of single issues is not reproduced, apart from confidential issues.
- A project GitLab reports as not found may be deleted, or the token may have lost access. HydraDB does not treat it as deleted.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

GitLab uses a personal, project or group access token with `read_api`.

<ResponseField name="private_token" type="secret string" required>
A GitLab access token with `read_api`.
</ResponseField>

**Connector settings**

<ResponseField name="api_url" type="string">
The API address of a self-managed GitLab, including `/api/v4`, for example `https://gitlab.example.com/api/v4`. Leave it empty for GitLab.com. Self-managed GitLab is not yet a supported setup.
</ResponseField>

**Token scope**

- `read_api`: reads projects, issues, merge requests, notes and repository files, and a private project's members for permissions.

### Set it up

<Steps>
  <Step title="Create a token">
    Create a GitLab access token with `read_api` for a user who is a member of every project you will select.
  </Step>
  <Step title="Create the connector">
    Paste the token as `private_token`. For self-managed GitLab, set `api_url`.
  </Step>
  <Step title="Select projects">
    HydraDB lists the projects the token's user is a member of, up to 2,000. Select the projects to sync.
  </Step>
</Steps>

One connector reads the projects one token's user is a member of.

<Accordion title="Connect through the API">

Use provider `gitlab` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default. Issues and merge requests are measured by last update, commits by creation and projects by last activity. Markdown files on the default branch can come across even when their last commit is older than the window.
- **New and changed items:** Each sync reads issues and merge requests updated since the last sync, new commits and active projects. When an issue or merge request changes or gets a new comment, all its notes are read again. Markdown files are read again when the default branch gets a commit inside the window. A project with no recent activity can be skipped, releases included.
- **Edits:** An edited issue or merge request updates its document. An edited note, or a note made internal, updates only when its issue or merge request changes or gets a new comment. An issue made confidential is replaced by its placeholder only when it is read again. Resetting the default branch to an older commit can leave newer file content in HydraDB.
- **Deletions:** Issues, merge requests, notes and files deleted in GitLab can stay searchable in HydraDB.
- A commit that appears in several selected projects is one document, attributed to the project read last.
- Markdown files larger than 512 KiB are skipped, and reading a repository stops after 100,000 entries.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

### Issues and merge requests

- **One document:** One issue or one merge request. Its notes are separate documents.
- **Title:** The title. An item with no title is called `GitLab issue` or `GitLab MR` with its id. A confidential issue is titled `Confidential GitLab issue`.
- **Text:** The description, else the title, then `Author` and `Assignees` lines, and for a merge request `Reviewers` and `Branch` lines. Labels are written as a `Labels` line and the creation time as a `Created` line. The title and the item id are searchable too. A confidential issue's text is a fixed placeholder sentence.
- **Date:** When the item was last updated, else when it was created.
- **Link back:** The issue or merge request page on GitLab. Confidential placeholders have none.
- **Files:** Attachments are not downloaded.

<ResponseField name="Item id" type="Searchable text">
`<project id>!<number>` for an issue and `<project id>!mr<number>` for a merge request. Keeps later syncs on the same document, also when an issue becomes confidential, and a search can match it.
</ResponseField>

<ResponseField name="labels" type="Searchable text">
Label names, written as the `Labels` line.
</ResponseField>

<ResponseField name="author" type="Searchable text">
The opener's username, written as the `Author` line. Not attached to the item as a person in the graph.
</ResponseField>

<ResponseField name="assignees" type="Searchable text">
Assignee names, written as the `Assignees` line. Not attached to the item as people in the graph.
</ResponseField>

<ResponseField name="reviewers" type="Searchable text">
A merge request's reviewer names, written as the `Reviewers` line.
</ResponseField>

<ResponseField name="source_branch, target_branch" type="Searchable text">
A merge request's branches, written as the `Branch` line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the item was created, written as the `Created` line. The result date when there is no update time.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the item was last updated. Not searchable.
</ResponseField>

<ResponseField name="mentions" type="Graph identity">
Each `@username` in the description, recorded as a person the item mentions. The field itself is not searchable, but the description it comes from is.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_iid" type="Query filter">
The issue or merge request number within its project. Combine it with `additional_metadata.gitlab_project_id` to pick out one item. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_redacted" type="Query filter">
True on a confidential issue's placeholder. Finds placeholders. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="state" type="Stored only">
`opened`, `closed`, `locked` or `merged`. It is not part of the text, so a query cannot match the state.
</ResponseField>

<ResponseField name="closed_at, merged_at" type="Stored only">
When the item was closed or merged.
</ResponseField>

</Accordion>

### Notes

- **One document:** One note on an issue or merge request. System notes, such as state and label changes, are left out. An internal or confidential note is kept as a placeholder with no content.
- **Title:** `Comment on` with the parent's id. A placeholder is titled `Comment on a confidential GitLab issue`. The title is not searchable.
- **Text:** The note text, with its author, its creation and update times and its parent's id. A placeholder's text is a fixed sentence.
- **Date:** When the note was last updated, else when it was created.
- **Link back:** The note on its issue or merge request page.
- **Files:** Attachments are not downloaded.

<ResponseField name="author" type="Searchable text, Graph identity">
The note author's username, else name. The graph records the note as written by this person.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The issue or merge request the note belongs to, written as the `Parent` line. Links the note to it.
</ResponseField>

<ResponseField name="thread_id" type="Graph connection">
Groups every note on one issue or merge request into one thread. Not searchable.
</ResponseField>

<ResponseField name="created_at, updated_at" type="Searchable text, Result date">
When the note was created and last updated. The update time, else the creation time, is the result date.
</ResponseField>

<ResponseField name="mentions" type="Graph identity">
Each `@username` in the note, recorded as a person the note mentions. The field itself is not searchable, but the note text is.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_note_id" type="Query filter">
The note id. Picks out one note. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_noteable_type" type="Query filter">
`Issue` or `MergeRequest`. Keeps only issue notes or only merge request notes. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_iid" type="Query filter">
The parent's number within its project. With `additional_metadata.gitlab_project_id`, returns every note on one issue or merge request. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_redacted" type="Query filter">
True on a placeholder note. Finds placeholders. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="discussion_id" type="Stored only">
The GitLab discussion the note belongs to. Notes in one discussion are not linked as replies to each other.
</ResponseField>

<ResponseField name="path, line" type="Stored only">
The file and line a diff note was left on.
</ResponseField>

</Accordion>

### Markdown files

- **One document:** One non-empty Markdown file, `.md` or `.mdx`, on the default branch, up to 512 KiB.
- **Title:** The file's first heading, else its file name without the extension.
- **Text:** The file content. The title is searchable too.
- **Date:** The time of the default branch's latest commit when the file was read.
- **Link back:** The file on GitLab.

<ResponseField name="additional_metadata.gitlab_project_path" type="Query filter">
The project path, for example `acme/backend`. Limits a query to one project by path. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_path" type="Query filter">
The file path in the repository. Picks out one file. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_blob_sha" type="Query filter">
The content hash of the file version read. Picks out one exact version. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_ref" type="Query filter">
The branch the file was read from. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="path, format" type="Stored only">
The repository path, and whether the file is `md` or `mdx`.
</ResponseField>

</Accordion>

### Commits

- **One document:** One commit. A commit that appears in several selected projects is one document.
- **Title:** The commit title, else the first line of the message, else `GitLab commit` with its short id.
- **Text:** The commit message, then an `Author` line. The title is searchable too.
- **Date:** When the commit was created, else committed, else authored.
- **Link back:** The commit on GitLab.

<ResponseField name="author" type="Searchable text">
The author's name, written as the `Author` line. Not attached to the commit as a person in the graph.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the commit was created. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_sha" type="Query filter">
The commit hash. Picks out one commit. Not searchable.
</ResponseField>

### Releases

- **One document:** One release.
- **Title:** The release name, else `Release` with its tag.
- **Text:** The release notes, else the title. The title is searchable too.
- **Date:** When the release was published, else when it was created.
- **Link back:** The release on GitLab.
- **Files:** Release assets are not downloaded.

<ResponseField name="released_at, created_at" type="Result date">
The publish time, else the creation time, is the result date. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.gitlab_tag_name" type="Query filter">
The release's Git tag. Picks out one release. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="tag_name" type="Stored only">
The release's Git tag.
</ResponseField>

</Accordion>

### Projects

- **One document:** One GitLab project.
- **Title:** The project name with its namespace, else its path, else its name.
- **Text:** The project description, else the title, then `Path` and `Topics` lines. The title is searchable too.
- **Date:** The project's last activity, else when it was created.
- **Link back:** The project on GitLab.

<ResponseField name="path" type="Searchable text">
The path with its namespace, written as the `Path` line.
</ResponseField>

<ResponseField name="created_at, last_activity_at" type="Result date">
The last activity, else creation, is the result date. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="default_branch" type="Stored only">
The project's default branch.
</ResponseField>

<ResponseField name="visibility" type="Stored only">
`private`, `internal` or `public`. Who can read the project's items is worked out from its members, not from this value.
</ResponseField>

</Accordion>

**Example searches**

- What did reviewers say on the merge request that changed the payment retry logic?
- What changed in release v2.4.0?

## How it fits into the graph

- Issues and merge requests use the Ticket class.
- Notes use the Comment class.
- Markdown files use the Page class.
- Commits use the Record class.
- Releases use the Page class.
- Projects use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections GitLab creates**

- A note to its issue or merge request, with all notes on one item grouped into one thread.
- A placeholder note to its confidential issue.
- Notes in one GitLab discussion are not linked as replies to each other.
- References such as `#12` or `!34` are not turned into links, and merge requests are not linked to the issues they close.
- No links to items in other tools.

**People and groups**

- The author of each note.
- Each `@username` mentioned in an issue, merge request or note.
- Issue and merge request authors, assignees and reviewers, and commit authors, appear only in the text.

**Found in the text**

Issue, merge request, note, file, commit and release text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Projects the token's user is not a member of.
- The content of confidential issues and internal notes. Only empty placeholders are kept.
- System notes, such as state and label changes.
- Code and diffs. Commits carry only their message, and only Markdown files are read.
- Pipelines, jobs, branches, tags, wikis, snippets, and label and milestone lists.
- Issue due dates, weights, time tracking, milestones and epics.
- Commit statistics and author and committer emails.
- Markdown files over 512 KiB, empty files, and files beyond the first 100,000 repository entries.
