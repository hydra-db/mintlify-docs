Use the SurveyMonkey connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `survey_details`
- `simplified_responses`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Use a SurveyMonkey app access token with View Surveys (surveys_read) and View Response Details (responses_read_detail). A draft app token expires after 90 days unless the app is deployed.
2. Before a draft token expires, replace it in the connector and validate discovery and sync; deployed OAuth apps must retain their refresh-token flow and reauthorize when scopes change.
3. Pick surveys after connecting. The full questionnaire and human-readable response answers are indexed; collectors and contacts are not. Basic accounts expose at most 25 detailed responses per survey through the API, while paid plans allow the complete response history.
4. HydraDB does not currently import SurveyMonkey team sharing as ACLs. Survey questions and responses are tenant-wide unless you configure a HydraDB resource ACL for the selected survey.

Use provider `surveymonkey` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
