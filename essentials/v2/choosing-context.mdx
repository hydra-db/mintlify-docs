Answer three decisions, get the exact request.

1. Knowledge or Memories?
2. If Memories: `infer: true` or `infer: false`?
3. What request should you send next?

This page is the short decision surface. For the full guides, see [Knowledge](/essentials/v2/knowledge) and [Memories](/essentials/v2/memories).

---

## Decision 1 - Knowledge vs Memories

Ask one question: **should every user in this database be able to retrieve this?**

<CardGroup cols={2}>
  <Card title="Knowledge" icon="book" href="/essentials/v2/knowledge">
    Shared across the database. Product docs, policy PDFs, wikis, runbooks, Slack exports, and other reusable material.
  </Card>
  <Card title="Memories" icon="brain" href="/essentials/v2/memories">
    Scoped to one user, workspace, or session. Preferences, traits, conversation history, and personal facts.
  </Card>
</CardGroup>

| If the content is… | Store it as… | Ingest with… |
|---|---|---|
| Shared across all users | [Knowledge](/essentials/v2/knowledge) | `type=knowledge` |
| Specific to one user or session | [Memory](/essentials/v2/memories) | `type=memory` |

Both stores use the same endpoints: ingest with [`POST /context/ingest`](/api-reference/v2/endpoint/ingest-context), then retrieve with [`POST /query`](/api-reference/v2/endpoint/query).

---

## Decision 2 - `infer: true` vs `infer: false`

`infer` only applies to **Memories**. It lives on each item inside the `memories[]` array, not as a top-level form field.

| Choice | Use when… | What HydraDB does |
|---|---|---|
| `infer: true` | The input is raw or noisy signal | Extracts the useful preference, trait, or fact |
| `infer: false` | The input is already the memory | Stores and indexes exactly what you send |

**Rule of thumb:** `infer: false` is faster and deterministic. `infer: true` is better when the useful memory must be derived from dialogue, logs, behavior, or indirect notes.

`custom_instructions` only takes effect when `infer: true`.

## Verified requests

All samples use v2 fields (`database` / `collection`), the env var `$HYDRA_DB_API_KEY`, and match the current v2 OpenAPI schema for [`POST /context/ingest`](/api-reference/v2/endpoint/ingest-context) and [`POST /query`](/api-reference/v2/endpoint/query).

### Path A - Knowledge

Shared documents for the whole database. Use a shared collection such as `team_docs` so later queries can target the same scope.

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])

with open("/path/to/policy.pdf", "rb") as f:
    result = client.context.ingest(
        type="knowledge",
        database="acme_corp",
        collection="team_docs",
        documents=[("policy.pdf", f, "application/pdf")],
    )
```

```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});

const result = await client.context.ingest({
  type: "knowledge",
  database: "acme_corp",
  collection: "team_docs",
  documents: [
    {
      path: "/path/to/policy.pdf",
      filename: "policy.pdf",
      contentType: "application/pdf",
    },
  ],
});
```

```bash cURL
curl -X POST 'https://api.hydradb.com/context/ingest' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -F "type=knowledge" \
  -F "database=acme_corp" \
  -F "collection=team_docs" \
  -F "documents=@/path/to/policy.pdf"
```
</CodeGroup>

### Path B - Memory with `infer: true`

Raw user signal that HydraDB should extract.

<CodeGroup>
```python Python SDK
import json
import os
from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])

result = client.context.ingest(
    type="memory",
    database="acme_corp",
    collection="user_alex",
    memories=json.dumps([
        {
            "text": "User toggled dark mode and kept it for a month.",
            "infer": True,
        }
    ]),
)
```

```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});

const result = await client.context.ingest({
  type: "memory",
  database: "acme_corp",
  collection: "user_alex",
  memories: JSON.stringify([
    {
      text: "User toggled dark mode and kept it for a month.",
      infer: true,
    },
  ]),
});
```

```bash cURL
curl -X POST 'https://api.hydradb.com/context/ingest' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -F "type=memory" \
  -F "database=acme_corp" \
  -F "collection=user_alex" \
  -F 'memories=[{"text":"User toggled dark mode and kept it for a month.","infer":true}]'
```
</CodeGroup>

## Then what?

Ingestion is asynchronous. The ingest call returns IDs; content is not queryable immediately.

1. Poll [`GET /context/status`](/api-reference/v2/endpoint/source-status) until the source reaches at least `graph_creation`, or wait for `indexing_status: completed` if you need full indexing.
2. Retrieve with [`POST /query`](/api-reference/v2/endpoint/query). Match the collections you ingested into: Knowledge in this guide uses `team_docs`, Memories use `user_alex`. For a personalized answer grounded in both, pass both scopes:

<CodeGroup>
```python Python SDK
result = client.query(
    database="acme_corp",
    collections=["team_docs", "user_alex"],
    query="What does this user prefer?",
    type="all",
    query_by="hybrid",
    mode="thinking",
)
```

```typescript TypeScript SDK
const result = await client.query({
  database: "acme_corp",
  collections: ["team_docs", "user_alex"],
  query: "What does this user prefer?",
  type: "all",
  queryBy: "hybrid",
  mode: "thinking",
});
```

```bash cURL
curl -X POST 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "collections": ["team_docs", "user_alex"],
    "query": "What does this user prefer?",
    "type": "all",
    "query_by": "hybrid",
    "mode": "thinking"
  }'
```
</CodeGroup>

Use `type: "knowledge"` with `collection: "team_docs"` for shared-doc RAG, `type: "memory"` with `collection: "user_alex"` for personalization, or `type: "all"` with both collections for grounded + personalized answers.

## Quick reference

| Decision | Choose | Endpoint / field |
|---|---|---|
| Shared across the database | Knowledge | `POST /context/ingest` with `type=knowledge` |
| User / workspace / session scoped | Memory | `POST /context/ingest` with `type=memory` |
| Raw signal that needs extraction | `infer: true` | Inside each `memories[]` item |
| Already-written fact or preference | `infer: false` | Inside each `memories[]` item |
| Wait until queryable | Status poll | `GET /context/status` |
| Retrieve later | Query | `POST /query` with `type: "knowledge" \| "memory" \| "all"` |
