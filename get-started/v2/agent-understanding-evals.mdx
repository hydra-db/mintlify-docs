---
title: "Agent Understanding Evals"
description: "A deterministic scorecard for checking whether HydraDB docs give coding agents the anchors they need for correct v2 integrations."
---

HydraDB docs already publish agent-readable surfaces such as `/llms.txt`, `/llms-full.txt`, and `AGENTS.mdx`. This eval checks whether those surfaces and the linked v2 pages expose the decisions a coding agent must recover before writing an integration.

It is intentionally lightweight: no HydraDB API key, no model key, no network call, and no live LLM judge. The first version is a deterministic docs regression check that can run in CI.

## What it checks

The fixture at `scripts/fixtures/agent_understanding_tasks.json` contains realistic agent tasks, each with required documentation anchors.

| Task area | Examples of required anchors |
| --- | --- |
| Memory vs Knowledge | `type: "memory"`, `type: "knowledge"`, `type: "all"`, `collection` |
| Ingestion readiness | `GET /context/status`, `graph_creation`, `completed`, terminal failure states |
| App sources | `app_knowledge`, `kind`, `provider`, `external_id`, `fields`, `query_apps: true` |
| Metadata | `metadata_filters`, `additional_metadata`, `database_metadata_schema`, `enable_match` |
| GraphRAG prompting | `graph_context`, `query_paths`, `chunk_relations`, `chunk_id_to_group_ids` |
| SDK correctness | Python `snake_case`, TypeScript `camelCase`, `response.data` payload access |
| LLM prompt construction | `build_string` / `buildString`, grounding instructions, ordered chunks |

## Run it locally

From the repository root:

```bash
npm run verify:agent-understanding
```

Equivalent direct command:

```bash
python scripts/score_agent_understanding.py --strict
```

Use `--verbose` to print every matched anchor:

```bash
python scripts/score_agent_understanding.py --strict --verbose
```

## How to read the output

The script prints one line per task and then an aggregate score:

```text
PASS memory_vs_knowledge_scope: 5/5 anchors
PASS app_source_ingestion_and_query: 7/7 anchors

Overall: 60/60 anchors matched (100.0%), 12/12 tasks passed
```

A failure means the docs no longer expose an anchor that agents rely on. Fix the relevant docs page or update the fixture if the product contract changed intentionally.

## What this is not

This eval does not prove that every LLM will generate perfect code. It proves that the docs contain the minimum retrievable contract an agent needs. A future live-agent eval can reuse the same task fixture and add model-based answer scoring on top.

## Contributor checklist

Before changing agent-facing pages, run:

```bash
npm run verify:agent-understanding
npm run verify:agents-endpoints
pnpm mintlify validate
```

If the eval fails, keep the fix close to the missing anchor. Avoid broad rewrites when a small clarification or cross-link restores agent understanding.
