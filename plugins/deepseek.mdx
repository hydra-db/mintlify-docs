The HydraDB plugin for the [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`)
retrieves relevant context before each turn, syncs workspace docs when files
change, and saves conversations as memories. It is a native
[Cordis](https://github.com/deepseek-ai/deepseek-harness) plugin that wires onto
the harness interception seams.

## Quickstart

<Steps>
  <Step title="Install">
    Requires the DeepSeek Harness (`dsh`) and Node.js 18+.

    The package ships as a dsh bundle, so `dsh plugin add` installs it from npm
    and wires it as a profile layer in one step:

    ```bash
    dsh plugin --profile <name> add dsh-hydradb
    ```

    dsh appends it to the profile's bundles and inserts the plugin row, so you
    edit no config file by hand.
  </Step>

  <Step title="Configure">
    Set credentials in the environment, or pass them in the bundle's `config`
    block:

    ```bash
    export HYDRADB_API_KEY="your-api-key"
    export HYDRADB_DATABASE="your-database"
    ```

    Optional: `HYDRADB_COLLECTION` (the collection to use) and `HYDRADB_BASE_URL`.
    The dsh-prefixed names `HYDRA_DEEPSEEK_API_KEY` and `HYDRA_DEEPSEEK_TENANT_ID`
    also work; the canonical `HYDRADB_*` names take precedence.
  </Step>

  <Step title="Run">
    Run a one-shot task with the `headless` command, reusing the profile you
    installed the plugin into (any other dsh surface works too):

    ```bash
    dsh --profile <name> headless "What did we decide last session?"
    ```

    On the first step of each turn, the plugin queries HydraDB and prepends
    relevant memory to the prompt.
  </Step>
</Steps>

## Configuration

This plugin runs on the same engine as the [Claude Code plugin](/plugins/claude-code), so the [modes](/plugins/claude-code#modes) and other [configuration settings](/plugins/claude-code#configuration) there apply here too.

## How it works

| dsh seam | Engine action |
| -------- | ------------- |
| `agent/created` | Sync workspace docs into HydraDB when a session opens |
| `agent/pre-step` (turn's first step) | Query memories and knowledge, and prepend the results to the step messages |
| `tools/post-execute` (file-writing tools) | Incremental workspace sync |
| `session/event` -> `turn/end` | Capture the completed turn |

Manual actions come from the shipped skills: `query`, `ingest`, `doctor`,
`setup`, and `last-recall`.
