## What syncs

**Indexed object types**

- `tasks`
- `subtasks`
- `stories`
- `projects`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Create a personal access token in Asana's Developer Console under My apps → Personal access tokens. PATs inherit the creating user's visibility and have no scope picker, so use a dedicated integration user with access to every project you intend to select.
2. Asana PATs do not refresh automatically. Rotate by creating a replacement token, updating the connector, verifying a sync, and only then revoking the old token; removing the integration user immediately invalidates its token.
3. Pick the projects to sync after connecting. Tasks, subtasks, projects and comment stories become searchable; system-generated activity stories are skipped. The connector only reads Asana.
4. HydraDB uses Asana's privacy_setting to capture each selected project's read audience: public_to_workspace includes active, non-guest workspace members plus explicit project memberships; private includes explicit project memberships; deprecated private_to_team includes the project team's users plus explicit project memberships. Memberships can grant admins, editors, commenters, viewers or teams. If project attribution is missing, Asana omits or returns an unknown privacy setting, hides a member email, or a permission read is incomplete, HydraDB refuses a partial ACL and shows a resource-level warning under the current fail-open policy; the content remains workspace-readable unless a customer resource rule governs it. Use a dedicated integration user's personal access token that can read the selected project, its memberships, and member email addresses.
5. Asana quotas are per token (150 requests/minute on free domains and 1,500 on paid domains). Large comment/subtask histories fan out per task, so a dedicated token also keeps this connector from sharing quota with unrelated automations.

Use provider `asana` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
