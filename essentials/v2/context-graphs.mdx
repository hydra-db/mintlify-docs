## 1. What it is

A context graph is the relationships HydraDB stores between pieces of your content. Each relationship is a directional triplet: a `source` entity, a `relation`, and a `target` entity, all returned as objects, not plain strings. Example: `billing_policy` (source) `governs` (relation) `failed_payment_handling` (target).

The graph adds to retrieval. The ranked `chunks` are still the main result.

## 2. When to use it

`graph_context` defaults to `true`, so the response shows how the retrieved chunks connect to each other and to your query. It helps when:

- The answer combines several chunks or sources.
- A relationship matters for correctness: cause and effect, ownership, sequence, or dependency.
- The question is multi-hop: "What team owns the service that failed?"

Skip it for direct lookups, because it makes the response larger and can add latency. Set `graph_context: false` when your code only reads `chunks`. That takes effect only in `fast` mode. `thinking` mode, including `auto` routed to thinking, always returns the graph.

---

## 3. How it works

**At ingestion**, a relationship enters the graph in one of three ways:

- HydraDB extracts it from your content (the default).
- A source declares a link to another source with a `relations` payload ([forceful relations](/essentials/v2/knowledge#7-forceful-relations)).
- You skip extraction for a source and send its entities and relations with [Bring Your Own Graph: per source](/essentials/v2/bring-your-own-graph).

**At query**, with `graph_context: true`, HydraDB runs hybrid retrieval, traverses the graph for relationships between the retrieved chunks, and returns the fields below. Empty graph fields are not an error. They mean the chunks share no entities or declared relations for that query.

---

## 4. Response fields

- **`query_paths`:** multi-hop chains of triplets from the query to retrieved chunks. Each path carries a relevancy score and the chunk IDs whose traversal produced it.
- **`chunk_relations`:** same shape, but anchored chunk-to-chunk: how returned chunks relate to one another.
- **`chunk_id_to_group_ids`:** maps each chunk ID to its path groups (for example `p_0`, `p_1`), so you can group chunks by the path that produced them.

Full schemas: [Query API Reference](/api-reference/v2/endpoint/query-overview).

### Connected subgraph

The graph also links *items*, not only entities: a Slack reply and its message, a page and the pages it links to, a comment and its ticket. Given one item's id, [Connected Subgraph](/api-reference/v2/endpoint/subgraph) walks those links breadth-first and returns everything reachable (the rest of the thread, the hierarchy above and below, the items it references) with the relations among them. Use it when you need what surrounds one result. The dashboard's **Subgraph** button opens the same view.

## 5. Example

<CodeGroup>

```bash cURL
curl -X POST 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "query": "How does the billing system handle failed payments?",
    "type": "knowledge",
    "query_by": "hybrid",
    "mode": "thinking",
    "graph_context": true
  }'
```

```typescript TypeScript SDK
const result = await client.query({
  database: "acme_corp",
  query: "How does the billing system handle failed payments?",
  type: "knowledge",
  queryBy: "hybrid",
  mode: "thinking",
  graphContext: true,
});

if (result.data?.graphContext) {
  for (const path of result.data.graphContext.queryPaths) {
    for (const t of path.triplets) {
      console.log(
        `${t.source.name} - ${t.relation.canonicalPredicate} → ${t.target.name}`,
      );
    }
  }
}
```

```python Python SDK
result = client.query(
    database="acme_corp",
    query="How does the billing system handle failed payments?",
    type="knowledge",
    query_by="hybrid",
    mode="thinking",
    graph_context=True,
)

if result.data.graph_context:
    for path in result.data.graph_context.query_paths:
        for t in path.triplets:
            print(
                t.source.name,
                " - ",
                t.relation.canonical_predicate,
                "→",
                t.target.name,
            )
```

</CodeGroup>

The `data` payload of a response with graph context:

```json
{
  "chunks": [ /* ranked chunks */ ],
  "graph_context": {
    "query_paths": [
      {
        "triplets": [
          {
            "source": { "name": "billing_policy", "type": "POLICY" },
            "relation": { "canonical_predicate": "governs" },
            "target": { "name": "failed_payment_handling", "type": "PROCESS" }
          }
        ],
        "relevancy_score": 0.84,
        "group_id": "p_0",
        "source_chunk_ids": ["chunk_abc", "chunk_def"]
      }
    ],
    "chunk_relations": [],
    "chunk_id_to_group_ids": { "chunk_abc": ["p_0"] }
  }
}
```

## 6. Using graph context in your prompt

The `buildContextString` / `build_context_string` helper in [How to Use API Results](/essentials/v2/api-results) handles `query_paths`, `chunk_relations`, and `chunk_id_to_group_ids`, and formats triplets as:

```
[billing_policy] -> governs -> [failed_payment_handling]: policy covering retry logic
  ↳ [failed_payment_handling] -> triggers -> [notification_service]: sends customer alert
```
