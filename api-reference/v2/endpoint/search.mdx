The single retrieval endpoint for everything. Use it any time you deliver the relevant context to your LLM.

Two independent dimensions control behavior:

- **`type`** picks **what** to search: `"knowledge"`, `"memory"`, or `"all"` (both, merged and re-ranked together).
- **`search_by`** picks **how** to match: `"hybrid"` (semantic \+ BM25, the default) or `"text"` (BM25 only  -  pair with `operator`).
- **`mode`** picks **how** to fetch context: `"fast"` (single-pass, low-latency), or `"thinking"` (expands query, considers more context from the graph, and can include forceful-relation context).

Read more about choosing the perfect mode for your use case [here](/api-reference/v2/endpoint/search-overview#recommended-configurations).

```python Python SDK
result = client.search.query(
    tenant_id="acme_corp",
    sub_tenant_id="user_alex",
    query="What is our refund policy, and how should I explain it to this user?",

    # What to search: "knowledge", "memory", or "all".
    type="all",

    # How to match: "hybrid" (default) or "text" (BM25).
    search_by="hybrid",

    # "thinking" improves quality; use "fast" for lowest latency.
    mode="thinking",

    # Ranking and response controls.
    max_results=10,
    alpha="auto",
    recency_bias=0.2,
    graph_context=True,

    # Pull author-declared related sources into additional_context.
    # Only applies when mode="thinking".
    search_forceful_relations=True,

    # Top-level keys match tenant_metadata; document_metadata is per-source.
    metadata_filters={
        "department": "support",
        "document_metadata": {
            "source": "policy",
        },
    },

    # Short factual hint; not a hard filter.
    additional_context="User is asking from the billing help center.",
)
```

## Request body

| Name | Description |
| --- | --- |
| <Field name="tenant_id" type="string" required /> | Owning tenant. |
| <Field name="sub_tenant_id" type="string or null" /> | Sub-tenant scope. Required for per-user memory searches. (default=default sub-tenant) |
| <Field name="query" type="string" required /> | Search terms or natural-language question. Cannot be empty. |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22; or &#x22;all&#x22;" /> | What collection to search. `"all"` runs knowledge and memory in parallel and merges by `relevancy_score`. (default=`"knowledge"`) |
| <Field name="search_by" type="&#x22;hybrid&#x22; or &#x22;text&#x22;" /> | Retrieval method. See [Search methods](#decision-matrix). (default=`"hybrid"`) |
| <Field name="search_apps" type="boolean" /> | Adds an app-aware retrieval lane for app sources while still searching the full selected knowledge scope. Set `true` for better app-source matching, thread/relation traversal, exact IDs, and actor/provider hints. It does **not** limit search to only app sources. (default=`false`) |
| <Field name="operator" type="&#x22;or&#x22; or &#x22;and&#x22; or &#x22;phrase&#x22;" /> | BM25 operator for `search_by: "text"`. Ignored for `hybrid`. (default=`"or"`) |
| <Field name="mode" type="&#x22;fast&#x22; or &#x22;thinking&#x22;" /> | Retrieval pipeline. Applies to `hybrid` only; ignored for `text`. (default=`"fast"`) |
| <Field name="max_results" type="integer or null" /> | Maximum chunks to return. Default `10`; maximum `50`. Start with `10`, use `5` for tight prompts, and increase only when reranking downstream. |
| <Field name="alpha" type="float 0.0–1.0 or &#x22;auto&#x22;" /> | Hybrid weight (`1.0` = pure semantic, `0.0` = pure BM25). Applies to `search_by: "hybrid"` only. (default=`0.8`) |
| <Field name="recency_bias" type="float 0.0–1.0" /> | Boost newer content. (default=`0.0`) |
| <Field name="graph_context" type="boolean" /> | When `true`, includes the entity/relation graph slice in the response under `graph_context`. Set to `false` when you only need ranked chunks. (default=`true`) |
| <Field name="search_forceful_relations" type="boolean" /> | Pull author-declared related sources into `additional_context`. **Only takes effect when `mode: "thinking"`**  -  silently ignored in `fast` mode. (default=`true`) |
| <Field name="additional_context" type="string or null" /> | Request-time hint to guide retrieval (e.g., "user is on the billing page"). This is different from the response `additional_context` map. (default=`null`) |
| <Field name="metadata_filters" type="object or null" /> | Deterministic narrowing before ranking. See [Filters](#decision-matrix). (default=`null`) |

### Advanced: How to tune your retrieval strategy 

<AccordionGroup>
  <Accordion title="Type selection">
    | Value | Searches | Best for |
    | --- | --- | --- |
    | `"knowledge"`_(default)_ | Knowledge documents, files, and app sources | Document Q&A, RAG context. |
    | `"search_apps=true"` | Full selected knowledge scope plus app-aware retrieval | App-specific Q&A that should still search non-app knowledge documents. |
    | `"memory"` | User memories | Personalization and user preferences. |
    | `"all"` | Both, merged in one ranked result set | Personalized answers grounded in both shared and user-specific context. |
  </Accordion>

  <Accordion title="Search methods">
    | Method | Pipeline | Best for |
    | --- | --- | --- |
    | `"hybrid"`_(default)_ | Dense vectors \+ BM25 keyword | General-purpose retrieval and RAG. |
    | `"text"` | BM25 only | Exact terms, compliance lookups, phrase search. Pair with `operator`. |
  </Accordion>

  <Accordion title="Modes">
    For `search_by: "hybrid"`:

    | Mode | Behavior | When to use |
    | --- | --- | --- |
    | `"fast"`_(default)_ | Single query pass | Real-time chat, autocomplete, simple lookups. |
    | `"thinking"` | Multi-query expansion \+ reranking \+ forceful-relation context | Complex queries, customer-facing answers, anything where quality matters. |
  </Accordion>

  <Accordion title="Filters">
    `metadata_filters` runs before ranking. The shape combines two filter scopes:

    ```json
    {
      "metadata_filters": {
        "department": "engineering",
        "region": "us-east",
        "document_metadata": {
          "source": "account_plan",
          "author": "alex"
        }
      }
    }
    ```

    | Where | What it matches |
    | --- | --- |
    | **Top-level keys** (`department`, `region`) | The source's `tenant_metadata`. Keys must be declared in the tenant's `tenant_metadata_schema` with `enable_match: true`, otherwise they are silently ignored. |
    | **Nested under `document_metadata`** | The source's free-form per-document fields. No schema declaration required. |
  </Accordion>
</AccordionGroup>

## Behavior notes

- `graph_context `**is on by default.** Set it to `false` if you only need ranked chunks and want to drop the graph slice from the response.

- `recency_bias `**is off by default.** Defaults to `0.0`  -  no recency boost is applied unless you set it.

- `search_forceful_relations `**requires** `mode: "thinking"`**.** In `fast` mode the flag is silently ignored. The server does not error or warn  -  your `additional_context` will simply be empty.
- `metadata_filters `**top-level keys need a schema.** Top-level keys must be declared in `tenant_metadata_schema` with `enable_match: true`. Undeclared keys are silently ignored. To filter free-form per-document fields, nest them under a `document_metadata` key.
- **Common mistakes.** Check [Source Status](https://docs.hydradb.com/api-reference/v2/endpoint/source-status) for recently ingested documents before searching. If you omit `sub_tenant_id`, HydraDB searches the default sub-tenant; use [List Sub-Tenants](https://docs.hydradb.com/api-reference/v2/endpoint/list-sub-tenants) to discover available IDs.
