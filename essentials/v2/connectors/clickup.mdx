Sync every task and subtask, including closed and archived ones, from the ClickUp Workspaces you select. Each task is one document with its description, status, people, checklists, custom fields, and its list, folder and space names. Each comment is its own document, linked to its task. Each Workspace is one short overview page listing its members.

ClickUp permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Task dependencies and linked tasks do not become links. Items deleted in ClickUp stay in HydraDB.

## Permissions

<Warning>
ClickUp permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- ClickUp guest access and private Spaces, Lists and Tasks are not reproduced. Set an access rule on each Workspace that should be restricted.
- Every synced item carries a fixed note saying ClickUp visibility is not captured, in `additional_metadata.rbac_warning`. The note itself restricts nothing.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

ClickUp uses a personal API token. It has no scopes to choose: it sees what its user sees.

<ResponseField name="api_token" type="secret string" required>
A ClickUp personal API token, which starts with `pk_`.
</ResponseField>

ClickUp limits requests per token by Workspace plan, starting at 100 a minute on Free, Unlimited and Business. To rotate the token, generate a new one, update the connector, check that HydraDB still lists your Workspaces and a sync succeeds, then revoke the old one.

### Set it up

<Steps>
  <Step title="Create a token">
    In ClickUp, open your avatar, Settings, Apps, API Token, and generate a token. Use a dedicated account that can open every Workspace you plan to select.
  </Step>
  <Step title="Create the connector">
    Paste the token as `api_token`.
  </Step>
  <Step title="Select Workspaces">
    HydraDB lists every Workspace the token can see. Select the Workspaces to sync. Each selected Workspace syncs its tasks and subtasks, whether open, closed or archived.
  </Step>
</Steps>

One connector reads what one token's ClickUp user can see.

<Accordion title="Connect through the API">

Use provider `clickup` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected Workspace reads back the window set by `lookback_days`, 30 days by default, measured on when tasks were last updated. The comments on those tasks are read in full, however old they are. Workspace overviews are read in full.
- **New and changed items:** Each sync reads the tasks updated since the last sync, whether open, closed or archived, and reads all comments on each of those tasks again.
- **Edits:** An edited task is picked up through its last-updated time and updates its document. A comment is read again only when its task is picked up.
- **Deletions:** Tasks and comments deleted in ClickUp stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

### Tasks

- **One document:** One ClickUp task or subtask. Its comments are separate documents.
- **Title:** The task name, or `ClickUp task` and its id when the name is empty.
- **Text:** The task name, then the description as plain text when it differs from the name. Then `Status`, `Assignees`, `Priority`, `Tags`, `List`, `Folder` and `Space` lines, each checklist with its items marked `[ ]` or `[x]`, each custom field with a value as `name: value`, and one `Attachment` line per file name. The creator, the first assignee, the creation and closure dates, the task id and the parent are written into the task details too. The title is searchable too.
- **Date:** When the task was last updated, or when it was created if there is no update time.
- **Link back:** The task's page in ClickUp.
- **Files:** Files attached to the task are downloaded with the connector's token and read, and their text becomes searchable with the task. A file with no id or download address is skipped. A file that fails to download or is not a supported type keeps only its details.

### Comments

- **One document:** One comment on a task.
- **Title:** `Comment by <author> on <task name>`, or `Comment on <task name>` without an author.
- **Text:** A `Task` line with the task name and id, then the comment text. The author, the comment time and the task id are written with it.
- **Date:** When the comment was posted.
- **Link back:** The task's page in ClickUp. Comments have no link of their own.

### Workspace overviews

- **One document:** One selected ClickUp Workspace.
- **Title:** The Workspace name, or `ClickUp workspace` and its id when the name is empty.
- **Text:** `ClickUp workspace:` and the name, then a `Members` line with member usernames or emails. The title is searchable too.
- **Date:** None.
- **Link back:** None.

<ResponseField name="member_names" type="Searchable text">

</ResponseField>

## How it fits into the graph

- Tasks use the Ticket class.
- Comments use the Comment class.
- Workspace overviews use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections ClickUp creates**

- A subtask to its parent task.
- A comment to its task.
- Task dependencies and linked tasks do not become links.
- No links to items in other tools.

**People and groups**

- The creator and the first assignee of each task.
- The author of each comment.
- Other assignees and Workspace members appear only in the text.

**Found in the text**

Task descriptions, checklist items, custom field values and comment text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Workspaces you did not select.
- Spaces, folders and lists as items of their own. Their names appear on tasks.
- Goals, time entries, tags as items of their own, custom field definitions and task templates.
- ClickUp visibility: guests, and private Spaces, Lists and Tasks.
- Comments marked deleted.
- Attached files with no usable id or download address.
