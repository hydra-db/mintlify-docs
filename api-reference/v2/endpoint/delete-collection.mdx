This action is irreversible. Deleting a collection removes all knowledge, memories, embeddings, and graph data stored under that collection. The parent database and its other collections are not affected. There is no soft-delete and no recovery window.

<RequestExample>
```python Python SDK
response = client.databases.delete_collection(
    database="my_first_database",
    collection="engineering",
)
```
```typescript TypeScript SDK
const response = await client.databases.deleteCollection({
  database: "my_first_database",
  collection: "engineering",
});
```
```bash cURL
curl -X DELETE 'https://api.hydradb.com/databases/collections?database=my_first_database&collection=engineering' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2"
```
</RequestExample>

## Query parameters
| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Identifier of the database that owns the collection. Formerly `tenant_id`; the `tenant_id` alias is still accepted (deprecated). |
| <Field name="collection" type="string" required /> | Identifier of the collection to delete. Formerly `sub_tenant_id`; the `sub_tenant_id` alias is still accepted (deprecated). |

## Deletion completion

Deletion is asynchronous. Treat deletion as complete when the collection no longer appears in `GET /databases/collections?database=...`.

After deletion completes, the same `collection` name can be reused by ingesting new data under it. Until then, avoid writing to or querying that collection.

## Behavior notes

<Warning>
**Irreversible action.** Ingested documents, memories, embeddings, graph nodes, and storage objects for this collection are permanently removed. Other collections in the same database are not touched. There is no recovery window.
</Warning>

- **Stop in-flight work first:** Stop ingestion, polling, query, and background jobs targeting this collection before deleting.
- **Async cleanup:** The endpoint returns immediately after accepting the request. Infrastructure cleanup of vector stores, graphs, and storage objects runs in the background.
- **Repeat calls:** Deleting an already-deleted collection is idempotent — cleanup runs again against empty stores and still returns `200`.
- **Dashboard:** Owners can also expand a database on the Databases page and delete a collection from the inline list.

## Errors

Common codes: `400 VALIDATION_ERROR`, `404 DATABASE_NOT_FOUND`, `401 UNAUTHORIZED`. See [Error Responses](/api-reference/v2/error-responses) for the full list.
