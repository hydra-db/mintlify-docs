The SDKs wrap every endpoint in the [API Reference](/api-reference/v2) with typed methods.

## Installation

v2 uses the same package names as v1, at major version 2. Pin `>=2.0.0`.

<CodeGroup>
```bash Python SDK
pip install "hydradb-sdk>=2,<3"
```
```bash TypeScript / Node.js
npm install @hydradb/sdk@^2
```
</CodeGroup>

## Client setup

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```
```python Python (Async)
import os
from hydra_db import AsyncHydraDB

async_client = AsyncHydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```
```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});
```
</CodeGroup>

<Info>
**Python:** `HydraDB` is synchronous and `AsyncHydraDB` is asynchronous. Both have the same methods.
</Info>

## Versioning

The SDKs send `API-Version: 2` on every request. Responses echo the resolved version in the `X-API-Version: 2` header.

## Naming conventions

- **Raw HTTP and cURL:** snake_case for every request and response field, such as `database`, `collection`, `query_by`.
- **Python SDK:** snake_case methods and parameters, such as `query()` with `database` and `query_by`.
- **TypeScript SDK:** camelCase methods, parameters, and response fields, such as `query()` with `database` and `queryBy`, `context.list()` with `pageSize`, or `status.data.infra.readyForIngestion`.

<Info>
**Use camelCase request fields in TypeScript:** `client.context.list({ database: "...", pageSize: 50 })`. The SDK converts them to snake_case on the wire and silently drops keys it does not recognize, such as `page_size: 50`. JSON-string values (`documentMetadata`, `memories`, `appKnowledge`) and free-form maps (`metadataFilters`) are sent as written, so keep snake_case inside them. Python is snake_case throughout: `client.context.list(database="...", page_size=50)`.

The old names `tenant_id` and `sub_tenant_id` remain accepted as deprecated aliases for `database` and `collection`.
</Info>

## Methods

Methods are grouped by URL prefix and listed by their Python names. TypeScript camelCases multi-word names: `delete_collection()` is `deleteCollection()`, and the connector method `list_resources()` is `listResources()`.

### Context: `client.context`

- `client.context.ingest()`: `POST /context/ingest`
- `client.context.status()`: `GET /context/status`
- `client.context.inspect()`: `GET /context/inspect`
- `client.context.list()`: `POST /context/list`
- `client.context.delete()`: `DELETE /context`
- `client.context.relations()`: `GET /context/relations`
- `client.context.update_source_metadata()`: `PATCH /context/{id}/metadata`
- `client.context.subgraph()`: `GET /context/{id}/subgraph`

### Query: `client.query`

One method for all retrieval. `type` (`"knowledge"`, `"memory"`, `"all"`) and `query_by` (`"hybrid"`, `"text"`) control behavior.

- `client.query()`: `POST /query`

### Databases: `client.databases`

Legacy `/tenants/*` paths remain as deprecated aliases.

- `client.databases.create()`: `POST /databases`
- `client.databases.list()`: `GET /databases`
- `client.databases.delete()`: `DELETE /databases`
- `client.databases.status()`: `GET /databases/status`
- `client.databases.collections()`: `GET /databases/collections`
- `client.databases.stats()`: `GET /databases/stats`
- `client.databases.delete_collection()`: `DELETE /databases/collections`
- `client.databases.update_metadata_schema()`: `PATCH /databases/{database}/metadata-schema`
- `client.databases.get_metadata_schema()`: `GET /databases/{database}/metadata-schema`

### Feedback: `client.feedback`

- `client.feedback.submit()`: `POST /feedback`

## Migrating from v1

v2 consolidates the v1 method groups:

- `client.upload.knowledge(...)` becomes `client.context.ingest(type="knowledge", ...)`
- `client.upload.addMemory(...)` becomes `client.context.ingest(type="memory", ...)`
- `client.upload.verifyProcessing(...)` becomes `client.context.status(...)`
- `client.search.fullRecall(...)` becomes `client.query(type="knowledge", ...)`
- `client.search.recallPreferences(...)` becomes `client.query(type="memory", ...)`
- `client.search.booleanRecall(...)` becomes `client.query(query_by="text", ...)`
- `client.fetch.listData(...)` becomes `client.context.list(...)`
- `client.fetch.graphRelationsBySourceId(...)` becomes `client.context.relations(...)`
- `client.fetch.content(...)` becomes `client.context.inspect(...)`
- `client.data.delete(...)` becomes `client.context.delete(type="knowledge", ...)`
- `client.upload.deleteMemory(...)` becomes `client.context.delete(type="memory", ...)`
- `client.tenant.create(...)` becomes `client.databases.create(...)`
- `client.tenant.getTenantIds(...)` becomes `client.databases.list(...)`
- `client.tenant.deleteTenant(...)` becomes `client.databases.delete(...)`
- `client.tenant.getInfraStatus(...)` becomes `client.databases.status(...)`
- `client.tenant.getSubTenantIds(...)` becomes `client.databases.collections(...)`
- `client.tenant.monitor(...)` becomes `client.databases.stats(...)`

The v1 methods remain available on the `<2.0.0` releases of `hydradb-sdk` and `@hydradb/sdk` for as long as v1 routes are supported.

## Getting started

### Create a database

A database is an isolated workspace. Most organizations create one database, with collections for users or teams. See [Multi-tenant](/essentials/v2/multi-tenant).

<CodeGroup>
```python Python SDK
response = client.databases.create(
    database="my_first_database",
    database_metadata_schema=[
        {"name": "department", "data_type": "VARCHAR"},
    ],
)
```
```python Python (Async)
import asyncio


async def create_database():
    return await async_client.databases.create(database="my_first_database")


response = asyncio.run(create_database())
```
```typescript TypeScript SDK
const response = await client.databases.create({
  database: "my_first_database",
  databaseMetadataSchema: [
    { name: "department", dataType: "VARCHAR" },
  ],
});
```
</CodeGroup>

Creation is asynchronous. Poll [`databases.status`](/api-reference/v2/endpoint/tenant-status) until `ready_for_ingestion` is `true`:

<CodeGroup>
```python Python SDK
import time

while True:
    status = client.databases.status(database="my_first_database")
    if status.data.infra.ready_for_ingestion:
        break
    time.sleep(2)
```
```typescript TypeScript SDK
while (true) {
  const status = await client.databases.status({
    database: "my_first_database",
  });
  // Response fields are optional in the TypeScript types.
  if (status.data?.infra?.readyForIngestion) break;
  await new Promise((r) => setTimeout(r, 2000));
}
```
</CodeGroup>

### Ingest knowledge

Upload documents, app sources, or both in one call:

<CodeGroup>
```python Python SDK
import json

with open("contract.pdf", "rb") as f1, open("policy.pdf", "rb") as f2:
    result = client.context.ingest(
        type="knowledge",
        database="my_first_database",
        documents=[
            ("contract.pdf", f1, "application/pdf"),
            ("policy.pdf", f2, "application/pdf"),
        ],
        document_metadata=json.dumps([
            {
                "id": "contract_q4",
                "metadata": {"department": "legal"},
                "additional_metadata": {"author": "Alice"},
            },
            {
                "id": "policy_2025",
                "metadata": {"department": "legal"},
                "additional_metadata": {"author": "Bob"},
            },
        ]),
    )
```
```typescript TypeScript SDK
const result = await client.context.ingest({
  type: "knowledge",
  database: "my_first_database",
  documents: [
    { path: "contract.pdf", filename: "contract.pdf", contentType: "application/pdf" },
    { path: "policy.pdf", filename: "policy.pdf", contentType: "application/pdf" },
  ],
  documentMetadata: JSON.stringify([
    {
      id: "contract_q4",
      metadata: { department: "legal" },
      additional_metadata: { author: "Alice" },
    },
    {
      id: "policy_2025",
      metadata: { department: "legal" },
      additional_metadata: { author: "Bob" },
    },
  ]),
});
```
</CodeGroup>

For app sources (Slack, Notion, Gmail, webpages), pass `app_knowledge`, alone or alongside `documents`.

### Add user memories

Use the same `ingest` method with `type: "memory"`:

<CodeGroup>
```python Python SDK
import json

result = client.context.ingest(
    type="memory",
    database="my_first_database",
    collection="user_alex",
    memories=json.dumps([
        {
            "text": "User prefers detailed technical explanations and dark mode",
            "infer": True,
            "user_name": "Alex",
            "metadata": {"team": "engineering"},
            "additional_metadata": {"source": "onboarding"},
        }
    ]),
)
```
```typescript TypeScript SDK
const result = await client.context.ingest({
  type: "memory",
  database: "my_first_database",
  collection: "user_alex",
  memories: JSON.stringify([
    {
      text: "User prefers detailed technical explanations and dark mode",
      infer: true,
      user_name: "Alex",
      metadata: { team: "engineering" },
      additional_metadata: { source: "onboarding" },
    },
  ]),
});
```
</CodeGroup>

<Info>
**`infer` defaults to `false`:** set `infer: true` to have HydraDB extract implicit preferences from conversational content. Leave it `false` to store content verbatim. See [Memories](/essentials/v2/memories).
</Info>

### Query

Switch `type` and `query_by` to change what the query reads and how:

<CodeGroup>
```python Python SDK
# Knowledge over documents
knowledge = client.query(
    database="my_first_database",
    query="What are the pricing tiers?",
    type="knowledge",
    query_by="hybrid",
    mode="thinking",
    graph_context=True,
)

# Personalized — searches knowledge AND user memories together
personalized = client.query(
    database="my_first_database",
    collection="user_alex",
    query="What are the pricing tiers, and how should I explain them to this user?",
    type="all",
    query_by="hybrid",
    mode="thinking",
)

# Exact-phrase BM25 search
exact = client.query(
    database="my_first_database",
    query="ERROR_429 rate limit",
    type="knowledge",
    query_by="text",
    operator="phrase",
)
```
```typescript TypeScript SDK
// Knowledge over documents
const knowledge = await client.query({
  database: "my_first_database",
  query: "What are the pricing tiers?",
  type: "knowledge",
  queryBy: "hybrid",
  mode: "thinking",
  graphContext: true,
});

// Personalized — searches knowledge AND user memories together
const personalized = await client.query({
  database: "my_first_database",
  collection: "user_alex",
  query: "What are the pricing tiers, and how should I explain them to this user?",
  type: "all",
  queryBy: "hybrid",
  mode: "thinking",
});

// Exact-phrase BM25 search
const exact = await client.query({
  database: "my_first_database",
  query: "ERROR_429 rate limit",
  type: "knowledge",
  queryBy: "text",
  operator: "phrase",
});
```
</CodeGroup>

## Response envelope

Endpoints other than connectors and `PATCH /databases/{database}/metadata-schema` wrap responses in an envelope:

```json
{
  "success": true,
  "data": {
    "message": "Success"
  },
  "error": null,
  "meta": {
    "request_id": "<uuid>",
    "latency_ms": 12.3
  }
}
```

The SDKs return the full envelope, so read the payload from `data` (`response.data`). On failure, the SDK raises a typed exception instead of returning an envelope with `error` populated.

## Type safety

Both SDKs are typed from the OpenAPI spec:

- **Methods and parameters:** autocomplete and inline docs for every field in the API reference.
- **Request and response objects:** typed to match each endpoint's JSON schema, nested objects included.
- **Required and optional fields:** match the API and are checked at compile time.
- **Enums:** `type`, `query_by`, `operator`, and `mode` are enum-typed.
- **Errors:** exception types mirror the error response format.

## Error handling

Both SDKs throw on non-2xx responses, and the error exposes the envelope's `error` payload:

<CodeGroup>
```python Python SDK
from hydra_db.core.api_error import ApiError
from hydra_db.errors import NotFoundError

try:
    result = client.query(
        database="my_first_database",
        query="...",
        type="knowledge",
    )
except NotFoundError:
    # Handle missing database / resource (HTTP 404)
    pass
except ApiError as exc:
    if exc.status_code == 429:
        # Rate limit — retry with backoff
        pass
    else:
        raise
```

```typescript TypeScript SDK
import { HydraDBError } from "@hydradb/sdk";

try {
  const result = await client.query({
    database: "my_first_database",
    query: "...",
    type: "knowledge",
  });
} catch (error) {
  if (error instanceof HydraDBError) {
    // error.body is typed `unknown`; it holds the raw snake_case error envelope.
    const code = (error.body as { error?: { code?: string } } | undefined)?.error?.code;

    if (code === "DATABASE_NOT_FOUND") {
      // Handle missing database
    } else if (error.statusCode === 429) {
      // Rate limit — retry with backoff
    } else {
      throw error;
    }
  } else {
    throw error;
  }
}
```
</CodeGroup>

<Info>
**Python:** typed exceptions in `hydra_db.errors` subclass `ApiError` and carry `status_code`, `headers`, and the parsed `body` (read `body["error"]["code"]`). `401` and `429` have no class of their own, so catch `ApiError` and branch on `status_code`, as in the example.
</Info>

Error codes and retry patterns: [Error Responses](/api-reference/v2/error-responses).
