Report on a query that already ran: what was missing, what was wrong, or that it was exactly right. Feedback is used to validate and improve retrieval quality. It does **not** change the result of the query it refers to.

People and agents can both submit, and `source` labels which. An agent that can tell a retrieval was unhelpful is often your best source of signal.

## Linking feedback to a query

Every response carries a `request_id` in `meta` and in the `X-Request-ID` header. Send it back so we can match your comment to the exact query: the text queried, what came back, and how long it took.

```json Query response {6}
{
  "success": true,
  "data": { "chunks": [ /* ... */ ] },
  "error": null,
  "meta": {
    "request_id": "9d13aef4-02f4-4e73-8c62-4c2601d04f9d",
    "api_version": "2.0.1",
    "latency_ms": 412.8
  }
}
```

<Note>
Send `request_id` **exactly as you received it**: the UUID from `meta.request_id` or the `X-Request-ID` header. Any other value returns `400`.
</Note>

Submit feedback only for queries that **returned**. If the query failed, there is no retrieval to judge; fix the request instead.

## Fields

- <Field name="request_id" type="string" required />: the `request_id` from the target query's `meta`. Must be a UUID.
- <Field name="feedback" type="string" />: what was right or wrong, in your own words. Up to 8000 characters. Required **unless** you send `ground_truth`.
- <Field name="ground_truth" type="object" />: what you already know the right answer to be. See [Ground truth](#ground-truth). Properties:
  - <Field name="answer" type="string" />: the response you expected. Up to 8000 characters.
  - <Field name="source_ids" type="string[]" />: IDs of the sources that actually contain the answer. Up to 100, each up to 256 characters.
- <Field name="rating" type="string" />: `positive`, `negative`, or `neutral`. Optional. Omitting it is not `neutral`: it records a comment without a rating.
- <Field name="source" type="string" />: who is submitting. `user` (default) or `agent`.
- <Field name="database" type="string" />: optional. Scopes the feedback to a database your API key can reach.
- <Field name="collection" type="string" />: optional. Requires `database`; sending it alone returns `400`.
- <Field name="metadata" type="object" />: optional string-to-string map for your own context (agent name, conversation id, eval run). Up to 20 entries; keys up to 64 characters, values up to 512.

## Ground truth

If you already know the right answer (from an evaluation set, or because you know which document the user needed), send it. It is a much stronger signal than a comment, because we can score it without a human reading it.

```json
"ground_truth": {
  "answer": "Refunds are processed within 14 days.",
  "source_ids": ["policy_2024", "handbook_q3"]
}
```

- **`answer`:** the response you expected.
- **`source_ids`:** the sources that actually contain the answer. This one grades retrieval: whether the query surfaced those documents, and where they ranked.

Send either or both. With `ground_truth`, `feedback` becomes optional, so an evaluation run with an answer key needs no prose per row. If `ground_truth` is your only signal, at least one of its two fields must carry something. Empty or all-whitespace values count as not sent.

```python Evaluation run
for case in eval_set:
    result = client.query(database="acme_corp", query=case.question)

    try:
        client.feedback.submit(
            request_id=result.meta.request_id,
            source="agent",
            ground_truth={
                "answer": case.expected_answer,
                "source_ids": case.expected_sources,
            },
        )
    except Exception:
        continue  # one unrecorded case should not abort the run
```

At eval volume you may hit the rate limit. Guard each call, as above, or a single `429` loses every remaining case.

Duplicate `source_ids` are collapsed and blank entries dropped, so you need not clean your answer key first. A list with one real id left is scored on that id.

## Submitting more than once

Each submission is stored separately. A second comment on the same query does not replace the first, so you can send several as your understanding develops, and several users can file feedback on one query.

## Rate limit

100 submissions per minute per organization. Over that, you get `429` with a `Retry-After` header and a message naming the seconds to wait; retrying after that is safe. An agent that reports on every query it makes stays well under the limit.

## Errors

A successful submission returns `201`.

- `400`: `request_id` missing or not a UUID; no usable signal (`feedback` blank or absent **and** `ground_truth` absent, empty, or blank); `feedback` too long; unknown `rating` or `source`; `collection` without `database`; or any other limit in [Fields](#fields) exceeded.
- `401`: missing or invalid API key.
- `404`: `database` does not exist or is not reachable by this key.
- `429`: over the rate limit. See `Retry-After`.
- `500`: feedback could not be recorded. Retrying is safe: each submission is its own row, so the worst case is a duplicate report.
