## Request body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Account-scoped database identifier, up to 255 characters of lowercase letters, digits, `-`, and `_`. Anything else, including uppercase or spaces, returns `400`. Deprecated alias: `tenant_id`. |
| <Field name="database_metadata_schema" type="array" /> | Database-level metadata fields. See [Scoping using metadata](/essentials/v2/metadata#step-1a-declare-the-schema-at-database-creation) for schema parameters. Deprecated alias: `tenant_metadata_schema`. (default=`null`) |

## Successful response

Creation is asynchronous. Poll [Database Status](/api-reference/v2/endpoint/tenant-status) until the database is ready.

## After you create a database

- **Default collection:** no collection exists until your first write. The first ingest without a `collection` creates the default collection, which then holds all context written without one. Create more collections any time to scope data to users, teams, or projects.
- **Retry failed databases:** if a database appears in `data.failed_databases` from [List Databases](/api-reference/v2/endpoint/list-tenants), fix the reported issue, re-create it with `POST /databases`, and poll status again.
- **Ingest, then wait for indexing:** once ready, [ingest context](/api-reference/v2/endpoint/ingest-context) and start querying when [ingestion status](/api-reference/v2/endpoint/source-status) shows `graph_creation` (searchable) or `completed`.

## Defining a metadata schema

<Warning>
  Schema field names are **immutable** after creation. You can add database-level fields later with [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema), additively only: no delete, rename, or type change. Dense and sparse search lanes (`enable_dense_embedding`, `enable_sparse_embedding`) can only be declared here. Free-form per-document metadata needs no schema. Plan your schema before you create the database.
</Warning>

A schema enables exact-match filtering (`enable_match`) or semantic and BM25 search over metadata text fields (`enable_dense_embedding`, `enable_sparse_embedding`). Data types, limits, shorthand flags, and examples are in the [metadata](/essentials/v2/metadata) guide.

Each dense or sparse flag adds one vector field, so a field with both uses two. A database can have at most 6. Going over returns `400`, as does declaring an `ARRAY` field.

## Errors

- `400 INVALID_INPUT`: missing or invalid `database`, or an invalid schema.
- `403 FORBIDDEN`: your plan's database limit is reached.
- `409 DATABASE_ALREADY_EXISTS`: the `database` is already in use. The deprecated `POST /tenants` route returns `INVALID_INPUT` here instead.
- `500 INTERNAL_ERROR`: retry. If the message says the rollback also failed, delete the database first, then create it again.
