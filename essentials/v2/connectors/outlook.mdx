Use the Outlook connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `mail_messages`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Connect with an Azure AD app registration (app-only, client credentials): in the Azure portal open Microsoft Entra ID → App registrations → New registration (any name, no redirect URI). Copy the Directory (tenant) ID as tenant and the Application (client) ID as client_id, then under Certificates &amp; secrets create a client secret and paste its Value (shown once) as client_secret.
2. Under API permissions → Add a permission → Microsoft Graph → Application permissions (not Delegated) add User.ReadBasic.All and Mail.Read, then click Grant admin consent (a Global or Application Administrator). The connect step fails with a message naming them when either is missing.
3. Pick the mailboxes to sync in the resource-selection step. A mailbox syncs every message received in the history window outside Drafts, Junk Email, Deleted Items, Outbox and Conversation History, with text bodies and attachment names.
4. Every email carries who may see it in Microsoft 365: the mailbox owner. With Enforce ACL enabled for a provider reporting acl_supported: true, permission-aware search shows each email only to that person; when the owner cannot be resolved the email remains tenant-public under the current fail-open policy and carries a persistent rbac_warning.
5. Mail.Read grants the app every mailbox in the tenant. To limit it to the mailboxes you select, create an Exchange application access policy (New-ApplicationAccessPolicy -AppId `<client_id>` -PolicyScopeGroupId `<group>` -AccessRight RestrictAccess); a selected mailbox outside the policy fails the sync with a message naming the policy rather than syncing silently empty.
6. Each sync reads only what changed: mail is filtered server-side on lastModifiedDateTime. Mail moved to Deleted Items or Junk Email after it was indexed is replaced by a hidden stub on the next sync; mail purged from Deleted Items leaves no trace until a full re-sync.
7. Rotate the client secret before it expires (Azure defaults to 6-24 months): an expired secret stops every sync with a message naming the fix. Pasting a new secret value re-enables the connector.

Use provider `outlook` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
