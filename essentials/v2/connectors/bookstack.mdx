Sync the books you select from your BookStack instance. Each page is one document holding its text. Each chapter and each book is also one document, holding its description. Pages and chapters carry the id of their book and chapter, so a query can be limited to one book or chapter.

BookStack permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Items carry no link back to BookStack. Images and files on pages are not synced, and items deleted in BookStack stay in HydraDB.

<Note>
BookStack is in beta.
</Note>

## Permissions

<Warning>
BookStack permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- BookStack page, chapter, book and role permissions are not applied.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

BookStack uses an API token, made of a token id and a token secret.

<ResponseField name="base_url" type="string" required>
The root address of your BookStack instance.
</ResponseField>

<ResponseField name="token_id" type="secret string" required>
The BookStack API token id.
</ResponseField>

<ResponseField name="token_secret" type="secret string" required>
The BookStack API token secret.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create an API token">
    In BookStack, create an API token and copy its id and secret. A page the token's user cannot read in full is synced with its title only.
  </Step>
  <Step title="Create the connector">
    Enter `base_url`, `token_id` and `token_secret`.
  </Step>
  <Step title="Select books">
    HydraDB lists the books in the instance. Select the books to sync. Their chapters and pages come with them. To reach items older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads one BookStack instance, as one API token.

<Accordion title="Connect through the API">

Use provider `bookstack` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected book reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the books, chapters and pages updated since the last sync.
- **Edits:** An updated item is read again and replaces its document. A page's content is read again with it.
- **Deletions:** Deleted items are not removed. A page, chapter or book deleted in BookStack stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every BookStack item

<ResponseField name="updated_at" type="Searchable text, Result date">
When the item was last updated, written as the `Updated` line. Sets the result date.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the item was created. Sets the result date only when the update time is missing. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.bookstack_type" type="Query filter">
`pages`, `chapters` or `books`. Limits a query to one kind of item. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `bookstack`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="owned_by" type="Stored only">
The BookStack user id of the item's owner. It does not restrict access.
</ResponseField>

<ResponseField name="owned_by_name" type="Stored only">
The owner's name, when it can be found. A search does not match it.
</ResponseField>

<ResponseField name="slug" type="Stored only">
The item's URL slug.
</ResponseField>

</Accordion>

### Pages

- **One document:** One BookStack page.
- **Title:** The page name. A page with no name is titled `BookStack page` and its id.
- **Text:** The page content as plain text, with its title and last-updated time. If the page's content could not be read, the title stands in for it.
- **Date:** When the page was last updated, else when it was created.
- **Link back:** None.
- **Files:** None. Images and files on pages are not synced.

<ResponseField name="additional_metadata.bookstack_id" type="Query filter">
The page's numeric BookStack id. Picks out one page. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.bookstack_book_id" type="Query filter">
The id of the book that holds the page. Limits a query to one book. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.bookstack_chapter_id" type="Query filter">
The id of the chapter that holds the page, when it is in one. Limits a query to one chapter. Not searchable.
</ResponseField>

### Chapters

- **One document:** One chapter's name and description. Its pages are their own documents.
- **Title:** The chapter name. A chapter with no name is titled `BookStack chapter` and its id.
- **Text:** The chapter description, or the title when there is none, with the last-updated time.
- **Date:** When the chapter was last updated, else when it was created.
- **Link back:** None.

<ResponseField name="additional_metadata.bookstack_id" type="Query filter">
The chapter's numeric BookStack id. Picks out one chapter, and matches `additional_metadata.bookstack_chapter_id` on its pages. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.bookstack_book_id" type="Query filter">
The id of the book that holds the chapter. Limits a query to one book. Not searchable.
</ResponseField>

### Books

- **One document:** One book's name and description. Its chapters and pages are their own documents.
- **Title:** The book name. A book with no name is titled `BookStack book` and its id.
- **Text:** The book description, or the title when there is none, with the last-updated time.
- **Date:** When the book was last updated, else when it was created.
- **Link back:** None.

<ResponseField name="additional_metadata.bookstack_id" type="Query filter">
The book's numeric BookStack id. Picks out one book, and matches `additional_metadata.bookstack_book_id` on its chapters and pages. Not searchable.
</ResponseField>

**Example searches**

- What does the runbook page say about restoring backups?
- Which pages in the Operations book mention VPN access?
- What is the Onboarding book about?

## How it fits into the graph

- Pages use the Page class.
- Chapters use the Page class.
- Books use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections BookStack creates**

- No links between items. A page's book and chapter are kept as filters, not as graph links.
- No links to items in other tools.

**People and groups**

- No people are attached. The owner is kept with the item only.

**Found in the text**

The page text and the book and chapter descriptions. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Books you did not select.
- Items last updated before the `lookback_days` window on the first sync.
- Images and files attached to pages.
- Page revisions and comments.
- Shelves.
- BookStack permissions and roles.
- A link back to the item in BookStack.
- Deletions: deleted items stay in HydraDB.
