Returns the **connected subgraph** of one ingested item: every item reachable from it through item-level relations (breadth-first, up to `depth` hops), the relations among those members, and the structural graph around them (entities, comments, attachments, people).

Call it after [Query](/api-reference/v2/endpoint/query) or [List Context](/api-reference/v2/endpoint/list-documents) when you need what surrounds one result. It is about *items*: which Slack message replies to which, which page links to which, which ticket a comment belongs to. For entity triplets *extracted from text* (`PaymentsWorker` `depends_on` `OrdersDB`), use [Inspecting Context Relations](/api-reference/v2/endpoint/source-relations).

## Path parameters

| Name | Description |
| --- | --- |
| <Field name="id" type="string" required /> | The item to start from: any `id` returned by Query, List Documents, or Ingest. URL-encode reserved characters. An id with a literal `/` cannot be one path segment, so pass it as `GET /context/subgraph?id=...`, the form the SDKs use for every id. |

## Query parameters

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Owning database. Deprecated alias: `tenant_id`. |
| <Field name="collection" type="string or null" /> | Collection scope. If omitted, the default collection is used. Deprecated alias: `sub_tenant_id`. (default=`null`) |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22;" /> | Which graph the `id` belongs to; set `memory` for a memory's `id`. The two graphs are completely separate and never connect. (default=`"knowledge"`) |
| <Field name="depth" type="integer" /> | Maximum traversal depth in hops, from `1` to `10`. (default=`5`) |
| <Field name="max_sources" type="integer" /> | Maximum members returned, from `1` to `1000`. `is_truncated` is `true` when this clips the traversal. (default=`200`) |
| <Field name="acl" type="string[]" /> | Principals to answer as (document ACLs). Only items they may see are included, filtered at every hop. Repeated (`acl=a&acl=b`) or comma-separated. Omit for no ACL scoping. |

## How items connect

Every member except the start item records how the traversal found it:

- **`discovered_relation`** names the mechanism: `same_thread` when the member shares a thread with an item already in the subgraph (Slack replies, ticket comments); `parent` or `child` for a hierarchy tie (a comment and its message, a page and its section); or the relation type of an explicit `relates_to` link declared at ingest (`reply_to`, `references`, or whatever the ingest named it).
- **`discovered_via`** is the `source_id` of the already-admitted member this one was first reached *from*. Follow it back to rebuild the traversal tree.

Traversal is breadth-first, so each member's `depth` is its distance from the start item. The start item is a member at depth `0`, with neither field set.

## Reading the response

- **`sources[]`** are the members. Pass any `source_id` to [Inspect Context](/api-reference/v2/endpoint/fetch-content) for the full document, or back to this endpoint to re-centre on it.
- **`relations[]`** are the item-level relations *among the members* (`relates_to`, `same_thread`, `parent_of`), in the same triplet shape as [Inspecting Context Relations](/api-reference/v2/endpoint/source-relations). Their endpoints are `SOURCE` entities whose `entity_id` is the item's id.
- **`auxiliary_relations[]`** is the structural graph around the members: who sent a message, which entities it mentions, which comments and attachments hang off it. It is recorded from the item itself, not extracted from text, so `context` is empty.
- **Not included:** the chunk-level entity relations that Query returns as `graph_context`.

## Notes

<Info>
  **An unknown `id` is an empty subgraph, not an error.** The endpoint does not confirm or deny that an item exists: an id never ingested and one the `acl` principals may not see get the same answer.
</Info>

- **An item nothing links to:** comes back as a one-member subgraph (itself, at depth `0`, with `max_depth_reached: 0`). That means "this stands alone", unlike an unknown id, which has no members.
- **Bounding the traversal:** when `max_sources` clips it, `is_truncated` is `true` and you get the members closest to the start item. `auxiliary_truncated` reports the same for the structural graph.
- **Completeness:** an item's links populate once its `indexing_status` reaches `completed`. Items still in `graph_creation` may show fewer connections.
- **Cost:** one request fans out into a bounded series of graph reads, so it is rate-limited like a Query, not like a status poll.

## Errors

- **`400 INVALID_INPUT`:** missing `database` or `id`, `depth` outside `1` to `10`, or `max_sources` outside `1` to `1000`.
- **`404 DATABASE_NOT_FOUND`:** the database does not exist.
- **`500 INTERNAL_ERROR`:** a transient graph read failure. Retry the request.

See [Error Responses](/api-reference/v2/error-responses).
