Sync the Superhuman docs you select. Each doc gives one document with its owner, workspace and folder, one document per page with the page's content, and one document per table row with its cell values. A page links to its parent page, or to its doc at the top level. Files in a row's attachment columns are downloaded when Superhuman hosts them.

Superhuman permissions are not imported, so everything in the selected docs is visible to everyone who can query the collection unless you set an access rule. The first sync reaches only items updated in the last 30 days unless you raise `lookback_days`. Docs, pages and rows deleted in Superhuman stay in HydraDB.

<Note>
Superhuman is in beta.
</Note>

## Permissions

<Warning>
Superhuman permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Superhuman doc permissions are read but not applied.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Superhuman, formerly Coda, uses a Coda API token. The token belongs to an account, not to a workspace.

<ResponseField name="auth_token" type="secret string" required>
A Coda API token for the account whose docs you want synced.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create an API token">
    Create a Coda API token for the account whose docs you want synced.
  </Step>
  <Step title="Create the connector">
    Paste the token as `auth_token`.
  </Step>
  <Step title="Select docs">
    HydraDB lists the docs the token can reach. Select the docs to sync. You select docs one by one: a whole workspace cannot be selected. To reach items older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads the docs one account's token can reach.

<Accordion title="Connect through the API">

Use provider `coda` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected doc reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the docs, pages and rows updated since the last sync. A change to a page's content sends that page again.
- **Edits:** An edited doc, page or row is read again and replaces its document.
- **Deletions:** Deleted docs, pages and rows are not removed. They stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Superhuman item

<ResponseField name="updated_at" type="Searchable text, Result date">
When the doc, page or row was last updated, written as the `Updated` line. Sets the result date.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the item was created. Sets the result date only when the update time is missing. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.coda_doc_id" type="Query filter">
The doc id. Limits a query to one doc, with its pages and rows. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `coda`. Not searchable.
</ResponseField>

### Docs

- **One document:** One doc's details. The doc's pages and table rows are their own documents.
- **Title:** The doc name. A doc with no name is titled `Coda doc` and its id.
- **Text:** The title, then `Owner`, `Workspace`, `Folder` and `Link` lines, leaving out empty ones.
- **Date:** When the doc was last updated, else when it was created.
- **Link back:** Opens the doc in Superhuman.

<ResponseField name="owner_name" type="Searchable text">
The name of the doc's owner, written as the `Owner` line, so a doc can be found by owner. The owner is not attached to the doc as a person in the graph.
</ResponseField>

<ResponseField name="workspace_name" type="Searchable text">
The workspace that holds the doc, written as the `Workspace` line.
</ResponseField>

<ResponseField name="url" type="Searchable text">
The doc's link, written as the `Link` line.
</ResponseField>

### Pages

- **One document:** One page of a doc, with its content.
- **Title:** The page name. A page with no name is titled `Coda page` and its id.
- **Text:** The page's content as text, with its title and subtitle. A very large page can be cut short.
- **Date:** When the page was last updated, else when it was created.
- **Link back:** Opens the page in Superhuman.

<ResponseField name="subtitle" type="Searchable text">
The page subtitle, written as a `Subtitle` line.
</ResponseField>

<ResponseField name="additional_metadata.coda_page_id" type="Query filter">
The page id. Picks out one page. Not searchable.
</ResponseField>

<ResponseField name="parent_id" type="Graph connection">
The parent page, or the doc for a top-level page. Links the page to it, so a doc's page tree is connected. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (4)">

<ResponseField name="doc_id" type="Stored only">
The id of the doc that holds the page. To limit a query to a doc, use `additional_metadata.coda_doc_id`.
</ResponseField>

<ResponseField name="content_type" type="Stored only">
The page type: `canvas`, `embed` or `syncPage`.
</ResponseField>

<ResponseField name="page_content_elements" type="Stored only">
How many content elements were read from the page, blank ones included. Not a measure of how much text is searchable.
</ResponseField>

<ResponseField name="page_content_truncated" type="Stored only">
True when the page's content was too large and was cut short.
</ResponseField>

</Accordion>

### Table rows

- **One document:** One row of a table.
- **Title:** The table name, a dash and the row name. A row with no name is titled by its table alone. When the table is not known, the row name alone, or `Coda row` and its id.
- **Text:** The title, a `Table` line when the table is known, then each non-empty cell as a labelled line, in column order. A column whose name is not known is labelled with its id and comes last. Money values show the amount and currency. Numbers are rounded to six decimal places. Cell values HydraDB cannot show as text are left out. A column that refers to another row is text, not a link.
- **Date:** When the row was last updated, else when it was created.
- **Link back:** Opens the row in Superhuman, or its table when the row has no link.
- **Files:** Files in attachment columns are downloaded so their text can be read, but only when they are hosted on coda.io or codahosted.io. Links to files elsewhere are dropped.

<ResponseField name="table_name" type="Searchable text">
The row's table. Starts the title and is the `Table` line, so rows can be found by table.
</ResponseField>

<ResponseField name="additional_metadata.coda_table_id" type="Query filter">
The table id. Limits a query to one table's rows. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.coda_row_id" type="Query filter">
The row id. Picks out one row. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="doc_id" type="Stored only">
The id of the doc that holds the row.
</ResponseField>

<ResponseField name="table_id" type="Stored only">
The id of the row's table.
</ResponseField>

</Accordion>

**Example searches**

- What does the Q4 planning doc say about hiring?
- Which rows in the Roadmap table have status Blocked?
- Who owns the Team Rituals doc?

## How it fits into the graph

- Docs use the Page class.
- Pages use the Page class.
- Table rows use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Superhuman creates**

- A page to its parent page, or to its doc for a top-level page.
- Rows are not linked to their table or doc in the graph.
- No links to items in other tools.

**People and groups**

- No people are attached. A doc owner's name is part of the doc's text only.

**Found in the text**

The doc details, page content and row cell values. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Docs you did not select.
- Items last updated before the `lookback_days` window on the first sync.
- Controls, formulas as definitions, and doc permissions. Formula results shown in row cells can still be searchable.
- Files in attachment columns that are not hosted on coda.io or codahosted.io.
- The rest of a very large page after it is cut short.
- Deletions: deleted docs, pages and rows stay in HydraDB.
