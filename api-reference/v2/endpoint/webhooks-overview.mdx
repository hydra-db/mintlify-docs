Webhooks deliver an HTTP callback to your endpoint when ingested content reaches a terminal indexing state, so you can react to `completed` or `errored` items without polling [Ingestion Status](/api-reference/v2/endpoint/source-status). See the [Webhooks guide](/essentials/v2/webhooks) for payload shapes, signature verification, and receiver examples.

## Endpoint references

| Endpoint | Method | Purpose |
| --- | --- | --- |
| [`/webhooks/indexing`](/api-reference/v2/endpoint/register-webhook) | `POST` | Register (or replace) the webhook for this API key |
| [`/webhooks/indexing`](/api-reference/v2/endpoint/get-webhook) | `GET` | Get the current webhook registration |
| [`/webhooks/indexing`](/api-reference/v2/endpoint/delete-webhook) | `DELETE` | Unregister the webhook |
| [`/webhooks/indexing/test`](/api-reference/v2/endpoint/test-webhook) | `POST` | Send a synthetic test delivery |
| [`/webhooks/indexing/deliveries`](/api-reference/v2/endpoint/list-deliveries) | `GET` | List recent delivery attempts |
| [`/webhooks/indexing/deliveries/:delivery_id`](/api-reference/v2/endpoint/get-delivery) | `GET` | Get a single delivery attempt |
| [`/webhooks/indexing/deliveries/:delivery_id/retry`](/api-reference/v2/endpoint/retry-delivery) | `POST` | Queue a failed delivery for retry |

## Typical call sequence

```text
POST /webhooks/indexing                        -> register your endpoint URL
POST /webhooks/indexing/test                   -> confirm your endpoint receives a request
POST /context/ingest                           -> ingest content as usual
(HydraDB POSTs to your URL on terminal status)
GET  /webhooks/indexing/deliveries?status=failed -> audit failures
POST /webhooks/indexing/deliveries/:id/retry   -> retry a failed delivery
```

## Authentication

All webhook management endpoints use your HydraDB API key:

```bash
Authorization: Bearer $HYDRADB_API_KEY
API-Version: 2
```

<Info>
Webhook management endpoints return their response object directly, not inside the standard v2 `{ success, data, error, meta }` envelope used by `/databases`, `/context/*`, and `/query`.
</Info>

## Key concepts

- **Registration**  -  one webhook registration per API key. `POST` with a new body replaces the existing registration.
- **Event**  -  the supported event is `indexing.status_changed`, fired when an item reaches `completed`, `errored`, or `success` (a legacy alias for `completed`).
- **Delivery**  -  a record of one event sent to your endpoint. Deliveries move through `pending`, `sweeping`, `delivered`, `failed`, and `permanently_failed` states, and failed sends are retried in the background.
- **Signing secret**  -  optional. When configured, HydraDB sends an `X-HydraDB-Signature` header your receiver should verify against the raw request body. See the [security checklist](/essentials/v2/webhooks#7-security-checklist).
