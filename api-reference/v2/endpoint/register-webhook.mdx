---
title: "Register Webhook"
description: "Register or replace the indexing webhook for this API key."
openapi: "api-reference/v2/openapi.json POST /webhooks/indexing"
---

import { Field } from "/snippets/field.jsx";

Registers the endpoint that receives `indexing.status_changed` events for this API key's organization. There is one registration per API key  -  calling this endpoint again **replaces** the existing registration, so the same call registers a new webhook and edits an existing one.

<Warning>
Your webhook URL must be reachable from the public internet. Localhost and private network addresses are blocked.
</Warning>

<RequestExample>

```bash cURL
curl -X POST 'https://api.hydradb.com/webhooks/indexing' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://api.example.com/webhooks/hydradb",
    "event_types": ["indexing.status_changed"],
    "signing_secret": "replace-with-at-least-16-characters"
  }'
```

</RequestExample>

## Request body

| Name | Description |
| --- | --- |
| <Field name="url" type="string" required /> | Public HTTPS endpoint that receives event `POST`s. |
| <Field name="event_types" type="string[]" required /> | Events to subscribe to. Currently `["indexing.status_changed"]`. |
| <Field name="signing_secret" type="string" /> | Optional secret (16+ characters) used to sign deliveries. When set, verify the `X-HydraDB-Signature` header against the raw request body. Omitting it while editing disables signing for future deliveries. |

<ResponseExample>

```json 200
{
  "registered": true,
  "url": "https://api.example.com/webhooks/hydradb",
  "event_types": ["indexing.status_changed"],
  "signing_secret_configured": true,
  "message": "Webhook registered."
}
```

</ResponseExample>

<Info>
Webhook management endpoints return their response object directly, not inside the standard v2 `{ success, data, error, meta }` envelope.
</Info>

After registering, use [Test Webhook](/api-reference/v2/endpoint/test-webhook) to confirm your endpoint receives a request before relying on it in production.
