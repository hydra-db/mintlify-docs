Sync every ticket in one Freshdesk helpdesk, with its replies. Each ticket is one document with its description, requester, assignee, company and group. Each reply is its own document, linked to its ticket.

Freshdesk agent scopes are not imported, so every synced ticket and reply is visible to everyone who can query the collection unless you set an access rule. Private agent notes are skipped unless you turn them on. Tickets deleted in Freshdesk stay in HydraDB. Attachments are not synced.

## Permissions

<Warning>
Freshdesk permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Freshdesk Global, Group and Restricted agent scopes are not reproduced.
- If you turn on `include_private_notes`, private agent notes are visible to everyone who can query the collection too.
- Every ticket and reply carries `additional_metadata.rbac_warning`, saying that Freshdesk visibility is not captured.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Freshdesk uses an agent's API key and your helpdesk's subdomain.

<ResponseField name="api_key" type="secret string" required>
An agent's API key, from the agent's Freshdesk profile settings.
</ResponseField>

<ResponseField name="domain" type="string" required>
The helpdesk subdomain only, for example `acme` for `acme.freshdesk.com`.
</ResponseField>

<ResponseField name="include_private_notes" type="boolean">
Off by default. Turn it on to also sync private agent notes.
</ResponseField>

There is no scope to choose. The key reads the tickets its agent can see under that agent's Global, Group or Restricted ticket scope. Pick an agent with Global scope, or only part of the helpdesk syncs.

### Set it up

<Steps>
  <Step title="Copy an agent API key">
    In Freshdesk, open the profile settings of an agent with Global ticket scope and copy the API key.
  </Step>
  <Step title="Create the connector">
    Paste the key as `api_key` and the subdomain as `domain`. Turn on `include_private_notes` only if everyone who can query the collection may read private notes, or set an access rule.
  </Step>
  <Step title="Configure the connector">
    HydraDB lists one account-wide resource, All data. Select it to sync the whole helpdesk as one unit.
  </Step>
</Steps>

One connector reads one Freshdesk helpdesk domain.

<Accordion title="Connect through the API">

Use provider `freshdesk` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads tickets updated since the last sync, together with their replies. Replies are read again only when their ticket changes.
- **Edits:** A changed ticket is read again with its replies and updates its documents.
- **Deletions:** Deleted tickets are not removed. A ticket synced before it was deleted or marked as spam stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Freshdesk item

<ResponseField name="additional_metadata.freshdesk_id" type="Query filter">
The ticket id on a ticket, the reply id on a reply. Targets one item, and keeps later syncs on the same document. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.rbac_warning" type="Query filter">
Set on every item, saying that Freshdesk visibility is not captured. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `freshdesk`. Not searchable.
</ResponseField>

### Tickets

- **One document:** One ticket. Spam and deleted tickets are skipped.
- **Title:** The ticket subject.
- **Text:** The plain-text description, converted from HTML when needed, or the subject when the description is empty. Then `Requester`, `Requester email`, `Assignee`, `Company` and `Group` lines. Status, priority and creation time are part of the text too. The subject is searchable too.
- **Date:** When the ticket was last updated, else when it was created.
- **Link back:** The ticket in the Freshdesk agent portal.
- **Files:** Ticket attachments are not synced.

<ResponseField name="status" type="Searchable text">
Open, Pending, Resolved or Closed, written as a `Status` line. A custom status is written as its raw number.
</ResponseField>

<ResponseField name="priority" type="Searchable text">
Low, Medium, High or Urgent, written as a `Priority` line.
</ResponseField>

<ResponseField name="requester" type="Searchable text">
The requester's name, written as the `Requester` line, where HydraDB can identify the customer.
</ResponseField>

<ResponseField name="requester_email" type="Searchable text">
The requester's email, written as the `Requester email` line, where HydraDB can connect the address to the customer.
</ResponseField>

<ResponseField name="assignee" type="Searchable text, Graph identity">
The assigned agent's name or email, written as the `Assignee` line. The graph records the ticket as assigned to that agent.
</ResponseField>

<ResponseField name="company" type="Searchable text">
The requester's company, written as the `Company` line, so every ticket from one company matches.
</ResponseField>

<ResponseField name="group" type="Searchable text">
The name of the agent group the ticket is assigned to, written as the `Group` line.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the ticket was created, written as a `Created` line. Used as the result date only when the update time is missing.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the ticket was last updated. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (5)">

<ResponseField name="type" type="Stored only">
The Freshdesk ticket type.
</ResponseField>

<ResponseField name="tags" type="Stored only">
The ticket's tags.
</ResponseField>

<ResponseField name="requester_id" type="Stored only">
The requester's Freshdesk contact id.
</ResponseField>

<ResponseField name="responder_id" type="Stored only">
The assigned agent's id. The agent's name is in `assignee`.
</ResponseField>

<ResponseField name="group_id" type="Stored only">
The assigned group's id. The group's name is in `group`.
</ResponseField>

</Accordion>

### Replies

- **One document:** One reply or note on a ticket. Empty replies are skipped. Private agent notes are included only when `include_private_notes` is on.
- **Title:** `Comment by` and the author's name. Without an author, the first 80 characters of the text.
- **Text:** An `Author` line, then the plain-text reply. The creation and update times are part of the text too.
- **Date:** When the reply was created, else when it was last updated.
- **Link back:** The parent ticket in the Freshdesk agent portal.
- **Files:** Reply attachments are not synced.

<ResponseField name="author" type="Searchable text, Graph identity">
The agent who wrote the reply, written as the `Author` line. The graph records the reply as written by that agent. Customers are not named, because Freshdesk contacts are not synced.
</ResponseField>

<ResponseField name="from_email" type="Searchable text">
The sender's email. Written as the `Author` line only when no agent name is found, which is the case for customer replies.
</ResponseField>

<ResponseField name="mentions" type="Searchable text, Graph identity">
Names mentioned in a private note. The names stay in the note text, and the graph records each as mentioned.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The ticket the reply belongs to. Links the reply to its ticket, so the whole conversation can be returned together.
</ResponseField>

<ResponseField name="additional_metadata.freshdesk_ticket_id" type="Query filter">
The id of the ticket the reply belongs to. Returns every reply on one ticket. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the reply was created, written as a `Created` line.
</ResponseField>

<ResponseField name="updated_at" type="Searchable text, Result date">
When the reply was last updated, written as an `Updated` line. Used as the result date only when the creation time is missing.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="private" type="Stored only">
True for a private agent note. It does not restrict who can read the note.
</ResponseField>

<ResponseField name="incoming" type="Stored only">
True when the reply came from the requester, so you can tell a customer message from an agent reply.
</ResponseField>

<ResponseField name="author_id" type="Stored only">
The Freshdesk user id of the reply's author.
</ResponseField>

</Accordion>

**Example searches**

- What did an agent say about a billing issue?
- Which urgent tickets are assigned to Priya?
- Which tickets came from Acme Corp?

## How it fits into the graph

- Tickets use the Ticket class.
- Replies use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Freshdesk creates**

- A reply to its ticket.
- No links to other tools.

**People and groups**

- The assigned agent of each ticket.
- The author of each agent reply.
- Names mentioned in a private note.
- The requester's name and email, and the company, appear in the ticket text, where HydraDB can identify them.
- Customers who reply are not attached as people. Their email appears in the reply text.

**Found in the text**

The ticket description with its requester, assignee, company and group lines, and the text of every reply. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Private agent notes, unless `include_private_notes` is on.
- Spam and deleted tickets. Replies on them can still be synced.
- Contacts and companies as documents of their own.
- Satisfaction ratings, time entries, solution articles and forum posts.
- Ticket custom fields.
- Ticket and reply attachments.
- Deletions: tickets deleted in Freshdesk stay in HydraDB.
