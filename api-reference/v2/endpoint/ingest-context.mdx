import { Field } from "/snippets/field.jsx";

Pick the form fields by what you are sending:

- **`type=knowledge`, files:** send PDFs, Office and iWork files, spreadsheets, images, and plain text in `documents` for HydraDB to parse. See [Supported file formats](#supported-file-formats).
- **`type=knowledge`, app sources:** send JSON you already extracted (Slack threads, Notion pages, emails, tickets) in `app_knowledge`. See [App sources](/essentials/v2/app-sources).
- **`type=memory`:** send per-user content in `memories`, scoped by `collection`. `infer: true` lets HydraDB extract preferences from raw signals; `infer: false` stores the text verbatim. See [Memories](/essentials/v2/memories).

<Note>
`database` and `collection` replace `tenant_id` and `sub_tenant_id`. The old names still work as deprecated aliases.
</Note>

## Form fields

| Name | Description |
| --- | --- |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22;" /> | Use singular `"memory"` when writing memories. (default=`"knowledge"`) |
| <Field name="database" type="string" required /> | Target database. Deprecated alias: `tenant_id`. |
| <Field name="collection" type="string" /> | Logical partition inside the database. Deprecated alias: `sub_tenant_id`. (default=`""`, the default collection) |
| <Field name="upsert" type="boolean" /> | Replace existing sources with the same ID. With `false`, a document or app source whose ID already exists is not replaced: it comes back `failed` with `error_code: "E9003"`. (default=`true`) |
| <Field name="documents" type="file[]" /> | Files for HydraDB to parse, **knowledge only**. See [Supported file formats](#supported-file-formats). (default=`[]`) |
| <Field name="document_metadata" type="string (JSON array)" /> | One entry per file in `documents`, in the same order. The item count must match the file count, or the request returns `400`. If omitted, documents index with inferred defaults such as filename and title. See the item shape below. |
| <Field name="app_knowledge" type="string (JSON object or array)" /> | Pre-extracted source objects (Slack, Notion, web pages, etc.), **knowledge only**. See the `app_knowledge` item shape below. |
| <Field name="graph_payload" type="string (JSON map)" /> | Map from source id to your own entities and relations. Replaces LLM graph extraction for each keyed source. For `type=knowledge` the key is a `document_metadata` id or an `app_knowledge` item id; for `type=memory` it is a memory `id`. See [Bring Your Own Graph](/essentials/v2/bring-your-own-graph) and the shape below. |
| <Field name="memories" type="string (JSON array)" /> | Memory items, **memory only**. Required and non-empty when `type=memory`. The form field is plural `memories`, even though `type` is singular `memory`. See the `memories` item shape below. |

<Note>
1. **`id` must not contain a comma (`,`).** [Ingestion Status](/api-reference/v2/endpoint/source-status) uses the comma to separate ids (`GET /context/status?ids=a,b`), so an `id` with a comma cannot be looked up. This applies to every `id` you send in `document_metadata`, `app_knowledge`, and `memories` items. An `id` with a comma is rejected with `400`.

2. **`202 Accepted` means queued, not indexed.** Ingestion is asynchronous. Before you query, poll [`GET /context/status`](/api-reference/v2/endpoint/source-status) with the returned IDs until each source reaches `graph_creation` (searchable), `completed` (graph ready), or `errored`. Or register a webhook for `indexing.status_changed` events (see [Webhooks](/essentials/v2/webhooks)).
</Note>


## Supported file formats

HydraDB reads any of these when you upload them in `documents`:

- **Documents:** `.pdf` `.doc` `.docx` `.docm` `.dot` `.dotx` `.odt` `.ott` `.rtf`
- **Spreadsheets:** `.xls` `.xlsx` `.xlsm` `.xlsb` `.ods` `.ots` `.csv` `.tsv`
- **Presentations:** `.ppt` `.pptx` `.pptm` `.odp` `.otp`
- **Apple iWork:** `.pages` `.numbers` `.key`
- **Images:** `.png` `.jpg` `.jpeg` `.tif` `.tiff` `.webp` `.gif` `.bmp`
- **Plain text:** `.txt` `.md` `.markdown` `.json`

What gets indexed depends on the type:

- **Documents and presentations:** the text, in reading order. Slide titles and body text both come through.
- **Spreadsheets:** cell values as a table, one per sheet. Formulas index as their computed result, not the formula.
- **Images and scans:** text read from the picture with OCR. A photo of a page and a scan of a page both work.
- **Plain text:** the file as is.

A scanned page or photo with no readable text indexes as an empty document. It does not fail.

### Formats we cannot read

These are rejected at upload, before anything is queued, so the answer is in the upload response, not minutes later.

- `.heic` `.heif` `.avif`: export the photo as JPEG or PDF.
- `.svg` `.ico`: export as PNG or JPEG.
- `.html` `.htm` `.xml`: save the page as PDF.
- `.eml` `.msg`: save the message as PDF, or send it as an app source.
- `.epub` `.wpd`: convert to PDF or DOCX.
- `.zip`: upload the files one by one.

<Note>
`.heic` is the default iPhone photo format, so it is the one people hit most often without realizing. On iOS, go to **Settings**, **Camera**, **Formats**, and pick **Most Compatible** to save JPEGs instead. Or export the photo as JPEG or PDF before uploading.
</Note>

### How we decide the format

The file extension decides. `report.pdf` is treated as a PDF because of `.pdf`, not because of what is inside it.

If the filename has no extension, the `Content-Type` you send with that part decides instead. A file with no extension, sent as `application/pdf`, is accepted.

<Note>
Renaming a file does not convert it. A `.heic` photo renamed to `photo.pdf` passes this check, because the check reads the name. It then fails during parsing and shows as `errored` on [`GET /context/status`](/api-reference/v2/endpoint/source-status). Upload files under their real extension.
</Note>

### Size limit

Each file in `documents` can be up to **50 MB**. A larger file is rejected with `413` and a message naming the file, and no part of the request is processed. Split large documents, or upload them separately.

## When a file is not supported

A rejected file does not stop the rest of your upload. Each file is checked on its own, so a batch of ten with one bad file still indexes the other nine.

The request still returns `202`. The rejected file comes back with `status: "failed"` and `error_code: "E1002"`, and every other file is queued:

```json
{
  "success": true,
  "data": {
    "success": false,
    "message": "Upload completed with some failures.",
    "results": [
      { "id": "6cc7bcd185b044cd", "filename": "report.pdf", "status": "queued", "error": null, "error_code": null },
      { "id": "f47411c736447126", "filename": "photo.heic", "status": "failed", "error": "This file format isn't supported. Please upload a PDF, Office document (Word, Excel, PowerPoint), image, CSV or text file.", "error_code": "E1002" },
      { "id": "d0c919bdec196a8d", "filename": "notes.txt", "status": "queued", "error": null, "error_code": null }
    ],
    "success_count": 2,
    "failed_count": 1
  },
  "error": null,
  "meta": { "request_id": "bcd03673-174d-4a73-83e6-73bfcdc16061", "api_version": "2.0.1" }
}
```

<Note>
`results`, `success_count`, and `failed_count` sit inside `data`, like every v2 response. The outer `success: true` means the request was accepted. `data.success` tells you whether every file in it was queued.
</Note>

<Note>
**Do not poll [`GET /context/status`](/api-reference/v2/endpoint/source-status) for a file rejected with `E1002`.** The file never entered the pipeline, so it has no status record, and the lookup returns `FILE_NOT_FOUND`, not the format error. The upload response is the only place `E1002` appears, so read `error_code` on each item in `data.results` and act on it there.
</Note>

## Common use cases

Each `document_metadata` item accepts `id`, `metadata`, `additional_metadata`, `relations`, `infer`, `evidence_kind`, and `evidence_subject`, plus the legacy aliases `source_id` and `file_id` (for `id`) and `document_metadata` (for `additional_metadata`). Any other key, including `title`, `type`, `url`, and `timestamp`, is rejected with a `400` that names it. It is not silently dropped.

  | --- | --- |
  | <Field name="<source_id>" type="object" /> | Top-level key: a `document_metadata` id or `app_knowledge` item id for `type=knowledge`, or a memory `id` for `type=memory`. Value is that source's graph. A key matching no source returns `400`. |

  | <Field name="entities[].name" type="string" required /> | Entity name, up to 256 characters. Normalized (lowercased) server-side so it matches at query time. |
  | <Field name="entities[].type" type="string" /> | Entity type (e.g. `PERSON`, `POLICY`). Stored as supplied. |
  | <Field name="entities[].namespace" type="string" /> | Logical grouping for the entity. Stored as supplied. |
  | <Field name="entities[].identifier" type="string" /> | Optional external id (email, URL, etc.), for display only. |
  | <Field name="relations" type="array" /> | Edges referencing entity-map keys. |
  | <Field name="relations[].source" type="string" required /> | Entity-map key of the source entity. |
  | <Field name="relations[].target" type="string" required /> | Entity-map key of the target entity. |
  | <Field name="relations[].predicate" type="string" required /> | Relationship label, any plain string, up to 256 characters. |

  <Note>
  **Per-source replace mode:** Each top-level key must match a source in the same request (see `<source_id>` above). You can attach graphs to several sources at once. Extraction is skipped for keyed sources. Caps per graph: up to 5,000 entities, 10,000 relations, and 500 relations per entity; over the cap returns `400`. Graphs survive re-ingest: a re-upload or connector re-sync re-applies the stored graph.

### Upload in-memory text as a `.txt` file

Have text in memory? Wrap it in a file-like object and send it in `documents` as a `text/plain` `.txt` file. You do not need a file on disk.

<CodeGroup>
```python Python SDK
import io
import json

text = """Q4 planning notes

- Launch checklist is owned by Priya.
- Legal review is due by Friday.
"""

# Create a file-like object in memory. No local .txt file is required.
txt_file = io.BytesIO(text.encode("utf-8"))

response = client.context.ingest(
    type="knowledge",
    database="acme_corp",
    collection="team_docs",
    documents=[("meeting-notes.txt", txt_file, "text/plain")],
    document_metadata=json.dumps([
        {"id": "meeting_notes_q4", "metadata": {"department": "product"}}
    ]),
)
```

import io
import json
import requests

- Legal review is due by Friday.

# Create a file-like object in memory. No local .txt file is required.

        "Authorization": "Bearer <your_api_key>",

        "collection": "team_docs",
        "document_metadata": json.dumps([
            {"id": "meeting_notes_q4", "metadata": {"department": "product"}}
        ]),
    },
    files={
        "documents": ("meeting-notes.txt", txt_file, "text/plain"),
    },
)
response.raise_for_status()

## Notes

- **Multipart form:** the fields on this page are `multipart/form-data` fields, so send the request as a form. Stringify every JSON field (`document_metadata`, `app_knowledge`, `memories`, `graph_payload`) before you put it in the form. An unsupported content type returns `415`.
- **Declare hot schema fields up front:** put fields you filter on often in `metadata`, and declare them in `database_metadata_schema` with `enable_match: true` when you [create the database](/api-reference/v2/endpoint/create-tenant). Use `additional_metadata` for free-form display or bookkeeping fields. You can add schema fields later, but newly added dense or sparse metadata lanes are not backfilled into existing Milvus collections.
- **Memory vs. knowledge:** use `type: "memory"` to ingest, list, and delete memories. Use `type: "all"` on `POST /query` to search both.
- **Default collection:** omitting `collection` writes to the default collection. List collections with [List Collections](/api-reference/v2/endpoint/list-sub-tenants).

## Errors

Common codes: `400` (invalid field, an `id` with a comma, an unknown `document_metadata` key, a `document_metadata` count that does not match `documents`, metadata over its size limit, a graph over its caps), `413` (a file over 50 MB), `415` (unsupported content type), `422` (validation error). See [Error Responses](/api-reference/v2/error-responses) for the full list.
