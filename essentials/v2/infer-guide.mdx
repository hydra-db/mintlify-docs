## The decision

```
Do you have raw, unstructured signal?
(conversation logs, UI events, feedback, dialogue)
        │
       YES → infer: true  → HydraDB extracts the underlying preference
        │
        NO
        │
Do you already have a structured fact?
("User is on Pro plan", "prefers bullet points")
        │
       YES → infer: false → HydraDB stores exactly what you send
```

**Rule of thumb:** Raw signal → `infer: true`. Structured fact → `infer: false`.

---

## Side-by-side: same user, same topic, both flags

The user prefers concise answers. You can tell HydraDB about this two ways.

<CodeGroup>
```python infer: true (raw signal)
import json

client.context.ingest(
    type="memory",
    database="acme_corp",
    collection="user_alice",
    memories=json.dumps([
        {
            "user_assistant_pairs": [
                {"user": "Can you make that shorter?", "assistant": "Sure..."},
                {"user": "Perfect, I like it that way.", "assistant": "Noted."},
            ],
            "infer": True,
            "custom_instructions": "Focus on communication style preferences.",
            "user_name": "Alice",
        }
    ]),
)
# HydraDB infers: "User prefers concise, direct answers."
```
```python infer: false (structured fact)
import json

client.context.ingest(
    type="memory",
    database="acme_corp",
    collection="user_alice",
    memories=json.dumps([
        {
            "id": "alice_style_pref",
            "text": "User prefers concise, direct answers with no preamble.",
            "infer": False,
        }
    ]),
)
# HydraDB stores exactly: "User prefers concise, direct answers with no preamble."
```
</CodeGroup>

**What's different:**

- `infer: true` — you send the raw evidence. HydraDB derives the structured memory. The phrasing may differ from your input.
- `infer: false` — you send the finished memory. HydraDB stores it verbatim. Fast, deterministic, no extraction step.

---

## When each flag is right

### Use `infer: true` when the input is raw signal

- Dialogue where the preference is implied
- Behavior logs and event streams
- Feedback ("the last summary was too long")
- Any input where the useful memory needs to be derived

`custom_instructions` guides extraction and only takes effect with `infer: true`. Use it to narrow the focus: `"Focus on UI and notification preferences only"`.

### Use `infer: false` when the input is already the memory

- Facts you've already captured: `"User's plan tier is Pro"`
- Pre-structured notes from your own system
- Content you want to retrieve exactly as written

---

## Common mistakes

| Mistake | What goes wrong | Fix |
|---|---|---|
| `infer: true` for already-structured facts | HydraDB may re-derive and change the phrasing | Use `infer: false` for facts you've already extracted |
| `infer: false` for raw conversation logs | Dialogue is stored verbatim as noise, not insight | Use `infer: true` for raw signal |
| `custom_instructions` with `infer: false` | Instructions are silently ignored | Only works with `infer: true` |
