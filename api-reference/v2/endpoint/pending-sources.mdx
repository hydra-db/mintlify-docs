Ingestion is asynchronous, so a query issued while content is still being indexed can return fewer results than expected with no other signal. This endpoint lists every source in a database/collection that has **not** reached the terminal `completed` state yet — i.e. it is still `queued` / `processing` / `graph_creation`, or `errored`.

Reach for it when a `/query` returns fewer results than you expect: the `pending_source_ids` tell you exactly what is still in flight (or failed). Query responses also carry a `meta.note` pointing here whenever they might be incomplete.

<Info>
  **Scope is the database/collection pair.** Results are the pending sources for the resolved `database` + `collection`. If `collection` is omitted, the default collection is used — the same scoping as [`GET /context/status`](/api-reference/v2/endpoint/source-status). To confirm the exact state (and `error_code`) of a specific ID, pass it to [`GET /context/status`](/api-reference/v2/endpoint/source-status).
</Info>

<RequestExample>

```python Python SDK
pending = client.context.pending(

    collection="team_docs",

```

curl -G 'https://api.hydradb.com/context/status/pending' \
  -H "Authorization: Bearer <your_api_key>" \

  --data-urlencode "collection=team_docs"

## Query parameters

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Database to inspect. Formerly `tenant_id`; the `tenant_id` alias is still accepted (deprecated). |
| <Field name="collection" type="string or null" /> | Collection scope. If omitted, the default collection is used. Formerly `sub_tenant_id`; the `sub_tenant_id` alias is still accepted (deprecated). (default=`null`) |

## Behavior notes

- **"Pending" means not `completed`.** A source appears here until it is fully indexed. Sources that terminally `errored` also appear (they never reach `completed`) — use [`GET /context/status`](/api-reference/v2/endpoint/source-status) with the ID to see the `error_code`.
- **Empty is the healthy steady state.** An empty `pending_source_ids` means every source in the scope has finished indexing.
- **Prefer webhooks for automation.** For event-driven flows, register a webhook for `indexing.status_changed` instead of polling. See [Webhooks](/essentials/v2/webhooks).

## Errors

Common codes: `422 VALIDATION_ERROR` (missing `database`), `404 DATABASE_NOT_FOUND`, `500 INTERNAL_ERROR`. See [Error Responses](/api-reference/v2/error-responses) for the full list.
