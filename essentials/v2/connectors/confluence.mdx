Sync pages, blog posts and their attached files from the Confluence Cloud spaces you select. Each page or blog post is one document, holding its text with the markup removed. Each attached file is its own document, linked to its page. Text from supported attachments is searchable when HydraDB can download and read the files. A page links to its parent page.

Space permissions and page view restrictions, including those inherited from parent pages, restrict search when Enforce ACL is on. An attached file follows only its space's permissions until its page has synced, so at first it can have a wider audience than its restricted page. Comments are not synced. Pages and files deleted in Confluence stay in HydraDB.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow Confluence permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** Two levels apply. A space's view permissions decide who can read its pages, and a space open to all licensed users can be read by everyone who can query the collection. A page's own view restriction, and the restrictions of its restricted parent pages, narrow that further: a reader must meet every one of them. An attached file follows its page.
- **How a person is identified:** A user's email address. Confluence groups are turned into their members' email addresses. This works only when the site shows user email addresses.
- **When permissions cannot be read:** If HydraDB cannot read a space's permissions, or cannot resolve a page's restrictions, the connector reports a permission warning. A page restricted to a user whose email the site hides cannot be resolved. On HydraDB Cloud, with Enforce ACL on, such an item follows the access rule you set on its resource. With no rule, it is hidden from search. Self-hosted deployments can be configured differently. Permission warnings appear in [Get Connector Status](/api-reference/v2/endpoint/get-connector-status).
- Reading a space's permissions needs the Space admin permission on that space.
- A page whose restriction levels resolve to nobody, or have no reader in common, is hidden.
- A file attached to a restricted page follows the space's permissions until its page has synced.
- Space admins' access through their admin role is not recorded.
- A restriction change that does not edit the page is checked on later syncs, not the first one. A restriction removed from a page can wait until the page is next edited.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

Confluence uses an Atlassian account email and an Atlassian API token. The token carries that user's own space permissions.

<ResponseField name="base_url" type="string" required>
Your Confluence Cloud address, for example `https://your-domain.atlassian.net/wiki`.
</ResponseField>

<ResponseField name="email" type="string" required>
The Atlassian account email used to sign in.
</ResponseField>

<ResponseField name="api_token" type="secret string" required>
An Atlassian API token for that account.
</ResponseField>

**What the Atlassian account needs**

- `View space`: required. Lists spaces and their pages.
- `View pages`: required. Reads page and blog post text.
- `Space admin`: optional, for search that follows Confluence permissions. Reads each space's permission list.
- `Browse users and groups`: optional, for search that follows Confluence permissions. Turns groups into their members' emails and users into emails.

For search that follows Confluence permissions, the site must also show user email addresses. Turn this on in admin.atlassian.com, under Settings, User email visibility.

### Set it up

<Steps>
  <Step title="Choose the account">
    Use an Atlassian account that can view every space you want synced. For search that follows Confluence permissions, give it Space admin on each of those spaces, and make the site show user email addresses.
  </Step>
  <Step title="Create an API token">
    Create an Atlassian API token for that account.
  </Step>
  <Step title="Create the connector">
    Enter `base_url`, `email` and `api_token`.
  </Step>
  <Step title="Select spaces">
    HydraDB lists the site's spaces. Select the spaces to sync. Each selected space syncs on its own.
  </Step>
</Steps>

One connector reads one Confluence Cloud site, as one Atlassian user.

<Accordion title="Connect through the API">

Use provider `confluence` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected space reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the pages, blog posts and files modified since the last sync, space by space. A newly uploaded file is picked up on its own, without a page edit.
- **Edits:** An edited page has a new version, so the next sync reads it again and updates its document.
- **Deletions:** Deleted pages and files are not removed. They stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

### On every Confluence item

<ResponseField name="additional_metadata.container_id" type="Query filter">

<ResponseField name="additional_metadata.container_name" type="Query filter">
The space display name. Limits a query to one space by name. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
Always `space`. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">

</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `confluence`. Not searchable.
</ResponseField>

<ResponseField name="Space and page restrictions" type="Access rule">
The space's view permissions and the page's restrictions, including inherited ones. A file uses its page's. Together they decide who can read the item when Enforce ACL is on. Not searchable.

### Pages and blog posts

- **One document:** One page or one blog post.
- **Title:** The page or blog post title. One with no title is titled `Confluence content` and its id.
- **Text:** The page body with all markup removed. If that leaves nothing, the title is used. The title, author and last-updated time are searchable too. Attached files are separate documents.
- **Date:** The time of the page's current version.
- **Link back:** Opens the page in Confluence.

<ResponseField name="created_by" type="Searchable text, Graph identity">
The creator's display name, or email if there is no name, written as the `Author` line. The graph records the page as written by that person.
</ResponseField>

<ResponseField name="created_by_email" type="Graph identity">
The creator's email, when Confluence shows it. Gives the author an email in the graph, so the same person is recognised across tools. Not searchable.
</ResponseField>

<ResponseField name="mentions" type="Graph identity">
People @mentioned in the page, as Confluence usernames or user keys, not display names. The graph records each as mentioned. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (5)">

<ResponseField name="content_type" type="Stored only">
`page` or `blogpost`.
</ResponseField>

<ResponseField name="status" type="Stored only">
The Confluence status, for example `current`.
</ResponseField>

<ResponseField name="created_at" type="Stored only">
When the page was created.
</ResponseField>

<ResponseField name="updated_by" type="Stored only">
The name or email of whoever made the current version. Not attached to the page as a person in the graph.
</ResponseField>

<ResponseField name="updated_by_email" type="Stored only">
That editor's email, when Confluence shows it.
</ResponseField>

</Accordion>

### Attached files

- **One document:** One file attached to a page or blog post.
- **Title:** The file name. A file with no name is titled `Confluence attachment` and its id.
- **Text:** The text read from the file. If no text can be read, the file name is still searchable. The last-modified time is searchable too.
- **Date:** When the file was last modified.
- **Link back:** Opens the file in Confluence.
- **Files:** Each file is downloaded with the connector's credentials. Text from supported attachments is searchable when HydraDB can download and read the files. Only files attached to pages or blog posts are kept. Space logos and template images are left out.

<ResponseField name="additional_metadata.confluence_page_id" type="Query filter">
The id of the page the file is attached to. Finds every file on one page. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.confluence_attachment_id" type="Query filter">
The attachment id. Picks out one file. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.confluence_file_id" type="Query filter">
The file id, which stays the same across the file's versions. Matches a file across versions. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.confluence_media_type" type="Query filter">
The file's type, for example `application/pdf`. Limits a query to one file type. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="content_type" type="Stored only">
The file's type.
</ResponseField>

<ResponseField name="created_at" type="Stored only">
When the file was uploaded.
</ResponseField>

<ResponseField name="file_size" type="Stored only">
The size in bytes.
</ResponseField>

</Accordion>

**Example searches**

- What does the ENG space say about our deploy process?
- Who wrote the incident postmortem page for the March outage?
- What is in the PDFs attached to the Security Policy page?

## How it fits into the graph

- Pages and blog posts use the Page class.
- Attached files use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Confluence creates**

- A page to its parent page.
- An attached file to its page or blog post.
- No links to items in other tools. A link to another page written in the page text does not become a connection.

**People and groups**

- The creator of each page and blog post.
- People @mentioned in a page, by Confluence username or user key.
- The editor of the current version is kept with the page but not attached as a person.

**Found in the text**

The page text and the text read from attached files. A file is read together with its page's title and text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Page comments and inline comments.
- Space logos and template images.
- Spaces the Atlassian account cannot view.
- Deletions: deleted pages and files stay in HydraDB.
