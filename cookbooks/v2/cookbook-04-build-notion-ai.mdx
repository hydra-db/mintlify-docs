Build an internal knowledge agent that ingests Notion, Confluence, and Slack into HydraDB and answers "why did we decide X?" with the decision context, not only the matching document.

## Prerequisites

- Base URL: `https://api.hydradb.com`
- A HydraDB API key from [app.hydradb.com](https://app.hydradb.com)
- Python 3.11 or 3.12 (`python --version`)
- `pip install hydradb-sdk`
- Python basics, REST APIs, environment variables

Install and export only the connectors you wire up; a missing variable fails at once.

| Source | Install | Environment |
| --- | --- | --- |
| Notion | `pip install notion-client` | `NOTION_TOKEN` |
| Confluence | `pip install atlassian-python-api beautifulsoup4` | `CONFLUENCE_URL`, `CONFLUENCE_USER`, `CONFLUENCE_TOKEN` |
| Slack | `pip install slack_sdk slack_bolt` | `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN` |

## How HydraDB works

Notion's built-in AI returns the document you asked about and stops. It can't tell you **why** a decision was made, who influenced it, or whether something newer replaced it. HydraDB parses, enriches, and links every memory into a **context graph**, so `POST /query` returns the context that fits the query, weighted by recency, relevance, relationships, and past usage.

You use three primitives:

- **Database:** your workspace. Data is isolated per database, and it supports multiple tenants. Create one per application.
- **Memory:** any unit of context, such as a Notion page, a Confluence doc, a Slack thread, or a user preference. HydraDB chunks, embeds, and links memories into the context graph, so you don't manage embeddings or vector indexes.
- **Search:** the call your agent makes before it acts. It runs metadata filtering, then graph traversal, then semantic retrieval, then personalized ranking.

## Step 1: Create a database

**Endpoint:** `POST /databases`

### Bash

```bash
curl -X POST 'https://api.hydradb.com/databases' \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"database": "notion-ai-workspace"}'
```

### Python

```python
import os, time, uuid
from hydra_db import HydraDB

API_KEY   = os.environ["HYDRA_DB_API_KEY"]
DATABASE_ID = "notion-ai-workspace"

client = HydraDB(token=API_KEY)

# Create database. Returns 409 if it already exists.
resp = client.databases.create(database=DATABASE_ID)
print("Database:", resp)
```

> **Collections for teams:** use `collection` to give Engineering, Sales, and HR their own namespace in your database. There is nothing to configure; pass the ID on upload.

## Step 2: Upload knowledge

### Notion connector

Format each Notion page as an app source and upload in batches. HydraDB creates the graph edges.

> **Batch limit:** max **20 sources per request**, with **1 second between batches** to respect rate limits.

```python
import json, time
from notion_client import Client

notion = Client(auth=os.environ["NOTION_TOKEN"])

def extract_text(page_id: str) -> str:
    """Extract plain text from all rich_text blocks on a page."""
    blocks = notion.blocks.children.list(block_id=page_id)["results"]
    lines  = []
    for b in blocks:
        rt   = b.get(b["type"], {}).get("rich_text", [])
        text = "".join(r["plain_text"] for r in rt)
        if text:
            lines.append(text)
    return "\n\n".join(lines)


def upload_batch(sources: list, collection: str = None) -> list:
    """Upload up to 20 sources. Returns list of IDs."""
    if collection:
        for s in sources:
            s["collection"] = collection
    result = client.context.ingest(
        database=DATABASE_ID,
        app_knowledge=json.dumps(sources),
    )
    return [r.id for r in (result.data.results or []) if r.id]


def ingest_notion_database(database_id: str, collection: str = None) -> list:
    pages   = notion.databases.query(database_id=database_id)["results"]
    batch   = []
    all_ids = []

    for page in pages:
        props      = page["properties"]
        title_prop = props.get("Name", props.get("Title", {}))
        title_arr  = title_prop.get("title", [])
        title      = title_arr[0]["plain_text"] if title_arr else "Untitled"
        text       = extract_text(page["id"])
        author     = page["created_by"]["id"]

        batch.append({
            "id":        page["id"],
            "title":     title,
            "type":      "notion_page",                    # required
            "timestamp": page["last_edited_time"],         # required ISO
            "content":   {"text": text},
            "url":       f"https://notion.so/{page['id'].replace('-','')}",
            "metadata": {
                "author": author,
                "tags":   ["notion", "knowledge"],
            },
        })

        if len(batch) == 20:
            all_ids += upload_batch(batch, collection)
            batch = []
            time.sleep(1)  # required 1-second interval between batches

    if batch:
        all_ids += upload_batch(batch, collection)
    return all_ids
```

### Confluence connector

Confluence pages use the same format, with `type: "confluence"`.

```python
from atlassian import Confluence
from bs4 import BeautifulSoup

conf = Confluence(
    url=os.environ["CONFLUENCE_URL"],
    username=os.environ["CONFLUENCE_USER"],
    password=os.environ["CONFLUENCE_TOKEN"],
    cloud=True,
)

def ingest_space(space_key: str, collection: str = None) -> list:
    pages   = conf.get_all_pages_from_space(
        space_key, expand="body.storage,history,version"
    )
    batch   = []
    all_ids = []

    for page in pages:
        html = page["body"]["storage"]["value"]
        text = BeautifulSoup(html, "html.parser").get_text("\n\n")

        batch.append({
            "id":        page["id"],
            "title":     page["title"],
            "type":      "confluence",                    # required
            "timestamp": page["version"]["when"],         # required ISO
            "content":   {"text": text},
            "metadata": {
                "author": page["history"]["createdBy"]["accountId"],
                "tags":   ["confluence", space_key.lower()],
            },
        })

        if len(batch) == 20:
            all_ids += upload_batch(batch, collection)
            batch = []
            time.sleep(1)

    if batch:
        all_ids += upload_batch(batch, collection)
    return all_ids
```

### Verify indexing

Wait for indexing before you query. A source is searchable from `graph_creation`; the code waits for `completed` and stops on `errored`.

**Endpoint:** `GET /context/status?ids=ID&database=DATABASE`

```python
def poll_until_indexed(id: str, timeout: int = 120, interval: int = 3):
    """Poll until indexed, errored, or timeout."""
    deadline = time.time() + timeout
    while time.time() < deadline:
        result = client.context.status(
            database=DATABASE_ID,
            ids=id,
        )
        items  = result.data.statuses or []
        status = items[0].indexing_status if items else None
        if status == "completed":
            return True
        if status == "errored":
            raise RuntimeError(f"Indexing failed for {id}")
        time.sleep(interval)
    raise TimeoutError(f"Indexing timed out for {id}")

def verify_all(ids: list):
    for fid in ids:
        poll_until_indexed(fid)
```

## Step 3: Add user memories

**User memories** store preferences, habits, and patterns that personalize search per user.

- `infer: true`: HydraDB extracts implicit signals from the text.
- `infer: false`: HydraDB stores the fact as written.

**Endpoint:** `POST /context/ingest`

### Bash

```bash
curl -X POST 'https://api.hydradb.com/context/ingest' \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "memories": [{
      "text": "Alice prefers concise bullet-point answers and always wants source links",
      "user_name": "alice",
      "infer": true
    }],
    "database": "notion-ai-workspace",
    "collection": "user-alice",
    "upsert": true
  }'
```

### Python

```python
def add_user_memory(
    user_name: str,
    preference: str,
    collection: str = None,
    infer: bool = True,
) -> dict:
    """
    Store a user memory/preference in HydraDB.
    Uses the SDK-spec body format with the memories[] array wrapper.
    """
    payload = {
        "memories": [{
            "text":      preference,
            "user_name": user_name,
            "infer":     infer,
        }],
        "database": DATABASE_ID,
        "upsert":    True,
    }
    if collection:
        payload["collection"] = collection

    return client.context.ingest(
    type='memory',**payload)


# Example usage
add_user_memory(
    user_name="alice",
    preference="Alice prefers concise bullet-point answers and always wants source links",
    collection="user-alice",
    infer=True,
)
```

To use these memories, query the user's collection with `type: "memory"` (see [More calls](#more-calls)) and pass the results to your LLM with the knowledge context. A knowledge query on another collection does not read them.

## Step 4: Search context

Before it answers, your agent calls `POST /query`, which returns ranked chunks plus `graph_context` showing how entities relate.

**Endpoint:** `POST /query`

```python
def recall_context(
    query: str,
    collection: str     = None,
    max_results: int    = 10,
    alpha: float        = 0.8,    # FIX: single definition, no duplicate
    recency_bias: float = 0.3,
    graph_context: bool = True,
) -> dict:
    """
    Full search - searches knowledge base (documents).
    To also retrieve user memories, call /query separately.
    collection: scope to a specific workspace or user namespace.
    mode: "thinking" enables personalised ranking.
    graph_context: true enables cross-document entity linking.
    """
    payload = {
        "database":     DATABASE_ID,
        "query":         query,
        "max_results":   max_results,
        "mode":          "thinking",
        "graph_context": graph_context,
        "alpha":         alpha,       # FIX: single key only
        "recency_bias":  recency_bias,
    }
    if collection:
        payload["collection"] = collection

    return client.query(**payload)
    # Response shape:
    # data["chunks"]        - ranked context chunks with relevancy_score
    # data["graph_context"] - entity paths and chunk_relations


# Example
context = recall_context(
    "Why did we migrate from MySQL to Postgres?",
    collection="workspace",
)
for chunk in (context.data.chunks or []):
    print(f"[{chunk.relevancy_score or 0:.2f}] {chunk.source_title or ''}")
    print((chunk.chunk_content or "")[:200])
```

## Step 5: Search and generate an answer

Pass the returned `chunks` and `sources` into your LLM prompt.

- `alpha`: 0 to 1, semantic against keyword (BM25) retrieval; higher leans semantic. This step uses `0.5` for an even blend; Step 4 uses `0.8`.
- `recency_bias`: 0 to 1; higher prefers newer content. Omitting it applies a mild `0.4` tilt; send `0` to turn it off.
- `graph_context`: returns entity paths across documents. Default `true`.
- `metadata_filters`: exact-match filters on declared metadata fields. The `source_type` filter works only if you declare that field in the database metadata schema and set it in each item's `metadata` at upload.

**Endpoint:** `POST /query`

```python
def ask_workspace(
    question: str,
    collection: str     = None,
    source_filter: str  = None,
    alpha: float        = 0.5,
    recency_bias: float = 0.3,
    max_results: int    = 10,
) -> dict:
    """
    Retrieve workspace context for a question.
    Returns chunks, sources, and graph_context. Generate the final answer in your app layer.
    """
    payload = {
        "database":     DATABASE_ID,
        "query":         question,
        "max_results":   max_results,
        "graph_context": True,
        "mode":          "thinking",
        "alpha":         alpha,
        "recency_bias":  recency_bias,
    }
    if collection:
        payload["collection"] = collection
    if source_filter:
        payload["metadata_filters"] = {"source_type": source_filter}

    return client.query(**payload)


def build_context(result) -> str:
    return "\n\n".join(
        chunk.chunk_content or ""
        for chunk in (result.data.chunks or [])
    )


# Usage examples
result = ask_workspace("Why did we choose Postgres over MySQL?")
print(build_context(result)[:1000])

# Follow-up questions call search again and your app includes any prior chat turns in the LLM prompt.
result2 = ask_workspace("What were the tradeoffs they considered?")
print(build_context(result2)[:1000])

# Filter to only Notion pages
notion_result = ask_workspace(
    "What's in our engineering RFC library?",
    source_filter="notion_page",
)
```

> **Maintaining conversation context:** HydraDB returns retrieval context; your app owns the final answer and conversation state. Store chat history in your app and include relevant prior turns in the LLM prompt.

## Step 6: Slack interface

When a user mentions `@wiki`, the bot calls `ask_workspace()` for context, which your app can pass to an LLM to write the reply.

```python
from slack_bolt import App

app = App(token=os.environ["SLACK_BOT_TOKEN"])

# Persist session IDs so conversation memory works across turns
user_sessions: dict = {}

def get_session(user_id: str) -> str:
    """Return or create a persistent session ID for this Slack user."""
    return user_sessions.setdefault(user_id, str(uuid.uuid4()))

@app.event("app_mention")
def handle_mention(event, client):
    slack_user = event["user"]
    question   = event["text"].split(">", 1)[-1].strip()

    # Acknowledge immediately so Slack doesn't time out
    msg = client.chat_postMessage(
        channel=event["channel"],
        thread_ts=event["ts"],
        text="_Searching your workspace..._",
    )

    session_id = get_session(slack_user)
    result     = ask_workspace(question)

    chunks = result.data.chunks or []
    answer = "\n\n".join(c.chunk_content or "" for c in chunks[:3]) or "No results found."
    sources = result.data.sources or []

    if sources:
        links  = "\n".join(f"• {s.title or ''}" for s in sources[:3])
        answer += f"\n\n*Sources:*\n{links}"

    client.chat_update(
        channel=event["channel"],
        ts=msg["ts"],
        text=answer,
    )

if __name__ == "__main__":
    from slack_bolt.adapter.socket_mode import SocketModeHandler
    SocketModeHandler(app, os.environ["SLACK_APP_TOKEN"]).start()
```

## More calls

The steps above do not use these calls. Base URL: `https://api.hydradb.com`. Header: `Authorization: Bearer YOUR_API_KEY`.

### Upload a single file (PDF or DOCX)

`POST /context/ingest` with `database` as a form field.

```bash
curl -X POST 'https://api.hydradb.com/context/ingest' \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "documents=@/path/to/document.pdf" \
  -F "database=notion-ai-workspace"
```

### Search user memories

`POST /query` with `type: "memory"`, scoped to the user's collection.

```json
{
  "database":     "notion-ai-workspace",
  "collection": "user-alice",
  "type":          "memory",
  "query":         "How should I format answers for this user?"
}
```

### Delete a memory

`DELETE /context` removes stale or incorrect memories. Send `type: "memory"`, the `ids` to delete, and the `collection` they live in; omitting `collection` targets the default collection.

## Benchmarks

HydraDB scores 90% search accuracy on LongMemEvals and runs at petabyte scale with sub-second latency. Against naive RAG over the same 12,400-document corpus (naive RAG first, then HydraDB):

- **Factual lookup queries:** 81% vs 90% search accuracy (+11%).
- **"Why did we..." decision queries:** 34% vs 79% search accuracy (+132%).
- **Stale doc surface rate:** 41% vs 7% of results (83% lower).
- **P95 query latency:** 220 ms vs under 200 ms (sub-second).

> **Benchmark methodology:** figures come from internal HydraDB testing; see the [formal benchmark paper](https://research.hydradb.com/hydradb.pdf). Results vary by corpus size, content quality, and query distribution.
