## What syncs

**Indexed object types**

- `feature_flags`
- `audit_log`
- `segments`
- `environments`
- `members`
- `teams`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Create the token in LaunchDarkly under Account settings → Authorization → Access tokens → Create token. LaunchDarkly has no scope checkboxes: a token carries a ROLE, and the role is the whole decision.
2. Set Role to Reader, which is the default. Reader is all this connector needs; verified against the API, every endpoint it calls answers 200 with a read-only token. Writer or Admin add only write access, so they buy you nothing and let a leaked token turn your flags on and off.
3. Tick "This is a service token". A personal token inherits the role of whoever minted it and stops working the moment that person is deactivated, which is the most common way this connection breaks. The token is shown once; copy it before closing the dialog.
4. After connecting, pick the projects to sync. Everything project-scoped follows that choice: the project's flags, its environments, and its segments.
5. Some data is account-wide and is always synced, whatever you pick: the audit log, account members and teams. Members and teams are what let a flag's maintainer resolve to a person or a group rather than a raw id.
6. Flags are indexed with their real targeting, per environment; on/off state, the default variation or percentage rollout, individual targets, prerequisite flags and each rule, including which segment a rule matches. Segments are indexed alongside, so "who is this flag on for" is answerable end to end.
7. Two things are never indexed. An environment's SDK key and mobile key are dropped before indexing, because they are live credentials for your own environment. So are a member's MFA state and whether they have a password.
8. A brand-new LaunchDarkly organization has one empty default project and no flags, so a correctly configured connector on a new org indexes almost nothing. That is the org being empty, not the token being wrong.
9. With permission-aware search on, each project is restricted to the members who can view it in LaunchDarkly: their base role, custom roles (preset roles included), team roles and permission grants are evaluated the way LaunchDarkly does. Flags, segments and environments follow their project, and so does each audit log entry about one project; members, teams and account-level audit entries are not restricted. Invited members who have not joined yet are not included. The token's role must read projects, members, teams and custom roles (the built-in Reader can). A role this evaluation cannot read exactly makes every project readable by everyone in your workspace, with a warning on the connector naming it.

Use provider `launchdarkly` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
