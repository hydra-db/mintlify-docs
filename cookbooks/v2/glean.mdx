Company search answers a question from everything the company has written, and shows each person only what they are allowed to see. This cookbook builds it with three ideas: one collection for all company context, an ACL on each source, and the asker's identity on every query.

| Benchmark | Result | What it shows here |
| --- | --- | --- |
| [EnterpriseRAG-Bench](https://benchmarks.hydradb.com/enterprise-rag-bench) | 88.7 overall, 96.7% document recall@10 | Retrieval across fragmented systems where knowledge is duplicated or outdated |
| [KyroBench](https://benchmarks.hydradb.com/kyrobench) | 0.776 nDCG | The current source ranked above the stale one |

## 1. Create one database and one collection

Put everything in one collection so a single query searches all of it. Separate collections are for context that must never meet in one query; permissions are handled by ACLs, not by splitting collections. See [Databases and Collections](/essentials/v2/databases-and-collections).

```python glean.py
import json

from hydra import answer, client, create_database, source_ids, wait_indexed

DATABASE, COLLECTION = "acme_corp", "company"

create_database(DATABASE)
```

## 2. Ingest sources from each app

Send records your code already holds as text items. `text` carries the record's content, `happened_at` its date, and `acl` lists who may see it. The samples include an outdated wiki page and the Slack message that replaced it, and a ticket only the finance lead can see.

```python glean.py
sources = [
    {
        "context_id": "notion_pricing_2025",
        "title": "Pricing (2025)",
        "text": "Pro is $79 per seat per month. Enterprise is $199.",
        "happened_at": "2025-03-01",
        "acl": ["domain:acme.com"],
    },
    {
        "context_id": "slack_C01_1788000000_000100",
        "title": "Pricing change - Slack #product",
        "text": "alice@acme.com: Decision: from October 1, 2026, Pro moves from $79 to $89 per seat.",
        "happened_at": "2026-09-01",
        "acl": ["domain:acme.com"],
    },
    {
        "context_id": "jira_FIN_42",
        "title": "FIN-42: Enterprise discount floor",
        "text": "Do not discount Enterprise below $150 per seat without CFO approval. "
        "Status: open. Assignee: grace@acme.com.",
        "happened_at": "2026-09-03",
        "acl": ["grace@acme.com"],
    },
]

result = client.context.ingest(
    database=DATABASE,
    collection=COLLECTION,
    context=json.dumps(sources),
)
wait_indexed(DATABASE, COLLECTION, source_ids(result))
```

## 3. Query as the person asking

Send the signed-in user's identity as `acl`. Take it from your session on the server, never from the client: a query without `acl` returns everything in scope. The other settings are the ones the EnterpriseRAG-Bench run used: hybrid matching, `thinking` mode, and 12 results.

```python glean.py
def search(question, user_email):
    return client.query(
        database=DATABASE,
        collection=COLLECTION,
        query=question,
        query_by="hybrid",
        mode="thinking",
        max_results=12,
        acl=[user_email],
    )
```

## 4. Answer with citations

Each chunk in the query result carries the ID of the source it came from, and [`POST /context/list`](/api-reference/v2/endpoint/list-context) returns its title. Print each source once under the answer.

```python glean.py
def ask(question, user_email):
    result = search(question, user_email)
    print(answer(question, result, "Prefer the most recent source when sources disagree."))
    cited = list(dict.fromkeys(chunk.context_id for chunk in result.data.chunks))
    if not cited:
        return
    listed = client.context.list(database=DATABASE, collection=COLLECTION, ids=cited).data
    for source in listed.sources:
        print(f"  - {source.title} ({source.id})")


ask("What does Pro cost per seat?", "bob@acme.com")
ask("How far can we discount Enterprise?", "bob@acme.com")
ask("How far can we discount Enterprise?", "grace@acme.com")
```

## Run it

```bash
python glean.py
```

The first answer should give $89 and cite the Slack decision alongside the older page. The second should say it does not know, because the ticket is restricted to Grace. The third should give the $150 floor and cite FIN-42.

## Use real data

Replace step 2 with [connectors](/essentials/v2/connectors): HydraDB then syncs each app on a schedule and copies its permissions into each source's ACL. Create one connector per app, all pointing at the same collection.

```python connect.py
from hydra import connect

connector_id = connect(
    provider="slack",
    account="T12345ACME",
    database="acme_corp",
    collection="company",
    credentials={"access_token": "xoxp-..."},
)
```

Keep sending `acl` on every query, and leave [`enforce_acl`](/essentials/v2/connectors#enforce-acl) off for this application. With `enforce_acl` on, HydraDB ignores the request's `acl` and uses the identity of whoever created the API key, so every user of your application would see what the key's creator can see. Enforcement fits a caller who authenticates as themselves, such as a user signed in through MCP OAuth.

## Common mistakes

- **Turning on `enforce_acl` behind one API key:** every query then runs with the key creator's permissions, not the asker's.
- **Querying without `acl`:** the query returns restricted sources to everyone. Send the user's identity on every query.
- **One collection per app or team:** a query that names one collection does not read the others. Keep one collection and narrow with [metadata filters](/essentials/v2/metadata).
- **Group permissions:** an email matches its `domain:` principal automatically, but not groups. Send `group:` principals yourself. See [Query](/essentials/v2/query#6-query-on-behalf-of-a-user).
