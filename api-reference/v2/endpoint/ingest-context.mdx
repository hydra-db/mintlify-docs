Ingest context into a database in one multipart request. Ingestion is asynchronous: the response returns an ID for each source, and a source is searchable once indexing completes. Choose the payload by what you are storing:

| Payload | Send | Use for |
| --- | --- | --- |
| Documents | `type: "knowledge"` and `documents` | Binary uploads that HydraDB should parse: PDFs, Office and iWork files, spreadsheets, images, and plain text. See [Supported file formats](#supported-file-formats). |
| Memories | `type: "memory"` and `memories` | Preferences, decisions, inferred behavior traits, and past conversations your agent should remember in future sessions. See [Context](/essentials/v2/context#2-save-memories). |

<RequestExample>

```python Python SDK
import json

with open("policy.pdf", "rb") as policy:
    result = client.context.ingest(
        database="acme_corp",
        collection="company_docs",
        type="knowledge",
        documents=[("policy.pdf", policy, "application/pdf")],
        document_metadata=json.dumps([{"id": "policy_main"}]),
    )
```

```typescript TypeScript SDK
const result = await client.context.ingest({
  database: "acme_corp",
  collection: "company_docs",
  type: "knowledge",
  documents: [{ path: "policy.pdf", filename: "policy.pdf", contentType: "application/pdf" }],
  documentMetadata: JSON.stringify([{ id: "policy_main" }]),
});
```

```bash cURL
curl -X POST 'https://api.hydradb.com/context/ingest' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "API-Version: 2" \
  -F "database=acme_corp" \
  -F "collection=company_docs" \
  -F "type=knowledge" \
  -F "documents=@policy.pdf" \
  -F 'document_metadata=[{"id":"policy_main"}]'
```

</RequestExample>

## Form fields

| Name | Description |
| --- | --- |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22;" /> | Use singular `"memory"` when ingesting memories. (default=`"knowledge"`) |
| <Field name="database" type="string" required /> | Target database. |
| <Field name="collection" type="string" /> | Collection to write to. A new name creates the collection automatically. Omit it to use the default collection. List existing collections with [List Collections](/api-reference/v2/endpoint/list-collections). |
| <Field name="upsert" type="boolean" /> | Replace existing sources with the same ID. Set to `false` to error on conflict: a document whose ID exists comes back `failed` with `error_code: "E9003"`. (default=`true`) |
| <Field name="documents" type="file[]" /> | Binary uploads, **knowledge only**. Required when `type=knowledge` and you want HydraDB to parse documents. Omit when ingesting memories. See [Supported file formats](#supported-file-formats). (default=`[]`) |
| <Field name="document_metadata" type="string (JSON array)" /> | One entry per file in `documents`, in the same order. The counts must match, or the request returns `400`. If omitted, documents index with inferred defaults such as filename/title. See [item fields](#examples-and-item-fields). |
| <Field name="graph_payload" type="string (JSON map)" /> | Map of source ID to your own entities and relations. Replaces LLM graph extraction for each keyed source. Works for `type=knowledge` and `type=memory`. See the "Bring your own graph" example in [item fields](#examples-and-item-fields) and the [Bring Your Own Graph](/essentials/v2/bring-your-own-graph#using-byog-without-cypher) guide. |
| <Field name="memories" type="string (JSON array)" /> | Memory items, **memory only**. Required and non-empty when `type=memory`. The form field is plural `memories`, even though `type` is singular `memory`. See [item fields](#examples-and-item-fields). |

- **Multipart, not JSON:** This endpoint uses `multipart/form-data`. Stringify all JSON arrays (`document_metadata`, `memories`) before placing them in the form field. A body that is neither a form nor JSON returns `415`.
- **`202 Accepted` means queued, not indexed:** A successful response only confirms your sources were accepted, not that they are ready to query. Before querying, poll [`GET /context/status`](/api-reference/v2/endpoint/source-status) with the returned IDs until each source reaches `graph_creation` (searchable), `completed`, or `errored`. Alternatively, register a webhook for `indexing.status_changed` events (see [Webhooks](/api-reference/v2/endpoint/webhooks-overview)).
- **Memory and knowledge:** Use `type: "memory"` for memory ingestion, listing, and deletion. Use `type: "all"` on `POST /query` when results should combine both.

## Supported file formats

<span id="size-limit"></span>

Each file in `documents` can be up to **50 MB**. A larger file returns `413` with a message naming the file, and no part of the request is processed. Split larger files before uploading.

<Accordion title="View supported and unsupported file formats">

HydraDB accepts these formats through `documents`:

| Type | Formats |
| --- | --- |
| Documents | `.pdf` `.doc` `.docx` `.docm` `.dot` `.dotx` `.odt` `.ott` `.rtf` |
| Spreadsheets | `.xls` `.xlsx` `.xlsm` `.xlsb` `.ods` `.ots` `.csv` `.tsv` |
| Presentations | `.ppt` `.pptx` `.pptm` `.odp` `.otp` |
| Apple iWork | `.pages` `.numbers` `.key` |
| Images | `.png` `.jpg` `.jpeg` `.tif` `.tiff` `.webp` `.gif` `.bmp` |
| Plain text | `.txt` `.md` `.markdown` `.json` |

What HydraDB extracts differs by type:

| Type | What gets indexed |
| --- | --- |
| Documents and presentations | The text, in reading order. Slide titles and body text both come through. |
| Spreadsheets | Cell values rendered as a table, one per sheet. Formulas are indexed as their computed result, not the formula itself. |
| Images and scans | Text read out of the picture with OCR. A photo of a page and a scan of a page both work. |
| Plain text | The file as-is. |

Files with no readable text fail with [`E2002`](/api-reference/v2/error-responses#ingestion-error-codes). Upload a version containing text.

### Unsupported formats

| Format | Upload this instead |
| --- | --- |
| `.heic` `.heif` `.avif` | Export the photo as JPEG or PDF |
| `.svg` `.ico` | Export as PNG or JPEG |
| `.html` `.htm` `.xml` | Save the page as PDF |
| `.eml` `.msg` | Save the message as PDF, or sync the mailbox with a [connector](/essentials/v2/connectors) |
| `.epub` `.wpd` | Convert to PDF or DOCX |
| `.zip` | Upload the files individually |

Use the file's real extension. When the filename has no extension, HydraDB uses the part's `Content-Type`. Renaming an unsupported file does not convert it: a renamed file may fail during indexing. Check [Ingestion Status](/api-reference/v2/endpoint/source-status) for that failure.

### When a file is not supported

An unsupported file is rejected in the upload response and does not block other files in the upload. The request returns `202` as usual. The rejected file comes back with `status: "failed"` and `error_code: "E1002"`, and every other file is queued normally:

```json
{
  "success": true,
  "data": {
    "success": false,
    "message": "Upload completed with some failures.",
    "results": [
      { "id": "6cc7bcd185b044cd", "filename": "report.pdf", "status": "queued", "error": null, "error_code": null },
      { "id": "f47411c736447126", "filename": "photo.heic", "status": "failed", "error": "This file format isn't supported. Please upload a PDF, Office document (Word, Excel, PowerPoint), image, CSV or text file.", "error_code": "E1002" },
      { "id": "d0c919bdec196a8d", "filename": "notes.txt", "status": "queued", "error": null, "error_code": null }
    ],
    "success_count": 2,
    "failed_count": 1
  },
  "error": null,
  "meta": { "request_id": "bcd03673-174d-4a73-83e6-73bfcdc16061", "api_version": "2.0.1" }
}
```

`data.success` is `true` only when every file was queued. Check `data.results` for individual failures.

Files rejected with `E1002` have no ingestion status record. Handle the format error from the upload response.

</Accordion>

## Shared item fields

Items in `document_metadata` and `memories` share three fields. The per-type tables under [Examples and item fields](#examples-and-item-fields) list only what differs.

| Field | Description |
| --- | --- |
| <Field name="id" type="string" /> | The source's ID and its upsert key. Use your application's ID to keep the same identifier in both systems. Must not contain a comma (`,`): the comma is reserved as the ID separator on [Ingestion Status](/api-reference/v2/endpoint/source-status) (`GET /context/status?ids=a,b`), so an item whose `id` contains a comma is rejected with a `400`. |
| <Field name="metadata" type="object" /> | Database-schema fields for filtering and search. Keys must be declared in `database_metadata_schema`. Send an object, for example `{ "department": "legal" }`. At most 16 KiB. (default=`{}`) |
| <Field name="additional_metadata" type="object" /> | Free-form per-source fields for display or bookkeeping, sent as an object. To filter on these at query time, nest them under `metadata_filters.additional_metadata`. At most 1 KiB. (default=`{}`) |

See [Metadata Filters](/essentials/v2/metadata#2-the-two-layers) for choosing metadata fields and filtering on them, and [metadata size limits](/essentials/v2/metadata#stored-metadata) for how HydraDB measures the caps.

  | Field | Description |
  | --- | --- |
  | <Field name="id" type="string" /> | Optional. If set, becomes the `id` for this document. See [shared item fields](#shared-item-fields). |
  | <Field name="metadata" type="object" /> | See [shared item fields](#shared-item-fields). |
  | <Field name="additional_metadata" type="object" /> | See [shared item fields](#shared-item-fields). |
  | <Field name="relations" type="object" /> | Forceful relations (links you declare between sources). Shape: `{ "ids": ["...", "..."] }`. Linked sources come back in `additional_context` on `mode: "thinking"` queries. |
  | <Field name="infer" type="boolean" /> | Run model enrichment on this file. (default=`false`) |
  | <Field name="evidence_kind" type="string" /> | How this content came to be known: `assertion`, `record`, `said`, `done`, `third_party`, or `inferred`. Any other value returns `400`. |
  | <Field name="evidence_subject" type="string" /> | A stable handle for who or what the content is about. |

  Those seven, plus the deprecated aliases `source_id` and `file_id` (for `id`) and `document_metadata` (for `additional_metadata`), are the only keys accepted. Anything else (including `title`, `type`, `url` and `timestamp`) is rejected with a `400` naming the unsupported key, rather than being silently dropped.

  In particular, a document's **title is derived, not settable**. It defaults to the uploaded filename and is returned as `source_title` on query results and `title` on `/context/list`. It cannot be overridden at ingest, and [`PATCH /context/{id}/metadata`](/api-reference/v2/endpoint/update-source-metadata) only merges `additional_metadata` and `database_metadata`. Use `additional_metadata` for your own display fields.

<Accordion title="Knowledge documents: upload in-memory text as a .txt file">

If you already have text in memory, create a file-like object and upload it through `documents` as a `text/plain` `.txt` file.

<CodeGroup>
```python Python SDK
import io
import json

text = """Q4 planning notes

- Launch checklist is owned by Priya.
- Legal review is due by Friday.
"""

# Create a file-like object in memory. No local .txt file is required.
txt_file = io.BytesIO(text.encode("utf-8"))

response = client.context.ingest(
    type="knowledge",
    database="acme_corp",
    collection="team_docs",
    documents=[("meeting-notes.txt", txt_file, "text/plain")],
    document_metadata=json.dumps([
        {"id": "meeting_notes_q4", "metadata": {"department": "product"}}
    ]),
)
```


<Accordion title="Bring your own graph: supply entities and relations">
  Sources keyed in `graph_payload` are still chunked and embedded, so they stay searchable. See [Bring Your Own Graph](/essentials/v2/bring-your-own-graph#using-byog-without-cypher) for the full guide.

  <CodeGroup>

  ```bash cURL

        "entities": {

        ]
      }
    }'
  ```

  | Field | Description |
  | --- | --- |
  | <Field name="<source_id>" type="object" /> | Top-level key: a `document_metadata` id for `type=knowledge`, or a memory `id` for `type=memory`. Value is that source's graph. A key matching no source returns `400`. |
  | <Field name="entities" type="object (map)" /> | Map keyed by a caller-local id; each value is an entity. The key is only a handle for `relations` to reference. It is not stored. |
  | <Field name="entities[].name" type="string" required /> | Entity name. Normalized (lowercased) server-side so it matches at query time. At most 256 chars. |
  | <Field name="entities[].type" type="string" /> | Entity type (e.g. `PERSON`, `POLICY`). Stored as supplied. |
  | <Field name="entities[].namespace" type="string" /> | Logical grouping for the entity. Stored as supplied. |
  | <Field name="entities[].identifier" type="string" /> | Optional external id (email, URL, etc.), display only. |
  | <Field name="relations" type="array" /> | Edges referencing entity-map keys. |
  | <Field name="relations[].source" type="string" required /> | Entity-map key of the source entity. |
  | <Field name="relations[].target" type="string" required /> | Entity-map key of the target entity. |
  | <Field name="relations[].predicate" type="string" required /> | Relationship label, any plain string. At most 256 chars. |
  | <Field name="relations[].context" type="string" /> | Optional sentence supporting the edge. At most 2,000 chars. |
  | <Field name="relations[].temporal_details" type="string" /> | Optional timing info (e.g. "since 2021", "in Q3"). |

  **Caps per graph:** at most 5,000 entities, 10,000 relations, and 500 relations per entity; over-cap returns `400`. Graphs survive re-ingest: a re-upload or connector re-sync re-applies the stored graph.
