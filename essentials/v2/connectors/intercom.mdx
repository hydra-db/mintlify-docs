Use the Intercom connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `conversations`
- `conversation_parts`
- `articles`
- `tickets`

## Connect

1. Use an Intercom private-app access token or OAuth token with Read conversations, Read and list users and companies, Read admins, Read and List articles, and Read tickets. The connector only reads.
2. Rotate a private-app token by replacing the connector secret and validating a sync before revoking the old token. OAuth installations must preserve refresh tokens and reauthorize if requested scopes or teammate visibility change.
3. Use the token of a teammate set to All conversations. Since July 2026, an OAuth token can read only conversations visible to the teammate who authorized it. Regenerate the token after changing that setting, or the index silently narrows.
4. Private teammate notes are excluded by default. When acl_supported is enabled for Intercom, each assigned conversation, conversation part and ticket is readable by its assignee and the members of its assigned team. Intercom's API does not expose which teammates can see all conversations, so this is a lower bound: such a teammate who is not the assignee or on the team is denied, never over-granted.
5. Unassigned conversations and tickets carry no ACL of their own and follow their resource. The workspace resource is public unless you set a HydraDB resource ACL on it. Help Center articles are unrestricted. An assignee or team that cannot be resolved makes no claim and carries an rbac_warning: the object then follows its resource, which is public for the workspace resource.
6. Intercom applies app/workspace rate limits and paginated-search limits that can vary by endpoint and plan. The connector honors 429 backoff; high-volume workspaces should avoid overlapping full syncs with other bulk exports.

Use provider `intercom` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
