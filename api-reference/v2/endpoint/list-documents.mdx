Page through what you ingested in a database or collection: `type: "knowledge"` (default) for documents and app sources, or `"memory"` for user memories. Use it to find IDs, show a source list, or check what landed. For metadata design, see [Scoping using metadata](/essentials/v2/metadata).

<RequestExample>

```python Python SDK
sources = client.context.list(
    database="acme_corp",
    type="knowledge",
    page=1,
    page_size=50,
    filters={
        "metadata": {"department": "legal"},
        "source_fields": {"type": "slack"},
    },
    include_fields=["title", "type", "timestamp", "additional_metadata"],
)
```


## Request body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Owning database. Deprecated alias: `tenant_id`. |
| <Field name="collection" type="string or null" /> | Collection scope. If omitted, the default collection is used. Deprecated alias: `sub_tenant_id`. (default=`null`) |
| <Field name="type" type="&#x22;knowledge&#x22; or &#x22;memory&#x22;" /> | Bucket to list. (default=`"knowledge"`) |
| <Field name="ids" type="string[] or null" /> | When non-empty, only items with these IDs are returned; pagination and filters still apply on top. At most `100` IDs. (default=`null`) |
| <Field name="page" type="integer" /> | Page number (1-indexed). (default=`1`) |
| <Field name="page_size" type="integer" /> | Items per page, from `1` to `100`. (default=`50`) |
| <Field name="filters" type="object" /> | Structured exact-match filters. See [Filters](#filters). (default=`null`) |
| <Field name="include_fields" type="string[] or null" /> | Field projection for `type=knowledge` (ignored for `type=memory`). Only the listed fields plus `id`, `database`, `collection` are populated. See [Field projection](#field-projection). (default=`null`, all fields) |
| <Field name="acl" type="string[]" /> | Principals to list as (document ACLs). Only knowledge sources those principals may see come back. Omitted, `[]`, or `["*"]` lists everything. Ignored for `type=memory`. See [Access Control](/essentials/v2/access-control). |

### Filters

`filters` has three optional categories. Each filter is an exact match on the stored value, except `source_fields.title`, a case-insensitive prefix match. All pairs combine with AND; for OR, run several calls and merge the results. There are no range, contains, or OR operators here. A `null` filter value returns `400`.

```json
{
  "filters": {
    "metadata": { "department": "Finance", "region": "US" },
    "additional_metadata": { "author": "Alice Smith" },
    "source_fields": { "type": "slack", "title": "standup" }
  }
}
```

| Category | Matched against | Notes |
| --- | --- | --- |
| <Field name="metadata" type="object" /> | The item's schema-aligned `metadata` | Database metadata fields. Legacy alias: `tenant_metadata`. Each key is an equality check on the stored `metadata`; none is ignored. In a database with a schema, ingest rejects undeclared keys, so filtering on one returns nothing, except `connector_id` and `provider`, which connectors always write. |
| <Field name="additional_metadata" type="object" /> | The item's `additional_metadata` | Free-form per-document JSON, no schema needed. Legacy alias: `document_metadata`. |
| <Field name="source_fields" type="object" /> | Built-in source fields (`type`, `title`, `description`, `url`, `timestamp`) and connector fields (`app_provider`, `app_kind`, `app_external_id`, `app_parent_id`) | `title` must be a string and matches by case-insensitive prefix: `"standup"` finds "Standup notes 2026-05-12". External IDs are unique only per provider, so pair `app_external_id` or `app_parent_id` with `app_provider`. Any other key returns `400`. |

If you send a legacy alias with its canonical key, the canonical key wins.

### Field projection

Pass `include_fields` to return only the fields you need. Treat any field you leave out as unavailable in that response; `id`, `database`, and `collection` always come back.

Allowed values: `title`, `type`, `description`, `note`, `timestamp`, `metadata`, `additional_metadata`, and `relations`, plus the legacy names `tenant_metadata` and `document_metadata`. Omit it or pass `null` to return everything.

<Note>
  `content`, `url`, and `attachments` are **not** projectable. They are stripped from list responses, and requesting one returns `400`. Fetch them per source with [Inspect Context](/api-reference/v2/endpoint/fetch-content).
</Note>

With `type=memory`, `data` is a `ListUserMemoriesResponse`: rows come back in `data.user_memories[]`, keyed by `memory_id`, instead of `data.sources[]`, with the same fields as knowledge rows. The memory text and `inferred_content` are not included; read them with [Inspect Context](/api-reference/v2/endpoint/fetch-content).

- **Scope fields:** every row carries `database` and `collection`, plus the deprecated `tenant_id` and `sub_tenant_id` with the same values.
- **Memory listing unavailable:** if the memory store cannot be read, the call still returns `200` with an empty `user_memories` and `message` set to `"Memories temporarily unavailable"`. Check `message` before you treat an empty list as "no memories".

## Errors

`400` for an invalid body, for example `page` below `1`, `page_size` outside `1` to `100`, more than `100` `ids`, an unknown `source_fields` key, a `null` filter value, or a non-projectable `include_fields` value. See [Error Responses](/api-reference/v2/error-responses).
