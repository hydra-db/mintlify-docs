Company search answers a question from everything the company has written, and shows each person only what they are allowed to see. This cookbook builds it with three ideas: one collection for all company knowledge, an ACL on each source, and the asker's identity on every query.

| Benchmark | Result | What it shows here |
| --- | --- | --- |
| [EnterpriseRAG-Bench](https://benchmarks.hydradb.com/enterprise-rag-bench) | 88.7 overall, 96.7% document recall@10 | Retrieval across fragmented systems where knowledge is duplicated or outdated |
| [KyroBench](https://benchmarks.hydradb.com/kyrobench) | 0.776 nDCG | The current source ranked above the stale one |

## 1. Create one database and one collection

Put everything in one collection so a single query searches all of it. Separate collections are for context that must never meet in one query; permissions are handled by ACLs, not by splitting collections. See [Databases and Collections](/essentials/v2/databases-and-collections).

```python glean.py
import json

from hydra import answer, client, create_database, wait_indexed

DATABASE, COLLECTION = "acme_corp", "company"

create_database(DATABASE)
```

## 2. Ingest sources from each app

Send records your code already holds as [app sources](/essentials/v2/app-sources). `kind` tells HydraDB what the record is, `fields` carries its content, and `acl` lists who may see it. The samples include an outdated wiki page and the Slack message that replaced it, and a ticket only the finance lead can see.

```python glean.py
sources = [
    {
        "id": "notion_pricing_2025",
        "title": "Pricing (2025)",
        "kind": "knowledge_base",
        "provider": "notion",
        "external_id": "page_pricing_2025",
        "url": "https://notion.so/acme/pricing-2025",
        "timestamp": "2025-03-01T09:00:00Z",
        "fields": {
            "kind": "knowledge_base",
            "title": "Pricing (2025)",
            "body": "Pro is $79 per seat per month. Enterprise is $199.",
            "updated_at": "2025-03-01T09:00:00Z",
        },
        "acl": ["domain:acme.com"],
    },
    {
        "id": "slack_C01_1788000000_000100",
        "title": "Pricing change - Slack #product",
        "kind": "message",
        "provider": "slack",
        "external_id": "1788000000.000100",
        "timestamp": "2026-09-01T10:00:00Z",
        "fields": {
            "kind": "message",
            "body": "Decision: from October 1, 2026, Pro moves from $79 to $89 per seat.",
            "author": "alice@acme.com",
            "thread_id": "1788000000.000100",
            "created_at": "2026-09-01T10:00:00Z",
        },
        "acl": ["domain:acme.com"],
    },
    {
        "id": "jira_FIN_42",
        "title": "FIN-42: Enterprise discount floor",
        "kind": "ticket",
        "provider": "jira",
        "external_id": "FIN-42",
        "timestamp": "2026-09-03T15:00:00Z",
        "fields": {
            "kind": "ticket",
            "title": "Enterprise discount floor",
            "description": "Do not discount Enterprise below $150 per seat without CFO approval.",
            "status": "open",
            "assignee": "grace@acme.com",
        },
        "acl": ["grace@acme.com"],
    },
]

result = client.context.ingest(
    type="knowledge",
    database=DATABASE,
    collection=COLLECTION,
    app_knowledge=json.dumps(sources),
)
wait_indexed(DATABASE, COLLECTION, [r.id for r in result.data.results])
```

## 3. Query as the person asking

Send the signed-in user's identity as `acl`. Take it from your session on the server, never from the client: a query without `acl` returns everything in scope. The other settings are the ones the EnterpriseRAG-Bench run used: hybrid matching, `thinking` mode, and 12 results.

```python glean.py
def search(question, user_email):
    return client.query(
        database=DATABASE,
        collection=COLLECTION,
        query=question,
        type="knowledge",
        query_by="hybrid",
        mode="thinking",
        max_results=12,
        acl=[user_email],
    )
```

## 4. Answer with citations

The query result lists the sources behind its chunks. Print them under the answer so the reader can open the original.

```python glean.py
def ask(question, user_email):
    result = search(question, user_email)
    print(answer(question, result, "Prefer the most recent source when sources disagree."))
    for source in result.data.sources:
        print(f"  - {source.title} ({source.url or source.id})")


ask("What does Pro cost per seat?", "bob@acme.com")
ask("How far can we discount Enterprise?", "bob@acme.com")
ask("How far can we discount Enterprise?", "grace@acme.com")
```

## Run it

```bash
python glean.py
```

The first answer should give $89 and cite the Slack decision alongside the older page. The second should say it does not know, because the ticket is restricted to Grace. The third should give the $150 floor and cite FIN-42.

## Use real data

Replace step 2 with [connectors](/essentials/v2/connectors): HydraDB then syncs each app on a schedule and copies its permissions into each source's ACL. Create one connector per app, all pointing at the same collection.

```python connect.py
from hydra import client

connector = client.connectors.create(
    provider="slack",
    database="acme_corp",
    collection="company",
    provider_account_scope="T12345ACME",
    credentials={"access_token": "xoxp-..."},
)
found = client.connectors.discover(connector.connector_id)
client.connectors.configure(
    connector.connector_id,
    resources=[
        {"resource_id": r.id, "resource_type": r.resource_type, "name": r.name}
        for r in found.resources
    ],
)
```

To make a connector's sources always enforce ACLs, turn on [`enforce_acl`](/essentials/v2/connectors#enforce-acl) for it.

## Common mistakes

- **Querying without `acl`:** the query returns restricted sources to everyone. Send the user's identity on every query.
- **One collection per app or team:** a query that names one collection does not read the others. Keep one collection and narrow with [metadata filters](/essentials/v2/metadata).
- **Group permissions:** an email matches its `domain:` principal automatically, but not groups. Send `group:` principals yourself. See [Access Control](/essentials/v2/access-control).
