Sync the cards in the Guru collections you select. Each card is one document with its text, collection, verification state and owner. Each comment and each reply is its own document, linked to its card or thread. Attached files can be downloaded and their text added to the card.

The Guru groups that can open a collection restrict search when Enforce ACL is on. Private cards are skipped unless you turn on `include_private_cards`. Tags, folders and verifiers are kept but are not searchable. Cards and comments deleted in Guru stay in HydraDB.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow Guru permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** A card can be read by the members of the Guru groups that can open its collection. A collection open to All Members or All Organization Members can be read by everyone who can query the collection. A private card, synced only when `include_private_cards` is on, can be read by its owner and its collaborators. A comment follows its card.
- **How a person is identified:** A member's email address. Guru groups are turned into their active members' email addresses.
- **When permissions cannot be read:** If HydraDB cannot read a collection's group access, or a private card's owner and collaborators, the connector reports a permission warning. On HydraDB Cloud, with Enforce ACL on, such an item follows the access rule you set on its resource. With no rule, it is hidden from search. Self-hosted deployments can be configured differently. Permission warnings appear in [Get Connector Status](/api-reference/v2/endpoint/get-connector-status).
- Reading a collection's group access needs the user token of a Guru Admin or of the collection's owner. A collection token cannot read it.
- Guru Admins are not added to a collection's readers.
- A group or audience too large to read in full counts as unreadable.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

Guru uses an API token, paired with either your Guru username for a user token, or a collection id for a collection token. Set exactly one of `email` and `collection_id`. The token reads as the user who generated it.

<ResponseField name="api_token" type="secret string" required>
A Guru user token.
</ResponseField>

<ResponseField name="email" type="string">
Your Guru username, usually your email.
</ResponseField>

<Accordion title="Other credential options">

**Collection token**

<ResponseField name="api_token" type="secret string" required>
A Guru collection token. It is read-only and covers one collection, and it cannot read who can open the collection.
</ResponseField>

<ResponseField name="collection_id" type="string">
The id of the token's collection.
</ResponseField>

</Accordion>

**Connector settings**

<ResponseField name="include_private_cards" type="boolean">
Set to `true` to also sync private cards, each readable only by its owner and collaborators. Off by default.
</ResponseField>

**What the Guru user needs**

- `Read access to each collection`: required. Cards in collections the user cannot open are never synced.
- `Manage Apps & Integrations`: required to generate the token. An Admin can generate it on behalf of the syncing user.
- `Admin or Collection Owner`: optional, for search that follows Guru permissions. Reads which groups can open each collection.

### Set it up

<Steps>
  <Step title="Generate a token">
    In Guru, open Manage, Apps & Integrations, API Access and generate a user token, or a collection token for a single collection. For search that follows Guru permissions, use the user token of a Guru Admin or of each collection's owner.
  </Step>
  <Step title="Create the connector">
    Paste the token as `api_token`. For a user token, add your Guru username as `email`. For a collection token, add the collection id as `collection_id`. To sync private cards, set `include_private_cards` to `true`.
  </Step>
  <Step title="Select collections">
    HydraDB lists the collections the token can read. Select the collections to sync. To reach cards older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads what one Guru user, or one collection token, can open.

<Accordion title="Connect through the API">

Use provider `guru` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected collection reads back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the cards that were edited, verified or commented on since the last sync. Each card's comments are sent again as their own documents.
- **Edits:** An edited card is read again and replaces its document.
- **Deletions:** Deleted cards are not removed. A card, comment or reply deleted in Guru stays searchable in HydraDB.
- If Guru refuses a card's comment list, a change to its comments only can be missed until the card changes again.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

### Cards

- **One document:** One Guru card.
- **Title:** The card title. A card with no title is titled `Guru card` and its id.
- **Text:** The card content with HTML removed. Plain text and Markdown pass through. If the content has no readable text, the title stands in. The title, author and last-modified time are searchable too.
- **Date:** The later of when the card was last modified and when it was last verified, so a re-verified card counts as recent.
- **Link back:** Opens the card in Guru.
- **Files:** Attached files can be downloaded and their text added to the card. A file over 25 MiB, of an unsupported type, or that fails to download keeps only its name.

<ResponseField name="created_by" type="Searchable text, Graph identity">
The card owner's display name, written as the `Author` line. The graph records the card as written by its owner.
</ResponseField>

<ResponseField name="owner" type="Searchable text, Graph identity">
The card owner's name or email, the same person as `created_by`.
</ResponseField>

<ResponseField name="created_by_email" type="Graph identity">
The owner's email. Gives the author an email in the graph, so the same person is recognised across tools. Not searchable.
</ResponseField>

<ResponseField name="last_verified" type="Result date">
When the card was last verified. When it is later than the last edit, it sets the result date. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.verification_state" type="Query filter">
The card's trust status, such as `TRUSTED` or `STALE`. Limits a query to trusted cards, or finds stale ones. Not searchable.
</ResponseField>

<ResponseField name="share_status" type="Access rule">
`TEAM`, `PRIVATE` or `PUBLIC`. Private cards are skipped, or with `include_private_cards` on, readable only by their owner and collaborators. Not searchable.
</ResponseField>

### Comments

- **One document:** One comment that starts a thread on a card, or one reply in a thread. Empty comments are skipped, except a thread opener whose replies have text.
- **Title:** `Comment by` the author's name `on` the card title, or `Comment on` the card title.
- **Text:** The comment text with markup removed, with `Author`, `Parent`, `Created` and `Updated` lines.
- **Date:** The later of when the comment was created and last modified.
- **Link back:** Opens the card the comment is on.

<ResponseField name="author" type="Searchable text, Graph identity">
The comment author as name and email, written as the `Author` line. The graph records the comment as written by that person.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The card for a thread opener, or the thread for a reply, written as the `Parent` line. Links the comment to it.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the comment was created, written as the `Created` line.
</ResponseField>

<ResponseField name="additional_metadata.guru_comment_id" type="Query filter">
The comment id. Picks out one comment. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="properties" type="Stored only">
The comment's status.
</ResponseField>

</Accordion>

**Example searches**

- What does our Guru card say about the refund policy for annual plans?
- Which trusted cards in the Sales collection cover competitor pricing?
- What did people comment on the onboarding checklist card?

## How it fits into the graph

- Cards use the Page class.
- Comments use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Guru creates**

- A comment that starts a thread to its card.
- A reply to its thread.
- No links to items in other tools.

**People and groups**

- The owner of each card, with name and email.
- The author of each comment and reply.
- Verifiers and editors are kept with the card but not attached as people.

**Found in the text**

The card text, the text read from attached files, and the comment text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Collections you did not select.
- Cards not edited, verified or commented on within the `lookback_days` window on the first sync.
- Private cards, unless `include_private_cards` is on.
- Collections the token's user cannot open.
- Deletions: deleted cards, comments and replies stay in HydraDB.
