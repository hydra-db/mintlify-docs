Use the Supabase connector to bring the following content into HydraDB.

## What syncs

Selected table row changes arrive through database webhooks. There is no history backfill.

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. List the tables you want indexed, one per line, as schema.table, for example public.customers. Always include the schema.
2. In your Supabase project, install the Database Webhooks integration if it is not already installed.
3. Establish the connection in the HydraDB dashboard, then select the tables you want to sync.
4. Run the SQL command generated by the dashboard in the Supabase SQL editor to add a trigger for each table. Replace the API key placeholder with your HydraDB API key.
5. Only changes made after connecting are reflected. Existing rows are sent when they are updated; there is no historical backfill.

Follow the Supabase connection flow in the dashboard. This is a push connector; the webhook triggers, not a polling credential, deliver changes.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
