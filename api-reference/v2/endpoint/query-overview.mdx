A query returns ranked chunks (passages of a source) with their source IDs. Choose how to match with `query_by`, and how much retrieval work to do with `mode`.

## Endpoint references

| Endpoint | SDK method | Purpose |
| --- | --- | --- |
| [`POST /query`](/api-reference/v2/endpoint/query) | `query` | Query your context |
| [`POST /feedback`](/api-reference/v2/endpoint/submit-feedback) | `feedback.submit` | Report how a query performed |

## Parameters that matter

These parameters shape most queries. [Query](/api-reference/v2/endpoint/query#request-body) lists every request field and its rules.

| Parameter | Values | Use it for |
|---|---|---|
| <Field name="query_by" /> | `"hybrid"`, `"text"` | Choose the matching method. Use `"hybrid"` by default and `"text"` for exact terms or phrases. |
| <Field name="mode" /> | `"fast"`, `"thinking"`, `"auto"` | Choose a single pass with `"fast"`, broader retrieval with `"thinking"`, or automatic routing with `"auto"`. Defaults to `"auto"`. |
| <Field name="max_results" /> | integer | Limit the returned chunks. Defaults to `10` for one collection. Maximum `250`. |
| <Field name="alpha" /> | `0.0` to `1.0`, or `"auto"` | Tune hybrid matching. Lower values favor keyword matching; higher values favor semantic similarity. Default `0.8`, which `"auto"` also resolves to. |
| <Field name="metadata_filters" /> | object | Narrow results by metadata. Top-level keys filter schema-backed fields. Free-form fields go under `additional_metadata`. |
| <Field name="collections" /> | `string[]` or weighted object | Search up to 100 existing collections. A list weights them equally. An object assigns relative weights, such as `{ "workspace_42": 2, "user_alex": 1 }`. |
| <Field name="graph_context" /> | boolean | Include entity and relation context with the chunks. On by default; set `false` with `mode: "fast"` for chunk-only responses (`thinking` always includes it). |
| <Field name="query_apps" /> | boolean | Improves matching on content synced by connectors. Enabled by default. The query still searches all selected context. |

## Recommended configurations

| User intent | Recommended config |
|---|---|
| Fast answers from documents | `query_by="hybrid"`, `mode="fast"`, `max_results=5-10`, `graph_context=false` |
| Broader document search | `query_by="hybrid"`, `mode="thinking"` (thinking always includes graph context) |
| Personalized answer | The user's `collection`, `query_by="hybrid"`, `mode="thinking"`. If shared documents live in another collection, list both in `collections` |
| User preferences only | The user's `collection`, `query_by="hybrid"` |
| Exact keyword or phrase | `query_by="text"`, `operator="phrase"` |
| Recent operational updates | `query_by="hybrid"`, `recency_bias=0.8-1.0`, a metadata filter for the right document type |
| Mixed or unpredictable query complexity | `query_by="hybrid"`, `mode="auto"`: let HydraDB route each query to `fast` or `thinking` |

## Typical patterns

Each pattern is a complete request body. [Query](/api-reference/v2/endpoint/query#example-requests) shows the same patterns as Python SDK, TypeScript SDK, and cURL calls.

<AccordionGroup>
  <Accordion title="Document Q&A from shared documents" defaultOpen>

Answer questions from files, tickets, pages, or other synced content.

```json
{
  "database": "acme",
  "query": "What is our refund policy?",
  "query_by": "hybrid",
  "mode": "thinking",
  "max_results": 10,
  "graph_context": true
}
```

  </Accordion>

  <Accordion title="Personalized answer with a user's conversations">

Search the shared documents collection and the collection the user's conversations were ingested into. Both collections must already exist.

```json
{
  "database": "acme",
  "collections": ["company_docs", "user_alex"],
  "query": "What is our refund policy, and how should I explain it to this user?",
  "query_by": "hybrid",
  "mode": "thinking"
}
```

  </Accordion>

  <Accordion title="Search multiple collections">

Search several collections and return one ranked result set. Use a list for equal weighting, or an object to give one collection more influence.

```json
{
  "database": "acme",
  "collections": {
    "workspace_42": 2,
    "user_alex": 1
  },
  "query": "What renewal risks should we discuss?",
  "query_by": "hybrid",
  "mode": "thinking"
}
```

  </Accordion>

  <Accordion title="Filtered query for a specific slice">

Top-level `metadata_filters` keys filter fields declared in `database_metadata_schema`. Free-form fields go under `additional_metadata`. All keys combine with AND. See [Metadata Filters](/essentials/v2/metadata) for operators.

```json
{
  "database": "acme",
  "query": "What launch constraints apply to enterprise customers?",
  "query_by": "hybrid",
  "metadata_filters": {
    "department": {"equals": "product"},
    "additional_metadata": {
      "source": "launch_plan"
    }
  }
}
```

  </Accordion>

  <Accordion title="Exact phrase lookup">

Use `query_by: "text"` when literal wording matters: legal clauses, SKUs, error codes, IDs, or compliance references.

```json
{
  "database": "acme",
  "query": "GDPR Article 17",
  "query_by": "text",
  "operator": "phrase"
}
```

  </Accordion>
</AccordionGroup>

## Response summary

By default, `data.llm_prompt` contains the question and retrieved context formatted for your model. Pass this string to the model to generate an answer. See [Query](/essentials/v2/query#7-use-the-results) for the model call and response formats.

The response also includes ranked `data.chunks[]` with source IDs, plus graph context and related chunks. Preserve chunk order when you format results yourself.
