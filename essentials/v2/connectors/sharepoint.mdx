Sync three kinds of content from the SharePoint Online sites you select: files in document libraries, site pages including news posts, and the rows of the site's lists. Each file, page and list row is one document. Text from supported files is searchable when HydraDB can download and read the files. A file whose text cannot be read is still findable by its name, library and folder path.

SharePoint permissions are not imported, so everything synced is visible to everyone who can query the collection unless you set an access rule. The first sync reaches only items modified in the last 30 days, files included, unless you raise `lookback_days`. Items deleted in SharePoint stay in HydraDB.

## Permissions

<Warning>
SharePoint permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- SharePoint site and item permissions are not reproduced. Set an access rule on each site that must be restricted.
- Every synced item carries `additional_metadata.rbac_warning`, a notice that SharePoint permissions were not captured.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

SharePoint uses a Microsoft Entra app registration with app-only access: a client id and client secret, with no signed-in user.

<ResponseField name="tenant" type="string" required>
Your Entra Directory (tenant) ID, as a GUID or its friendly name.
</ResponseField>

<ResponseField name="client_id" type="secret string" required>
The Application (client) ID of the Entra app.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The client secret's Value, not its Secret ID.
</ResponseField>

SharePoint is its own connector. Connecting it does not sync Microsoft Teams chat or Outlook mail.

**Microsoft Graph application permissions**

- `Sites.Read.All`: lists the tenant's sites and reads document libraries, site pages and lists with their columns and rows.
- `Files.Read.All`: reads file details and downloads files so their text can be read.

Both must be application permissions with tenant-wide admin consent. Delegated permissions do not work.

### Set it up

<Steps>
  <Step title="Register an Entra app">
    In Microsoft Entra, register an app for app-only access and create a client secret.
  </Step>
  <Step title="Grant permissions">
    Add the Microsoft Graph application permissions `Sites.Read.All` and `Files.Read.All`, then grant tenant-wide admin consent.
  </Step>
  <Step title="Create the connector">
    Enter `tenant`, `client_id` and `client_secret`.
  </Step>
  <Step title="Select sites">
    HydraDB lists the tenant's sites. Select the sites to sync. Everything in a selected site is synced: its document libraries, pages and lists. You cannot select a single library or list. To reach items older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads one Microsoft Entra tenant. `Sites.Read.All` covers every site in the tenant, but HydraDB reads only the sites you select.

<Accordion title="Connect through the API">

Use provider `sharepoint` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected site reads back the window set by `lookback_days`, 30 days by default. This applies to files too: a file not modified within the window is not synced, even on the first sync.
- **New and changed items:** Each sync reads files, pages and list rows modified since the last sync.
- **Edits:** A changed file, page or row is read again and replaces its document.
- **Deletions:** Deleted files, pages and list rows are not removed. They stay searchable in HydraDB.
- If SharePoint refuses access to a list, the sync fails.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every SharePoint item

<ResponseField name="author" type="Searchable text, Graph identity">
The creator's display name, or email if there is no name, written as the `Author` line. The graph records the item as written by that person.
</ResponseField>

<ResponseField name="updated_at" type="Searchable text, Result date">
When the item was last modified, written as the `Updated` line. Sets the result date.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
The document library id for a file, the site id for a page, or the list id for a list row. Limits a query to one library, site or list. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_name" type="Query filter">
The library name for a file, the site name for a page, or the list name for a list row. Limits a query by that name. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
`drive` for a file, `site` for a page, `list` for a list row. Says what the two keys above refer to. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.sharepoint_site_id" type="Query filter">
The site id. Limits a query to one site across its files, pages and list rows. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.rbac_warning" type="Query filter">
A notice that SharePoint permissions were not captured. Present on every item. An access rule you set still applies. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `sharepoint`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="site_id" type="Stored only">
The site's id.
</ResponseField>

<ResponseField name="created_at" type="Stored only">
When the item was created. The result date uses the modified time instead.
</ResponseField>

</Accordion>

### Files

- **One document:** One file in a document library. Folders are not documents.
- **Title:** The library name, folder path and file name joined with slashes, for example `Documents/Reports/2026/Q3.pdf`. A file with no name is titled `SharePoint file` and its id.
- **Text:** The file's text when it could be read. Otherwise the title followed by `Type`, `Library`, `Path`, `Author`, `Link` and `Modified` lines, leaving out empty ones. The title, author and modified time are searchable in either case.
- **Date:** When the file was last modified.
- **Link back:** Opens the file in SharePoint.
- **Files:** Text from supported files is searchable when HydraDB can download and read the files. Files over 50 MiB keep only their details. Web pages (`.aspx`) and OneNote files (`.one`, `.onetoc2`) are not synced as files.

<ResponseField name="drive_name" type="Searchable text">
The document library name. Starts the title, and is the `Library` line when the file's text could not be read.
</ResponseField>

<ResponseField name="path" type="Searchable text">
The folder path inside the library. Part of the title, so files can be found by folder, and the `Path` line when the file's text could not be read.
</ResponseField>

<ResponseField name="mime_type" type="Searchable text">
The file type as SharePoint reports it, written as the `Type` line. Searchable only on files whose text could not be read.
</ResponseField>

<ResponseField name="url" type="Searchable text">
The file's SharePoint link. Written as the `Link` line only on files whose text could not be read.
</ResponseField>

<ResponseField name="additional_metadata.sharepoint_drive_id" type="Query filter">
The document library id. Limits a query to one library. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.sharepoint_item_id" type="Query filter">
The file id, unique only inside its library. Picks out one file. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="site_name" type="Stored only">
The site's display name. To limit a query to a site, use `additional_metadata.sharepoint_site_id`.
</ResponseField>

<ResponseField name="drive_id" type="Stored only">
The document library's id.
</ResponseField>

<ResponseField name="size" type="Stored only">
The file size in bytes.
</ResponseField>

</Accordion>

### Site pages

- **One document:** One site page or news post.
- **Title:** The page title, else its name. A page with neither is titled `SharePoint page` and its id.
- **Text:** The text of the page's web parts, with markup removed. The title, author and modified time are searchable too.
- **Date:** When the page was last modified.
- **Link back:** Opens the page in SharePoint.

<ResponseField name="additional_metadata.sharepoint_page_id" type="Query filter">
The page id, unique only inside its site. Picks out one page. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="site_name" type="Stored only">
The site's display name. To limit a query to a site, use `additional_metadata.container_name` or `additional_metadata.sharepoint_site_id`.
</ResponseField>

<ResponseField name="page_layout" type="Stored only">
`article`, `home` or `newsLink`.
</ResponseField>

<ResponseField name="is_news_post" type="Stored only">
Whether the page was promoted as a news post.
</ResponseField>

</Accordion>

### List rows

- **One document:** One row of a SharePoint list. Folder rows are skipped.
- **Title:** The list name, a colon, and the row's Title column. When Title is empty, the first column with a value is used, and otherwise the row id.
- **Text:** The title, a `List` line with the list and site names, then the row's columns in list order as labelled lines, then `Author`, `Modified` and `Link` lines. Empty values are left out. Hidden, reserved and most read-only columns are left out, and so are values that cannot be shown as text. If a list's column definitions cannot be read, its column values are left out. Columns are searchable as text, not as separate filters.
- **Date:** When the row was last modified.
- **Link back:** The row's display form in SharePoint, else the row's web link.
- **Files:** None. Files attached to list rows are not downloaded.

<ResponseField name="list_name" type="Searchable text">
The list's display name. Starts the title and the `List` line.
</ResponseField>

<ResponseField name="site_name" type="Searchable text">
The site's display name, written in the `List` line.
</ResponseField>

<ResponseField name="url" type="Searchable text">
The row's link, written as the `Link` line.
</ResponseField>

<ResponseField name="additional_metadata.sharepoint_list_id" type="Query filter">
The list id. Limits a query to one list. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.sharepoint_list_item_id" type="Query filter">
The row id, unique only inside its list. Picks out one row. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="list_id" type="Stored only">
The list's id.
</ResponseField>

<ResponseField name="list_template" type="Stored only">
The list template, such as `genericList`, `events` or `tasks`.
</ResponseField>

</Accordion>

**Example searches**

- What does the travel policy PDF on the HR site say about per diem?
- Which items in the Projects list mention the Platform team?
- Find the Q3 board deck in the Finance Documents library.

## How it fits into the graph

- Files use the Page class.
- Site pages use the Page class.
- List rows use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections SharePoint creates**

- No links between items, and no links to items in other tools. Site, library and list are kept as filters, not as graph links.

**People and groups**

- The creator of each file, page and list row.

**Found in the text**

The file text, the page text and the list row's columns. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Sites you did not select.
- Items last modified before the `lookback_days` window on the first sync, files included.
- SharePoint site and item permissions.
- Personal OneDrive, OneNote notebooks, comments, and metadata columns on library files.
- Files attached to list rows, hidden lists and system lists.
- Hidden, reserved and most read-only list columns, values that cannot be shown as text, and lookup-type columns beyond twelve per list.
- Text of files over 50 MiB.
- Deletions: deleted files, pages and list rows stay in HydraDB.
