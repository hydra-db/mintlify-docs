Sync issues from the Linear teams or projects you select, and Linear Documents attached to teams, projects, issues and initiatives. Each issue is one document with its description and up to 50 of its comments. Each Linear Document is one page. A sub-issue links to its parent, and an issue links to the GitHub pull requests attached to it.

Private-team membership restricts search only when Enforce ACL is on and HydraDB can read the team's members. Projects and Workspace Documents carry no Linear permissions. Issue labels are not synced. Issues and documents deleted in Linear stay in HydraDB.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow Linear permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** Access follows the team. A public team's issues can be read by everyone who can query the collection. A private team's issues can be read by its active members. A restricted team uses the members of the private team that contains it. A team's Documents resource follows the same rule. A project resource and Workspace Documents carry no Linear permissions, so set an access rule on them to restrict them.
- **How a person is identified:** A member's email address, in lower case. Linear bots, apps and deactivated members are left out.
- **When permissions cannot be read:** If HydraDB cannot read a team's full membership, the connector reports a permission warning. On HydraDB Cloud, with Enforce ACL on, such an item follows the access rule you set on its resource. With no rule, it is hidden from search. Self-hosted deployments can be configured differently. Permission warnings appear in [Get Connector Status](/api-reference/v2/endpoint/get-connector-status).
- Public-team access includes everyone who can query the collection, including people Linear treats as guests.
- An issue in both a selected team and a selected project is stored once, and the resource that synced it last decides its access. A project gives no team audience, so set an access rule on any project you select.
- Documents attached only to an initiative sit under Workspace Documents. A project document can also land there when its project belongs to more teams than HydraDB reads.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

Linear uses a personal API key.

<ResponseField name="access_token" type="secret string" required>
A Linear personal API key.
</ResponseField>

**Access the key needs**

- `read`: lists teams and projects, and reads issues, comments and attachments.

### Set it up

<Steps>
  <Step title="Create an API key">
    In Linear, open Settings, Account, Security and access, API keys, and create a key.
  </Step>
  <Step title="Create the connector">
    Paste the key as `access_token`.
  </Step>
  <Step title="Select teams, projects and documents">
    HydraDB lists every team, every project, a `<team> Documents` resource for each team, and one `Workspace Documents` resource. Select the ones to sync. A team's Documents resource holds the documents of the team, of its projects and of its issues. A document reachable through several teams is synced under one of them only. Workspace Documents holds documents no team claims, in practice documents attached only to an initiative.
  </Step>
</Steps>

One connector reads what one API key's Linear user can see.

To connect more than one Linear account, give each connector its own `provider_account_scope`, such as `linear-account-a` and `linear-account-b`. These are labels you choose, not Linear's own account ids, and HydraDB does not check them. Two connectors that share a scope and write to the same collection can overwrite each other's items. See [several accounts from one provider](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider).

<Accordion title="Connect through the API">

Use provider `linear` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected resource reads back the window set by `lookback_days`, 30 days by default, measured on when items were last updated.
- **New and changed items:** Each sync reads the issues and documents updated since the last sync.
- **Edits:** An edited issue or document is picked up through its last-updated time and updates its document. Comments are read again only when their issue is picked up.
- **Deletions:** Deleted issues and documents are not removed. An item that disappears from Linear stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Issues

- **One document:** One Linear issue, with up to 50 of its comments inside it. A search result is the issue, not an individual comment.
- **Title:** The issue title.
- **Text:** The issue's fields, written as `name: value` lines: the description, workflow state, priority and its label, assignee and creator with their emails, creation and update times, team key and name, project name, and the issue's address. Up to 50 comments are searchable with the issue. The title is searchable too.
- **Date:** When the issue was last updated.
- **Link back:** The issue's page in Linear.
- **Files:** Files uploaded into the description or comments are downloaded with the connector's key and read, and their text is searchable with the issue. Only files stored by Linear's upload service are read. Link attachments, such as GitHub, Figma or plain links, are kept as references and not opened. Up to 50 link attachments are kept per issue.

</ResponseField>

### Documents

- **One document:** One Linear Document, attached to a team, project, issue or initiative.
- **Title:** The document title.
- **Text:** The document's markdown content. The author and the update time are written with it. The title is searchable too.
- **Date:** When the document was last updated.
- **Link back:** The document's page in Linear.
- **Files:** Files uploaded into the content are downloaded and read, and their text is searchable with the document.

<ResponseField name="author" type="Searchable text, Graph identity">
The creator's name, or email when there is no name. The graph records the document as written by that person.
</ResponseField>

<ResponseField name="author_email" type="Graph identity">
The creator's email. Identifies the author in the graph. Not searchable.
</ResponseField>

<ResponseField name="Uploaded files" type="Searchable text">
The text read from each uploaded file, searchable with the document.
</ResponseField>

<ResponseField name="updated_at" type="Searchable text, Result date">
When the document was last updated, written as the `Updated` line. Sets the result date and decides when a sync picks the document up.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `linear`. Not searchable.
</ResponseField>

<ResponseField name="Documents resource" type="Access rule">
The team's Documents resource the document was synced under. A private or restricted team's members decide who can read it. Workspace Documents carries no Linear permissions. Not searchable.
</ResponseField>

## How it fits into the graph

- Issues use the Ticket class.
- Documents use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Linear creates**

- A sub-issue to its parent issue.
- An issue to each GitHub pull request attached to it, up to 50. The link reaches the pull request when the GitHub connector also syncs that repository. A repository name capitalized differently from GitHub's does not match.
- A document is not linked to the team, project, issue or initiative it is attached to.
- Teams and projects appear only as text on issues, not as links.

**People and groups**

- The assignee and the creator of each issue.
- The author of each embedded comment, as a commenter.
- The author of each document.

**Found in the text**

Issue descriptions, embedded comments and document content. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Teams, projects and Documents resources you did not select.
- Comments beyond the first 50 on an issue.
- Issue labels.
- Projects, cycles, milestones, labels and initiatives as items of their own.
- The contents of link attachments such as GitHub, Figma and plain links. Only uploaded files are read.
- Deletions: deleted issues and documents stay in HydraDB.
