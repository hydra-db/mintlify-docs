A chief of staff remembers what was decided, who committed to what, and what has changed since. This cookbook builds one from two types of context: meetings and email as knowledge, and the decisions drawn from them as memories that HydraDB keeps current.

| Benchmark | Result | What it shows here |
| --- | --- | --- |
| [BEAM 1M](https://benchmarks.hydradb.com/beam-1m) | 82% overall across ten dimensions | Decisions, tasks, and events tracked over months, where newer information replaces older |

No benchmark tests a chief of staff end to end. BEAM 1M tests the memory underneath it.

## 1. Create a database with two collections

Work records go in one collection. The executive's own decisions and commitments go in another, so they can be queried alone or together with the records.

```python chief_of_staff.py
import json

from hydra import answer, client, create_database, wait_indexed

DATABASE = "acme_corp"
RECORDS, EXECUTIVE = "work_records", "exec_dana"

create_database(DATABASE)
```

## 2. Ingest meetings and email as knowledge

Meetings and email are [app sources](/essentials/v2/app-sources). The `meeting` and `email` kinds keep participants, senders, and dates, which is what lets a query answer "what did Priya agree to on the September call".

```python chief_of_staff.py
records = [
    {
        "id": "gong_call_0912",
        "title": "Q4 planning call",
        "kind": "meeting",
        "provider": "gong",
        "external_id": "call_0912",
        "timestamp": "2026-09-12T16:00:00Z",
        "fields": {
            "kind": "meeting",
            "title": "Q4 planning call",
            "body": "Dana: we launch the EU region on November 3. Priya: I will "
            "have the data residency review done by October 15.",
            "host": "Dana Okafor",
            "participants": [{"name": "Priya Shah", "email": "priya@acme.com"}],
            "started_at": "2026-09-12T16:00:00Z",
        },
    },
    {
        "id": "gmail_msg_1002",
        "title": "EU launch date",
        "kind": "email",
        "provider": "gmail",
        "external_id": "msg_1002",
        "timestamp": "2026-10-02T09:30:00Z",
        "fields": {
            "kind": "email",
            "subject": "EU launch date",
            "body": "Legal needs two more weeks. Moving the EU launch to November 17.",
            "from": "dana@acme.com",
            "to": ["leadership@acme.com"],
            "thread_id": "thread_eu_launch",
            "created_at": "2026-10-02T09:30:00Z",
        },
    },
]

result = client.context.ingest(
    type="knowledge",
    database=DATABASE,
    collection=RECORDS,
    app_knowledge=json.dumps(records),
)
wait_indexed(DATABASE, RECORDS, [r.id for r in result.data.results])
```

## 3. Save decisions as memories

After each meeting or thread, save what was decided as a [memory](/essentials/v2/memories). With `infer: true`, HydraDB extracts the facts and checks them against what the collection already holds, so the October change to the launch date is reconciled with the September decision instead of sitting beside it.

```python chief_of_staff.py
def remember(text):
    result = client.context.ingest(
        type="memory",
        database=DATABASE,
        collection=EXECUTIVE,
        memories=json.dumps([{"text": text, "infer": True, "user_name": "Dana"}]),
    )
    wait_indexed(DATABASE, EXECUTIVE, [r.id for r in result.data.results])


remember("2026-09-12: Decided to launch the EU region on November 3. "
         "Priya owns the data residency review, due October 15.")
remember("2026-10-02: Moved the EU launch to November 17 because legal needs two more weeks.")
```

## 4. Ask what is current

Query both collections at once with `type: "all"`. `recency_bias` favors newer context, and `thinking` mode reranks, so the current launch date ranks above the one it replaced.

```python chief_of_staff.py
def brief(question):
    result = client.query(
        database=DATABASE,
        collections=[RECORDS, EXECUTIVE],
        query=question,
        type="all",
        mode="thinking",
        recency_bias=0.6,
    )
    return answer(question, result, "When facts conflict, the most recent one is current. "
                                    "Name the owner and due date of each commitment.")


print(brief("When is the EU launch, and what is still open before it?"))
```

## Run it

```bash
python chief_of_staff.py
```

The answer should give November 17, note that the date moved from November 3, and list Priya's data residency review as the open commitment.

## Use real data

Connect the calendar, meeting, and email apps with [connectors](/essentials/v2/connectors) in place of step 2. Keep step 3 in your application: decide what counts as a decision, and save it when the meeting ends.

## Common mistakes

- **Saving decisions as knowledge only:** a transcript records what was said. A memory records what is true now. Save both.
- **Querying one collection:** a query that names only `RECORDS` does not read the memories. Use `collections` with both names.
- **Leaving dates out of memories:** write the date into the memory text. It is what lets a later change supersede an earlier one.
