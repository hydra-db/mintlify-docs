Five ideas cover the product.

## Knowledge

Knowledge is shared context: PDFs, DOCX, Markdown, CSVs, emails, Slack threads, Notion pages, and other app content.

HydraDB parses each source and links related pieces in a [context graph](/essentials/v2/context-graphs). A query uses vector search for what is similar to the question and the graph for what is connected to it, such as material that shares a project or a person. Details: [Knowledge](/essentials/v2/knowledge).

## Memories

A memory is context about one user: a preference, a past conversation, or a fact HydraDB inferred from what they did. Memories make retrieval fit the person, not only the query: two people asking for the "Project Acme changelog" may need design decisions or release notes. Memories build up with every interaction.

`infer` controls what gets stored:

- `infer: false` (the default): HydraDB stores exactly the text you send. Use it for facts you already captured.
- `infer: true`: you send raw signal (interaction events, UI actions, dialogue), and HydraDB extracts the preference or fact inside it.

Details: [Memories](/essentials/v2/memories).

## How knowledge and memories differ

- **Who reads it:** knowledge is shared across users. A memory belongs to one user.
- **How it changes:** you replace or delete a knowledge source when it changes. You add memories as the user interacts.
- **How it is processed:** knowledge is parsed and chunked. Only memories take `infer`.
- **Where it lives:** both are stored in a `collection`. A query reads only the collections it names, or the default collection if it names none.
- **How you query it:** `type: "knowledge"`, `type: "memory"`, or `type: "all"` for both in one ranked list. `all` reads both stores from the same collection, so if the documents live in another one, list both in `collections`. See [How to Use API Results](/essentials/v2/api-results).

## Query

[`POST /query`](/api-reference/v2/endpoint/query) is how agents read. One call filters on metadata, matches by meaning and keyword, and walks the [context graph](/essentials/v2/context-graphs).

- `type`: `knowledge`, `memory`, or `all`.
- `query_by`: `hybrid` (meaning plus keywords) or `text` (keywords only).
- `mode`: `fast` (one pass), `thinking` (expands the query and reranks), or `auto` (the default, which picks one per query).
- `graph_context`: returns the graph relations behind the results. On by default. `false` takes effect only in `fast` mode.

Details: [Query](/essentials/v2/query).

## Databases and collections

A **database** is an isolated workspace that cannot read another database's data, usually one per customer organization. A **collection** is a partition inside it: a user, a team, or a project.

- **B2B:** one database per customer. Collections are their teams or users.
- **B2C:** one database for your app. Each person is a collection.
- **Internal tools:** one database per company or environment. Collections are departments or projects.

Requests send `database` and `collection`. The older `tenant_id` and `sub_tenant_id` still work as deprecated aliases. To limit documents to certain people inside one database, use [Access Control](/essentials/v2/access-control). Details: [Multi-tenant](/essentials/v2/multi-tenant).

## Metadata

Use metadata when a result must match a hard rule, such as "only approved policies". The filter runs before ranking.

- `metadata`: fields declared in the database schema, filtered with `metadata_filters`. Plan them before you ingest. You can add fields later but cannot rename, retype, or delete one.
- `additional_metadata`: free-form fields on one document, for context your agent reads or fields outside the schema.

At ingest, both go on each `document_metadata` item (one per file) or each memory item:

```json
{
  "metadata": { "compliance_framework": "SOC2", "region": "us" },
  "additional_metadata": {
    "owner": "sarah.chen@acme.com",
    "status": "approved"
  }
}
```

At query time:

```json
{
  "query": "latest pricing strategy",
  "metadata_filters": { "compliance_framework": "SOC2" }
}
```

Details: [Metadata](/essentials/v2/metadata).
