title: "Query"
description: "How to call POST /query, and which parameters change the result."
---

`POST /query` reads what you stored. `type` picks the store: [knowledge](/essentials/v2/knowledge), [memories](/essentials/v2/memories), or both. Ranking uses meaning (vectors), keywords (BM25), and the [context graph](/essentials/v2/context-graphs). The parameters below are the controls.

Request and response fields: [Query API](/api-reference/v2/endpoint/query-overview).

## 1. Starting points

- Shared documents: `type: "knowledge"`, `query_by: "hybrid"`, `mode: "thinking"`. Keep `graph_context` on (the default) when the answer depends on how entities connect.
- Exact tokens (error codes, IDs, names): `type: "knowledge"`, `query_by: "text"`. Optionally set `operator` to `"and"` or `"or"`.
- One user's memory: `type: "memory"`, `query_by: "hybrid"`, `mode: "thinking"`.
- Shared documents plus that user's memory: `type: "all"`, `query_by: "hybrid"`, `mode: "thinking"`. If the documents and the memories are in different collections, list both in `collections`.
- App data (Slack, mail, tickets) mixed with other knowledge: `query_apps` is on by default and adds ID, actor, and thread lookup. It does not limit the query to app sources. Send `query_apps: false` to turn the lane off.

## 2. Parameter reference

When to send `database` and `collection`: [Multi-tenant](/essentials/v2/multi-tenant#2-when-to-use-each). Older names `tenant_id` and `sub_tenant_id` still work as deprecated aliases.

### Retrieval

- `type`: `"knowledge"` (default), `"memory"`, or `"all"`. `"all"` reads both stores from the same scope in one call and ranks the results together.
- `query_by`: `"hybrid"` (default) combines vector similarity and BM25 keyword scores. `"text"` is BM25 keyword matching only.
- `operator`: `"or"` (default), `"and"`, or `"phrase"`. Controls how BM25 matches query terms. Applies only with `query_by: "text"`. Sending `"and"` or `"phrase"` with any other `query_by` returns `400`.
- `alpha`: a number from `0.0` (pure BM25) to `1.0` (pure semantic), or `"auto"`. Weights the two scores in `query_by: "hybrid"`. Default `0.8`. `"auto"` also resolves to `0.8`.
- `mode`: how much work the query does.
  - `"fast"`: a single low-latency pass.
  - `"thinking"`: expands the query into several, reranks, and fetches the relations you declared at ingest.
  - `"auto"`: the default when `mode` is omitted. HydraDB scores the query before retrieval and routes it to `"fast"` or `"thinking"`, choosing `"thinking"` when the signal is inconclusive. If it picks `"thinking"`, the graph slice is always included.

### Scope

| Parameter | Type / values | Purpose |
| --- | --- | --- |
| `collections` | `string[]` or `{ [collection]: positive number (max one decimal place) }` | Preferred query-time scope selector. Use a single-item list for one user or workspace, a longer list to fan out with equal normalized weights, or an object of relative ranking weights (at most one decimal place). HydraDB runs the whole query in each collection and merges the results. Every listed collection must exist. Maximum 100 collections. |
| `collection` | string | Single-scope selector. Also used at ingest. Send one collection ID to scope the query to it. If you send neither field, the query reads the database's default collection. |

### Graph

| Parameter | Type / values | Purpose |
| --- | --- | --- |
| `graph_context` | boolean | Includes the entity and relation graph slice in the response. Default `true`. `false` takes effect only in fast mode (explicit, or `auto` routed to fast). See [Context Graphs](/essentials/v2/context-graphs). |
| `query_forceful_relations` | boolean | Fetches the related sources you declared at ingest (see [`relations` on ingest](/api-reference/v2/endpoint/ingest-context)) into the response `additional_context`. **Takes effect only in thinking mode** (explicit, or `auto` routed to thinking). Default `true`. |

### Shaping results

| Parameter | Type / values | Purpose |
| --- | --- | --- |
| `max_results` | integer | Maximum chunks to return. Default `10`, maximum `250`. |
| `recency_bias` | float, `0.0` to `1.0` | Boost for newer content. Default `0.4`, a mild tilt applied when you omit the field. Send `0` to turn it off. |
| `query_apps` | boolean | Adds an app-aware retrieval lane for ingested app data (Slack, Gmail, Confluence, Jira, Salesforce): exact ID and actor lookups, reconstructed threads, and parent/child traversal. It does not restrict the query to app sources. HydraDB still queries the full selected knowledge scope. Applies to knowledge only. Pair with `mode: "thinking"`. See [App Sources](/essentials/v2/app-sources). Default `true`. Send `false` to turn the lane off. |
| `additional_context` | string | Request-time hint to guide retrieval, such as "user is on the billing page". Not the same as the response `additional_context`, which carries forceful-relation results. Default `null`. |
| `metadata_filters` | object | Deterministic narrowing before ranking. See [Metadata](/essentials/v2/metadata). Default `null`. |

### Access control

| Parameter | Type / values | Purpose |
| --- | --- | --- |
| `acl` | `string[]` | Query on behalf of an identity: results are restricted to documents that identity may retrieve. Send the caller's email (`["grace@acme.com"]`); `__public__` and the caller's `domain:` principal are added automatically. Omitted, empty, or `["*"]` disables filtering entirely, which is the default. See [Access Control](/essentials/v2/access-control). Default `null`. |

## 3. Tuning heuristics

The defaults usually work. When they do not, start here:

- `mode`: leave it unset (`"auto"`) for mixed traffic. Set `"fast"` or `"thinking"` explicitly when you know your traffic shape and want a deterministic pipeline.
- `alpha`: start at `0.8`. Lower it toward `0.3` to `0.5` when the query contains literal tokens (error codes, SKUs, product names). Raise it toward `0.9` for conceptual questions. Use `"auto"` when query shape varies across calls.
- `max_results`: start at `10`. Drop to `5` for tight context windows. Raise to `20` if you rerank or summarize downstream.
- `additional_context`: use it when the query alone is ambiguous. Keep it short and factual, such as known session state (page, feature, role). It sharpens retrieval without an extra call.
- `graph_context`: keep it on when answers depend on entity relationships (multi-hop questions, "how does X relate to Y"). Pair it with `mode: "thinking"`, because in `"fast"` mode the graph slice is shallow. Set it to `false` with `mode: "fast"` when you only need ranked chunks. `"thinking"` always includes the graph slice, whatever you send.

## 4. Minimal working example

A personalized answer takes one call: `POST /query` with `type: "all"` returns knowledge and memories from the scope you name, in one ranked result set. If shared knowledge lives in its own collection, list it next to the user's in `collections`. See [Multi-tenant](/essentials/v2/multi-tenant#shared-knowledge-plus-user-personalization).

### Setup

```bash
# Set your key as an environment variable - used in every request below
export HYDRA_DB_API_KEY="your_api_key"
# All requests: -H "Authorization: Bearer $HYDRA_DB_API_KEY" -H "API-Version: 2"
```

```typescript
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});
```

```python
import os
from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```

### One call for knowledge and memories

```bash
curl -X POST 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "collection": "user_john_123",
    "query": "How do I reset my password?",
    "type": "all",
    "query_by": "hybrid",
    "mode": "thinking",
    "max_results": 8,
    "graph_context": true
  }'
```

```typescript
const result = await client.query({
  database: "acme_corp",
  collection: "user_john_123",
  query: "How do I reset my password?",
  type: "all",
  queryBy: "hybrid",
  mode: "thinking",
  maxResults: 8,
  graphContext: true,
});
```

```python
result = client.query(
    database="acme_corp",
    collection="user_john_123",
    query="How do I reset my password?",
    type="all",
    query_by="hybrid",
    mode="thinking",
    max_results=8,
    graph_context=True,
)
```

### Merge into the LLM prompt

The response is one `RetrievalResult` with `chunks[]`, `sources[]`, and, when present, `graph_context` and `additional_context`. Knowledge and memory chunks are already interleaved and ranked, so you do not merge them yourself. The helper in [How to Use API Results](/essentials/v2/api-results) turns the result into a context string for your prompt:

```typescript
const context = buildContextString(result);

const completion = await openai.chat.completions.create({
  model: "gpt-4o",
  messages: [
    {
      role: "system",
      content: "Answer using only the provided context. Match the user's preferred style.",
    },
    {
      role: "user",
      content: `${context}\n\nQuestion: How do I reset my password?`,
    },
  ],
});
```

To query several users, teams, or workspaces at once, pass `collections` (see [Scope](#scope)). Weights apply before the final merged ranking. `max_results` caps the merged response across all selected collections, not each one:

```json
{
  "database": "acme_corp",
  "collections": {
    "workspace_42": 2,
    "user_john_123": 1
  },
  "query": "What context matters for this renewal?",
  "type": "all"
}
```

To format knowledge and memories differently in the prompt, call `/query` twice in parallel with `type: "knowledge"` and `type: "memory"`, then merge client-side.

### Production checklist

- **Use `type: "all"` for personalized answers:** one call instead of two, scoped with `collections`.
- **Set per-call timeouts:** generous for `thinking` (3 to 5 s), tight for `fast` (500 ms or less). For `mode: "auto"`, size the timeout for `thinking`, because auto can pick either pipeline and leans toward `thinking` when unsure.
- **App sources:** leave `query_apps` on (the default). Send `false` only to turn off the app lane.
- **Session state:** pass known page, feature, or role in `additional_context`.

## 5. Common mistakes

| Symptom | Cause | Fix |
| --- | --- | --- |
| Empty `query_paths` / `chunk_relations` | `graph_context` is off, or no relations exist for the result set | Set `graph_context: true`. Empty arrays are normal when there is nothing to return. See [Context Graphs](/essentials/v2/context-graphs). |
| Recent uploads do not appear in results | Indexing not finished | Poll `GET /context/status?ids=...&database=...`. Chunks are invisible until processing reaches at least `graph_creation`. |
| `metadata_filters` does not narrow results | The key is in the wrong namespace, the value does not match exactly, or a frequently used top-level field was not declared with `enable_match` | Top-level keys match `metadata`. Free-form per-document fields must be nested under `additional_metadata`. Declare frequently used filter keys in `database_metadata_schema` with `enable_match: true` before production ingest. |
| Memories missing from a `type: "knowledge"` query | Wrong store selected | Use `type: "memory"` or `type: "all"`. |
| Recency does not seem to matter, or matters too much | Omitting `recency_bias` applies a mild `0.4` tilt | Set it explicitly. Raise it toward `1.0` for a stronger boost, or send `0` to turn it off. |
| `400`: "operator is only valid with query_by=text" | `operator` is `"and"` or `"phrase"` but `query_by` is not `"text"` | `operator` applies only to BM25 text query. Switch `query_by` to `"text"`. |
| `query_forceful_relations` ignored | Request uses `mode: "fast"`, or `"auto"` routed the query to fast | Forceful-relation context is fetched only in thinking mode. Set `mode: "thinking"`. |
| `graph_context: false` ignored | `mode` is `"thinking"`, or `"auto"` (the default) routed the query to thinking | Thinking always includes the graph slice. Use `mode: "fast"` to drop it. |
| Expected a deterministic `fast` or `thinking` pipeline, got auto-routed instead | `mode` was omitted | Omitting `mode` defaults to `"auto"`. Set `mode` to `"fast"` or `"thinking"` to turn off automatic routing. |

## 6. Advanced patterns

- **Hybrid and text in two parallel calls:** when a query mixes a literal token (error code, SKU, function name) with natural-language intent, run `query_by: "hybrid"` and `query_by: "text"` in parallel, dedupe by chunk ID, and treat text hits as results you must include.
- **Recall, then rerank:** ask for more chunks than you need (`max_results: 20`) and apply your own reranker (recency windows, compliance filters, business rules) before you pick the final top-k for the prompt.
- **Cache the prompt context:** if the same query repeats inside a session, cache the `RetrievalResult` keyed by `(database, collection, query, type, query_by)`.
