The SDKs wrap every endpoint in the [API Reference](/api-reference/v2) with typed methods and IDE autocomplete. They automatically set the `API-Version: 2` header on every request, so you do not need to send it manually.

## Installation

Install version 2 of the Python or TypeScript SDK:

<CodeGroup>
```bash Python SDK
pip install "hydradb-sdk>=2.1.7,<3"
```
```bash TypeScript / Node.js
npm install @hydradb/sdk@^2.1.7
```
</CodeGroup>

## Client setup

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```
```python Python (Async)
import os
from hydra_db import AsyncHydraDB

async_client = AsyncHydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```
```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});
```
</CodeGroup>

**Python:** Both synchronous (`HydraDB`) and asynchronous (`AsyncHydraDB`) clients are available. They expose the same methods; use `AsyncHydraDB` with `await`.

## Naming conventions

The REST API and Python SDK use **snake_case** for request and response fields. The TypeScript SDK uses **camelCase** for multi-word method names and fields in typed request and response objects.

| | Method naming | Parameter field naming | Example |
|---|---|---|---|
| **Raw HTTP / cURL** | N/A | snake_case | `database`, `collection`, `query_by` |
| **Python SDK** | snake_case | snake_case | method: `query()`, params: `database`, `query_by` |
| **TypeScript SDK** | camelCase for multi-word methods | camelCase | method: `query()`, params: `database`, `queryBy` |

For example, use `client.context.list({ database: "...", pageSize: 50 })` in TypeScript. The SDK sends `page_size` to the API and drops unrecognized typed fields, including a caller-supplied `page_size`.

JSON strings (`documentMetadata`, `memories`, `appKnowledge`) and free-form maps (`metadataFilters` and a connector resource update's `body`) are sent as written. Use REST field names inside them, such as `additional_metadata` or `custom_instructions`, and preserve your own metadata keys.

The Python SDK also uses snake_case throughout (e.g., `client.context.list(database="...", page_size=50)`).

`database` and `collection` are the current field names (formerly `tenant_id` and `sub_tenant_id`). The old names remain accepted as deprecated aliases for full backward compatibility.

## SDK method structure

SDK methods are grouped under top-level namespaces, one per `/api-reference/v2` group:

| URL prefix | SDK group | Purpose |
|---|---|---|
| `/context/*` and `/context` | `client.context` | Ingest, status, fetch, list, delete, metadata updates, graph relations, subgraph |
| `/query` | `client.query` | Unified retrieval over knowledge, memories, or both |
| `/feedback` | `client.feedback` | Feedback on query results |
| `/databases/*` and `/databases` | `client.databases` | Create, list, delete, status, collections, stats, collection deletion, metadata schema. Legacy `/tenants/*` paths remain as deprecated aliases. |
| `/connectors/*` and `/connectors` | `client.connectors` | Create, configure, sync, and manage app connectors. `GET /connectors/providers` is `client.list_providers()`. |
| `/webhooks/indexing*` | `client.webhooks` | Register, inspect, test, and delete the indexing webhook; list and retry deliveries |

## Getting started

### Create a database

A database isolates context for a customer, environment, or product. See [Multi-tenancy](/essentials/v2/multi-tenant) for guidance on choosing database and collection scopes.

<CodeGroup>
```python Python SDK
response = client.databases.create(
    database="my_first_database",
    database_metadata_schema=[
        {"name": "department", "data_type": "VARCHAR"},
    ],
)
```
```python Python (Async)
import asyncio

async def create_database():
    return await async_client.databases.create(
        database="my_first_database",
        database_metadata_schema=[{"name": "department", "data_type": "VARCHAR"}],
    )

response = asyncio.run(create_database())
```
```typescript TypeScript SDK
const response = await client.databases.create({
  database: "my_first_database",
  databaseMetadataSchema: [
    { name: "department", dataType: "VARCHAR" },
  ],
});
```
</CodeGroup>

Database creation is asynchronous. Poll [`databases.status`](/api-reference/v2/endpoint/tenant-status) until provisioning completes:

<CodeGroup>
```python Python SDK
import time

while True:
    status = client.databases.status(database="my_first_database")
    if status.data.infra.ready_for_ingestion:
        break
    time.sleep(2)
```
```typescript TypeScript SDK
while (true) {
  const status = await client.databases.status({
    database: "my_first_database",
  });
  // Response fields are optional in the TypeScript types.
  if (status.data?.infra?.readyForIngestion) break;
  await new Promise((r) => setTimeout(r, 2000));
}
```
</CodeGroup>

### Ingest knowledge

Upload documents, app sources, or both in one call:

<CodeGroup>
```python Python SDK
import json

with open("contract.pdf", "rb") as f1, open("policy.pdf", "rb") as f2:
    result = client.context.ingest(
        type="knowledge",
        database="my_first_database",
        collection="company_docs",
        documents=[
            ("contract.pdf", f1, "application/pdf"),
            ("policy.pdf", f2, "application/pdf"),
        ],
        document_metadata=json.dumps([
            {
                "id": "contract_q4",
                "metadata": {"department": "legal"},
                "additional_metadata": {"author": "Alice"},
            },
            {
                "id": "policy_2025",
                "metadata": {"department": "legal"},
                "additional_metadata": {"author": "Bob"},
            },
        ]),
    )
```
```typescript TypeScript SDK
const result = await client.context.ingest({
  type: "knowledge",
  database: "my_first_database",
  collection: "company_docs",
  documents: [
    { path: "contract.pdf", filename: "contract.pdf", contentType: "application/pdf" },
    { path: "policy.pdf", filename: "policy.pdf", contentType: "application/pdf" },
  ],
  documentMetadata: JSON.stringify([
    {
      id: "contract_q4",
      metadata: { department: "legal" },
      additional_metadata: { author: "Alice" },
    },
    {
      id: "policy_2025",
      metadata: { department: "legal" },
      additional_metadata: { author: "Bob" },
    },
  ]),
});
```
</CodeGroup>

For app sources (Slack, Notion, Gmail, webpages), pass `app_knowledge` instead of `documents`. You can combine both in a single request.

### Add user memories

Use the same `ingest` method with `type: "memory"`:

```python Python SDK
result = client.context.ingest(

            "id": "alex_preferences",
            "text": "User prefers detailed technical explanations and dark mode",
            "infer": True,
            "user_name": "Alex",
            "metadata": {"department": "engineering"},
            "additional_metadata": {"source": "onboarding"},

```
```typescript TypeScript SDK
const result = await client.context.ingest({
  type: "memory",
  database: "my_first_database",
```

### Wait for indexing

Wait until the documents and memories are indexed before querying them. Check each collection separately, using the IDs supplied at ingestion or returned in `data.results`.

<CodeGroup>
```python Python SDK
import time

def wait_for_indexing(collection, ids):
    while True:
        result = client.context.status(
            database="my_first_database", collection=collection, ids=ids,
        )
        statuses = [item.indexing_status for item in result.data.statuses]
        if any(status == "errored" for status in statuses):
            raise RuntimeError("Indexing failed; check the status response for details.")
        if len(statuses) == len(ids) and all(status == "completed" for status in statuses):
            return
        time.sleep(2)

wait_for_indexing("company_docs", ["contract_q4", "policy_2025"])
wait_for_indexing("user_alex", ["alex_preferences"])
```
```typescript TypeScript SDK
async function waitForIndexing(collection: string, ids: string[]) {
  while (true) {
    const result = await client.context.status({
      database: "my_first_database", collection, ids,
    });
    const statuses = result.data?.statuses?.map((item) => item.indexingStatus) ?? [];
    if (statuses.some((status) => status === "errored")) {
      throw new Error("Indexing failed; check the status response for details.");
    }
    if (statuses.length === ids.length && statuses.every((status) => status === "completed")) return;
    await new Promise((resolve) => setTimeout(resolve, 2000));
  }
}

await waitForIndexing("company_docs", ["contract_q4", "policy_2025"]);
await waitForIndexing("user_alex", ["alex_preferences"]);
```
</CodeGroup>

### Query

A single method covers every retrieval pattern: switch `type` and `query_by` to control behavior:

<CodeGroup>
```python Python SDK

knowledge = client.query(
    database="my_first_database",
    collection="company_docs",
    query="What is our refund policy?",
    type="knowledge",
    query_by="hybrid",
    mode="thinking",
    graph_context=True,

# Shared knowledge and this user's memories
personalized = client.query(
    database="my_first_database",

    type="all",
    query_by="hybrid",
    mode="thinking",
)

# Exact-phrase BM25 search
exact = client.query(
    database="my_first_database",
    collection="company_docs",
    query="ERROR_429 rate limit",
    type="knowledge",
    query_by="text",
    operator="phrase",
)
```

## Response envelope

All responses, except connector endpoints and `PATCH /databases/{database}/metadata-schema`, are wrapped in a consistent envelope:

```json
{
  "success": true,
  "data": {
    "message": "Success"
  },
  "error": null,
  "meta": {
    "request_id": "<uuid>",
    "latency_ms": 12.3
  }
}
```

The SDKs return the full envelope. Read the payload from the `data` field (e.g. `response.data`); on failure the SDK raises a typed exception instead of returning an envelope with `error` populated.

### Object labels and SDK types

Throughout the API reference, `object` and `object[]` describe JSON values, not an untyped SDK return value. Expand **Show child attributes** to see the fields of a fixed structure. The SDKs generate named models from those same schemas; the reference does not invent separate names such as `Result object` or `Alias expansion.object`.

| Response value | Reference label | Python and TypeScript model |
|---|---|---|
| Query `data`, for structured results | `object` | `SearchV2RetrievalResult` |
| Query `data.alias_expansions` elements | `object[]` | `SearchAliasExpansionNote` |
| List Context `data` | `object` | `ListV2ListResponse` |

Python exposes these models from `hydra_db.types`; TypeScript exposes them in the `HydraDB` namespace from `@hydradb/sdk`. Python fields use snake_case (`alias_expansions`), while TypeScript fields use camelCase (`aliasExpansions`). Query `data` can also be a string when `response_format` is `markdown`, so narrow that union before reading structured fields.

Customer-defined maps, such as `metadata` and `additional_metadata`, intentionally allow arbitrary keys and values. Their contents cannot have fixed property autocomplete; the surrounding response and its known fields still have declared types. An SDK update must be released before improvements to the generated models reach installed packages.

## Error handling

Both SDKs throw exceptions for non-2xx responses. Error objects expose the envelope's `error` payload:

<CodeGroup>
```python Python SDK
from hydra_db.core.api_error import ApiError
from hydra_db.errors import NotFoundError

try:
    result = client.query(
        database="my_first_database",
        query="...",
        type="knowledge",
    )
except NotFoundError:
    # Handle missing database / resource (HTTP 404)
    pass
except ApiError as exc:
    if exc.status_code == 429:
        # Rate limit: retry with backoff
        pass
    else:
        raise
```

```typescript TypeScript SDK
import { HydraDBError } from "@hydradb/sdk";

try {
  const result = await client.query({
    database: "my_first_database",
    query: "...",
    type: "knowledge",
  });
} catch (error) {
  if (error instanceof HydraDBError) {
    // error.body is typed `unknown`; it holds the raw snake_case error envelope.
    const code = (error.body as { error?: { code?: string } } | undefined)?.error?.code;

    if (code === "DATABASE_NOT_FOUND") {
      // Handle missing database
    } else if (error.statusCode === 429) {
      // Rate limit: retry with backoff
    } else {
      throw error;
    }
  } else {
    throw error;
  }
}
```
</CodeGroup>

The Python SDK raises a typed exception per status from `hydra_db.errors`. Each subclasses `ApiError` and carries `status_code`, `headers`, and the parsed response `body`, from which you can read `body["error"]["code"]`.

Not every status has its own class: `401` and `429` do not. Catch the base `ApiError` and branch on `status_code`, as above, whenever you need to handle those.

For the full list of error codes and retry patterns, see [Error Responses](/api-reference/v2/error-responses).
