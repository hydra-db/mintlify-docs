Use the PagerDuty connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `incidents`
- `schedules`
- `escalation_policies`

## Connect

1. Create a READ-ONLY REST API key: PagerDuty → Integrations → API Access Keys → Create New API Key, and tick Read-only. This connector never writes, and a full-access key would let a leaked token trigger or resolve real incidents.
2. Set the email field to the account the key belongs to. PagerDuty sends it as the From header and rejects calls where it does not match a real user, so a mistyped address fails every request rather than some of them.
3. Mint the key at the ACCOUNT level, not scoped to a single user. A user-scoped key cannot list services, so discovery returns nothing and there is no way to choose what to sync; an empty picker is what that mistake looks like.
4. Services are picked after connecting. Incidents are scoped to the services you select, including their alerts, notes and status updates; schedules and escalation policies are account-wide and always synced, which is what makes "who is on call" answerable.
5. Incident notes and status updates are indexed by default because they are where the human response text lives. Turn off fetch_incident_prose if you would rather not index them, or to cut the per-incident request count on a very large account. Disabling excludes the note text; the fact that a note was added stays visible in the incident timeline.
6. With permission-aware search on, each service is readable by PagerDuty owners and admins, and by everyone else only from inside one of its teams (a service on no team is readable by every role that reads public services). Schedules and escalation policies carry the same rule over their own teams and are refreshed every sync. PagerDuty's API does not say whether a team is private, so a Manager, Responder or Observer outside a team does not see its services here even when the team is public. The read-only key must be able to read users, teams, services, schedules and escalation policies; when it cannot, the service is readable by everyone in your workspace, with a warning on the connector, until you reconnect or set an access rule on it.

Use provider `pagerduty` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
