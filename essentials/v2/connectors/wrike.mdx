Sync tasks and their comments from the Wrike spaces you select, including tasks anywhere inside each space. Each task is one document with its description and status. Each comment on a task is its own document, linked to the task. A subtask links to each of its parent tasks.

Wrike sharing is not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Assignees, folders, projects, custom fields and attachments are not synced. Tasks and comments deleted in Wrike can stay in HydraDB.

## Permissions

<Warning>
Wrike permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Wrike sharing is not captured. Set an access rule on each space that should be restricted.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Wrike uses a permanent access token.

<ResponseField name="token" type="secret string" required>
A Wrike permanent access token.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create a token">
    In Wrike, open Apps and Integrations, API, and create a permanent access token for a user who can see the spaces you will select.
  </Step>
  <Step title="Create the connector">
    Paste the token as `token`.
  </Step>
  <Step title="Select spaces">
    HydraDB lists your Wrike spaces. Select the spaces to sync. Tasks anywhere inside a selected space are synced.
  </Step>
</Steps>

One connector reads what one token's Wrike user can see.

<Accordion title="Connect through the API">

Use provider `wrike` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected space reads back the window set by `lookback_days`, 30 days by default, measured on when tasks were last updated.
- **New and changed items:** Each sync reads the tasks updated since the last sync in each selected space. It then reads the comments on those tasks and keeps the ones updated since the last sync.
- **Edits:** An edited task is picked up through its last-updated time and updates its document. An edited comment is picked up only when its task is read in the same sync, so a comment edit can be missed.
- **Deletions:** Tasks and comments deleted in Wrike can stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Wrike item

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `wrike`. Not searchable.
</ResponseField>

### Tasks

- **One document:** One Wrike task. Its comments are separate documents.
- **Title:** The task title, or `Wrike task` and its id when the title is empty.
- **Text:** The task description as plain text, or the brief description when there is none. The status and the task id are written as lines too. The title is searchable too.
- **Date:** When the task was last updated, or when it was created if there is no update time.
- **Link back:** The task's Wrike permalink.
- **Files:** Attachments are not synced.

<ResponseField name="Task id" type="Searchable text">
The Wrike task id. It keeps later syncs on the same document.
</ResponseField>

<ResponseField name="status" type="Searchable text">
`Active`, `Completed`, `Deferred` or `Cancelled`, written as the `Status` line.
</ResponseField>

<ResponseField name="updated_date" type="Result date">
When the task was last updated. Sets the result date and decides when a sync picks the task up. Not searchable.
</ResponseField>

<ResponseField name="Parent tasks" type="Graph connection">
The tasks this task is a subtask of. A task can have several. Links the task to each parent. Not searchable.
</ResponseField>

<ResponseField name="mentions" type="Graph identity">
Names of people @mentioned in the description, leaving out group mentions. The graph records each as mentioned by the task. The field itself is not searchable, but the description is.
</ResponseField>

<ResponseField name="additional_metadata.wrike_task_id" type="Query filter">
The Wrike task id. Picks out one task. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="importance" type="Stored only">
`High`, `Normal` or `Low`. It is not written into the text.
</ResponseField>

<ResponseField name="created_date" type="Stored only">
When the task was created. It is not written into the text.
</ResponseField>

<ResponseField name="completed_date" type="Stored only">
When the task was completed.
</ResponseField>

</Accordion>

### Comments

- **One document:** One comment on a task.
- **Title:** `Wrike comment` and the comment id. The title carries no content, so search matches the comment text.
- **Text:** The comment as plain text. The author and the task id are written with it.
- **Date:** When the comment was created, or updated if there is no creation time.
- **Link back:** None.

<ResponseField name="author" type="Searchable text, Graph identity">
The author's first and last name from Wrike contacts, or the author's id when no name is found, written as the `Author` line. The graph records the comment as written by that person.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
The id of the task the comment is on, written as the `Parent` line. Links the comment to that task, so a task and its discussion are found together.
</ResponseField>

<ResponseField name="mentions" type="Graph identity">
Names of people @mentioned in the comment. The graph records each as mentioned. The field itself is not searchable, but the comment text is.
</ResponseField>

<ResponseField name="additional_metadata.wrike_comment_id" type="Query filter">
The Wrike comment id. Picks out one comment. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.wrike_task_id" type="Query filter">
The id of the task. Returns every comment on one task. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="author_id" type="Stored only">
The author's Wrike contact id.
</ResponseField>

<ResponseField name="created_date, updated_date" type="Stored only">
When the comment was created and last updated, as Wrike sends them.
</ResponseField>

</Accordion>

**Example searches**

- What does the Wrike task about the vendor contract say?
- Which Wrike tasks are Deferred?
- Who commented on the budget review task?

## How it fits into the graph

- Tasks use the Ticket class.
- Comments use the Comment class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Wrike creates**

- A subtask to each of its parent tasks.
- A comment to its task.
- No links to items in other tools.

**People and groups**

- The author of each comment.
- People @mentioned in task descriptions and comments.
- Task assignees are not synced.

**Found in the text**

Task descriptions and comment text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Spaces you did not select.
- Folders, projects and spaces as items of their own.
- Comments on folders and projects.
- Task assignees, custom fields and dependencies.
- Attachments.
- Timelogs, workflows and custom field definitions.
