Sync the rows of every table in the Airtable bases you select. Each row is one document, with its field values written as labelled lines of text. A linked-record field links the row to the rows it references. Attachment file names are searchable, and a file's text can be added when it can be downloaded and read.

Airtable permissions are not imported, so every synced row is visible to everyone who can query the collection unless you set an access rule. You cannot pick single tables: every table in a selected base is synced. A row's date is when it was created, not when it was last edited. Rows deleted in Airtable stay in HydraDB.

<Note>
Airtable is in beta.
</Note>

## Permissions

<Warning>
Airtable permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Airtable base and workspace collaborators, sharing and interface permissions are not reproduced. Set an access rule on each base that must be restricted.
- Every synced row carries `additional_metadata.rbac_warning`, a notice that Airtable collaborators were not captured.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Airtable uses a personal access token.

<ResponseField name="token" type="secret string" required>
An Airtable personal access token with the scopes below and access to the bases you want synced.
</ResponseField>

Personal access tokens do not refresh. To rotate one, create a replacement with the same scopes and bases, update the connector, check that the bases still list and sync, then revoke the old token.

**Scopes for the token**

- `data.records:read`: reads the rows of each table.
- `schema.bases:read`: lists bases, their tables and their fields.

Scopes alone do not open a base. Add every base you want synced to the token.

### Set it up

<Steps>
  <Step title="Create a personal access token">
    In Airtable, create a personal access token with `data.records:read` and `schema.bases:read`.
  </Step>
  <Step title="Give it your bases">
    Add every base you want synced to the token.
  </Step>
  <Step title="Create the connector">
    Paste the token as `token`.
  </Step>
  <Step title="Select bases">
    HydraDB lists the bases the token can reach. Select the bases to sync. Every table in a selected base is synced. To reach rows older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads the bases one personal access token can reach.

<Accordion title="Connect through the API">

Use provider `airtable` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected base reads back the window set by `lookback_days`, 30 days by default, measured by each row's last modified time.
- **New and changed items:** Each sync reads every table in the base and picks up the rows modified since the last sync.
- **Edits:** A modified row is sent again and replaces its document. A formula or rollup value that changes because of another table, or because time passed, does not count as a modification of the row. It stays out of date until the row itself is edited.
- **Deletions:** Deleted rows are not removed. A row deleted in Airtable stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

<Warning>
Give every field in a table a distinct name. Field names are lowercased and their spaces and punctuation simplified before they are written. Two fields whose names then match can overwrite each other, and a field whose name becomes `id` can replace the record id that identifies the row.
</Warning>

### Rows

- **One document:** One row of a table in a selected base.
- **Title:** The row's field named `name`, `title` or `subject`. Otherwise the first non-empty field in alphabetical order, skipping linked-record fields. A row with none is titled `Airtable record` and its id.
- **Text:** The title, then one line per non-empty field in alphabetical order, as the field name in title case and its value. Lists are joined with commas. An object shows its name, title, text, file name, email or URL. An attachment field shows file names only. Linked-record fields are left out of the text, because they become graph connections. Numbers are written with at most six decimal places. Fields are searchable as text, not as separate filters.
- **Date:** When the row was created. Airtable rows carry no last-edited time.
- **Link back:** None.
- **Files:** Files in attachment fields are downloaded and read when they are hosted by Airtable, can be downloaded and are of a supported type. A file that is missing, too large or unsupported keeps only its name in the row text.

<ResponseField name="Attachments" type="Searchable text">
File names in the row text, plus the text read from each file that could be read.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the row was created. Used as the result date, so ranking by date reflects creation, not the last edit. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
The table as base id and table id joined by a colon. Limits a query to one table, and stays the same when the table is renamed. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_name" type="Query filter">
The table name. Limits a query to one table by name. Two tables can share a name, so use the id keys to tell them apart. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
Always `table`. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.airtable_base_id" type="Query filter">
The base id, which starts with `app`. Limits a query to one base. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.airtable_table_id" type="Query filter">
The table id. Limits a query to one table by id. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.rbac_warning" type="Query filter">
A notice that Airtable collaborators were not captured. Present on every row. It neither grants nor denies access. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's rows. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `airtable`. Not searchable.
</ResponseField>

<ResponseField name="Linked records" type="Graph connection">
Each linked-record field links the row to the rows it references, across tables in the same base. The field is not kept as searchable text. Not searchable.
</ResponseField>

**Example searches**

- Which rows in the Customers table are on the Enterprise plan?
- What is the status and owner of the Website relaunch project?
- Which tasks are linked to the Q3 Launch project?

## How it fits into the graph

- Rows use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Airtable creates**

- A row to each row it references through a linked-record field, across tables in the same base.
- No links to items in other tools.

**People and groups**

- No people are attached. Collaborator, user and person fields are written as text, by name or email.

**Found in the text**

Every field value in the row's text, and the text read from attached files. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Bases you did not select.
- Rows last modified before the `lookback_days` window on the first sync.
- Comments on records and revision history.
- Base and workspace collaborators.
- Field types and field descriptions.
- A link back to the row in Airtable.
- Deletions: deleted rows stay in HydraDB.
