Use the ClickUp connector to bring the following content into HydraDB.

## What syncs

The provider description lists these indexed object types:

- `team`
- `task`
- `task_comment`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Create a personal API token under avatar → Settings → Apps → API Token. ClickUp personal tokens have no scope picker and inherit the user; use a dedicated account that can open every Workspace you intend to select.
2. ClickUp personal tokens have no refresh flow. Rotate by generating a replacement, updating the connector, verifying discovery and sync, and then revoking the old token; an OAuth installation must use ClickUp's refresh-token lifecycle instead.
3. Pick Workspaces after connecting. Tasks and subtasks are indexed with descriptions, status, assignees, priority, tags and list/folder context. Task comments are indexed as first-class comment documents with human author and parent-task context. ClickUp limits personal and OAuth tokens per Workspace plan, starting at 100 requests/minute on Free, Unlimited and Business.
4. HydraDB does not currently reproduce ClickUp guest or private Space/List/Task visibility. Synced tasks and comments are tenant-wide under the current fail-open policy, carry a persistent rbac_warning, and can be restricted with a HydraDB resource ACL for the selected Workspace.

Use provider `clickup` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
