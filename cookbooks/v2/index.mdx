Each benchmark, its headline result, the metric, and what it tests:

| Benchmark | Result | Metric | What it tests |
| --- | --- | --- | --- |
| [EnterpriseRAG-Bench](https://benchmarks.hydradb.com/enterprise-rag-bench) | 88.7 overall | Answer correctness and completeness | Company knowledge across nine fragmented systems |
| [KyroBench](https://benchmarks.hydradb.com/kyrobench) | 0.776 nDCG | Retrieval ranking quality | The current, in-scope source ranked above stale and out-of-scope copies |
| [CodeWikiBench](https://benchmarks.hydradb.com/codewiki-bench) | 90.73 / 100 | Generated documentation quality | A repository understood as a graph |
| [LongMemEval-S](https://benchmarks.hydradb.com/longmemeval) | 90.79% | Answer accuracy | Facts and preferences kept current across about 50 sessions |
| [BEAM 1M](https://benchmarks.hydradb.com/beam-1m) | 82% overall | Average score across ten memory tasks | Decisions, tasks, and events tracked over months |

| [FinanceBench](https://benchmarks.hydradb.com/financebench) | 91.4% recall@10 | Retrieval recall | Exact figures in dense filings |

The mapping is ours. These reports measure retrieval, answer accuracy, or generated documentation. They do not benchmark these exact cookbook applications. Results are self-reported; each report states its setup.

## How the cookbooks work

Every cookbook follows the same five steps, which are the whole HydraDB loop:

1. Create a database.
2. Ingest context with [`POST /context/ingest`](/api-reference/v2/endpoint/ingest-context).
3. Wait for indexing.
4. Query with [`POST /query`](/api-reference/v2/endpoint/query).
5. Pass the result to a model.

Each cookbook ingests a few sample sources, so it runs with a HydraDB API key and an OpenAI API key. The exception is Cursor, which indexes a repository you point it at. To use your own data, replace the samples or connect the app with a [connector](/essentials/v2/connectors). New to HydraDB? Start with the [Quickstart](/get-started/v2/quickstart).
