title: "Update Source Metadata"
description: "Merge database metadata and additional metadata into one existing source without re-ingesting it."
openapi: "api-reference/v2/openapi.json PATCH /context/{id}/metadata"
---

import { Field } from "/snippets/field.jsx";

Change one source's metadata in place, by ID, without re-ingesting its content. HydraDB updates the source row and its indexed chunk metadata, so [`/query`](/api-reference/v2/endpoint/query) metadata filters and [`/context/list`](/api-reference/v2/endpoint/list-documents) filters see the change.

```http
PATCH /context/{id}/metadata
```

<Note>
  The legacy route `PATCH /context/sources/{source_id}/metadata` still works but is deprecated, so migrate to the route above. Both dispatch to the same handler; `source_id` and `id` name the same value.
</Note>

<RequestExample>

```bash cURL
curl -X PATCH 'https://api.hydradb.com/context/policy_main/metadata' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "acme_corp",
    "collection": "team_docs",
    "database_metadata": {
      "department": "legal",
      "priority": 7
    },
    "additional_metadata": {
      "author": "Legal Team",
      "doc_version": 3
    }
  }'
```

```python Python SDK
result = client.context.update_source_metadata(
    "policy_main",
    database="acme_corp",
    collection="team_docs",
    database_metadata={"department": "legal", "priority": 7},
    additional_metadata={"author": "Legal Team", "doc_version": 3},
)
```

```typescript TypeScript SDK
const result = await client.context.updateSourceMetadata({
  id: "policy_main",
  database: "acme_corp",
  collection: "team_docs",
  databaseMetadata: { department: "legal", priority: 7 },
  additionalMetadata: { author: "Legal Team", doc_version: 3 },
});
```

</RequestExample>

## Request

### Path parameters

| Name | Description |
| --- | --- |
| <Field name="id" type="string" required /> | Existing source ID to update. This is the `id` you supplied at ingest, or the source ID returned by HydraDB. |

### Body

| Name | Description |
| --- | --- |
| <Field name="database" type="string" required /> | Owning database. (deprecated alias: `tenant_id`) |
| <Field name="collection" type="string" required /> | Collection that contains the source. This endpoint does not default it. (deprecated alias: `sub_tenant_id`) |
| <Field name="database_metadata" type="object" /> | Schema-backed metadata fields to merge into the source's `metadata`. Keys must satisfy the tenant metadata schema when one exists. (deprecated alias: `tenant_metadata`) |
| <Field name="additional_metadata" type="object" /> | Free-form metadata fields to merge into the source's `additional_metadata`. |
| <Field name="acl" type="string[] or null" /> | Replaces the source's access-control list. Send the complete new list. `[]` or `null` revokes access for everyone. Omit it to leave the stored list unchanged. See [Access Control](/essentials/v2/access-control). |

At least one of `database_metadata`, `additional_metadata`, or `acl` is required.

<Warning>
  Send schema-backed fields as `database_metadata`. The shorter `metadata` field from ingest and list is not accepted in this body. `tenant_metadata` still works as a deprecated alias; if you send both, `database_metadata` wins.

  `document_metadata` is **not accepted** here either: any non-null value returns `400`, whatever its size. It is an alias for `additional_metadata` on [`/context/ingest`](/api-reference/v2/endpoint/ingest-context) only. Send `additional_metadata`.
</Warning>

## Behavior

- **Merge, not replace:** keys you send are inserted or overwritten. Keys you omit are kept. `acl` is the exception: it replaces the stored list.
- **Existing sources only:** the source must already exist. This endpoint does not create sources.
- **One source per call:** bulk metadata edits are not supported.
- **Dense or sparse fields:** if an edited tenant metadata field has `enable_dense_embedding` or `enable_sparse_embedding`, HydraDB synchronously refreshes the matching vector store metadata search lane.
- **Match-only fields:** if the edited fields are `enable_match` only, the edit stays MongoDB-only and `vector_sync_required` is `false`.

## Validation and errors

- **`400`:** missing `database`, missing `collection`, empty metadata payload, `document_metadata` sent, unknown tenant metadata key when a schema exists, wrong type, reserved key, payload over the size limit, nesting too deep, or `null` for a dense or sparse enabled field.
- **`404`:** no source with this `id` in the `(database, collection)` scope.
- **`500`:** the edit failed. Retry it.

If the metadata is saved but the dense or sparse vector store sync fails, the call still returns `200`. `vector_synced` is absent and `vector_sync_error` explains why. Retry the same edit; it is idempotent and converges.

### Size limits

`database_metadata` (and its `tenant_metadata` alias) is capped at **16 KiB**, and `additional_metadata` at **1 KiB**. Each cap covers the whole map, measured as compact JSON in UTF-8 bytes. Keys, quotes, and punctuation count, so budget in bytes, not characters of content.

The cap applies to the payload in **this** request, before the merge, not to the stored map the merge produces. A small edit to an already large map is accepted, so treat the cap as a per-request budget, not a limit on the final stored size. Over the cap, the whole edit fails with `400` and the message reports both numbers:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_INPUT",
    "message": "invalid metadata edit: additional_metadata is too large (1065 bytes when serialized; the maximum is 1024). Reduce the number or size of metadata fields."
  }
}
```

See [Size limits](/essentials/v2/metadata#size-limits) in Scoping using metadata.
