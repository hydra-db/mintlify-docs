## The decision table

| Data you have | Store | Why |
|---|---|---|
| Slack messages (org-wide) | Knowledge | Shared across all users |
| Notion pages / wikis | Knowledge | Shared reference docs |
| PDF files, runbooks, policies | Knowledge | Shared, versioned content |
| User's raw chat history | Memory + `infer: true` | Per-user, behavioral signal |
| User's stated preference | Memory + `infer: false` | Already a structured fact |
| CRM notes tied to one user | Memory | User-scoped context |
| You need both in one query | Both | Use `type: "all"` at query time |

**The one question:** "Should every user in this database be able to retrieve this?"

- **Yes** → Knowledge
- **No** → Memory

---

## What goes wrong when you pick wrong

**Shared doc stored as Memory:** It won't surface when any agent calls `type: "knowledge"` or `type: "all"` without a `collection` match. It also counts against per-user memory, adding noise.

**Per-user data stored as Knowledge:** Every user in the database can retrieve it. Preferences, plan tiers, and personal history intended for one user bleed across the entire workspace.
