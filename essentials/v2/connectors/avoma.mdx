Sync the recorded meetings and scorecard reviews an Avoma API key can see. Each meeting is one document with its details, Avoma's AI summary and the transcript, each line labelled with its speaker. Each answered scorecard review is its own document, linked to the meeting it reviews.

Avoma permissions are not imported, so private meetings are visible to everyone who can query the collection unless you set an access rule. Changes are picked up only for a short time: 2 hours for meetings and 7 days for reviews. A transcript or summary that arrives after the 2-hour window is not picked up. Meetings deleted in Avoma can stay in HydraDB.

## Permissions

<Warning>
Avoma permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Private meetings that only some Avoma users can see are synced like any other meeting when the key has Organization scope.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

<Warning>
Create the API key with Organization scope to sync everyone's meetings. A key's scope cannot be changed after it is created, and a key with a narrower scope syncs only the meetings that scope allows.
</Warning>

### Credentials

Avoma uses an API key. Only an Avoma admin can create one.

<ResponseField name="api_key" type="secret string" required>
The whole Avoma API key exactly as issued: both parts, with the colon between them.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create an API key">
    Have an Avoma admin create an API key with Organization scope.
  </Step>
  <Step title="Create the connector">
    Paste the whole key as `api_key`, including both parts and the colon.
  </Step>
  <Step title="Select the organization">
    HydraDB lists one item for all the meetings and reviews the key can see. Select it. You cannot pick individual meetings.
  </Step>
</Steps>

One connector reads the meetings its API key's scope allows in one Avoma organization.

<Accordion title="Connect through the API">

Use provider `avoma` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads meetings and reviews from the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads meetings by start time and reviews by creation time. It reaches 2 hours back for meetings and 7 days back for reviews, to pick up recent changes.
- **Edits:** Changes are picked up only inside those windows. A transcript or summary that arrives after the 2-hour window is not picked up. A review with no answers yet is skipped, and is picked up if it is answered within the 7 days. A change to a meeting does not update its reviews.
- **Deletions:** Meetings and reviews deleted in Avoma can stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Avoma item

Limits a query to this connector's meetings and reviews. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `avoma`. Not searchable.

### Meetings

- **One document:** One meeting, with its summary and full transcript.
- **Title:** The meeting subject, or `Avoma meeting <id>` when it has none.
- **Text:** The title, then `Purpose`, `When`, `Organizer` and `Attendees` lines. Then Avoma's AI summary under `Summary`, and the transcript under `Transcript` as one `Speaker: text` line per segment. The title is searchable too.
- **Date:** When the meeting started, else when it was created.
- **Link back:** The meeting in Avoma's web app.
- **Files:** None. Recordings are not downloaded.

<ResponseField name="summary" type="Searchable text">
Avoma's AI summary, written under `Summary`.
</ResponseField>

<ResponseField name="purpose" type="Searchable text">
The meeting's purpose or template label, written as the `Purpose` line.
</ResponseField>

<ResponseField name="organizer" type="Searchable text">
The organizer's name or email, written as the `Organizer` line. The organizer is not attached to the meeting as a person in the graph.
</ResponseField>

<ResponseField name="attendees" type="Searchable text">
Attendee names, written as the `Attendees` line. Attendees are not attached to the meeting as people in the graph.
</ResponseField>

</ResponseField>

<ResponseField name="additional_metadata.avoma_meeting_id" type="Query filter">

<ResponseField name="additional_metadata.recording_uuid" type="Query filter">

### Scorecard reviews

- **One document:** One scorecard review of one meeting. A review with no answers yet is skipped.
- **Title:** The scorecard template name, or `Scorecard review` when it has none, followed by the meeting subject when there is one.
- **Text:** The title, then `Meeting`, `Reviewed`, `Reviewer` and `Overall score` lines. Then each question in order, with its score, answer and reasoning. Avoma's citation markers are removed. The title is searchable too.
- **Date:** When the review was created, else when the meeting started.
- **Link back:** None.

<ResponseField name="scorecard_name" type="Searchable text">
The scorecard template's name, written in the title.
</ResponseField>

<ResponseField name="meeting_subject" type="Searchable text">
The reviewed meeting's subject, written in the title and as the `Meeting` line.
</ResponseField>

<ResponseField name="scored_for" type="Searchable text">
The person reviewed, written as the `Reviewed` line.
</ResponseField>

<ResponseField name="scored_by" type="Searchable text">
The reviewer, written as the `Reviewer` line. For a review Avoma's AI wrote, this can be Avoma's AI email when there is no name.
</ResponseField>

<ResponseField name="overall_score" type="Searchable text">
The overall score, written as the `Overall score` line.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the review was created. Sets the result date and decides which reviews each sync reads. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.avoma_meeting_id" type="Query filter, Graph connection">
The reviewed meeting's id. Fetches every review of one meeting, and links the review to that meeting. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.avoma_review_id" type="Query filter">
The review's id. Picks out one review. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.scorecard_id" type="Query filter">
The scorecard template's id. Limits a query to one scorecard. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.scored_for_email" type="Query filter">
The reviewed person's email. Finds every review of one person. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.scored_by_email" type="Query filter">
The reviewer's email, or `ai@avoma.com` for a review Avoma's AI wrote. Separates human and AI reviews. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="reviewed_by_ai" type="Stored only">
Whether Avoma's AI wrote the review, worked out from the reviewer's email.
</ResponseField>

<ResponseField name="answer_count" type="Stored only">
How many answers the review returned. A question appears in the text only when it has question text.
</ResponseField>

</Accordion>

## How it fits into the graph

- Meetings use the Page class.
- Scorecard reviews use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Avoma creates**

- A scorecard review to the meeting it reviews.
- No links to other tools. Linked CRM records are kept as ids for filtering only.

**People and groups**

The connector does not attach organizers, attendees, speakers or reviewers to items as people. Their names are part of the text.

**Found in the text**

Each meeting's details, summary and transcript, and each review's text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Audio and video files.
- Meetings outside the API key's scope.
- Avoma meeting sharing permissions.
- A review's company name, deal names and modified time.
- Changes after the 2-hour window for meetings or the 7-day window for reviews.
- Deletions: meetings and reviews deleted in Avoma can stay in HydraDB.
