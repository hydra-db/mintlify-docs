## Basics

- **Base URL:** `https://api.hydradb.com`
- **Auth:** `Authorization: Bearer <your_api_key>` on every call. Get a key at [app.hydradb.com](https://app.hydradb.com).
- **Version:** send `API-Version: 2`. The SDKs set it for you.
- **New here:** run the [Quickstart](/get-started/v2/quickstart) first. It is the whole loop in code: create a database, wait until it is ready, ingest, wait until indexing finishes, query.
- **Errors:** [Error Responses](/api-reference/v2/error-responses).
- **Coding agents:** the [agent guide](/AGENTS) and the [v2 OpenAPI spec](/api-reference/v2/openapi.json).

## Terms used on every page

The full model is in [Core Concepts](/get-started/v2/core-concepts).


- `database` (formerly `tenant_id`): your isolated workspace for data, metadata schema, and queries. Send it on every call.
- `collection` (formerly `sub_tenant_id`): an optional partition inside a database, such as a user, team, or customer. If you omit it, the default collection is used. See [Multi-tenant](/essentials/v2/multi-tenant).
- `type`: `knowledge` for shared content ([Knowledge](/essentials/v2/knowledge)) or `memory` for one user's context ([Memories](/essentials/v2/memories)). Ingest, list, delete, and query all use the same values. Query also accepts `all`.
- `database_metadata_schema`: fields you declare on the database so you can filter on them later, such as department, customer, region, plan, or compliance label.
- `document_metadata`: a JSON string sent with a file upload, one entry per file. It carries the source `id`, title, schema-backed `metadata`, free-form `additional_metadata`, and relations to other sources.
- `ids`: returned by ingest and by `/context/list`. Use them to poll status, inspect content, list a subset, delete sources, or read relations.

## Endpoints

### [Databases](/api-reference/v2/endpoint/tenants-overview)

- [`POST /databases`](/api-reference/v2/endpoint/create-tenant) (`databases.create`): create a database, with an optional metadata schema.
- [`GET /databases/status`](/api-reference/v2/endpoint/tenant-status) (`databases.status`): wait for provisioning before you ingest.
- [`GET /databases`](/api-reference/v2/endpoint/list-tenants) (`databases.list`): list the databases your API key can see.
- [`GET /databases/collections`](/api-reference/v2/endpoint/list-sub-tenants) (`databases.collections`): list the collections in a database.
- [`GET /databases/stats`](/api-reference/v2/endpoint/tenant-stats) (`databases.stats`): object counts for a database.
- [`PATCH /databases/{database}/metadata-schema`](/api-reference/v2/endpoint/update-metadata-schema) (`databases.update_metadata_schema` in Python, `databases.updateMetadataSchema` in TypeScript): add filterable fields after the database exists.
- [`DELETE /databases/collections`](/api-reference/v2/endpoint/delete-collection) (`databases.delete_collection` in Python, `databases.deleteCollection` in TypeScript): delete one collection and its data.
- [`DELETE /databases`](/api-reference/v2/endpoint/delete-tenant) (`databases.delete`): permanently delete a database and its data.

### [Context](/api-reference/v2/endpoint/sources-overview)

- [`POST /context/ingest`](/api-reference/v2/endpoint/ingest-context) (`context.ingest`): upload documents, app sources, or memories.
- [`GET /context/status`](/api-reference/v2/endpoint/source-status) (`context.status`): check whether ingested IDs are queryable.
- [`POST /context/list`](/api-reference/v2/endpoint/list-documents) (`context.list`): browse with pagination, filters, field projection, or a set of `ids`.
- [`GET /context/inspect`](/api-reference/v2/endpoint/fetch-content) (`context.inspect`): fetch the original content or a presigned URL.
- [`PATCH /context/{id}/metadata`](/api-reference/v2/endpoint/update-source-metadata) (`context.update_source_metadata` in Python, `context.updateSourceMetadata` in TypeScript): merge `metadata` or `additional_metadata` onto one source without re-ingesting.
- [`DELETE /context`](/api-reference/v2/endpoint/delete-source) (`context.delete`): delete sources or memories by ID.
- [`GET /context/relations`](/api-reference/v2/endpoint/source-relations) (`context.relations`): graph relations for a source or collection.
- [`GET /context/{id}/subgraph`](/api-reference/v2/endpoint/subgraph) (`context.subgraph`): the connected subgraph around one source.

### [Query](/api-reference/v2/endpoint/query-overview)

- [`POST /query`](/api-reference/v2/endpoint/query) (`query`): retrieve knowledge, memories, or both, with `hybrid` or `text` matching.
- [`POST /feedback`](/api-reference/v2/endpoint/submit-feedback) (`feedback.submit`): tell HydraDB whether a query gave you what you needed.

### [Connectors](/api-reference/v2/endpoint/connectors-overview)

Keep data from Slack, GitHub, Google Drive, Supabase, and other apps synced into a database without writing ingest code. The overview lists every connector endpoint in call order: list providers, create, discover resources, configure, then check status, sync, pause, resume, update, or delete.

### Webhooks

Get a `POST` to your URL when indexing finishes, instead of polling. [Register](/api-reference/v2/endpoint/register-webhook), [get](/api-reference/v2/endpoint/get-webhook), [test](/api-reference/v2/endpoint/test-webhook), or [delete](/api-reference/v2/endpoint/delete-webhook) the webhook, and [list](/api-reference/v2/endpoint/list-webhook-deliveries), [read](/api-reference/v2/endpoint/get-webhook-delivery), or [retry](/api-reference/v2/endpoint/retry-webhook-delivery) deliveries. Guide: [Webhooks](/essentials/v2/webhooks).

## SDKs

Official SDKs wrap these endpoints.

- Python: [`hydradb-sdk`](https://pypi.org/project/hydradb-sdk/), `pip install hydradb-sdk`
- TypeScript: [`@hydradb/sdk`](https://www.npmjs.com/package/@hydradb/sdk), `npm install @hydradb/sdk`

**Quick init:**

<CodeGroup>

```python Python
import os
from hydra_db import HydraDB, AsyncHydraDB

client = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
async_client = AsyncHydraDB(token=os.environ["HYDRA_DB_API_KEY"])
```

```typescript TypeScript
import { HydraDBClient } from "@hydradb/sdk";

const client = new HydraDBClient({
  token: process.env.HYDRA_DB_API_KEY,
});
```

</CodeGroup>

SDK methods mirror the API: `client.<group>.<method>()` maps to the matching endpoint. The SDKs are generated from the OpenAPI spec. Full guide: [SDKs](/api-reference/v2/sdks).

## Conventions

Every raw HTTP call sends the auth and version headers:

```bash
curl -X POST 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "my_first_database",
    "query": "What are the pricing tiers?",
    "type": "knowledge",
    "query_by": "hybrid"
  }'
```

**Response envelope:** `/databases`, `/context/*`, `/query`, `/feedback`, and `/webhooks/indexing*` wrap every response the same way. The payload is under `data`. Connector endpoints (`/connectors*`) and `PATCH /databases/{database}/metadata-schema` are the exception: they return their documented object directly.

```json
{
  "success": true,
  "data": {},
  "error": null,
  "meta": {
    "request_id": "request-id",
    "latency_ms": 12.3
  }
}
```

Errors use the same envelope with `success: false`, `data: null`, and an `error` object with `code` and `message`. Log `meta.request_id` when you report a problem.

**Deprecation notices:** if a request uses a legacy `/tenants` route or a deprecated field (`tenant_id`, `sub_tenant_id`, or `sub_tenant_ids` on `/query`), `meta` includes a `deprecation` list and the response carries a `Deprecation: true` header. Each entry has `deprecated`, `message`, and `deprecated_since`. Field-level notices also add `deprecated_field` and `preferred_field`. The status code does not change. See [Migrating from `tenant_id` and `sub_tenant_id`](/essentials/v2/multi-tenant#7-migrating-from-the-legacy-tenant-and-sub-tenant-fields).

- **Aliases:** `tenant_id`, `sub_tenant_id`, and the `/tenants` routes still work. Sending a new name and its alias with **different** values returns `400`.
- **Async operations:** creating a database, deleting a database or a collection, and ingesting content return as soon as the work is queued. Poll the matching status endpoint before the next step.
- **Pagination:** `/context/list` returns pagination fields for large result sets.
- **Casing:** the REST API and the Python SDK use snake_case keys (`max_results`). The TypeScript SDK uses camelCase keys and method names (`maxResults`, `deleteCollection`) and drops request keys it does not recognize, so snake_case keys sent through it are ignored. See [SDKs](/api-reference/v2/sdks#naming-conventions).

**Status codes:**

- `200`: success
- `202`: accepted, async work queued
- `400`: invalid parameters
- `401`: authentication required
- `402`: your plan does not allow the request
- `403`: forbidden
- `404`: not found
- `409`: conflict, for example the database already exists
- `413`: request body too large
- `415`: wrong content type, for example JSON sent to the multipart-only ingest endpoint
- `422`: validation error, or a query sent before the database is ready
- `429`: rate limit exceeded
- `500`: internal server error
- `503`: service unavailable

Error codes, response shapes, and retry patterns: [Error Responses](/api-reference/v2/error-responses).

## Rate limits

Rate limits apply per API key. Retry `429` responses with exponential backoff. For current limit values, contact [founders@hydradb.com](mailto:founders@hydradb.com).
