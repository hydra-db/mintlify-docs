---
title: "Webhooks: Overview"
description: "Register a webhook for indexing updates, track its deliveries, and manage its signing secret."
---

A webhook is an HTTP `POST` that HydraDB sends to your endpoint when ingested content reaches a terminal indexing state, `completed` or `errored`, so you do not have to poll [Ingestion Status](/api-reference/v2/endpoint/source-status). One webhook is registered per organization, for the `indexing.status_changed` event. The [Webhooks guide](/essentials/v2/webhooks) covers the payload, signature verification, and receiver examples.

## Endpoint references

SDK methods are listed by their Python names. The TypeScript SDK uses the same names in camelCase, such as `webhooks.listDeliveries`.

Set up the webhook:

| Endpoint | SDK method | Purpose |
|---|---|---|
| [`POST /webhooks/indexing`](/api-reference/v2/endpoint/register-webhook) | `webhooks.register` | Register your endpoint, or replace the current registration. Send `generate_signing_secret: true` to get a signing secret in the same call. |
| [`POST /webhooks/indexing/test`](/api-reference/v2/endpoint/test-webhook) | `webhooks.test` | Send a synthetic, signed delivery to confirm your endpoint and your signature check work. |
| [`GET /webhooks/indexing`](/api-reference/v2/endpoint/get-webhook) | `webhooks.get` | Read the current registration and whether a signing secret is set. |

Track deliveries:

| Endpoint | SDK method | Purpose |
|---|---|---|
| [`GET /webhooks/indexing/deliveries`](/api-reference/v2/endpoint/list-webhook-deliveries) | `webhooks.list_deliveries` | List deliveries, most recent first. Filter by `status` to find failures. |
| [`GET /webhooks/indexing/deliveries/{delivery_id}`](/api-reference/v2/endpoint/get-webhook-delivery) | `webhooks.get_delivery` | Read one delivery, using the id from the `X-HydraDB-Delivery-ID` header. |
| [`POST /webhooks/indexing/deliveries/{delivery_id}/retry`](/api-reference/v2/endpoint/retry-webhook-delivery) | `webhooks.retry_delivery` | Queue a `failed` or `permanently_failed` delivery for another attempt. |

Manage signing or delete the webhook:

| Endpoint | SDK method | Purpose |
|---|---|---|
| [`POST /webhooks/indexing/signing-secret`](/api-reference/v2/endpoint/set-webhook-signing-secret) | `webhooks.set_signing_secret` | Generate a new signing secret, or store one you supply. It is returned once and takes effect immediately. If you supply it, configure your receiver to accept it before this call. |
| [`DELETE /webhooks/indexing/signing-secret`](/api-reference/v2/endpoint/disable-webhook-signing) | `webhooks.clear_signing_secret` | Disable signing. |
| [`DELETE /webhooks/indexing`](/api-reference/v2/endpoint/delete-webhook) | `webhooks.delete` | Delete the registration and its signing secret. |

## Typical call sequence

1. `POST /webhooks/indexing` with your HTTPS endpoint and `generate_signing_secret: true`. Store the signing secret it returns. Your endpoint must be reachable over public HTTPS; localhost and private network addresses are rejected.
2. `POST /webhooks/indexing/test` to check your receiver accepts the delivery and verifies the signature.
3. Ingest content as usual. Each item that finishes indexing produces one delivery.
4. `GET /webhooks/indexing/deliveries?status=failed` to find deliveries your endpoint rejected, then retry them once the problem is fixed.

## Delivery and retries

- Each delivery contains the event body and an `X-HydraDB-Delivery-ID` header. Signed deliveries also include `X-HydraDB-Signature`.
- Failed deliveries retry with exponential backoff. HydraDB Cloud marks a delivery `permanently_failed` after 16 attempts or 48 hours after the first failure, whichever comes first.
- Automatic and manual retries use your current signing secret.
- Test deliveries do not appear in the delivery history.
