Databases are physically isolated spaces for storing context, for example one per enterprise customer. Most integrations create a database once, wait for provisioning, then ingest and query inside it.

## Endpoint references

Calls marked async return before the work finishes, so poll for completion.

- [`POST /databases`](/api-reference/v2/endpoint/create-tenant) (`databases.create`, async): create a new isolated workspace.
- [`DELETE /databases`](/api-reference/v2/endpoint/delete-tenant) (`databases.delete`, async): permanently remove a database.
- [`GET /databases`](/api-reference/v2/endpoint/list-tenants) (`databases.list`): list all databases for the organization.
- [`GET /databases/status`](/api-reference/v2/endpoint/tenant-status) (`databases.status`): check provisioning readiness.
- [`GET /databases/stats`](/api-reference/v2/endpoint/tenant-stats) (`databases.stats`): monitor database load.
- [`GET /databases/collections`](/api-reference/v2/endpoint/list-sub-tenants) (`databases.collections` in TypeScript and Python): list active collections.
- [`DELETE /databases/collections`](/api-reference/v2/endpoint/delete-collection) (`databases.delete_collection` in Python, `databases.deleteCollection` in TypeScript, async): permanently remove one collection.
- [`PATCH /databases/{database}/metadata-schema`](/api-reference/v2/endpoint/update-metadata-schema) (`databases.update_metadata_schema` in Python, `databases.updateMetadataSchema` in TypeScript): add metadata schema fields.

## Typical call sequence

For a new database:

1. Create the database: `POST /databases`
2. Wait for provisioning: `GET /databases/status` until `infra.ready_for_ingestion` is `true`
3. Ingest content: `POST /context/ingest`
4. Wait for indexing: `GET /context/status` until sources are searchable
5. Retrieve context: `POST /query`
6. Inspect usage: `GET /databases/stats`
7. Delete: `DELETE /databases`

On an existing database, the routine calls are `GET /databases` to list databases in the org, `GET /databases/collections` to list active collections, and `GET /databases/stats` to check health and growth.

## Key concepts

- **Collection:** a partition inside a database, for scoping data per user, team, or customer. The first collection is created implicitly at ingestion.
- **Metadata schema:** structured fields you define at database creation to enable query-time filtering. You can add fields later with [Update Metadata Schema](/api-reference/v2/endpoint/update-metadata-schema).
