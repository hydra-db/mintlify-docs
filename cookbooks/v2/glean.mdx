Company search answers a question from everything the company has written, and shows each person only what they are allowed to see. This cookbook builds it with three ideas: one collection for all company knowledge, connectors that sync each app along with its permissions, and the asker's identity on every query.

| Benchmark | Result | What it shows here |
| --- | --- | --- |
| [EnterpriseRAG-Bench](https://benchmarks.hydradb.com/enterprise-rag-bench) | 88.7 overall, 96.7% document recall@10 | Retrieval across fragmented systems where knowledge is duplicated or outdated |
| [KyroBench](https://benchmarks.hydradb.com/kyrobench) | 0.776 nDCG | The current source ranked above the stale one |

## 1. Create one database and one collection

Put everything in one collection so a single query searches all of it. Separate collections are for context that must never meet in one query; permissions are handled by ACLs, not by splitting collections. See [Databases and Collections](/essentials/v2/databases-and-collections).

```python glean.py
import json
import os

from hydra import answer, client, connect, create_database

DATABASE, COLLECTION = "acme_corp", "company"

create_database(DATABASE)
```

## 2. Connect each app

A [connector](/essentials/v2/connectors) syncs one app account into the collection and keeps it in sync on a schedule. For Slack, Jira, Confluence, and the other providers [that capture permissions](/essentials/v2/connectors#what-each-provider-captures), it also copies the app's permissions into each source's ACL, so a private Slack channel stays private in search. `connect` from `hydra.py` makes the connector calls: create, discover, configure, and status.

```python glean.py
connect(
    "slack",
    DATABASE,
    COLLECTION,
    credentials={"access_token": os.environ["SLACK_TOKEN"]},
    account_scope=os.environ["SLACK_WORKSPACE_ID"],
)

# Add one call per app, all pointing at the same collection. Each provider has
# its own credentials: client.list_providers(id="jira") returns the shape.
for provider in ("jira", "confluence"):
    variable = f"{provider.upper()}_CREDENTIALS"
    if variable in os.environ:
        connect(provider, DATABASE, COLLECTION, credentials=json.loads(os.environ[variable]))
```

`connect` syncs every channel, page, or project the credentials can reach, and the last 30 days of each. To sync only some, pass a shorter `resources` list to [`configure`](/api-reference/v2/endpoint/configure-connector). To fetch more history, pass `lookback_days`.

<Warning>
Connect only providers that capture permissions this way. A provider that does not, such as Notion or Gmail, syncs its content with no ACL, so every asker can retrieve it. For those, pass `acl` to `connect` to set who may read what it syncs.
</Warning>

## 3. Query as the person asking

Send the signed-in user's identity as `acl`. Take it from your session on the server, never from the client: a query without `acl` returns everything in scope. The other settings are the ones the EnterpriseRAG-Bench run used: hybrid matching, `thinking` mode, and 12 results.

```python glean.py
def search(question, user_email):
    return client.query(
        database=DATABASE,
        collection=COLLECTION,
        query=question,
        type="knowledge",
        query_by="hybrid",
        mode="thinking",
        max_results=12,
        acl=[user_email],
    )
```

## 4. Answer with citations

Each chunk in the query result carries the ID and title of the source it came from. Print each source once under the answer.

```python glean.py
def ask(question, user_email):
    result = search(question, user_email)
    print(answer(question, result, "Prefer the most recent source when sources disagree."))
    cited = {chunk.id: chunk.source_title for chunk in result.data.chunks}
    for source_id, title in cited.items():
        print(f"  - {title} ({source_id})")


ask("What did we decide about pricing?", "bob@acme.com")
ask("What did we decide about pricing?", "grace@acme.com")
```

## Run it

Set `SLACK_TOKEN` and `SLACK_WORKSPACE_ID`, and optionally `JIRA_CREDENTIALS` and `CONFLUENCE_CREDENTIALS`. Replace the two emails with people in your workspace, and run:

```bash
python glean.py
```

The first run waits for the first sync, which takes a few minutes. Each answer cites the Slack messages and pages it came from. If the decision was made in a private channel, only the person who is a member of that channel gets it; the other is told the context does not say.

Keep sending `acl` on every query, and leave [`enforce_acl`](/essentials/v2/connectors#enforce-acl) off for this application. With `enforce_acl` on, HydraDB ignores the request's `acl` and uses the identity of whoever created the API key, so every user of your application would see what the key's creator can see. Enforcement fits a caller who authenticates as themselves, such as a user signed in through MCP OAuth.

## Common mistakes

- **Turning on `enforce_acl` behind one API key:** every query then runs with the key creator's permissions, not the asker's.
- **Connecting a provider that captures no permissions:** its content is synced unrestricted and reaches every asker. Pass `acl` to `connect` for it.
- **Querying without `acl`:** the query returns restricted sources to everyone. Send the user's identity on every query.
- **One collection per app or team:** a query that names one collection does not read the others. Keep one collection and narrow with [metadata filters](/essentials/v2/metadata).
- **Group permissions:** an email matches its `domain:` principal automatically, but not groups. Send `group:` principals yourself. See [Query](/essentials/v2/query#6-query-on-behalf-of-a-user).
