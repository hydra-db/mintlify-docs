Sync a catalogue of the files in the Figma projects you select. Each file is one document holding its name, project, last modified time and link, so a search can find a file by name and take you to it.

Design content is not read: frames, text layers, components and comments are not synced. Figma permissions are not imported, so every synced file is visible to everyone who can query the collection unless you set an access rule. The first sync lists only files modified in the last 30 days unless you raise `lookback_days`. Files deleted in Figma stay in HydraDB.

<Note>
Figma is in beta.
</Note>

## Permissions

<Warning>
Figma permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

<Warning>
HydraDB needs your Figma team ids to list your projects, because Figma's API cannot list a user's teams. The connection form does not ask for them yet, which is why Figma is in beta.
</Warning>

### Credentials

Figma uses a personal access token.

<ResponseField name="api_token" type="secret string" required>
A Figma personal access token.
</ResponseField>

### Set it up

<Steps>
  <Step title="Create a personal access token">
    In Figma, create a personal access token for a user who can see the projects you want catalogued.
  </Step>
  <Step title="Create the connector">
    Paste the token as `api_token`.
  </Step>
  <Step title="Select projects">
    HydraDB lists the projects of your Figma teams. Select the projects to sync. To reach files older than 30 days, raise `lookback_days` when you select them.
  </Step>
</Steps>

One connector reads what one Figma user's token can see.

<Accordion title="Connect through the API">

Use provider `figma` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected project reads back the window set by `lookback_days`, 30 days by default. Files last modified before that window are not listed.
- **New and changed items:** Each sync lists the files modified since the last sync.
- **Edits:** A file whose last modified time moved is sent again with its new details.
- **Deletions:** Deleted files are not removed. A file deleted in Figma stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Files

- **One document:** One Figma file's details. Its design content is not included.
- **Title:** The file name. A file with no name is titled `Figma file` and its key.
- **Text:** The title, then `Project`, `Last modified` and `Link` lines. This is the only searchable text for a file.
- **Date:** When the file was last modified.
- **Link back:** Opens the file in Figma.
- **Files:** None.

<ResponseField name="project_name" type="Searchable text">
The project name, written as the `Project` line when HydraDB has it. The name is often missing, so to limit a query to a project, use `additional_metadata.figma_project_id`.
</ResponseField>

<ResponseField name="last_modified" type="Searchable text, Result date">
When the file was last modified, written as the `Last modified` line. Sets the result date.
</ResponseField>

<ResponseField name="url" type="Searchable text">
The Figma link built from the file key, written as the `Link` line.
</ResponseField>

<ResponseField name="additional_metadata.figma_project_id" type="Query filter">
The id of the project that holds the file. Limits a query to one project's files. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.figma_file_key" type="Query filter">
The file key. Picks out one file. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's files. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `figma`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="thumbnail_url" type="Stored only">
The address of the file's thumbnail image, for your own app to show. HydraDB does not read the image.
</ResponseField>

</Accordion>

**Example searches**

- Is there a Figma file for the checkout redesign?
- Which files in this Figma project changed recently?
- What is the link to the onboarding flow design?

## How it fits into the graph

- Files use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Figma creates**

- No links between files, and no links to items in other tools.

**People and groups**

- No people are attached.

**Found in the text**

The file name and, when present, the project name. There is no design content to read. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Projects you did not select.
- Files last modified before the `lookback_days` window on the first sync.
- Design content: frames, text layers and components.
- Comments.
- Version history.
- Thumbnail images. Only their address is kept.
- Deletions: deleted files stay in HydraDB.
