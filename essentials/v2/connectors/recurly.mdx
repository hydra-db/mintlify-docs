Sync customer accounts, invoices, subscriptions and transactions from one Recurly site. Each record is one document with a readable summary, with amounts shown in their currency, such as `49.99 USD`. Invoices, subscriptions and transactions link to the account they belong to.

Recurly permissions are not imported, so every synced record is visible to everyone who can query the collection unless you set an access rule. Records deleted in Recurly stay in HydraDB. Plans, coupons, adjustments and billing info are not synced as documents.

## Permissions

<Warning>
Recurly permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Recurly uses a private API key together with your site's subdomain.

<ResponseField name="api_key" type="secret string" required>
A Recurly private API key.
</ResponseField>

<ResponseField name="subdomain" type="string" required>
Your Recurly site code, for example `acme` for `acme.recurly.com`.
</ResponseField>

<ResponseField name="user_agent" type="string">
Filled in automatically. Leave it empty.
</ResponseField>

### Set it up

<Steps>
  <Step title="Get a private API key">
    Get a private API key for your Recurly site.
  </Step>
  <Step title="Create the connector">
    Paste the key as `api_key` and your site code as `subdomain`.
  </Step>
  <Step title="Select the site">
    Select the `All data` resource. It syncs accounts, invoices, subscriptions and transactions together. You cannot select these record types separately.
  </Step>
</Steps>

One connector reads one Recurly site.

<Accordion title="Connect through the API">

Use provider `recurly` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads accounts, invoices and subscriptions updated since the last sync, and transactions collected since the last sync.
- **Edits:** An edited account, invoice or subscription replaces its document. Transactions are found by when they were collected, so a later change to a collected transaction's status may not be picked up.
- **Deletions:** Deleted records are not removed. A record deleted in Recurly stays searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Recurly item

<ResponseField name="updated_at" type="Result date">
When the record was last updated in Recurly. When there is none, the creation time is used, and for a transaction then the collection time. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.recurly_id" type="Query filter">
The Recurly record id. Finds one account, invoice, subscription or transaction. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's records. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `recurly`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (2)">

<ResponseField name="stream_type" type="Stored only">
The record type: `accounts`, `invoices`, `subscriptions` or `transactions`.
</ResponseField>

<ResponseField name="Other Recurly fields" type="Stored only">
Every other field Recurly returns for the record, such as an account's address, custom fields, cc emails and VAT number. Kept for inspection only. A query does not match them and cannot filter on them.
</ResponseField>

</Accordion>

### Accounts

- **One document:** One customer account.
- **Title:** The company. Otherwise the first and last name, then the email, then the account code.
- **Text:** `Name`, `Company`, `Email`, `Code` and `State` lines. The title is searchable too.
- **Date:** When the account was last updated, or created when there is no update time.
- **Link back:** None.

<ResponseField name="email" type="Searchable text, Graph identity">
The account's email, in the `Email` line and the title when there is no company or name. Identifies the account as a person in the graph.
</ResponseField>

<ResponseField name="username" type="Graph identity">
The account's username, when Recurly has one. Identifies the account as a person in the graph, even without an email. Not searchable.
</ResponseField>

<ResponseField name="company, first_name, last_name, code" type="Searchable text">
The company, name and account code, in the title and the `Name`, `Company` and `Code` lines.
</ResponseField>

<ResponseField name="state" type="Searchable text">
The account's state, in the `State` line.
</ResponseField>

### Invoices

- **One document:** One invoice.
- **Title:** `Invoice <number> - <account>`, with the account shown as its company, name, email or code.
- **Text:** The customer notes, then `Account`, `State`, `Total` and `Balance` with the currency, `Due date` and `Line items` lines. Each line item shows its description. The title is searchable too.
- **Date:** When the invoice was last updated, or created when there is no update time.
- **Link back:** None.
- **Files:** Invoice PDFs are not downloaded.

<ResponseField name="account" type="Searchable text, Graph connection">
The account the invoice belongs to. Its id links the invoice to the account's document. Its name is in the title and the `Account` line. The id itself is not searchable.
</ResponseField>

<ResponseField name="number" type="Searchable text">
The invoice number, in the title.
</ResponseField>

<ResponseField name="line_items" type="Searchable text">
Each line's description, in the `Line items` line. Other line details are not searchable.
</ResponseField>

### Subscriptions

- **One document:** One subscription.
- **Title:** `<plan name> subscription - <account>`.
- **Text:** The customer notes, then `Plan`, `Account`, `State`, `Amount` (the unit amount with its currency), `Quantity` and `Current period ends` lines. The title is searchable too.
- **Date:** When the subscription was last updated, or created when there is no update time.
- **Link back:** None.

<ResponseField name="account" type="Searchable text, Graph connection">
The subscribed account. Its id links the subscription to the account's document. Its name is in the title and the `Account` line. The id itself is not searchable.
</ResponseField>

<ResponseField name="plan" type="Searchable text">
The plan name, in the title and the `Plan` line. Plans are not their own documents.
</ResponseField>

### Transactions

- **One document:** One payment transaction.
- **Title:** `Transaction <amount> <currency> - <account>`.
- **Text:** The customer message, then `Account`, `Amount`, `Status`, `Type`, `Origin`, `Invoice` (the invoice number) and `Collected at` lines. The title is searchable too.
- **Date:** When the transaction was last updated. Otherwise when it was created, then when it was collected.
- **Link back:** None.

<ResponseField name="account" type="Searchable text, Graph connection">
The paying account. Its id links the transaction to the account's document. Its name is in the title and the `Account` line. The id itself is not searchable.
</ResponseField>

<ResponseField name="invoice" type="Searchable text">
The invoice number, in the `Invoice` line. It is text only. The transaction is not linked to the invoice's document.
</ResponseField>

**Example searches**

- What is the outstanding balance on Acme Corp's latest Recurly invoice?
- Which plan is Acme Corp subscribed to, and when does the current period end?
- Did the payment from jane@example.com on 2026-11-02 succeed?

## How it fits into the graph

- Accounts use the Record class.
- Invoices use the Record class.
- Subscriptions use the Record class.
- Transactions use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Recurly creates**

- An invoice to its account.
- A subscription to its account.
- A transaction to its account.
- Transactions are not linked to their invoice. The invoice number is in the text only.
- No links to other tools.

**People and groups**

- Each account, as a person identified by its email and username.

**Found in the text**

Account details, customer notes and messages, plan names, line items and the rest of each record's summary. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Billing info, adjustments, coupons, coupon redemptions, plans and plan add-ons as documents.
- Invoice PDFs.
- Account custom fields, addresses and billing details as searchable text. They are stored for inspection only.
- Deletions: records deleted in Recurly stay in HydraDB.
