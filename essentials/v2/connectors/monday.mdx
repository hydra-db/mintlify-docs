Sync items and subitems from the Monday.com boards you select. Each item is one document with its name and every filled column value. Each attached file whose text can be read becomes its own page, linked to its item. Subitems link to their parent, and board-relation columns link items to each other.

Monday.com permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. Item updates, the comments on an item, are not synced. People columns are text only. Items archived or deleted in Monday.com stay in HydraDB.

## Permissions

<Warning>
Monday.com permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- The token lists only boards its user can open, but synced items do not keep that restriction. Item-level visibility is not reproduced either. Set an access rule on each board that should be restricted.
- Each selected board shows a warning in connector status that its permissions are not captured.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Monday.com uses an API token: a personal token, or an OAuth access token from an app with `boards:read`.

<ResponseField name="auth_token" type="secret string" required>
A Monday.com personal API token, or an OAuth access token.
</ResponseField>

Monday.com limits API complexity and daily calls by plan. Very large boards can need a longer sync interval. To rotate a personal token, update the connector with the new token and check that it works before revoking the old one.

**Scope for an OAuth app token**

- `boards:read`: lists boards and reads items and column values.

### Set it up

<Steps>
  <Step title="Get a token">
    In Monday.com, open Profile, Developers, My Access Tokens and copy your personal token, or use an OAuth app token with `boards:read`. Use a user who can open every board you plan to select. Private boards that user cannot open are not listed.
  </Step>
  <Step title="Create the connector">
    Paste the token as `auth_token`.
  </Step>
  <Step title="Select boards">
    HydraDB lists every board the token can see. Select the boards to sync.
  </Step>
</Steps>

One connector reads the boards one token's Monday.com user can open.

<Accordion title="Connect through the API">

Use provider `monday` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected board reads back the window set by `lookback_days`, 30 days by default, measured on when items were last updated.
- **New and changed items:** Each sync reads every item and subitem updated since the last sync, and the files on those items. Up to four boards sync at once.
- **Edits:** An edited item is picked up through its last-updated time and updates its document. Its files are read again.
- **Deletions:** Items archived or deleted in Monday.com stay searchable in HydraDB.
- If a board makes no progress for five minutes, that sync fails and the board is tried again on the next sync.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Monday.com item

<ResponseField name="additional_metadata.monday_board_id" type="Query filter">
The board id. Limits a query to one board. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.monday_board_name" type="Query filter">
The board name. Limits a query to one board by name. Empty when the board name could not be read. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `monday`. Not searchable.
</ResponseField>

### Items

- **One document:** One Monday.com item or subitem, at any level.
- **Title:** The item name, or `Monday item` and the board and item ids when the name is empty.
- **Text:** The item name, then one line per filled column, as `Column title: value`. An item with no column values is just its name. The item key, creation date and parent are written into the item details too. The title is searchable too.
- **Date:** When the item was last updated, or when it was created if there is no update time.
- **Link back:** The item's card in Monday.com.
- **Files:** Attached files are their own documents, described below.

<ResponseField name="Column values" type="Searchable text">
Each filled column, such as status, people, dates, numbers and text, as `Column title: value`. People columns are text only: owners and assignees are not added to the graph as people.
</ResponseField>

<ResponseField name="Item key" type="Searchable text">
The board id and item id together. It keeps later syncs on the same document.
</ResponseField>

<ResponseField name="created_at" type="Searchable text">
When the item was created, written as the `Created` line.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the item was last updated. Sets the result date and decides when a sync picks the item up. Not searchable.
</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">
For a subitem, its parent item, written as the `Parent` line. Links the subitem to its parent.
</ResponseField>

<ResponseField name="Board-relation columns" type="Graph connection">
Each item a board-relation column points to becomes a link from this item, as long as that item is also synced, which means it is on a selected board. The linked ids themselves are not searchable.
</ResponseField>

<ResponseField name="additional_metadata.monday_id" type="Query filter">
The item id. Picks out one item. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="state" type="Stored only">
The item's state: `active`, `archived` or `deleted`.
</ResponseField>

<ResponseField name="board_id" type="Stored only">
The board id.
</ResponseField>

<ResponseField name="board_name" type="Stored only">
The board name.
</ResponseField>

</Accordion>

### Files

- **One document:** One file attached to an item, once its text has been read. A file whose text could not be read is not synced.
- **Title:** The file name, with `.pdf` or `.docx` added when the name has no extension, or `Monday attachment` and the file id when the name is empty.
- **Text:** The text read from the file, or the file name when there is no text. The update time is written as the `Updated` line. The title is searchable too.
- **Date:** When the file was last updated, else when it was created, else when its item was last updated.
- **Link back:** The card of the item the file is attached to.

<ResponseField name="updated_at" type="Searchable text, Result date">
When the file was last updated, written as the `Updated` line. Sets the result date.
</ResponseField>

<ResponseField name="parent_id" type="Graph connection">
The item the file is attached to. Links the file to that item, so an item and its files are found together. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (3)">

<ResponseField name="board_id, board_name" type="Stored only">
The board of the item the file is attached to.
</ResponseField>

<ResponseField name="item_id" type="Stored only">
The id of the item the file is attached to.
</ResponseField>

<ResponseField name="file_extension" type="Stored only">
`pdf` or `docx`.
</ResponseField>

</Accordion>

**Example searches**

- Which items on the Marketing Campaigns board are marked Stuck?
- What does the contract PDF attached to the Acme onboarding item say?
- What are the subitems of the Website Launch item?

## How it fits into the graph

- Items use the Ticket class.
- Files use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Monday.com creates**

- A subitem to its parent item.
- An item to each item in its board-relation columns, when that item is also synced.
- A file to the item it is attached to.
- No links to items in other tools.

**People and groups**

No people are attached to items. People columns, such as owners and assignees, are text only.

**Found in the text**

The column values of every item, and the text of attached files. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Boards you did not select, and boards the token's user cannot open.
- Item updates: the comments and replies on an item.
- Archived and deleted items. One that was synced earlier stays searchable.
- Files whose text could not be read.
- Board views, groups, columns, workspaces and users as items of their own.
- Monday.com docs and dashboards.
