---
title: "List or Describe Providers"
description: "List every supported connector provider, or get detailed configuration info for one specific provider."
openapi: "api-reference/v2/openapi.json GET /connectors/providers"
---

Without the `id` query parameter, this returns every supported connector provider along with its availability, maturity, category, and sync engine — the full connector catalog.

With `id=<provider>` (e.g. `id=slack`), it instead returns detailed configuration info for that one provider:

- **`indexed_object_types`** — the data streams from that provider that become searchable documents (e.g. channels, messages)
- **`searchable_fields`** — the fields from those objects that get rendered into the indexed text
- **`filterable_fields`** — fields you can filter on, each with the exact `filter_key` to pass inside a query's `metadata_filters`
- **`credential_schema`** — what credentials are required to connect this provider

<RequestExample>

```bash cURL (list all providers)
curl 'https://api.hydradb.com/connectors/providers' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2"
```

```bash cURL (describe one provider)
curl 'https://api.hydradb.com/connectors/providers?id=slack' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2"
```

</RequestExample>

<ResponseExample>

```json 200 (describe one provider)
{
  "provider": "slack",
  "indexed_object_types": ["channel_message", "thread_reply"],
  "searchable_fields": ["text", "user", "channel_name"],
  "filterable_fields": [
    {
      "field": "channel",
      "filter_key": "channel"
    }
  ],
  "credential_schema": {
    "auth_type": "oauth",
    "required_fields": ["access_token"]
  }
}
```

```json 404
{
  "detail": {
    "error_code": "PROVIDER_NOT_FOUND",
    "message": "Unknown provider id",
    "success": false
  }
}
```

</ResponseExample>
