---

title: "Tenant Stats"
description: "Retrieve usage statistics for a tenant."
openapi: "api-reference/v2/openapi.json GET /tenants/stats"
---

Returns detailed metrics including storage growth, object counts, vector dimensions, and graph storage usage.

The response groups stats into:
- `data.knowledge_collection` (Knowledge) and `data.memory_collection` (User memories) — row count and embedding dimensionality for each
- `data.graph_storage` — billable graph object counts and plan allowance

Counts aggregate across all sub-tenants in the tenant unless you pass `sub_tenant_id` to scope graph usage to a single sub-tenant.

## Query parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `tenant_id` | string | Yes | The tenant to inspect. |
| `sub_tenant_id` | string | No | Scope graph storage usage to a specific sub-tenant. Omit to count the full tenant graph. |

## Response fields

### `graph_storage`

| Field | Type | Description |
|---|---|---|
| `entity_nodes` | integer | Billable Entity nodes in graph storage. |
| `chunk_nodes` | integer | Billable Chunk nodes in graph storage. |
| `relationships` | integer | Billable relationships between Entity and Chunk nodes. |
| `total_graph_objects` | integer | Sum of `entity_nodes` + `chunk_nodes` + `relationships`. |
| `included_graph_objects` | integer \| null | Graph objects included in your plan. `null` means unlimited (Enterprise or custom contract). |
| `remaining_graph_objects` | integer \| null | Remaining allowance before limit. `null` means unlimited. |
| `usage_percent` | number \| null | Percentage of plan allowance used. `null` means unlimited. |
| `limit_exceeded` | boolean | `true` if usage exceeds the plan allowance. |
| `metering_unit` | string | Always `"graph_object"`. One graph object = one Entity node, Chunk node, or relationship. |

## Behavior notes

<Info>
  **`row_count` is chunks, not sources.** One ingested document typically becomes many chunks (e.g., a 30-page PDF can produce 100\+ rows). To count distinct sources, use [List Documents](/api-reference/v2/endpoint/list-documents) with `page_size=1` and read `total`.
</Info>

- **Both collections always exist:** Even if you've only ingested knowledge (or only memories), both collections are provisioned. Empty collections report `row_count: 0` with the configured `dimensions`.
- **Stats are eventually consistent:** Immediately after ingestion or deletion, counts may lag until background processing completes. Check [Ingestion Status](/api-reference/v2/endpoint/source-status) for recently ingested IDs before treating counts as final.
- **Graph storage may be null:** If graph metering is unavailable (e.g., during graph database maintenance), `graph_storage` may be `null`. The endpoint still returns collection stats.
