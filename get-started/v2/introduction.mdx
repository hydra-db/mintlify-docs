## What HydraDB is

HydraDB is a unified context layer for your AI. One brain for all your working context:

- **Memories:** Preferences, decisions, and past conversations that persist across sessions.
- **Knowledge:** Documents, app sources, and facts your AI reasons over.

Everything lives in a **database** you create. You ingest your context and connect the tools your team already uses; HydraDB builds a context graph from it and indexes it in the background. It is serverless: you never provision, shard, or scale anything, and the same code runs at ten documents or ten million.

New here? The [Quickstart](/get-started/v2/quickstart) takes you from an empty database to your first query in five minutes.

## The problem we're solving

> _VectorDBs find what's similar. But your agents want what's useful._

Vector search returns the closest embeddings and stops there. It cannot tell "Python" the language from "Python" the snake, has no answer for "who owns this customer escalation", and returns the same list to a sales rep and an engineer asking the same question. So teams stitch together a vector database, a graph database, a relational store, and a cache, then spend months keeping it all working.

HydraDB replaces that stack with one graph that holds your knowledge and every user's memories, and returns the context that fits the person asking.

## The principle

HydraDB gives you primitives, not a fixed product. The graph, the memory primitives, the retrieval pipeline, and the ranking knobs are yours to compose into your own context stores, memory layers, and workflows. Your context. Your opinions.

## Performance

- **Memory recall:** 90.79% on [LongMemEval-S](https://arxiv.org/abs/2410.10813).
- **Company knowledge:** 88.7 overall on [EnterpriseRAG-Bench](https://github.com/onyx-dot-app/EnterpriseRAG-Bench), retrieval across more than half a million documents from nine enterprise systems.
- **Coding harness:** 90.73 on [CodeWikiBench](https://github.com/FSoft-AI4Code/CodeWikiBench) for nlohmann/json, against 66.06 for DeepWiki and 61.28 for CodeWiki.
- **Long-term memory at scale:** 82% overall on [BEAM 1M](https://github.com/mohammadtavakoli78/BEAM), across ten dimensions.
- **Financial AI:** 91.4% recall@10 on [FinanceBench](https://arxiv.org/abs/2311.11944), over dense filings and enterprise data.
- **Low latency:** sub-200 ms retrieval.

The full technical breakdown of each run is in our [benchmarks](https://benchmarks.hydradb.com/).

## More in the box

- **Connectors:** 70 providers, including Slack, Gmail, Google Drive, Notion, GitHub, Jira, Confluence, Linear, HubSpot, Zendesk, and Microsoft Teams, synced on a schedule. Where the provider supports it, the source app's permissions come along as access control, so a query that sends a user's identity as `acl` only returns what that user may see. See [Connectors](/essentials/v2/connectors) and [Access Control](/essentials/v2/access-control).
- **SDKs:** [Python and TypeScript](/api-reference/v2/sdks), with a helper that turns a query result into a prompt string.
- **Tools:** an [MCP server](/plugins/mcp) for Claude, Cursor, and other MCP clients; a [CLI](/plugins/cli); and memory plugins for coding agents and agent frameworks such as [Claude Code](/plugins/claude-code), [Codex](/plugins/codex), [Hermes](/plugins/hermes), and [OpenClaw](/plugins/openclaw).
