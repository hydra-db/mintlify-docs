Sync events from every calendar on one Google account's calendar list. Each event is one document that reads as a short event card: title, time, place, organizer, attendees and description. A changed occurrence of a recurring meeting links to its series.

Google Calendar sharing and event visibility are not imported, so private events are visible to everyone who can query the collection unless you set an access rule. You cannot pick individual calendars: every calendar on the account's list is synced. The first sync picks events by when they were last edited, not by when they take place. An event cancelled after it was synced can stay in HydraDB.

## Permissions

<Warning>
Google Calendar permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Private events are synced like any other event.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Google Calendar uses a Google OAuth 2.0 client id and client secret, with a refresh token for the Google account to sync.

<ResponseField name="client_id" type="secret string" required>
The Google OAuth 2.0 client id.
</ResponseField>

<ResponseField name="client_secret" type="secret string" required>
The Google OAuth 2.0 client secret.
</ResponseField>

<ResponseField name="refresh_token" type="secret string" required>
A refresh token for the Google account, issued with a Calendar read scope such as `calendar.readonly`.
</ResponseField>

### Set it up

<Steps>
  <Step title="Get a client and refresh token">
    Get a Google OAuth 2.0 client id and secret, and a refresh token for the account whose calendars you want to sync. Issue the token with a Calendar read scope such as `calendar.readonly`.
  </Step>
  <Step title="Create the connector">
    Paste the three values as `client_id`, `client_secret` and `refresh_token`.
  </Step>
  <Step title="Select the account">
    HydraDB lists one item, All data, that covers every calendar on the account's list. Select it.
  </Step>
</Steps>

One connector reads one Google account. Every calendar on that account's calendar list is synced.

<Accordion title="Connect through the API">

Use provider `google_calendar` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reads events last edited within the window set by `lookback_days`, 30 days by default. When an event has no edit time, its creation time is used. Events with neither are read regardless. The window is about edits, not meeting dates: an old recurring meeting that was not edited recently may not be picked up, and a future event edited recently is.
- **New and changed items:** Each sync reads, calendar by calendar, the events edited since the last sync.
- **Edits:** An edited event is read again and replaces its document.
- **Deletions:** Cancelled events are not added. An event cancelled after it was synced can stay searchable in HydraDB.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Events

- **One document:** One calendar event. A recurring series is one document for the series, plus one for each occurrence that was changed. An event that appears with the same event id on more than one calendar of the account is one document, and each calendar's copy can replace the other.
- **Title:** The event title, or `Calendar event <id>` when it has none.
- **Text:** The title, then a `When` line with the start and end, a `Where` line with the location, an `Organizer` line, an `Attendees` line, then the event description. Descriptions are kept as Google supplies them, so an HTML description keeps its markup. The title is searchable too.
- **Date:** When the event was last edited, else when it was created. It is not the time the event takes place.
- **Link back:** None.
- **Files:** None. Event attachments are not synced.

<ResponseField name="organizer" type="Searchable text">
The organizer's display name, or email when there is no name, written as the `Organizer` line. The same name is kept as `author`. The organizer is not attached to the event as a person in the graph unless the same email is also among the attendees.
</ResponseField>

<ResponseField name="attendees" type="Searchable text, Graph identity">
Each attendee's email, display name and response status. Names, or emails when there is no name, are written as the `Attendees` line. The graph attaches each attendee to the event by email. Response statuses are kept on the event but are not searchable.
</ResponseField>

<ResponseField name="location" type="Searchable text">
The free-text location, written as the `Where` line.
</ResponseField>

<ResponseField name="start_at" type="Searchable text">
The scheduled start, or the date for an all-day event, written in the `When` line. It does not set the result date.
</ResponseField>

<ResponseField name="end_at" type="Searchable text">
The scheduled end, or the date for an all-day event, written after the start in the `When` line when the event has a start.
</ResponseField>

<ResponseField name="updated_at" type="Result date">
When the event was last edited. Sets the result date and decides which events each sync reads. Not searchable.
</ResponseField>

<ResponseField name="created_at" type="Result date">
When the event was created. Sets the result date only when the event has no edit time. Not searchable.
</ResponseField>

<ResponseField name="Recurring series" type="Graph connection">
For a changed occurrence, the recurring series event it belongs to. Links the occurrence to the series document. Not searchable.
</ResponseField>

<ResponseField name="thread_id" type="Graph connection">
The recurring series an occurrence belongs to, empty for one-off events. Groups the occurrences of one series together in the graph. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
The calendar's id. Limits a query to one calendar. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_name" type="Query filter">
The calendar's name. Limits a query to a calendar by name. Not searchable: the calendar name is not part of the event text.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
Always `calendar`. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's events. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `google_calendar`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="status" type="Stored only">
`confirmed` or `tentative`. It is not part of the event text.
</ResponseField>

</Accordion>

**Example searches**

- What was the agenda in the description of last Tuesday's planning meeting?
- Which meetings did Dana organize this month?
- Where is the offsite being held?

## How it fits into the graph

- Events use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Google Calendar creates**

- A changed occurrence of a recurring meeting to its series.
- Changed occurrences of the same series to each other, so they group together.
- No links to other tools, including Gmail invitations.

**People and groups**

- Each attendee, by email.
- The organizer only when the organizer is also an attendee.
- Attendee names and response statuses are kept with the event but do not identify people in the graph.

**Found in the text**

The event card: title, time, place, organizer, attendees and description. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Calendar sharing and event visibility settings.
- Event attachments, audio and video, and conference details beyond what the location or description says.
- Unchanged occurrences of a recurring series as documents of their own.
- Events last edited before the first sync's window.
- Cancellations: an event cancelled after it was synced can stay in HydraDB.
