Sync posts from the X (Twitter) accounts you list and, optionally, the direct messages of the account that authorized the connector. Each post is one document and includes the text of the post it quotes, replies to or retweets, when available. Direct messages are grouped into one document per conversation per time window, which can repeat up to 12 earlier messages for context.

X permissions are not imported, so direct messages are visible to everyone who can query the collection unless you set an access rule on the inbox. Retweets are skipped by default. Media is not fetched. Edited posts are not guaranteed to be refreshed, and deleted posts and messages stay in HydraDB. Reads count against your own X developer app.

## Permissions

<Warning>
Twitter permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Direct messages are private on X, but HydraDB does not limit them to the inbox owner. Set an access rule on the inbox before you sync it.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

X uses your own X developer app. For posts, use an app-only bearer token or a user access token. Direct messages need a user access token from the inbox owner, with a refresh token and your app's OAuth client credentials so syncing continues after the access token expires.

<ResponseField name="bearer_token" type="secret string">
An app-only bearer token for your X developer app. Reads posts only.
</ResponseField>

<Accordion title="Other credential options">

**User access token, for posts and direct messages**

<ResponseField name="access_token" type="secret string">
An OAuth 2.0 user access token from the inbox owner. Needed for direct messages.
</ResponseField>

<ResponseField name="refresh_token" type="secret string">
The matching refresh token. Without it, direct message syncing stops when the access token expires, after about two hours.
</ResponseField>

<ResponseField name="client_id" type="secret string">
Your app's OAuth client id, used to renew the access token.
</ResponseField>

<ResponseField name="client_secret" type="secret string">
Your app's OAuth client secret. The app must be a confidential client.
</ResponseField>

</Accordion>

**Connector settings**

<ResponseField name="handles" type="string list">
The X handles, or numeric user ids, whose posts to sync.
</ResponseField>

<ResponseField name="exclude_retweets" type="boolean">
Skip retweets. On by default.
</ResponseField>

<ResponseField name="exclude_replies" type="boolean">
Skip replies. Off by default.
</ResponseField>

<ResponseField name="sync_profiles" type="boolean">
Also read the profiles of the accounts you list, for display names and follower counts. Each profile costs one user read. Off by default.
</ResponseField>

<Accordion title="Connector-wide defaults (4)">

<ResponseField name="max_posts_per_account_per_sync" type="number">
The most posts read per account in one sync, 500 by default and at least 5. Use a whole number. Posts dropped because they fall outside the time window still count.
</ResponseField>

<ResponseField name="max_dms_per_sync" type="number">
The most direct message events read in one sync, 1,000 by default and at least 5. Use a whole number.
</ResponseField>

<ResponseField name="max_backfill_days" type="number">
How far back a first sync reaches when no history window is set, 90 days by default. Use a whole number. Configuring the connector sets a window, which takes its place.
</ResponseField>

<ResponseField name="dm_event_types" type="string">
Which direct message event types to read. `MessageCreate` by default.
</ResponseField>

</Accordion>

**For direct messages**

- `dm.read`: scope on the user access token.
- `tweet.read`: scope on the user access token.
- `users.read`: scope on the user access token.
- `offline.access`: scope on the user access token, so a refresh token is issued.
- `Read and write and Direct message`: app permission.

Changing the app's permission level later invalidates tokens already issued.

### Set it up

<Steps>
  <Step title="Prepare your X developer app">
    Use your own X developer app. Reads are billed to it. For direct messages, give it the Read and write and Direct message permission and make it a confidential client.
  </Step>
  <Step title="Get a token">
    For posts only, get an app-only bearer token. For direct messages, have the inbox owner authorize the app with the scopes above, and keep the access token and refresh token.
  </Step>
  <Step title="Create the connector">
    Paste `bearer_token`, or paste `access_token`, `refresh_token`, `client_id` and `client_secret`. List the accounts to follow in `handles`.
  </Step>
  <Step title="Select accounts and the inbox">
    HydraDB looks up each handle or id and lists it as an account to sync. A handle that cannot be found is rejected. With a user access token, HydraDB also lists the owner's inbox. Select the accounts, and select the inbox to sync direct messages.
  </Step>
</Steps>

One connector reads the posts of the accounts you list, and at most one inbox: that of the account that authorized its access token.

<Accordion title="Connect through the API">

Use provider `twitter` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Each selected account and the inbox reach back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the posts and direct messages created since the last sync. Direct message history that did not fit in one sync continues on later syncs with whatever is left of the read cap, so a busy inbox can delay older history.
- **Edits:** Edits are not tracked. An edited post is not guaranteed to be refreshed.
- **Deletions:** Posts and direct messages deleted on X stay searchable in HydraDB.
- The sync interval for this connector must be between 10 minutes and 6 hours.
- A direct message window is as long as the sync interval, kept between 10 minutes and 6 hours. Changing the interval changes the window for future syncs only. Documents already written keep the old size.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Twitter item

<ResponseField name="author" type="Searchable text, Graph identity">
The handle, without `@`, of the post's author or of whoever opened a direct message window, written as the From line. The graph records the item as sent by that account.
</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">
When the post was published, or when the newest message in a direct message window was sent, written as the Sent line.
</ResponseField>

<ResponseField name="thread_id" type="Graph connection">
The X conversation id. Groups every post, or every direct message window, of one conversation into one thread. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_id" type="Query filter">
For a post, the author's numeric user id. For direct messages, the conversation id. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_name" type="Query filter">
For a post, the author's `@handle`. For direct messages, `DM with` and the participants' handles. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.container_type" type="Query filter">
`twitter_account` for posts and `twitter_dm_conversation` for direct messages. Separates the two. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.conversation_id" type="Query filter">
The X conversation id. Limits a query to one thread or direct message conversation. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.urls" type="Searchable text, Query filter">
The full URLs of shared links. Finds items that link to a given URL. Searchable on posts, where the full URLs are in the text. Not searchable as a field on direct messages.
</ResponseField>

<ResponseField name="additional_metadata.referenced_post_id" type="Query filter">
For a post, the post it replies to, quotes or retweets. For a direct message window, the first post shared in it. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `twitter`. Not searchable.
</ResponseField>

### Posts

- **One document:** One post.
- **Title:** The post text on one line, cut to about 80 characters, or `Post by @handle` when there is no text. Search matches the post text, not this title.
- **Text:** `Name (@handle) on X`, then the post text with t.co short links replaced by their full URLs, then the text of the quoted, replied-to or retweeted post, labelled `Quoting`, `In reply to` or `Retweet of`. The author is written as a From line and the time as a Sent line.
- **Date:** When the post was published.
- **Link back:** The post's x.com link.
- **Files:** None. Media is not fetched.

<ResponseField name="additional_metadata.mentions" type="Searchable text, Query filter, Graph identity">
Handles mentioned in the post. Finds posts that mention a handle. The graph records each as mentioned. The handles also appear in the post text.
</ResponseField>

<ResponseField name="parent_id" type="Graph connection">
For a reply, the post it answers. Joins the reply to that post. Quotes and retweets are not linked this way. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_handle" type="Query filter">
The author's handle. Limits a query to one author. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_name" type="Query filter">
The author's display name. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_id" type="Query filter">
The author's numeric id. Keeps working after a handle change. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_followers" type="Query filter">
The author's follower count when the post was synced, only when `sync_profiles` is on. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.lang" type="Query filter">
The post's detected language. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.is_reply" type="Query filter">
Whether the post is a reply. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.is_retweet" type="Query filter">
Whether the post is a retweet. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.is_quote" type="Query filter">
Whether the post quotes another post. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.hashtags" type="Query filter">
Hashtags, without `#`. Limits a query to a hashtag. This field is not searchable, but hashtags stay in the post text.
</ResponseField>

<ResponseField name="Followed account" type="Access rule">
The selected account. An access rule you set on it governs its posts. Not searchable.
</ResponseField>

### Direct messages

- **One document:** All messages of one conversation inside one time window. The window is as long as the sync interval, between 10 minutes and 6 hours. A later sync rewrites the same window document with the complete window.
- **Title:** Built from the window's opening message and how many messages followed.
- **Text:** A single message shows its direction, sender and text, with the text of a shared post or a media count. A longer exchange shows each speaker and message, with up to 12 messages from the previous exchange under `Earlier in the conversation` and the current window under `New messages`. A media count appears only for a message with no text. Each window is marked as a direct message.
- **Date:** When the newest message in the window was sent.
- **Link back:** None.
- **Files:** None. Media is counted, not fetched.

<ResponseField name="mentions" type="Searchable text, Graph identity">
The known participants' handles. The graph records each as mentioned. The handles can also appear in the text with each speaker.
</ResponseField>

<ResponseField name="additional_metadata.author_handle" type="Query filter">
The handle of the window's opening sender only, not of every sender in it. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_name" type="Query filter">
The name of the window's opening sender. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.author_id" type="Query filter">
The numeric id of the window's opening sender. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.is_outbound" type="Query filter">
`true` only when every new message in the window was sent from the inbox. `false` covers both mixed and entirely inbound windows. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.message_count" type="Query filter">
How many messages the window holds. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.context_message_count" type="Query filter">
How many earlier messages the window repeats for context. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.participants" type="Query filter">
The handles of known participants. Members who never wrote in the history HydraDB read can be missing. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.participant_ids" type="Query filter">
Member ids, only when X provides them. Usually incomplete. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.is_group_conversation" type="Query filter">
`true` when the conversation is known to have more than two members. `false` or missing does not prove a one-to-one conversation. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.account_handle" type="Query filter">
The inbox owner's handle, when a message sent from the inbox shows it. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.counterpart_handles" type="Query filter">
The known participants other than the inbox owner. Left out when the owner's handle is not known. Not searchable.
</ResponseField>

<ResponseField name="additional_metadata.media_keys" type="Query filter">
X media keys. Marks windows that carried media. The media itself is not fetched. Not searchable.
</ResponseField>

<ResponseField name="Inbox" type="Access rule">
The selected inbox. An access rule you set on it governs its direct messages. Not searchable.
</ResponseField>

**Example searches**

- What has @competitor posted about pricing this month?
- Which posts from accounts we follow link to our blog?
- What did @jane and I discuss in direct messages about the partnership?

## How it fits into the graph

- Posts use the Message class.
- Direct messages use the Message class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Twitter creates**

- A reply to the post it answers.
- Every post, and every direct message window, to its conversation.
- Quotes and retweets are not linked. Their text is included in the post instead.
- No links to other tools.

**People and groups**

- The author of each post, and the opening sender of each direct message window.
- Handles mentioned in a post, and the known participants of a direct message conversation.

**Found in the text**

The post or exchange text, including quoted posts and full link URLs. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Media files.
- Lists of liked or bookmarked posts.
- Direct messages, unless you connect with a user access token and select the inbox.
- Retweets, unless you turn off `exclude_retweets`. Replies, when `exclude_replies` is on.
- Profiles as their own documents, and bios, images and other profile fields.
- Replies by accounts you did not list, unless their text arrives as part of a listed account's post.
- Deletions and edits after a post or message was synced.
