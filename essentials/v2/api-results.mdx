`POST /query` retrieves context for your question. By default, `data.llm_prompt` contains the question, matching passages, source references, and citation instructions in one Markdown string. Pass this string to your model and ask it to answer using the supplied context.

<span id="1-what-the-response-looks-like"></span>
<span id="1-read-the-response"></span>

## Choose a response format

Set `response_format` on the query request. The result is under `data` in the response envelope.

| `response_format` | Returned `data` |
|---|---|
| Omitted, the default | Object containing `llm_prompt` and individual results. |
| `"markdown"` | The same Markdown text returned directly as `data`. |
| `"structured"` | Object containing individual results, without `llm_prompt`. |

## Send context to your model

In SDK 2.1.7 or later, `build_string(result)` in Python and `buildString(result)` in TypeScript read `data.llm_prompt` into the `context` variable below. The model call then includes `context` and the original `question` in the same message.

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB
from hydra_db.helpers import build_string
from openai import OpenAI

hydra = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
openai_client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

question = "How does authentication work?"

result = hydra.query(
    database="your-database",
    collection="your-collection",
    query=question,
    type="knowledge",
    query_by="hybrid",
    mode="fast",
    graph_context=True,
)

context = build_string(result)

completion = openai_client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "system",
            "content": "You are a helpful assistant. Answer the user's question using only the context provided. If the answer is not in the context, say you don't know.",
        },
        {
            "role": "user",
            "content": f"Context:\n{context}\n\nQuestion: {question}",
        },
    ],
)

print(completion.choices[0].message.content)
```
```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";
import { buildString } from "@hydradb/sdk/helpers";
import OpenAI from "openai";

const hydra = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY });
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const question = "How does authentication work?";

const result = await hydra.query({
  database: "your-database",
  collection: "your-collection",
  query: question,
  type: "knowledge",
  queryBy: "hybrid",
  mode: "fast",
  graphContext: true,
});

const context = buildString(result);

const completion = await openai.chat.completions.create({
  model: "gpt-4o",
  messages: [
    {
      role: "system",
      content: "You are a helpful assistant. Answer the user's question using only the context provided. If the answer is not in the context, say you don't know.",
    },
    {
      role: "user",
      content: `Context:\n${context}\n\nQuestion: ${question}`,
    },
  ],
});

console.log(completion.choices[0].message.content);
```
```python Python SDK (Async)

import os

            {
                "role": "system",
                "content": "You are a helpful assistant. Answer the user's question using only the context provided. If the answer is not in the context, say you don't know.",
            },
            {
                "role": "user",
                "content": f"Context:\n{context}\n\nQuestion: {question}",
            },
        ],
    )

    print(completion.choices[0].message.content)

```

### Request Markdown only

Set `response_format: "markdown"` to return the same context text directly as `data`, instead of inside `data.llm_prompt`. The SDK helpers above handle both formats.

```json
{
  "database": "acme_corp",
  "query": "What is our refund policy?",
  "response_format": "markdown"
}
```

### Read citations and content labels

The prompt numbers ranked results as `[1]`, `[2]`, and so on. Explicitly linked results use `[R1]`, `[R2]`, and so on. Ask your model to keep these labels when citing the context.

A result can contain **Original content**, the source text, **Enriched content**, context HydraDB added, or both. Sections for related facts, dated facts, and sources appear when relevant. A query with no matches returns a no-results message rather than an empty prompt, including any filters that constrained the search.

## Work with structured results

Use `response_format: "structured"` to omit `llm_prompt` when your application formats the results itself. Individual passages, scores, and source details are available in both the default and structured responses.

<CodeGroup>
```python Python SDK
result = hydra.query(
    database="your-database",
    collection="your-collection",
    query="How does authentication work?",
    response_format="structured",
)

for chunk in result.data.chunks:
    print(chunk.source_title, chunk.chunk_content)
```
```typescript TypeScript SDK
const result = await hydra.query({
  database: "your-database",
  collection: "your-collection",
  query: "How does authentication work?",
  responseFormat: "structured",
});

if (!result.data || typeof result.data === "string") {
  throw new Error("Expected structured query results.");
}
for (const chunk of result.data.chunks ?? []) {
  console.log(chunk.sourceTitle, chunk.chunkContent);
}
```
```bash cURL
curl --fail-with-body 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "your-database",
    "collection": "your-collection",
    "query": "How does authentication work?",
    "response_format": "structured"
  }'
```

```json
              "canonical_predicate": "DEPENDS_ON",
              "context": "reason text"
            }
          }
        ]
      }
    ]
  },
  "additional_context": {
    "ctx-id-1": {
      "source_title": "related_doc.pdf",
      "chunk_content": "Extra related content..."
    }
  }

```

The structured fields are available when you need to inspect or format individual results:

- **`chunks`**: passages from matching documents or memories. Ranked by relevance; preserve the order HydraDB returns.
- **`sources`**: source IDs, titles, and URLs. Use them to display links when a source has a URL.
- **`graph_context.query_paths`**: chains of relationships connecting named people, services, or topics relevant to the query. See [Context Graphs](/essentials/v2/context-graphs).
- **`graph_context.chunk_relations`** + **`chunk_id_to_group_ids`**: per-chunk graph relations grouped by `group_id`, so you can attach the right triplets to each chunk.
- **`additional_context`** (legacy): a map keyed by `chunk_uuid`. When a chunk includes `extra_context_ids`, use those IDs to look up related chunks here.

## Combine knowledge and memories

Use one `POST /query` with `type: "all"`. HydraDB queries both stores in parallel and returns one merged, ranked result set.

This example searches shared documents in `company_docs` and the user's memories in `user_123`. Use the collections you ingested into; both must exist. For restricted documents, also send the caller's identity as `acl`. Use the printed context in the [model call shown above](#send-context-to-your-model).

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB
from hydra_db.helpers import build_string

hydra = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])

question = "What is our refund policy?"

result = hydra.query(
    database="acme_corp",
    collections=["company_docs", "user_123"],
    query=question,
    type="all",
    query_by="hybrid",
    mode="thinking",
)

print(build_string(result))
```
```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";
import { buildString } from "@hydradb/sdk/helpers";

const hydra = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY });

  collections: ["company_docs", "user_123"],
  query: question,
  type: "all",
  queryBy: "hybrid",
  mode: "thinking",
});

console.log(buildString(result));
```
```python Python SDK (Async)

import os

from hydra_db.helpers import build_string

    )

asyncio.run(main())
```
</CodeGroup>

If knowledge and memories need different search terms, make separate `POST /query` requests with `type: "knowledge"` and `type: "memory"`.

## Common mistakes

| Mistake | What goes wrong | Fix |
|---|---|---|
| Reading `data.llm_prompt` with `response_format: "structured"` | The prompt field is omitted | Read the structured fields, or omit `response_format` to get both. |
| Passing the raw result object to the LLM | Wastes tokens on IDs and metadata | Use `build_string` / `buildString`. |
| Not including `collection` (formerly `sub_tenant_id`) when querying memories | Queries the default collection instead of the user's | Always pass the same `collection` used at ingestion. |
| Including too many chunks | Token overflow or answer quality drops | Start at `max_results: 10`; reduce if needed. |
| Re-sorting chunks client-side | Overrides HydraDB's ranking | Preserve the server-returned order. |
| Missing a grounding instruction | The model invents answers when retrieval is thin | System prompt: answer only from the provided context. |
| Setting `graph_context: false` and expecting graph fields | Graph context will be omitted (in fast mode; thinking always returns it) | `graph_context` is on by default; only set it to `false` when you explicitly don't want graph data. |
| Using `query_forceful_relations` with `mode: "fast"` | Flag is ignored | `query_forceful_relations` only takes effect when `mode: "thinking"` (or `"auto"` routed to thinking). |
| Looking up `chunk_relations` without `chunk_id_to_group_ids` | The right relations don't attach to the right chunk | Use `chunk_id_to_group_ids[chunk_uuid]` to find the `group_id`s, then filter `chunk_relations` by them. |
