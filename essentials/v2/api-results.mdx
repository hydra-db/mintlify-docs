Use the context returned by `POST /query` as a model prompt, or read individual passages and source details. HydraDB retrieves the context. Your model writes the answer.

<a id="1-what-the-response-looks-like"></a>
<a id="1-read-the-response"></a>

## Choose a response format

Set `response_format` on the query request. The result is under `data` in the response envelope.

| `response_format` | Returned `data` |
|---|---|
| Omitted, the default | Result object with `llm_prompt`. |
| `"markdown"` | The prompt string. |
| `"structured"` | Result object without `llm_prompt`. |

## Send context to your model

With the default format, `data.llm_prompt` is ready to pass to your model alongside the question. You do not need to format the results yourself.

In SDK 2.1.7 or later, `build_string` / `buildString` returns that string unchanged. It also reads Markdown-only responses and can format responses from older servers.

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB
from hydra_db.helpers import build_string
from openai import OpenAI

hydra = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
openai_client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

question = "How does authentication work?"

result = hydra.query(
    database="your-database",
    collection="your-collection",
    query=question,
    type="knowledge",
    query_by="hybrid",
    mode="fast",
    graph_context=True,
)

context = build_string(result)

completion = openai_client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "system",
            "content": "You are a helpful assistant. Answer the user's question using only the context provided. If the answer is not in the context, say you don't know.",
        },
        {
            "role": "user",
            "content": f"Context:\n{context}\n\nQuestion: {question}",
        },
    ],
)

print(completion.choices[0].message.content)
```
```typescript TypeScript SDK

    },
    {
      role: "user",
      content: `Context:\n${context}\n\nQuestion: ${question}`,
    },
  ],
});

console.log(completion.choices[0].message.content);
```

### Request Markdown only

Add `response_format: "markdown"` to return the prompt as `data` directly. There is no `data.llm_prompt` field in this format. The SDK helper above handles either format.

```json
{
  "database": "acme_corp",
  "query": "What is our refund policy?",
  "response_format": "markdown"
}
```

### Read citations and content labels

The prompt numbers ranked results as `[1]`, `[2]`, and so on. Explicitly linked results use `[R1]`, `[R2]`, and so on. Ask your model to keep these labels when citing the context.

Each result separates **Original content**, the source text, from **Enriched content**, context HydraDB added. Sections for related facts, dated facts, and sources appear when relevant. A query with no matches returns a no-results message rather than an empty prompt, including any filters that constrained the search.

## Work with structured results

Set `response_format: "structured"` when you need individual passages, scores, or source details. The examples below print the matching passages. They do not call a model.

<CodeGroup>
```python Python SDK
result = hydra.query(
    database="your-database",
    collection="your-collection",
    query="How does authentication work?",
    response_format="structured",
)

for chunk in result.data.chunks:
    print(chunk.source_title, chunk.chunk_content)
```
```typescript TypeScript SDK
const result = await hydra.query({
  database: "your-database",
  collection: "your-collection",
  query: "How does authentication work?",
  responseFormat: "structured",
});

if (!result.data || typeof result.data === "string") {
  throw new Error("Expected structured query results.");
}
for (const chunk of result.data.chunks ?? []) {
  console.log(chunk.sourceTitle, chunk.chunkContent);
}
```
```bash cURL
curl --fail-with-body 'https://api.hydradb.com/query' \
  -H "Authorization: Bearer $HYDRA_DB_API_KEY" \
  -H "API-Version: 2" \
  -H "Content-Type: application/json" \
  -d '{
    "database": "your-database",
    "collection": "your-collection",
    "query": "How does authentication work?",
    "response_format": "structured"
  }'
```

```json
{
  "chunks": [
    {
      "chunk_uuid": "doc-001_chunk_0",
      "source_title": "my_document.pdf",
      "chunk_content": "Text content of the retrieved chunk...",
      "relevancy_score": 1.09,
      "extra_context_ids": ["ctx-id-1"],
      "additional_metadata": {
        "author": "Support Team"
      }
    }
  ],
  "graph_context": {
    "query_paths": [
      {
        "triplets": [
          {
            "source": { "name": "EntityA" },
            "target": { "name": "EntityB" },
            "relation": {
              "canonical_predicate": "DEPENDS_ON",
              "context": "reason text",
              "temporal_details": "2024-01"
            }
          }
        ]
      }
    ],
    "chunk_id_to_group_ids": {
      "doc-001_chunk_0": ["group-1"]
    },
    "chunk_relations": [
      {
        "group_id": "group-1",
        "triplets": [
          {
            "source": { "name": "EntityA" },
            "target": { "name": "EntityB" },
            "relation": {
              "canonical_predicate": "DEPENDS_ON",
              "context": "reason text"
            }
          }
        ]
      }
    ]
  },
  "additional_context": {
    "ctx-id-1": {
      "source_title": "related_doc.pdf",
      "chunk_content": "Extra related content..."
    }
  }
}
```

The structured fields are available when you need to inspect or format individual results:

- **`chunks`**: passages from matching documents or memories. Ranked by relevance; preserve the order HydraDB returns.
- **`sources`**: source IDs, titles, and URLs. Use them to display links when a source has a URL.
- **`graph_context.query_paths`**: chains of relationships connecting named people, services, or topics relevant to the query. See [Context Graphs](/essentials/v2/context-graphs).
- **`graph_context.chunk_relations`** + **`chunk_id_to_group_ids`**: per-chunk graph relations grouped by `group_id`, so you can attach the right triplets to each chunk.
- **`additional_context`** (legacy): a map keyed by `chunk_uuid`. When a chunk includes `extra_context_ids`, use those IDs to look up related chunks here.

## Combine knowledge and memories

Use one `POST /query` with `type: "all"`. HydraDB queries both stores in parallel and returns one merged, ranked result set.

This example searches shared documents in `company_docs` and the user's memories in `user_123`. Use the collections you ingested into; both must exist. For restricted documents, also send the caller's identity as `acl`.

<CodeGroup>
```python Python SDK
import os
from hydra_db import HydraDB
from hydra_db.helpers import build_string
from openai import OpenAI

hydra = HydraDB(token=os.environ["HYDRA_DB_API_KEY"])
openai_client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

question = "What is our refund policy?"

result = hydra.query(
    database="acme_corp",
    collections=["company_docs", "user_123"],
    query=question,
    type="all",
    query_by="hybrid",
    mode="thinking",
)

context = build_string(result)

completion = openai_client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "Answer using only the context provided."},
        {"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"},
    ],
)

print(completion.choices[0].message.content)
```

<Accordion title="Run separate searches for knowledge and memories">

If you need different searches for knowledge and memories, call `POST /query` twice in parallel. Each response includes its own formatted context and instructions:

<CodeGroup>
```python Python SDK
import asyncio
import os
from hydra_db import AsyncHydraDB
from hydra_db.helpers import build_string

hydra = AsyncHydraDB(token=os.environ["HYDRA_DB_API_KEY"])
question = "What is our refund policy?"

async def main():
    knowledge_result, memory_result = await asyncio.gather(
        hydra.query(
            database="acme_corp",
            collection="company_docs",
            query=question,
            type="knowledge",
            query_by="hybrid",
            mode="thinking",
        ),
        hydra.query(
            database="acme_corp",
            collection="user_123",
            query="answer style preferences",
            type="memory",
            query_by="hybrid",
        ),
    )

    prompt = (
        f"User preferences:\n{build_string(memory_result)}\n\n"
        f"Relevant docs:\n{build_string(knowledge_result)}\n\n"
        f"Question: {question}"
    )
    return prompt

asyncio.run(main())
```
```typescript TypeScript SDK
import { HydraDBClient } from "@hydradb/sdk";
import { buildString } from "@hydradb/sdk/helpers";

const hydra = new HydraDBClient({ token: process.env.HYDRA_DB_API_KEY });
const question = "What is our refund policy?";

const [knowledgeResult, memoryResult] = await Promise.all([
  hydra.query({
    database: "acme_corp",
    collection: "company_docs",
    query: question,
    type: "knowledge",
    queryBy: "hybrid",
    mode: "thinking",
  }),
  hydra.query({
    database: "acme_corp",
    collection: "user_123",
    query: "answer style preferences",
    type: "memory",
    queryBy: "hybrid",
  }),
]);

const prompt =
  `User preferences:\n${buildString(memoryResult)}\n\n` +
  `Relevant docs:\n${buildString(knowledgeResult)}\n\n` +
  `Question: ${question}`;
```
</CodeGroup>

If the memory query fails or times out, fall back to the knowledge-only prompt.

<a id="5-practical-guidance"></a>

## Practical guidance

- **Preserve server order:** Don't re-sort chunks client-side.
- **Start small on chunks:** `max_results: 10` is a reasonable default. Drop to 5 if you hit token limits, raise to 20 if you rerank downstream.
- **Use graph context selectively:** It helps with questions about relationships; for simple lookups, use `mode: "fast"` and `graph_context: false` to reduce prompt size. See [Context Graphs](/essentials/v2/context-graphs).
- **Give the model a grounding instruction:** Use a system prompt like "answer only from the provided context" to reduce unsupported answers when retrieval is thin.

<a id="6-common-mistakes"></a>

## Common mistakes

| Mistake | What goes wrong | Fix |
|---|---|---|
| Reading `data.llm_prompt` with `response_format: "structured"` | The prompt field is omitted | Read the structured fields, or omit `response_format` to get both. |
| Passing the raw result object to the LLM | Wastes tokens on IDs and metadata | Use `build_string` / `buildString`. |
| Not including `collection` (formerly `sub_tenant_id`) when querying memories | Queries the default collection instead of the user's | Always pass the same `collection` used at ingestion. |
| Including too many chunks | Token overflow or answer quality drops | Start at `max_results: 10`; reduce if needed. |
| Re-sorting chunks client-side | Overrides HydraDB's ranking | Preserve the server-returned order. |
| Missing a grounding instruction | The model invents answers when retrieval is thin | System prompt: answer only from the provided context. |
| Setting `graph_context: false` and expecting graph fields | Graph context will be omitted (in fast mode; thinking always returns it) | `graph_context` is on by default; only set it to `false` when you explicitly don't want graph data. |
| Using `query_forceful_relations` with `mode: "fast"` | Flag is ignored | `query_forceful_relations` only takes effect when `mode: "thinking"` (or `"auto"` routed to thinking). |
| Looking up `chunk_relations` without `chunk_id_to_group_ids` | The right relations don't attach to the right chunk | Use `chunk_id_to_group_ids[chunk_uuid]` to find the `group_id`s, then filter `chunk_relations` by them. |
