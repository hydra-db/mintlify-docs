## What syncs

**Indexed object types**

- `cards`

## Connect

Create one connector per account, using that account's credentials where required. Use a separate connector for a different account; see [account scopes](/essentials/v2/connectors#6-connect-several-accounts-from-one-provider). Shared destinations are allowed, but collection names do not authorize access.

1. Connect with a Guru API token: in Guru open Manage → Apps &amp; Integrations → API Access and click Generate User Token (Admins, and roles with the Manage Apps &amp; Integrations permission, can generate one, including on behalf of another user). A user token pairs the Guru username, usually the email, with the token (pass them as email and api_token) and reads exactly what that user can read; there is no scope picker. A collection token pairs the collection ID with the token (pass them as collection_id and api_token) and is read-only, scoped to that one collection; the connector then offers only that collection. Set exactly one of email or collection_id.
2. Pick the collections to sync in the resource-selection step; each card becomes one searchable document carrying its collection, folders, tags, verification state, verifiers, owner and comment count. Comment threads and replies are separate searchable comment documents linked to their card with comment_on and to their parent thread with reply_to, not embedded into the card. Each sync picks up cards edited, re-verified or commented on since the last one.
3. With permission-aware search on, each collection is restricted to the members of the Guru groups that can open it. Reading that needs the user token of a Guru Admin or of the collection's owner. With a collection token, or a member's token Guru refuses, the collection stays readable by everyone in this workspace and the connector shows a warning naming the token to use, until you reconnect with one or set an access rule on the resource.
4. Restricted (PRIVATE) cards are skipped by default: Guru shows them only to their author and the people they are shared with. Set include_private_cards to index them too; each is then indexed with exactly that audience (author and live collaborators, groups expanded to their members), enforced while permission-aware search is on. A card whose audience cannot be read completely is still indexed, with its collection's access.

Use provider `guru` with [Create Connector](/api-reference/v2/endpoint/create-connector), then [discover resources](/api-reference/v2/endpoint/discover-connector-resources) and [configure the resources](/api-reference/v2/endpoint/configure-connector) you want to sync. The [provider description](/api-reference/v2/endpoint/list-connector-providers) supplies the credential fields for your deployment.

## Common mistakes

- A provider page describes indexed content, not the access granted to your credentials. Select resources the connected account can read.
- Synced content is not automatically private to each person. Review [ACL enforcement](/essentials/v2/connectors#enforce-acl) and set resource access rules where needed.
- API-key requests must omit `enforce_acl`, including `false`. Only a signed-in human workspace owner or writer can change **Enforce ACL** in dashboard connector settings, and enabling it requires `acl_supported: true`.
