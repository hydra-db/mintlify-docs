Sync monitors with their runbook messages, dashboard summaries, SLO definitions, notebooks and incidents from one Datadog organization. Each is one document. Each sync also adds a log count for the sync window, and metric and SLO histories when you set their query or SLO id.

Raw logs, traces, metric points and dashboard widgets are not synced. Only incidents carry a Datadog restriction: with Enforce ACL on, a private incident is hidden from everyone, including its participants. Items deleted in Datadog can stay in HydraDB.

## Permissions

Turn on **Enforce ACL** for this connector to make search follow Datadog permissions. With Enforce ACL off, HydraDB does not enforce them. Only a workspace owner or writer signed in to HydraDB can turn it on. API-key requests must omit `enforce_acl`, including `false`. See [Enforce ACL](/essentials/v2/connectors#enforce-acl).

- **Who can read an item:** Only incidents carry a Datadog restriction. An incident Datadog marks private can be read by no one, not even its participants, because Datadog does not list them. Monitors, dashboards, SLOs, notebooks, log and metric summaries, and incidents visible to the organization follow the access rule you set on the resource. With no rule, everyone who can query the collection can read them.
- **How a person is identified:** No people are read. A private incident is closed to everyone.
- **When permissions cannot be read:** If Datadog reports an incident visibility HydraDB does not recognise, HydraDB makes no permission claim for that incident. It follows the access rule you set on its resource. With no rule, everyone who can query the collection can read it.
- With Enforce ACL off, private incidents are searchable like any other item.

You can also [set your own rule on a resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).

## Before you connect

### Credentials

Datadog uses an API key and an application key. The application key's scopes decide what syncs.

<ResponseField name="api_key" type="secret string" required>
A Datadog API key, from Organization Settings, API Keys. It identifies your org.
</ResponseField>

<ResponseField name="app_key" type="secret string" required>
A Datadog application key, from Organization Settings, Application Keys. It is created without scopes, so edit it afterwards to add the scopes below.
</ResponseField>

**Connector settings**

<ResponseField name="site" type="string">
Your Datadog site if it is not US1, for example `us5.datadoghq.com` or `datadoghq.eu`.
</ResponseField>

<ResponseField name="log_query" type="string">
A full logs query to count. Takes priority over `log_service`.
</ResponseField>

<ResponseField name="log_service" type="string">
One service name to narrow the log count. Ignored when `log_query` is set.
</ResponseField>

<ResponseField name="log_measure" type="string">
A log measure to sum alongside the count, for example `@duration`.
</ResponseField>

<ResponseField name="metric_query" type="string">
A metrics query to sync as a history. Leave it blank to skip metrics.
</ResponseField>

<ResponseField name="slo_id_us" type="string">
An SLO id whose history to sync, labelled US. Every SLO id field reads from your configured site.
</ResponseField>

<ResponseField name="slo_id_eu" type="string">
An SLO id whose history to sync, labelled EU.
</ResponseField>

<ResponseField name="slo_id_ca" type="string">
An SLO id whose history to sync, labelled CA.
</ResponseField>

**Scopes to add to the application key**

- `timeseries_query`: runs `metric_query`.
- `slos_read`: reads SLO history.
- `logs_read_data`: runs the log count.
- `monitors_read`
- `dashboards_read`
- `notebooks_read`
- `incident_read`: if Datadog refuses it on the first request, incidents are skipped and everything else syncs.

An application key left without scopes has its owner's full permissions. Set exactly these scopes. Most refused reads fail the sync.

### Set it up

<Steps>
  <Step title="Create the keys">
    In Datadog, create an API key under Organization Settings, API Keys, and an application key under Organization Settings, Application Keys.
  </Step>
  <Step title="Scope the application key">
    Open the new application key and edit its scopes to exactly the list above.
  </Step>
  <Step title="Create the connector">
    Paste the keys as `api_key` and `app_key`. Set `site` if your org is not on US1.
  </Step>
  <Step title="Select All data">
    There is nothing to browse. Select the single All data resource.
  </Step>
  <Step title="Choose what to summarise">
    Narrow the log count with `log_query` or `log_service`, and add `log_measure` for a sum. Left blank, logs are still counted across the default `main` index, normally as one total. Set `metric_query` and the SLO id fields to sync those histories. Left blank, they are skipped.
  </Step>
</Steps>

One connector reads one Datadog organization on one site.

<Accordion title="Connect through the API">

Use provider `datadog` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Monitors, dashboards, SLOs, notebooks and incidents are read in full, whatever their age. The log count, metric history and SLO history cover the window set by `lookback_days`, 30 days by default. Each metric or SLO history document covers the month up to one day, not that day alone.
- **New and changed items:** Monitors, dashboards, SLOs, notebooks and incidents are read in full on every sync, and ones that did not change are skipped. Metric and SLO histories add documents as days pass. The log count is recalculated for each sync window.
- **Edits:** A changed monitor, dashboard, SLO, notebook or incident updates its document on the next sync.
- **Deletions:** Items deleted in Datadog can stay searchable in HydraDB. Dashboards Datadog has marked as deleted are not synced.
- A changed log count can become a new document instead of replacing the old one, so earlier counts can stay searchable.
- An unknown metric can return an empty history.
- If HydraDB cannot read every incident, the sync fails instead of keeping a partial list.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### On every Datadog item

<ResponseField name="additional_metadata.datadog_stream" type="Query filter">
The kind of record: `monitors`, `dashboards`, `slos`, `notebooks`, `incidents`, `aggregate_logs`, `metric_response_time`, `slo_history_us_prod`, `slo_history_eu_prod` or `slo_history_ca_prod`. Keeps only monitors, only incidents, and so on. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's items. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `datadog`. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="stream_type" type="Stored only">
The kind of record, the same value as `additional_metadata.datadog_stream`.
</ResponseField>

</Accordion>

### Monitors

- **One document:** One monitor.
- **Title:** The monitor name, else `Datadog monitor`.
- **Text:** The name, then `Type`, `Status`, `Priority`, `Query`, `Tags`, `Created by` and `Modified` lines, then the monitor message, usually the runbook, word for word. The title is searchable too.
- **Date:** When the monitor was last modified.
- **Link back:** None.

<ResponseField name="Modified" type="Searchable text, Result date">
When the monitor was last modified, written as the `Modified` line.
</ResponseField>

<ResponseField name="Service tags" type="Graph connection">
Each `service:` tag links the monitor to that service, as `service:<name>`, together with the SLOs and incidents of the same service. The tags themselves are searchable in the `Tags` line. Not searchable as links.
</ResponseField>

<ResponseField name="Composite monitor query" type="Graph connection">
A composite monitor links to each monitor in its query. Not searchable as links.
</ResponseField>

### Dashboards

- **One document:** One dashboard summary, without its widgets.
- **Title:** The dashboard title, else `Datadog dashboard`.
- **Text:** The title, then `Description`, `Author`, `Layout`, `URL` and `Modified` lines.
- **Date:** When the dashboard was last modified.
- **Link back:** None. The dashboard's address is the searchable `URL` line.

<ResponseField name="Modified" type="Searchable text, Result date">
When the dashboard was last modified, written as the `Modified` line.
</ResponseField>

### SLOs

- **One document:** One SLO definition.
- **Title:** The SLO name, else `Datadog SLO`.
- **Text:** The name, then `Description`, `Type`, `Timeframe`, the target or per-timeframe thresholds, the `Numerator` and `Denominator` queries, and `Tags`. The title is searchable too.
- **Date:** When the SLO was last modified.
- **Link back:** None.

<ResponseField name="Monitors" type="Graph connection">
Links the SLO to each monitor it is built on. Not searchable.
</ResponseField>

<ResponseField name="Service tags" type="Graph connection">
Each `service:` tag links the SLO to that service, as `service:<name>`. Not searchable as links.
</ResponseField>

<ResponseField name="Modified" type="Result date">
When the SLO was last modified. Not searchable.
</ResponseField>

### Notebooks

- **One document:** One notebook with its markdown cells.
- **Title:** The notebook name, else `Datadog notebook`.
- **Text:** The name, then `Author`, `Status` and `Modified` lines, then the text of every markdown cell. Graph cells add nothing. The title is searchable too.
- **Date:** When the notebook was last modified.
- **Link back:** None.

<ResponseField name="Modified" type="Searchable text, Result date">
When the notebook was last modified, written as the `Modified` line.
</ResponseField>

### Incidents

- **One document:** One declared incident, private ones included.
- **Title:** The incident title, else `Datadog incident`.
- **Text:** The title, then `Visibility`, `State`, `Severity`, `Customer impacted`, `Customer impact scope`, `Declared`, `Detected` and `Resolved` lines, and the incident's own fields, such as services and teams.
- **Date:** When the incident was last modified.
- **Link back:** None.
- **Files:** A postmortem notebook attached to the incident becomes a link to that notebook. Other attachments are not read.

<ResponseField name="visibility" type="Searchable text, Access rule">
`organization` or `private`, written as the `Visibility` line. With Enforce ACL on, a private incident is hidden from everyone.
</ResponseField>

<ResponseField name="Postmortem" type="Graph connection">
Links the incident to its postmortem notebook. Not searchable as a link.
</ResponseField>

<ResponseField name="Services" type="Graph connection">
Each service named on the incident links it to that service, as `service:<name>`. Not searchable as links.
</ResponseField>

<ResponseField name="Modified" type="Result date">
When the incident was last modified. Not searchable.
</ResponseField>

### Log counts

- **One document:** One log count for the sync window, usually a single total. Individual log messages are not synced.
- **Title:** `Datadog log aggregate`, with the host and status added when present.
- **Text:** `Host`, `Status` and `Count` lines, and the sum of `log_measure` when set. The title is searchable too.
- **Date:** None.
- **Link back:** None.

<ResponseField name="host, status" type="Searchable text">
The host and status the count is grouped by, in the title and text. Usually empty for the default total.
</ResponseField>

### Metric histories

- **One document:** One window of `metric_query`. Only when `metric_query` is set.
- **Title:** `Datadog metric:` followed by the metric or query.
- **Text:** `Query` and `Window` lines, and one `Series` line per returned series with a summary of its points. The title is searchable too.
- **Date:** The end of the window.
- **Link back:** None.

<ResponseField name="query, metric, window_start, window_end" type="Searchable text, Result date">
The query, the metric name and the window. The window end is the result date.
</ResponseField>

### SLO histories

- **One document:** One history window of an SLO id set in `slo_id_us`, `slo_id_eu` or `slo_id_ca`.
- **Title:** A `Datadog SLO` history title with the SLO name.
- **Text:** `SLO`, `Description`, `SLI Value`, `Target`, `Type`, `Tags`, `Creator`, `Window`, `Region` and `SLO Id` lines. The title is searchable too.
- **Date:** The end of the window.
- **Link back:** None.

<ResponseField name="slo_id" type="Searchable text, Graph connection">
The SLO id, written as the `SLO Id` line. Links the history window to the SLO's own record when it is synced.
</ResponseField>

<ResponseField name="sli_value, target, region" type="Searchable text">
The measured value, the target and the region label. The region is a label only.
</ResponseField>

<ResponseField name="window_start, window_end" type="Searchable text, Result date">
The history period, written as the `Window` line. The window end is the result date.
</ResponseField>

**Example searches**

- What is the runbook for the checkout latency monitor?
- Which SLOs are built on the api-errors monitor?
- What did the on-call write in the database migration notebook?

## How it fits into the graph

- Monitors use the Record class.
- Dashboards use the Record class.
- SLOs use the Record class.
- Notebooks use the Record class.
- Incidents use the Record class.
- Log counts use the Record class.
- Metric histories use the Record class.
- SLO histories use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Datadog creates**

- An SLO to each monitor it is built on.
- A composite monitor to each monitor in its query.
- An incident to its postmortem notebook.
- An SLO history window to its SLO.
- Monitors, SLOs and incidents to their service, from `service:` tags and incident service fields.
- Dashboards are not linked to the monitors or SLOs they show, because widgets are not synced.
- Links reach only items this connector has synced, that are not deleted. No links to items in other tools.

**People and groups**

No one is attached as a person in the graph. Monitor creators and dashboard and notebook authors appear only in the text.

**Found in the text**

Monitor messages, notebook cells, descriptions and incident text. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Dashboard widgets and graphs.
- Raw logs, traces, events and metric points beyond the log count, `metric_query` and the SLO ids you set.
- Log indexes other than `main`.
- Notebook graph cells.
- Incident timelines, to-dos and attachments other than postmortem notebook links.
- Synthetics, security signals, RUM and APM.
- Dashboards Datadog has marked as deleted.
