Permanently deletes a database and everything in it: ingested knowledge, memories, the metadata schema, vector indices, and graphs.

<Warning>
This action is irreversible. There is no soft-delete and no recovery window. The examples use a placeholder name, `database_to_delete`. Replace it with the database you mean to destroy before running them, and check the name twice on a shared or team account, where you may not be the only one using it.
</Warning>

<RequestExample>
```python Python SDK
response = client.databases.delete(database="database_to_delete")
```
```typescript TypeScript SDK
const response = await client.databases.delete({
  database: "database_to_delete",
});
```
```bash cURL
curl -X DELETE 'https://api.hydradb.com/databases?database=database_to_delete' \
  -H "Authorization: Bearer <your_api_key>" \
  -H "API-Version: 2"
```
</RequestExample>

## Deletion completion

Deletion is asynchronous: the endpoint returns once the database is deregistered, and cleanup of vector stores, graphs, and storage objects runs in the background for a few minutes. Treat deletion as complete when the database no longer appears in `GET /databases`, or when `GET /databases/status?database=...` returns `DATABASE_NOT_FOUND`.

**Reusing the database name:** After deletion completes, the same `database` can be used in a new `POST /databases` request. Until then, do not re-create the database or retry ingestion or queries against it.

**Stop in-flight work first:** Stop all ingestion, polling, query, and background jobs targeting this database before deleting. Calls made after deregistration can fail with `DATABASE_NOT_FOUND` even while infrastructure cleanup is still running.

**Repeat calls:** Deleting an already-deleted database returns `404 DATABASE_NOT_FOUND`. Deleting a database that is still deleting returns `200` again. Deleting a database that is still provisioning, or whose provisioning or earlier deletion failed, is treated as a request to tear down that database.

## Errors

Common codes: `400 INVALID_INPUT` (missing `database`), `401 UNAUTHORIZED`, `404 DATABASE_NOT_FOUND`, and `500 INTERNAL_ERROR` (transient; retry the same `DELETE`). See [Error Responses](/api-reference/v2/error-responses) for the full list.
