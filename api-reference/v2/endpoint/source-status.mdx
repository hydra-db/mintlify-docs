Ingestion is asynchronous. Call this endpoint with the IDs returned by [Ingest Context](/api-reference/v2/endpoint/ingest-context) to learn when each document, app source, or memory is ready to query.

To be notified instead of polling, register a webhook for `indexing.status_changed` events. HydraDB sends a `POST` to your endpoint when a source reaches a terminal state (`completed` or `errored`). See [Webhooks](/api-reference/v2/endpoint/webhooks-overview) for setup and receiver examples.

<RequestExample>

```python Python SDK
status = client.context.status(
    database="acme_corp",
    collection="team_docs",
    ids=["policy_main", "runbook_deploy", "typo_in_id"],
)
```

```typescript TypeScript SDK
const status = await client.context.status({
  database: "acme_corp",
  collection: "team_docs",
  ids: ["policy_main", "runbook_deploy", "typo_in_id"],
});
```

## Passing IDs

- Send IDs in `ids`, a single ID in `id`, or both. HydraDB merges them. At least one ID is required.
- `ids` accepts repeated parameters (`ids=a&ids=b`) or one comma-joined value (`ids=a,b`). Source IDs never contain commas (ingest rejects them), so the comma-joined form always splits unambiguously.
- Whitespace is trimmed, empty entries are dropped, and duplicates are removed.

## Status values

Each entry in `data.statuses` describes one requested ID. Read its `indexing_status`:


| Status | Searchable? | Meaning |
| --- | --- | --- |
| `queued` | No | Accepted by the server, not yet picked up by a worker. |
| `processing` | No | Content is being parsed, chunked, and embedded. |
| `graph_creation` | **Yes** | Searchable through `/query`. Graph creation is still in progress. |
| `completed` | Yes | Fully indexed and graphed. Ready for all retrieval modes. |
| `errored` | No | Indexing failed. Inspect `error_code` and `error_message`. Terminal. |

## Error code values

`error_code` explains why an ID was not found or ingestion failed. It is empty unless `indexing_status` is `errored`.

| `error_code` | Meaning | What to do |
| --- | --- | --- |
| `FILE_NOT_FOUND` | The ID was not found in this database and collection. | Check the ID and scope, or ingest the source. |
| `E####` | Ingestion failed. | Follow the [error code guidance](/api-reference/v2/error-responses#ingestion-error-codes). |

- `error_message` explains an ingestion failure. It is empty otherwise, including for `FILE_NOT_FOUND`.
- `message` describes the lookup, not indexing. Use `indexing_status` and `error_code` in your application logic. Message text may change.
- Status records can expire. A source that completed still reports `completed` after its record expires. A source that never finished before its record expired reports `errored` with `E9004`; ingest it again.

## Polling patterns

### Stop when content is searchable

Use this for most retrieval flows. At `graph_creation`, chunks are indexed and a query can return them.

<CodeGroup>

```python Python
import time

ids = ["policy_main", "runbook_deploy"]

while True:
    response = client.context.status(
        database="acme_corp",
        collection="team_docs",
        ids=ids,
    )
    statuses = [s.indexing_status for s in response.data.statuses]

    if len(statuses) == len(ids) and all(s in ("graph_creation", "completed") for s in statuses):
        break
    if any(s == "errored" for s in statuses):
        raise RuntimeError("Context processing failed")

    time.sleep(5)
```

```typescript TypeScript
const ids = ["policy_main", "runbook_deploy"];

while (true) {
  const response = await client.context.status({
    database: "acme_corp",
    collection: "team_docs",
    ids: ids,
  });

  const statuses = response.data?.statuses?.map((s) => s.indexingStatus) ?? [];
  if (statuses.length === ids.length && statuses.every((s) => s === "graph_creation" || s === "completed")) break;
  if (statuses.some((s) => s === "errored")) throw new Error("Context processing failed");

  await new Promise((r) => setTimeout(r, 5000));
}
```

</CodeGroup>

### Stop when graph processing is complete

Use this before graph-heavy operations such as `/context/relations`, or when you require complete `graph_context`.

```python
import time

ids = ["policy_main", "runbook_deploy"]

while True:
    response = client.context.status(
        database="acme_corp",
        collection="team_docs",
        ids=ids,
    )
    statuses = [s.indexing_status for s in response.data.statuses]

    if len(statuses) == len(ids) and all(s == "completed" for s in statuses):
        break
    if any(s == "errored" for s in statuses):
        raise RuntimeError("Graph processing failed")

    time.sleep(5)
```

Typical indexing time:

- **Memories** (text, markdown, conversation pairs): seconds
- **Small documents** (under 50 pages): 1 to 5 minutes
- **Large documents** (50\+ pages): 5 to 15 minutes

## Errors

Common codes: `400 INVALID_INPUT` (for example `database` and `tenant_id` both sent with different values), `404 DATABASE_NOT_FOUND`, `422 VALIDATION_ERROR` (missing `database`, or no ID). See [Error Responses](/api-reference/v2/error-responses) for the full list.
