Sync daily search performance reports for one Search Console property. Each report row is one small document: one day for one search query, page, country or device, or one day for the whole property, with its clicks, impressions, click-through rate and average position. A busy site produces one document per query per day.

Search Console permissions are not imported, so every synced row is visible to everyone who can query the collection unless you set an access rule. Only web search performance is read. Rows that drop out of a later report stay in HydraDB.

<Note>
Google Search Console is in beta.
</Note>

## Permissions

<Warning>
Google Search Console permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Search Console uses a Google service-account JSON key together with the property to read.

<ResponseField name="client_secrets" type="secret string" required>
The service account's JSON key, pasted whole.
</ResponseField>

<ResponseField name="site_url" type="string" required>
The Search Console property to read, written as Search Console names it: a URL-prefix property such as `https://example.com/`, or a domain property such as `sc-domain:example.com`.
</ResponseField>

**Scopes the connector requests**

- `https://www.googleapis.com/auth/webmasters`
- `https://www.googleapis.com/auth/webmasters.readonly`

### Set it up

<Steps>
  <Step title="Create a service account key">
    In Google Cloud, create a service account and download its JSON key.
  </Step>
  <Step title="Create the connector">
    Paste the key as `client_secrets` and the property as `site_url`.
  </Step>
  <Step title="Select the property">
    HydraDB lists one `All data` resource for the property. Select it. Report types cannot be selected separately.
  </Step>
</Steps>

One connector reads one Search Console property.

<Accordion title="Connect through the API">

Use provider `google_search_console` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** Reaches back the window set by `lookback_days`, 30 days by default.
- **New and changed items:** Each sync reads the days since the last sync, plus the three days before them again. The current UTC day is not read until the next day. The freshest data Search Console has, which can still change, is included.
- **Edits:** Rows for the three re-read days replace their earlier documents, so late changes Search Console makes to those days come across.
- **Deletions:** Rows are never removed. A row that drops out of a later report stays searchable in HydraDB.
- On a day with more than 50,000 rows in one report, some of that day's rows are skipped.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Report rows

- **One document:** One day of one report: one search query, one page, one country or one device, or the whole property for that day.
- **Title:** For a query row, the query in quotes followed by ` - search performance (<date>)`. For a page, country, device or keys row, the value followed by ` - search performance (<date>)`. For a whole-property row, `Search performance for <site> (<date>)`.
- **Text:** The title, then `Site`, the row's own line (`Query`, `Page`, `Country`, `Device` or `Keys`), `Date`, `Clicks`, `Impressions`, `CTR` and `Avg position` lines. `CTR` is a percentage with two decimals and `Avg position` has one decimal. Empty values are left out.
- **Date:** The report day, at midnight UTC.
- **Link back:** None.
- **Files:** None.

<ResponseField name="query, page, country, device, keys" type="Searchable text">
The value the row reports on, written into the title and its own line. The keys report asks only for the date, so its rows repeat the whole-property daily totals.
</ResponseField>

<ResponseField name="clicks, impressions, ctr, position" type="Searchable text">
The day's metrics, written as the `Clicks`, `Impressions`, `CTR` and `Avg position` lines.
</ResponseField>

<ResponseField name="date" type="Searchable text, Result date">
The report day. It is written into the title and the `Date` line and sets the result date.
</ResponseField>

<ResponseField name="site_url" type="Searchable text">
The property, written into the `Site` line with everything up to the first colon removed. `https://example.com/` reads as `//example.com/` and `sc-domain:example.com` reads as `example.com`.
</ResponseField>

<ResponseField name="additional_metadata.google_search_console_stream" type="Query filter">
The report the row came from: `performance_report_query`, `performance_report_page`, `performance_report_date`, `performance_report_country`, `performance_report_device` or `performance_report_keys`. Limits a query to one report, for example only per-query rows. Not searchable.
</ResponseField>

<ResponseField name="connector_id" type="Query filter">
Limits a query to this connector's rows. Not searchable.
</ResponseField>

<ResponseField name="provider" type="Query filter">
Always `google-search-console`, with hyphens. A filter on `google_search_console` matches nothing. Not searchable.
</ResponseField>

<Accordion title="Stored only, not searchable (1)">

<ResponseField name="stream_type" type="Stored only">
The report the row came from, shown when you inspect the item. To limit a query to one report, use `additional_metadata.google_search_console_stream`.
</ResponseField>

</Accordion>

**Example searches**

- How did the search query "running shoes" perform on 2026-11-03?
- How many clicks and impressions did the /pricing page get on 2026-11-03?
- What was our average position on mobile devices last week?

## How it fits into the graph

- Report rows use the Record class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Google Search Console creates**

- None. Rows are not linked to each other, to pages or to the property.
- No links to other tools.

**People and groups**

No people or groups are attached to rows.

**Found in the text**

The report text: the site, the query, page, country or device, the date and the metrics. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Image, video and news search performance. Only web search is read.
- URL inspection, index coverage, sitemaps and other Search Console reports.
- Query and page pairs as one combined report.
- Properties other than the one set in `site_url`.
- Removals: rows that drop out of a later report stay in HydraDB.
