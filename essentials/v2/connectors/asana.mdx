Sync tasks, subtasks, comments and project overviews from the Asana projects you select. Each task and subtask is one document. Each comment on a task is its own document, linked to the task. Each project is one overview page. Tasks link to their parent task, their projects and the tasks they block or are blocked by.

Asana permissions are not imported, so every synced item is visible to everyone who can query the collection unless you set an access rule. A task in two selected projects is stored once per project. Attachments, task activity other than comments, tags and custom fields are not synced. Items deleted in Asana stay in HydraDB.

## Permissions

<Warning>
Asana permissions are not imported, so **Enforce ACL** is unavailable for this connector. Every synced item is visible to everyone who can query the collection, unless you [set an access rule on the resource](/essentials/v2/connectors#set-your-own-rule-on-a-resource).
</Warning>

- Asana project privacy, project membership and per-task visibility are not reproduced. Set an access rule on each project that should be restricted.
- A task in two selected projects is stored as one copy per project, and each copy follows its own project's rule.

API-key requests must omit `enforce_acl`, including `false`. See [ACL on synced content](/essentials/v2/connectors#5-acl-native-rbac-awareness).

## Before you connect

### Credentials

Asana uses a personal access token. It has no scopes to choose: it sees what its user sees.

<ResponseField name="personal_access_token" type="secret string" required>
An Asana personal access token.
</ResponseField>

Asana limits requests per token: 150 a minute on free domains and 1,500 on paid ones. A dedicated token keeps this connector from sharing that limit with other automations. To rotate it, create a new token, update the connector, check that a sync succeeds, then revoke the old token. Removing the token's user invalidates the token.

### Set it up

<Steps>
  <Step title="Create a token">
    In Asana's Developer Console, under My apps, Personal access tokens, create a token. A dedicated integration user works best. Add that user to every project you plan to select.
  </Step>
  <Step title="Create the connector">
    Paste the token as `personal_access_token`.
  </Step>
  <Step title="Select projects">
    HydraDB lists every non-archived project in every workspace the token can see. Select the projects to sync.
  </Step>
</Steps>

One connector reads what one token's Asana user can see, across that user's workspaces.

<Accordion title="Connect through the API">

Use provider `asana` with [Create Connector](/api-reference/v2/endpoint/create-connector). Then call [Discover Connector Resources](/api-reference/v2/endpoint/discover-connector-resources) to list the resources the connector can sync, and [Configure Connector](/api-reference/v2/endpoint/configure-connector) to choose what to sync.

</Accordion>

## Keeping in sync

- **First sync:** A newly selected project reads back the window set by `lookback_days`, 30 days by default, measured on when tasks and projects were last modified.
- **New and changed items:** Each sync reads the tasks, subtasks and projects modified since the last sync. Comments are read again on every sync, without a time window.
- **Edits:** An edited task or project is picked up through its modified time and updates its document. An edited comment is picked up because comments are read again on every sync.
- **Deletions:** Tasks, comments and projects deleted in Asana stay searchable in HydraDB.
- A project that refuses access on the first request is skipped and reported, and its unread window is kept for a later sync.

After the first sync, HydraDB syncs every hour by default. Set `sync_interval_seconds` on the connector to change it.

## What gets synced

### Tasks and subtasks

- **One document:** One task or subtask, as it appears in one selected project. Its comments are separate documents.
- **Title:** The task name, or `Asana task` and its id when the name is empty.
- **Text:** The task notes as plain text. A task with no notes gets a short summary instead: name, assignee, due date, status (`Open` or `Completed`) and projects. A subtask ends with a `Parent task` line that names its parent. The assignee, creation date, task key and parent are written as lines too. The title is searchable too.
- **Date:** When the task was last modified, or when it was created if there is no modification time.
- **Link back:** The task's Asana permalink.
- **Files:** Task attachments and their contents are not synced.

### Comments

- **One document:** One comment on a task. A task in two selected projects has a copy of each comment per project.
- **Title:** `Comment by <author> on <task name>`, leaving out whichever part is missing.
- **Text:** The comment as plain text, then a `Parent task` line that names the task. The author, the posting time and the task's key are written with it.
- **Date:** When the comment was posted.
- **Link back:** None.

</ResponseField>

<ResponseField name="created_at" type="Searchable text, Result date">

</ResponseField>

<ResponseField name="parent_id" type="Searchable text, Graph connection">

### Projects

- **One document:** One selected Asana project, as an overview page.
- **Title:** The project name, or `Asana project` and its id when the name is empty.
- **Text:** The project notes as plain text, then the title of the latest status update when Asana supplies one. A project with neither is written as `Project: <name>`. The modification time is written as the `Updated` line. The title is searchable too.
- **Date:** When the project was last modified, or when it was created if there is no modification time.
- **Link back:** The project's Asana permalink.

## How it fits into the graph

- Tasks and subtasks use the Ticket class.
- Comments use the Comment class.
- Projects use the Page class.

[Graph classes](/essentials/v2/connector-providers#graph-classes) explains each class.

**Connections Asana creates**

- A subtask to its parent task.
- A task to each project it belongs to.
- A task to each task it depends on, and to each task that depends on it.
- A comment to its task.
- No links to items in other tools.

**People and groups**

- The assignee of each task.
- The author of each comment.
- People @mentioned in task notes and comments.
- A project's owner is kept on the project but not added to the graph.

**Found in the text**

Task notes, comment text and project notes. HydraDB identifies people, organizations, projects and other named things in this text. To steer what it looks for, use [custom instructions](/essentials/v2/connectors#4-custom-ingestion-instructions).

## Not synced

- Projects you did not select. Archived projects are not listed for selection.
- Task activity other than comments, such as assignments and field changes.
- Task attachments and their contents.
- Sections, tags, custom fields and portfolios, including tag and custom-field values on tasks.
- Comment likes, task followers and start dates.
- Project status contents, apart from the latest status update's title.
- Comments on a nested subtask that does not appear in its project's task list.
